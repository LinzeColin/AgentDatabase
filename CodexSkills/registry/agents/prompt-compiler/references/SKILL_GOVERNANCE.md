# Skill 路由、白箱迭代、专家复审与验收记录

本文件记录方法合同如何转化为代码和测试。无法提供真实隔离 SubAgent 或人物 dossier 时，审查标记为 `role_separated_same_model`，不冒充独立专家团队 PASS。Teleiosis 采用合同级应用，不声称原生正式运行。

## Pass A｜Baseline / Discovery

| 方法 | 发现 | 落地 | Developer Burden Delta |
|---|---|---|---|
| Skill Catalog 路由 | v0.0.0.2 以综合分和等份预算为主，不能保证逐维第一 | 命中文脉中枢、Teleiosis、专家角色、Verifier、Grilling、行动优先合同 | 删除 Build Agent 的重新研究与规则解释 |
| Teleiosis 合同 | Baseline 与 Candidate 缺少逐维支配不变量 | 冻结 15 维冠军合同、状态机和回滚语义 | 关闭“综合分掩盖弱项”P0 |
| 专家角色复审 | 竞品仅作候选源会造成虚假“吸收即超越” | 冻结同层对手 + 下层执行器双角色 | 关闭竞品身份消失 P0 |
| Verifier | 报告布尔字段可被篡改 | 设计独立证据文件和哈希重读 | 关闭伪发布 P0 |

## Pass B｜Candidate / Remediation

| 视角 | 实质变化 | 关闭风险 |
|---|---|---|
| 产品与价值 | Pursuing Goal 改为每个冻结维度第一 | 目标漂移 P1 |
| 架构 | 四竞品双平面、Prompt Compiler 自身独立候选臂 | 同层竞争被降级 P0 |
| 算法 | 最低探测 + 自适应守恒预算 + 单变更 KEEP/REVERT | 预算放大与不可归因 P0 |
| 数据 | 最终测试密封、动态维度冻结 | 测试污染和漏报弱项 P0 |
| 选择 | 硬安全→最弱维度→最弱切片→总体→稳定性→长度 | 平均分掩盖灾难 P0 |
| 证据 | 配对 Bootstrap、满分并列例外、缺证据失败关闭 | 假冠军 P0 |
| 性能 | 精确执行合同缓存和同正文终审复用 | 重复模型调用 P1 |
| 运行 | 事务式安装、备份、失败回滚 | 升级破坏 P1 |

## Pass C｜Frozen Final

- 竞品注册表双角色校验；
- 逐维冠军核心单元测试；
- 缺竞品、缺维度、低于满分并列、竞品领先、哈希篡改均为负向测试；
- 完整运行时回归；
- 清洁安装、复验、升级备份、卸载恢复；
- 三轮无缓存 QA；
- 冻结制品后独立 Verifier 只读检查。

## 六角色复审

角色分离但由同一模型执行，状态为 `role_separated_same_model`：

1. 产品：冠军目标是否可测；
2. 架构：双角色、预算和候选权力边界；
3. 数据安全：数据密封、隐私和供应链；
4. SRE：安装、回滚、失败关闭和 CI；
5. 测试：Oracle、负向测试和证据哈希；
6. 反证：寻找任何单维失利却仍放行的路径。

第二轮只复审变化项；未发现新 P0/P1 后冻结。
