# 卡住了：换方法，不是换参数

**为什么需要它**：大模型很聪明，但默认会用**训练数据里最常见的那个方法**。
「调参数 + A/B 测试」正好是最常见的 —— 所以卡住时的第一反应几乎总是它，
而它是**局部搜索**：从当前点小步优化，不知道往哪调时会无限打转。

> 实证（2026-08-24 DouyinOps）：备一批发布物料，**返工三次**。
> 每次都在调参数（换裁切比例、换排序、换阈值），直到用户说「你看图」才换方法。
> 判图片重复度也一样：先用 dHash（最常见），它给出「有差异」，**肉眼一看就是同一张图**。
> **三次返工的共同点：一次都没换过方法。**

---

## 0 · 什么时候必须用（不只靠人喊卡住）

| 触发条件 | 说明 |
|---|---|
| **同一个交付返工 ≥2 次** | ← **硬性**。第二次返工就停手过一遍本表，别等第三次 |
| 调了 ≥3 轮参数没有方向性进展 | 参数空间搜完了不等于问题无解，通常是方法错了 |
| 「做了很多但感觉没用」 | 典型的度量错了或约束找错了 |
| 用户说：卡住 / 死循环 / 没进展 / 缺 idea | 直接进 |

---

## 1 · 先分类，别直接找方法

**说清楚一句话：我卡在哪一类？** 分错类换错方法，等于换了个姿势继续打转。

| 症状（你现在的感觉） | 去用 |
|---|---|
| 不知道目标长什么样，调哪个参数都是猜 | **M1 复刻已验证解** |
| 优化很久，数字就是不动 | **M2 换度量** |
| 有个结论卡着，推不动也推不翻 | **M3 找反例** |
| 投入很多，产出不涨 | **M4 看约束** |
| 加了一堆东西还是不行 | **M5 拿掉一个** |
| 照着别人做的，效果差很多 | **M6 问他有什么我没有** |
| 同一个错误犯了第二次 | **M7 让机器判定** |
| 有个检查/闸门从来不报警 | **M9 对检查本身做变异** |
| 文档里的数字对不上 / 引用了作废的规则 | **M10 关键数字现算** |
| 上面都试过了 | **M8 换人看** |

## 2 · 十个方法（每个都有本工作间的实例）

### M1 · 复刻一个已验证的解，再反向拆解
**别从零调参，先找一个**已经成功的成品**，一比一复刻出来，再倒推它为什么成。**
调参是从当前点小步走；复刻是**直接跳到一个已知能用的点**，然后理解它。

> 实例：2D 素材线程长期困在「调参数 + A/B」，用户提出「先找一个爆款成品复刻，
> 再反向开源分析」—— **阻碍迅速解开**。

**现成工具**：视频类直接用 `video-replica` skill。图文类：找对标账号那条爆款，
逐项列出它和我们的差异（构图/景别/服装/文案结构/标签/时段），**一次只对齐一项**。

⚠ 复刻不是照抄 —— 见 M6。

### M2 · 换度量，不换参数
**优化很久数字不动，先怀疑度量错了，而不是参数不够好。**

> 实例一：判图片重复度用 dHash，8 个角色算出相似度 45~65%、全判「有差异」，
> **肉眼一看就是同一张母图的三个裁切**。度量对裁切敏感 → 换成生成对照表用眼看，立刻解决。
>
> 实例二：素材线程的指标是「整体完成度 42.7%」（PMX/LoRA 覆盖率），
> 优化它对流量**零影响**。换成「新作 +2h 播放」后，一眼看出体系在失效。

**判据**：如果这个数变好了，我要的那个结果会跟着变好吗？答不出 = 度量错了。

### M3 · 找一个反例，不找更多正例
**结论卡住时，找一条能推翻它的数据，比找十条支持它的更快。**

> 实例：「爱莉希雅被降权」这个结论已下发四条策略。找**一个反例**（同日 12.4h 的读数：
> 1433 播放/赞率 17.5% 全账号第一）—— 整条结论链当场垮掉，四条策略全撤。

**判据**：这个结论如果是错的，最先会在哪个数据上露馅？去查那个数据。

### M4 · 看约束，不看目标
**投入很多产出不涨时，瓶颈几乎从不在你正在使劲的地方。**

> 实例：素材利用率 2.3%（828 张可发图只用了 30 张）。第一反应是「产能不够，多产」——
> 实际瓶颈在「决定发什么」这一步，那是每天要做三次的决策，每次都要现想。
> **产能从来不是约束。**

**判据**：把我正在优化的那个环节产能翻倍，最终结果会翻倍吗？不会 = 找错约束了。

### M5 · 拿掉一个，别再加一个
**加了很多还是不行时，下一步大概率也不是再加。**

> 实例一：我提议「加一张周需求单」来解决上下游脱节，用户否决：
> 「东西越搞越复杂，治理难度越来越高，登记的东西越来越多，收益完全不能覆盖成本」。
> 改成在已有脚本上加一个开关 —— 零新增负担。
>
> 实例二：一批 8 条文案「句式各不相同」，实际只是**给它们起了不同的名字**，
> 结构上仍是三条同构。加的是标签不是差异。

**判据**：这次改动会让下一个人多记住几件事？多于 0 就要重新想。

### M6 · 问「他有什么我没有」
**对标是找差异，不是找相同。照抄的前提是你有他的基本盘。**

> 实例：文案模板推荐照抄博主的「360°XX展示」句式，依据是他 9.5 万赞。
> 我们照抄 → **赞率 6.2%、藏率 0.92%，两项全账号垫底**。
> 他 8.9 万粉，我们 128 粉。**照抄句式 ≠ 复现数据。**

**判据**：他这条成功，有多少来自内容本身、多少来自他已有的粉丝盘/账号权重/历史标签？
**只抄能迁移的那部分。**

### M7 · 让机器判定，不靠自觉
**同一个错误犯第二次，说明它不该由人记住。**

> 实例：「取素材前查已发登记」这条规则写在 README 里，**我自己写的、自己违反了** ——
> 6/8 角色的素材已发过还拿来用，整批 24 张作废。做成 `查重.py` 之后，再没犯过。

**判据**：这条规则被违反时，有人会知道吗？没有 = 它迟早失效。**给不出闸门的规则不许立。**

### M9 · 对你的检查本身做变异 —— 证明它不是恒真的
**「闸门存在」和「闸门有用」是两件事。** 一道从不报警的检查，可能是没问题，
也可能是**它根本拦不住东西**。区分办法只有一个：**故意把东西改坏，看它红不红**。

> 方法出处：`_protected/workbuddy-hub-delivery/checks/evidence/mutation_full_v2.5.118/`
> ——「变异集是证明那 128 道门不是恒真的唯一手段」。113 条变异打红 124/128 道门，
> 剩下 4 道零覆盖的**逐个做定向负对照**（单独改坏它守的那件事），全部翻红 ⇒ 不是恒真门。
>
> 迁移实例（2026-08-24 DouyinOps 首跑）：G 轴幼态闸 —— **代码逻辑是对的，但数据线断了**。
> 名单表建好了，**没有任何代码在读它**，`R5` 永远为假 ⇒ 闸门第一行直接 return。
> 我自己前一天刚建的表，以为补上了缺口，**实际只补了一半**。

**三条判据**（照搬 workbuddy 的口径）：
1. **零红不等于好** —— 没被打红的门要单独做定向负对照
2. **要能排除"碰巧红"** —— 若每次变异都红同一批门，那批是「整树门」（动任何字节都红），
   不能算作它守住了那件具体的事
3. **测试本身也会有 bug** —— 首跑时我的判据 `"已发布" in out` 匹配到了表头里的
   「已发布 18 条」，误报了一次。**变异台自己也要被负对照验一遍**

**工具**：`00_治理与登记/闸门变异测试.py`

### M10 · 关键数字必须现算，不能手写
**手写的数字会在别处变化时静默过期，而且越关键的文档越容易被漏掉。**

> 出处：`_protected/kimi-code-distillation/ONE_LINE_PROMPT.md` 自述 ——
> 「它曾经是手写的，于是在门数从 23 涨到 126 的过程中一直印着旧数
> —— **最关键的那份文档反而是唯一没被守住的**。」
>
> 同类实例（DouyinOps）：根 README 引用了 `文案模板.md` **v3 已明写作废的 v2 规则**
> （「总可见 ≤12 字」）。唯一真源改版了，引用它的文件不会自动跟着改。

**做法**：文档里的关键数字改成**跑一条命令现算**，或至少标注「冻结值·非现算·取自 X 时点」。

### M8 · 换人看
前七个都试过还不动，就是真的需要外部视角了。

- **`persona-distiller-group`** —— 多个专家身份独立看同一个问题，带对抗与裁决
- **`verifier`** —— 独立验收，不信你自己的结论
- **Kimi 专家团队 / BookBuddy** —— 领域知识与书籍侧输入
  ⚠ 非 Anthropic 产出按 **70-80% 可信度**处理：可作初稿/线索/候选，
  **落成结论前必须复核**（查它编没编、引的数据在不在、跟本仓实测冲不冲突）
- **用户** —— 最快的一个。我返工三次，用户一句「你看图」点破。
  **说不清自己卡在哪，就先把 §1 的分类问出来。**

## 3 · 用完之后（否则下次还从零开始）

1. **换方法解开了 → 把「原方法 / 新方法 / 为什么换」写进 `dev-notes/`**，不只写结论
2. **如果这次用的方法不在上面十个里 → 回来加第十一个**，配上你的实例
3. 如果是某条产线特有的方法，写进那条产线的 skill，不要堆在这里

> **这个 skill 的价值不在于列了十个方法，在于它强制你在动手前停一次。**
> 十个方法都可以过时，「返工两次就停手换方法」这条不会。
