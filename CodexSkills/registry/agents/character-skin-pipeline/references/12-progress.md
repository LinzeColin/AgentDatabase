# 白箱进度：让用户自己能查，不靠我口头汇报

**判据**：用户问过「你是不是在空转」「我怎么看不到进度」「现在到底什么进度」——
问这三句就说明进度不可见。**进度必须能被一条命令问出来。**

```bash
python3 tools/progress.py            # 一次快照
python3 tools/progress.py --watch    # 每 60 秒刷一次
```

输出三段，缺一段就不算白箱：

```
【本轮出图】包 0.0.1 · 账本 run-v001/state.json
  ████████░░░░░░░░░░░░░░░░░░░░  28.2%   已落盘 31 / 110
  未结算 79 · 已花 $2.15 · 轮次 1
  远端批次 in_progress：████████████░░░░░░░░ 66/110 已出图（整批完成才落盘）
  按 IP：异环 30/108 · 鸣潮 1/2
【阶段】 ▶ 跑着 批次驱动 · 其余停
【素材库】目录 353 条 · 原神 162 · 崩铁 60 · 绝区零 86 · 鸣潮 45
```

## 三段各自解决一个问题

| 段 | 解决什么 | 没有它会怎样 |
|---|---|---|
| **百分比 + 已完成/未完成** | 还剩多少、什么时候完 | 只知道「在跑」，不知道离完成多远 |
| **远端批次 request_counts** | **批次在 OpenAI 那边烤时本机没有任何进程** | 八个阶段全显示「停」，看起来像什么都没做 |
| **阶段是否在跑** | 是不是卡住了 | 分不清「跑得慢」和「早就死了」 |

**第二段是这版最关键的补丁。** 只看本机进程的版本，在批次提交之后必然全「停」——
用户看到的就是「你什么都没在做」，而实际上 110 张正在生成。

## 进程判活踩过的三个坑

1. **macOS 的 `pgrep` 没有 `-a`**（那是 Linux 的），只返回 PID。
   按命令行做的过滤全部落空 → 要么全报「跑着」，要么全报「停」。
   正确做法：`pgrep -f` 拿 PID，再 `ps -o command= -p` 拿命令行。
2. **包装 shell 也会被匹配到**。命令行里含 `shell-snapshots` 或以 `/bin/zsh -c` 开头的，
   是 harness 的包装层，不算业务进程。
3. **等待循环自匹配**：`until ! pgrep -f xxx.py; do sleep; done` 会匹配到**它自己的命令行**，
   于是永远等不到退出。这是本项目里空转时间最长的一次。
   要么在 pattern 里排掉自己，要么直接等文件出现。

## 什么时候必须主动贴进度

- 用户问「到哪了」之前 —— 每完成一个阶段就贴一次
- 任何一步预计超过 5 分钟 —— 先说清楚「这一步大概多久、怎么自己查」
- **发现自己在等一个不会来的通知时** —— 立刻查一次快照再说话
