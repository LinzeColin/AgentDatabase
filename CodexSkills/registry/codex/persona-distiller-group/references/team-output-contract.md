# 团队产出契约（v0.0.0.7 新增）

## 为什么需要这份契约

v0.0.0.6 规定了团队的**流程**（正向 → 反证 → 复审 → 裁判），但**从未规定团队要交出什么**。
于是产出是即兴的，与「不组队直接回答」在形态上没有区别——这是使用者反馈
「产出、影响结论帮助都不显著」的另一半根因（另一半是团队拿不到推理内容，已由 dossier 修复）。

**本契约的核心判据只有一条：**

> **把团队产出里所有带 `claim_id` 的行删掉，如果剩下的内容与「不组队直接回答」没有实质差别，
> 那么这次组队就没有发生。**

## 必须产出的五个部分

### 1. 团队构成与时效声明

| 字段 | 要求 |
|---|---|
| 成员 | 姓名 + `subject_slug` + 所属身份族 |
| 角色 | 正向解决者 / 独立复审 / 最终裁判 / 反证分析（后三者必须隔离） |
| **时效构成** | 在世 / 已故 / 未标注 各几人；**若全组无在世成员且任务涉及当前实践，必须在此显式声明局限** |
| 选择理由 | 每人一句，须指向其 `key_capabilities` 或 `application_scenarios` 的具体条目 |

### 2. 各专家的实质贡献 —— **每条必须带 `claim_id`**

格式固定：

```
【<人物名>】<贡献内容> <!-- claim:clm-xxxxxxxxxxxx -->
```

**硬性规则：**

- **引用不出 `claim_id` 的贡献视为未发生**，不得计入产出。
- `claim_id` 必须存在于该成员 dossier 的 `claim_index` 中——**引用别人的 claim 无效**。
- 一条贡献可引多个 claim，但**至少一个**。
- **不得把模型自己的通用知识冠以人物名义**。若某人物在该问题上无可引用的 claim，
  正确做法是**明说他在这一点上没有可依据的立场**，而不是替他生成一个。

### 3. 组内分歧 —— **不得抹平**

dossier 的 `divergences` 非空时，必须设独立小节呈现：

- 分歧双方各自的立场（**各带 `claim_id`**）
- **各自的成立条件**——多数分歧不是谁对谁错，是前提不同
- **明确写出「本产出采纳了哪一方、为什么，以及另一方在什么条件下更适用」**

**禁止的处理方式：** 取中、折中、「两者结合」、只提一方而不提分歧存在。

> 实例：Bogle 与 Lynch 在「普通人能否靠选股取胜」上直接对立；
> Bogle 与 Soros 在「判断能否做对」上前提相反。
> 这类分歧一旦被抹平，产出就退化成了一段谁都不得罪的中庸建议。

### 4. 边界与拒答 —— **生成前生效**

- 列出本次触发的 `hard_boundaries` 与 `refusal_template` 条目。
- **越界请求必须在产出中显式拒绝并给出理由**，理由须落到实质（如「不知道你的处境、
  期限与承受能力」），**不得用免责声明搪塞**。
- 列出本次适用的 `known_distortions`（「不得写成」清单），并确认产出未违反。

### 4.5 合议宣称 —— **票数不得超过实际点名的人数**（v0.0.0.13 落成判据）

**这一条不是新规矩，是把第 2 条「每条贡献带人物名」缺失的那个检查器补上。**

2026-08-02 三臂盲判，席 B 抓到：

> 它用「三个人一致」「三票否决」赋予自己一种**从未展示的合议权威**——
> **t1 只摆了两路却称三票。**

回看原文，实情比席 B 说的还差一格：**全文一个成员名都没出现。**
落成判据后扫同一批 8 道题，**3 道（t1／t2／t5）都是「宣称三人一致、点名 0 人」**。

- 宣称任何票数／人数的合议（`N 票`、`N 人一致`、`N 个人都同意`…）时，
  **正文中必须至少点到同样多的成员名**。
- **少说不算错**（点名 3 人只说「其中两人反对」是诚实的收敛）；**多说才算错**。
- 无数词的「大家一致认为」不在判据射程内——**但它同样不构成合议证据**，
  写它不如按第 2 条逐条署名。

判据：`scripts/check_team_attribution.py`（负对照 9 项，含用 t1 原文做的真实样本对照）。

**射程**：它数的是**名字有没有出现**，不是**这个人是否真的持这个观点**。
把三个名字撒进正文就能骗过它——**它挡的是「凭空宣称票数」，不是「冒名代言」。**
后者仍由第 2 条的 `claim_id` 规则负责。

> **合议是团队层唯一的卖点。** 团队臂相对裸模型 −0.0219、相对单人物 +0.0825，
> 能解释那 +0.0825 的只有「多个不同视角」；
> 一份不点名的合议宣称，恰好把这个唯一的卖点变成了不可核验的断言。

### 5. 反证与裁判记录

- **反证分析**：针对主要结论，给出至少一条可检验的反面情形。
- **独立复审**：指出产出中最弱的一环。
- **最终裁判**：只看密封的候选结果与证据摘要，给出采纳结论与理由。
- 三者**不得由担任正向解决者的同一上下文产生**。

## 自检清单（交付前逐条过）

- [ ] 每位人物专家的贡献都带至少一个 `claim_id`，且该 id 属于其本人
- [ ] **合议宣称的票数 ≤ 正文实际点名的人数**（`check_team_attribution.py` 判）
- [ ] `divergences` 非空时，已设独立小节且未抹平
- [ ] 已列出触发的边界，越界请求已显式拒绝
- [ ] 已列出 `known_distortions` 并确认未违反
- [ ] 时效构成已声明；全组无在世成员时已声明局限
- [ ] 反证、复审、裁判三者与正向解决者隔离
- [ ] **删掉所有带 `claim_id` 的行后，剩余内容与「不组队直接回答」有实质差别**

**最后一条不过，整次组队判定为无效，须重跑。**

## 与蒸馏侧的接口

本契约依赖蒸馏产物提供：`evidence/claims.jsonl`（带 `claim_id`、`category`、
`falsifiers`）、`boundaries.md`、`divergence-map.md`、以及 team-card 的
`distillation_traits`（作为 `known_distortions`）与 `hard_boundaries`。

**任一缺失都会让本契约降级失效**，因此人物蒸馏 skill 的 release 硬门必须保证这些文件存在且非占位。
