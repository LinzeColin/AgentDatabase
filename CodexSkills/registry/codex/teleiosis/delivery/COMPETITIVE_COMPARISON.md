# Competitive Comparison — Teleiosis v0.0.0.2

## Product-layer separation

| Project / method | Primary strength | What Teleiosis adopts | Boundary |
|---|---|---|---|
| Darwin Skill | lightweight baseline→experiment→keep/revert ratchet | frozen baseline, attributable Candidate, no-gain stop | not a full assurance/release control plane |
| Luban Skill | premise challenge, peer/ecosystem research, real artifacts and productization | five mandatory gates and reheat | product craft alone does not prove task outcome |
| Anthropic skill-creator | practical test-driven Skill creation and description optimization | baseline comparison and progressive disclosure | creator is not an external trust root |
| Microsoft SkillOpt | trajectory-driven, validation-gated optimization and multi-backend direction | trajectory evidence, rejected-edit retention, replaceable optimization backend | reported benchmark gains require local reproduction |
| SkillHone | persistent cross-session decision history | structured strategy memory, not private chain-of-thought | memory cannot override current evidence |
| SkillRevise / SkillGrad / SkillMOO | diagnosis, gradient/portfolio and multi-objective evolution | adaptive briefs, branch portfolio and Pareto selection | no fixed algorithm becomes Genesis |
| Skill Coverage research | measures whether declared constraints are exercised | hard-behavior coverage Gate | coverage is not correctness |
| Skill Shadowing research | Skill libraries change retrieval and activation behavior | library-scale selection/false-activation/outcome-drop Gate | retrieval engine remains replaceable |
| Agent Skills specification | portable folder/frontmatter and progressive disclosure | thin kernel, references/scripts/schemas | optional implementation details are not constitutional |
| Curzibn/Luban | Android image-compression engineering analogy | empirical policy, worse-output fallback, input defence | **Engineering analogy**, not an Agent Skill and cannot satisfy the five-peer market minimum |
| EasyDarwin/EasyDarwin | streaming-server engineering analogy | adapter matrix, environment diagnosis, on-demand control surface | **Engineering analogy**, not an Agent Skill and cannot satisfy the five-peer market minimum |

## Present differentiation

Teleiosis combines evolution, productization and assurance in one white-box lifecycle: immutable baselines, current-environment evidence, real peers, multi-objective outcome/cost evaluation, non-negative selection, external review boundary, deterministic release and rollback. Its current disadvantage is cost and operational complexity; therefore adaptive run modes and no-gain stopping are required.

No table row proves full-market outcome leadership. Formal comparison requires same task, model, runtime, permissions, budget, sealed holdout and raw results.
