# Why Teleiosis repeatedly failed to prove full-market leadership

**Analysis date:** 2026-07-26 (Australia/Sydney)

## Root cause

Previous iterations were locally exhaustive but globally open-ended. Each run closed the known issue list, while later threads changed the comparison set, inspected different layers or used newer research. A bounded system cannot prove that no unknown closed-source system or future release exists. The correct objective is therefore not a permanent “market first” certificate but an expiring, falsifiable current-environment Pareto status.

## Structural reasons new gaps kept appearing

| Failure pattern | Why it survived prior testing | v0.0.0.2 response |
|---|---|---|
| Known-gap optimization | Tests were derived from already observed failures | Frontier scan, competitor Dataset, adversarial probes and reheat events discover new evidence |
| Control-plane/outcome category error | Hashes, install and Gates were easier to test than real model outcomes | Separate Track A/B/C and block outcome claims without equal-budget sealed tasks |
| Task-only evaluation | A task can pass without exercising safety or authority constraints | Behavior-coverage contract and hard-constraint coverage |
| Isolated-Skill bias | Single Skill tests omit library retrieval/ranking competition | Shadowing and false-activation evaluation |
| Stochastic overclaim | Small samples and best-of-N selection look better than they are | Predeclared trial/interval rule and `INCONCLUSIVE` state |
| Static freshness | Research date existed, but outputs lacked executable expiry | Evidence lease, second environment snapshot and event-driven reheat |
| Fork regression | Each enhancement branch removed capabilities from the other | Mechanism-level convergence and cross-fork differential audit |
| Self-certification | Local roles can look independent while sharing context and failure modes | External receipt root, unique runs and distinct read-only verifier remain mandatory |

## What cannot honestly be claimed today

- universal or permanent market leadership;
- best real-task outcome across every model/runtime/task;
- complete cost evidence when provider usage is unavailable;
- real external 2×6+1 review in this runtime;
- support for untested closed systems or future releases.

## What this release can prove after final seal

- base and effective Genesis integrity are externally anchorable;
- Candidate/Exam separation, white-box ledger and fail-closed states work under included tests;
- merged mechanisms do not lose the verified capabilities of either uploaded branch;
- deterministic packaging and reversible installation work in the tested environment;
- the system refuses stale, undercovered, shadowed, statistically inconclusive or externally unreviewed superiority claims.

“Current strongest” is now a machine state that must be earned and expires; it is no longer a marketing sentence.
