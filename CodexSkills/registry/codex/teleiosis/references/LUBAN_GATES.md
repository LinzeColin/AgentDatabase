# Luban Five Gates

## A. Existence challenge

Before the first change, answer with evidence: Is the user problem real? What is uniquely reusable? Why install rather than ask once? What observable artifact proves value? Decision: `CONTINUE / REPOSITION / MERGE / SPLIT / RETIRE`.

`RETIRE` stops mutation and produces a preservation/exit recommendation; it does not delete, unpublish or overwrite anything. `REPOSITION / MERGE / SPLIT` requires an architecture plan before polishing.

## B. Five real peers

Use the qualifying rules in `COMPETITOR_INTELLIGENCE.md`. The quota is about real projects, not five URLs.

## C. Ecosystem and falsifiable niche

Analyse origin, current form, next horizon and replacement risks; compare problem fit, mechanism, installability, evidence, safety, portability, efficiency and maintainability; define avoided niche, target niche, falsifiable advantage and disconfirming test.

## D. Live artifacts

Observe real outputs, files, commands, timestamps, freshness, rendering and reproduction. README, green CI, mock and dry-run do not substitute for live evidence. Check target artifacts and at least two peer artifacts.

## E. Install, release and reheat

All profiles require short value, shortest install, first invocation, three real scenarios, release notes, deterministic package, post-install verification, rollback and reheat. Evidence is profile-aware:

- public: visual showcase;
- internal: operator result bundle;
- infrastructure: healthcheck, runbook and verification transcript;
- method: worked example and comparison result.
