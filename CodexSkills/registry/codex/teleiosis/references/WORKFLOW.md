# Workflow

## Phase 0 - verify and contract

Verify the external Genesis anchor and package. Define target, scope, non-goals, user requirements, permissions, dependencies, budgets, known failures and acceptance criteria.

## Phase 1 - freeze and branch

Create an external workspace. Freeze a read-only baseline. Create a portfolio of candidates selected for the problem: incremental, architecture, clean-slate, composition or custom. Freeze the stable optimizer control plane separately.

## Phase 2 - challenge and research

Before any change:

1. challenge whether the Skill should continue, reposition, merge, split or retire;
2. run a dated freshness scan across models/runtimes, methods/architectures, evaluation, standards/security and competitors;
3. build at least five real peer records with direct, indirect and craft coverage;
4. record mechanism/licence adoption and deliberate non-adoption;
5. analyse vertical evolution, horizontal capability, avoided niche, target niche and a falsifiable advantage;
6. observe real target and peer artifacts;
7. seal research.

## Phase 3 - freeze evaluation

Create baseline/candidate/no-skill systems as applicable. Freeze metric definitions, hard gates, protected task families, datasets, blind-judge policy and cross-model matrix. Holdout prompts remain outside candidate-visible roots.

## Phase 4 - ten system perspectives

The first ten round records must cover exactly these perspectives, in any order:

1. `requirements-scope-pain`
2. `peers-ecosystem-reuse`
3. `triggering-boundaries`
4. `workflow-failure-branches`
5. `security-authority-supply-chain`
6. `architecture-progressive-disclosure`
7. `evaluation-holdout-transfer`
8. `runtime-install-release-rollback`
9. `efficiency-maintenance-cost`
10. `live-artifacts-future-blindspots`

A round can compare several candidates or a coherent architecture patch set. It must expose evidence, hypothesis, exact diff, raw evaluation and `KEEP / REVERT / NO_CHANGE`. Ten reviews are mandatory; ten edits are not.

## Phase 5 - bounded extension

After ten perspectives, continue only while a configured run budget remains and new evidence, an unresolved hard defect, a holdout regression or a falsifiable high-value hypothesis exists. Repeated tree hashes, saturation threshold, exhausted budgets, unavailable capability or unchanged state stops the run. A later reheat is a new run, not recursion.

## Phase 6 - independent review

Generate twelve sealed evidence packets. Run two panels of six genuinely isolated SubAgents. Collect provider-identifiable actor/context/run IDs. Resolve hard findings by changing a new Candidate and rerunning affected gates. A distinct thirteenth read-only verifier decides promotion.

## Phase 7 - release

Select only a candidate that passed hard gates, protected-task checks and the Pareto frontier. Validate release profile, deterministic archive, post-extract verification, atomic install, rollback, receipt and reheat policy. Remote push/deploy/release requires separate explicit authorization.
