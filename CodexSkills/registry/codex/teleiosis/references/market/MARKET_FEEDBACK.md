## 1. 市场反馈定义

真实市场证据至少满足：

```text
真实任务
× 外部用户或独立执行者
× 可观察结果与现实代价
× Skill ON/OFF 或 Baseline/Candidate 因果对照
× 独立验收
× 可复核原始轨迹
```

“有人说不错”不是完整市场证据。需要知道：谁在什么任务上使用了哪个精确版本，是否完成、接受、返工、复用、付费或发生事故，以及对照条件如何表现。

每条市场事件必须形成最小因果链：

```text
event_id
→ task_id
→ run_id
→ arm_id
→ artifact_digest
→ consent_ref
→ result / cost / acceptance / incident
```

聚合器必须确认 `run_id + task_id + arm_id + artifact_digest` 与已记录执行结果完全一致。孤儿反馈、错误制品、单臂反馈或模拟竞品的市场声明都 fail-closed。市场等级取 Candidate 与冻结主 Comparator 的**共同最低等级**，不能由第三臂或 Candidate-only 事件抬高。

## 2. 事件驱动期程

不以等待日期作为 Agent 任务节点，使用入口/出口条件推进。

| 期程 | 入口 | 主要动作 | 出口 |
|---|---|---|---|
| M0 测量校准 | Skill 与目标明确 | 20–50 个高信息任务、No Skill、Oracle 校准 | 数据和 Gate 可区分好坏 |
| M1 因果实验室 | M0 通过 | Baseline/Candidate/Competitor/Ablation 配对重复 | 主要切片有配对差异和成本 |
| M2 压力与规模 | M1 无硬阻断 | 六类压力、跨版本、千至十万级流式运行 | 失效边界、容量和预算清楚 |
| M3 真实重放 | M2 候选稳定 | 历史轨迹重放、只读 Shadow | 无副作用且接近真实分布 |
| M4 Opt-in Canary | M3 通过且已授权 | 盲化 A/B、最小匿名反馈、自动中止 | 达到 L5 或触发回退 |
| M5 外部经济验收 | M4 有正向信号 | 真实 Issue/PR/交付/微赏金 | 达到 L6，外部接受可复核 |
| M6 持续价值 | 已受控发布 | 留存、复用、付费、实际节省与事故率 | L7 或 REHEAT_REQUIRED |

日历估计仅用于资源规划，不能替代出口证据。若真实用户不足，不得用更多模拟填补 M4/M5。

## 3. 四种现实机制

### 3.1 Opt-in 最小匿名反馈

每次执行后只收集必要结果：

```text
完成 / 部分 / 失败 / 放弃
是否被接受
人工修改秒数
大约节省分钟数
是否愿意再次使用
是否发生事故
```

默认只记录：Skill 版本、任务类别、成功状态、成本、时延、脱敏 trace ID。默认不记录原始 Prompt、输出、文件、密钥或身份。

硬要求：

- 明确 consent reference；
- 可撤回或按政策删除；
- 不用暗黑模式诱导；
- 反馈缺失不等于正向；
- 只对当前精确版本有效。

### 3.2 盲化 Canary / A-B

将自愿用户随机分配到 No Skill、Baseline 或 Candidate。用户不必知道版本名称，但必须知道其参与受控实验及数据处理方式。

观察行为而不是先问偏好：

- 是否完成；
- 用时和返工；
- 是否重试、绕过、撤销或放弃；
- 是否再次主动使用；
- 是否产生越权、隐私或数据事故。

Canary 必须有：

- 最大用户/事件数；
- 费用和 Token 上限；
- 自动 abort；
- 立即回退路径；
- on-call 或明确责任人；
- 精确 deployment identity。
- Candidate 与主 Comparator 各自达到冻结的最小事件数；不能只收 Candidate 正向反馈。

### 3.3 真实 Issue、PR、交付物与微赏金

选择真实未解决任务，冻结：

- 仓库 commit 或输入制品；
- Acceptance 和测试；
- 预算与权限；
- 输出格式；
- 外部验收者；
- 赏金或现实价值。

No Skill、Baseline 与 Candidate 分别执行，移除标签后由维护者或领域专家验收。指标：

- 一次通过率；
- PR 合并或交付接受；
- 返工轮数；
- 完成时间；
- 实际支付或可量化节省；
- 维护者是否愿意再次使用。

不得购买虚假好评、操纵开源维护者或把未合并 PR 计为市场成功。

### 3.4 生产负行为回流

高信息事件通常是：

- 重复重试；
- 手工撤销或大量修改；
- 绕过或禁用 Skill；
- 卸载或回滚；
- 中途放弃；
- 投诉、隐私问题或事故；
- 成本或时延异常；
- 结果被外部验收拒绝。

每个真实失败转成：

```text
事件 → 脱敏 → 最小复现 → incident_replay
→ Candidate 修复 → 全五臂回归 → Gate
```

## 4. Shadow 与 Canary

### 4.1 Shadow Mode

对真实历史或实时输入执行 Candidate，但不把其结果写回用户或生产系统。对比正式 Baseline 的结果和 world state。

Shadow 能发现分布漂移、成本和错误，但不能证明用户接受，因为用户未实际依赖 Candidate。

### 4.2 Canary 入口 Gate

必须满足：

- L0–L3 通过；
- 无 P0/P1 安全、隐私和数据完整性问题；
- Candidate 与 Baseline 精确绑定；
- 自动停止和回滚可执行；
- consent 与保留政策完成；
- 费用、用户数、任务数和副作用上限已冻结；
- 关键保护任务无负迁移。

### 4.3 Canary 出口

允许晋级，当：

- 达到最小独立事件数；
- 完成/接受/复用中至少一项相对 Baseline 改善；
- 返工、成本与时延在预算内；
- 无 high/critical 事故；
- 结果在主要用户切片一致；
- 外部验收或经济任务已安排用于 L6。

## 5. 外部经济验收

市场价值不等于收入，但至少要承担现实代价。可使用：

- 外部维护者是否合并；
- 客户是否接受交付；
- 真实人工小时是否减少；
- 微赏金是否支付；
- 支持工单是否关闭；
- 重复使用或续用；
- 事故成本是否下降。

估算节省时记录区间与来源，不用伪精确 ROI。自报“节省 3 小时”与系统观测应分开标记。

## 6. 负反馈回流

### 6.1 事件优先级

| 事件 | 严重度建议 | 动作 |
|---|---|---|
| 隐私泄漏、未授权副作用、数据损坏 | Critical | 立即停止、回退、保留证据 |
| 关键任务错误、外部错误决策 | High | 停止相关切片、incident replay |
| 大量返工、频繁重试、成本超限 | Medium | 限流、分析、候选回炉 |
| 轻微文案或非关键体验问题 | Low | Backlog，不阻断当前版本 |

### 6.2 不要只收星级

五星评价易受礼貌、选择偏差和新鲜感影响。优先观测完成、接受、返工、复用、付费、回滚和事故。

### 6.3 反沉默失败

没有投诉不代表成功。需要主动检测：

- 用户是否停止使用；
- 是否绕过 Skill；
- 是否在结果后大量编辑；
- 是否转回旧版本；
- 是否因成本过高降低使用频次。

## 7. 自动中止与风险

任何以下事件应自动 abort：

```text
critical incident > 0
privacy leak > 0
unauthorized side effect > 0
identity mismatch > 0
protected task regression beyond threshold
cost or latency ceiling breached
consent or retention contract violated
```

中止后：

1. 停止新流量；
2. 保留原始证据和精确版本；
3. 回退已接受 Baseline；
4. 通知责任人；
5. 建立最小 incident replay；
6. 不在同一实验中降低 Gate；
7. 重新授权后开启新 experiment_id。

除中止外，下列情况不允许市场晋级：

- Candidate 或 Comparator 任一臂不足最小事件数；
- 两臂最高证据等级不对称，无法形成共同证据级别；
- completion / acceptance 差异低于冻结门；
- Candidate 的人工修改负担超过冻结上限；
- feedback 无法追溯到同一实验中的真实 run。

## 8. 结果解释

| 观察 | 正确结论 |
|---|---|
| 模拟很好，真实任务不足 | 实验室候选，不是市场验证 |
| L5 正向但无外部接受 | 有初级用户信号，继续 M5 |
| 外部交付接受但成本过高 | 市场价值可能存在，产品化未通过 |
| 平均提升但关键事故 | 回退，不用平均分抵消 |
| 复用和付费持续改善 | L7 强证据，但仍需监控漂移 |
| 市场无增益但实验室增益 | 可能解决了错误问题，重新定位或退役 |
