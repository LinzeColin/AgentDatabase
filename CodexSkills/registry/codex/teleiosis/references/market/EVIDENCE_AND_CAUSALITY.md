## 1. 为什么必须有因果对照

目标不是证明 Candidate 能完成任务，而是证明：

```text
Candidate 的结果
- 同模型无 Skill 的结果
- 当前 Baseline 的结果
- 额外成本、时延、风险和维护负担
= 可归因的净价值
```

没有 `No Skill` 时，基础模型本来会完成的工作会被错误归功于 Skill。没有 Baseline 时，不能证明新版本值得替换当前版本。没有消融时，无法知道哪个机制产生收益。没有真实竞品时，不能判断市场相对位置。

## 2. 七级证据阶梯

| Level | 证据 | 结论上限 |
|---:|---|---|
| L0 | Schema、安装、权限、静态检查 | 可运行性 |
| L1 | No Skill / Skill ON 配对离线任务 | 边际实验室价值 |
| L2 | 模拟用户、模拟工具、多 Agent 情景 | 情景覆盖 |
| L3 | 红队、故障注入、极限压力、长上下文 | 鲁棒性与失效边界 |
| L4 | 真实历史轨迹重放、Shadow Mode | 近真实流量适配 |
| L5 | 自愿真实用户 Canary / A-B | 初级市场信号 |
| L6 | 真实 Issue、PR、交付物、微赏金、外部盲验收 | 强市场接受证据 |
| L7 | 重复使用、留存、付费、实际节省、事故率 | 持续市场价值 |

证据等级是上限，不是总分。大量 L2 数据不能累积成 L5。真实用户事件若无 consent、精确版本、结果或成本，也不能自动成为 L5。

## 3. 五个实验臂

| Arm | 定义 | 必要性 |
|---|---|---|
| No Skill | 同模型、工具、权限和预算，不加载目标 Skill | 永久对照，必选 |
| Baseline | 当前已接受正式 Skill | 版本增量，默认必选 |
| Candidate | 待验证版本 | 只能有一个正式候选 |
| Competitor | 锁定真实同行；必要时另建模拟/代理臂 | 市场相对性 |
| Ablation | 去掉一个机制的候选 | 归因机制贡献 |

### 3.1 运行同质性

每个臂必须尽可能相同：

- 模型 snapshot 与 sampling；
- system 与非 Skill 上下文；
- 工具及权限；
- 输入任务与 Oracle；
- Token、费用、工具调用和时间预算；
- 运行系统、依赖与网络；
- 重试政策；
- 评委和评分合同。

若无法相同，必须记录差异并降低结论置信度。

### 3.2 模拟竞品不等同真实竞品

`simulated` 臂用于提出“同行可能采用什么机制”的假设，不能参与市场接受结论。真正直接比较要求：

- 锁定版本或 commit；
- 可执行制品或可复核输出；
- 合法许可和授权；
- 相同预算与任务；
- 精确 source reference 与 digest。

## 4. 配对、盲化与随机化

### 4.1 配对

同一 `task_id + repetition` 在所有臂运行，比较差值而不是独立总体均值。配对能减少任务难度差异造成的噪声。

### 4.2 重复

非确定性 Agent 任务默认每个声明切片至少 3 次独立 trial。高风险或差异很小的结论增加重复次数；确定性构建或 Schema 检查可单次执行。

### 4.3 随机顺序

对每个任务和 repetition 随机化臂执行顺序，避免缓存、速率限制、时间漂移或学习效应系统性偏向某个臂。固定 seed 以复现分配。

### 4.4 盲化

- 执行器接收 `condition_code`，控制器保留 arm 映射；
- 评委接收去标签输出，不知道 Candidate 或作者意图；
- Candidate 不读取 holdout、blind map、评分答案或前一轮诊断；
- 外部人工验收者只看交付物和 Acceptance。

blind map 泄漏后，实验必须重建，不能只重新命名臂。

## 5. Oracle 与评委

### 5.1 Oracle 优先级

1. 确定性 world state、测试、Schema、文件或 API 结果；
2. 外部领域专家或真实维护者验收；
3. 校准过的独立 LLM grader；
4. 生成器自评只能作线索。

### 5.2 Oracle 合同

每个任务至少包含：

```text
task_id
partition
origin
prompt or external task reference
expected outcome
oracle type
protected flag
sensitivity
consent_ref when market-derived
```

冻结后不得因 Candidate 失败而降低阈值。若 Oracle 被证明错误，应废止该任务并创建新合同，而不是静默修分。

### 5.3 测试判别力

关键测试应通过至少一种方式证明会在错误实现时失败：

- mutation；
- 故障注入；
- property-based 反例；
- 已知失败回放；
- 人工构造违反不变量的制品。

不会抓到错误的测试不构成强证据。

## 6. 指标与不确定性

### 6.1 主要 Outcome

- 任务成功率；
- 0–1 归一化任务评分；
- 外部接受率；
- 完成率与放弃率；
- 人工修正时间；
- 重试、撤销、回滚和事故；
- 实际节省或付费价值。

### 6.2 资源与风险

- Token；
- 费用；
- 时延；
- 工具调用；
- 维护复杂度；
- 安全、隐私、越权与数据损坏事件。

### 6.3 配对差异

默认报告：

```text
candidate_success - comparator_success
candidate_score - comparator_score
candidate_acceptance - comparator_acceptance
candidate_cost - comparator_cost
candidate_latency - comparator_latency
```

脚本使用配对 percentile bootstrap 输出均值和区间。区间是实验不确定性，不是市场普遍性的保证。任务来源高度相关时应按来源或项目分组重采样；当前通用脚本未自动实现 cluster bootstrap，应在正式高风险研究中用外部统计 Adapter 补强。

### 6.4 多指标不做伪总分

先过硬门，再检查保护任务，然后使用 Pareto 判断：

- 效果提高且成本下降：支配 Baseline；
- 效果提高、成本略升：检查预算与真实价值；
- 平均提高但关键切片退化：阻断或消融；
- 无效果但成本增加：KEEP_BASELINE；
- 安全或身份失败：BLOCKED / REVERT。

## 7. 样本量与停止

### 7.1 从 20–50 个高信息任务开始

初始任务集覆盖：

- 显式触发；
- 隐式触发；
- 上下文触发；
- 不应触发；
- 核心结果；
- 高风险边界；
- 真实历史失败。

先验证测量系统和失效机制，再扩大到千级或十万级。

### 7.2 扩样原则

增加样本应解决一个明确问题：

- 缩窄不确定性；
- 覆盖新来源；
- 覆盖新失效机制；
- 检查跨模型/运行时迁移；
- 验证真实市场切片。

一万条同源改写不能替代一百条独立真实任务。

### 7.3 停止合同

停止当前实验，当出现：

- 冻结任务、预算或轮次上限；
- 明确不可恢复硬门；
- 连续两轮无新机制、无新 P0/P1、无 Developer Burden Reduction；
- 新数据不能改变当前决策；
- 边际价值低于成本；
- 需要新权限、真实市场或独立验收，实验室继续运行无意义。

## 8. 常见错误

| 错误 | 后果 | 修复 |
|---|---|---|
| 同一模型生成、回答和评分十万题 | 同源自证 | 外部来源、确定性 Oracle、盲评 |
| 没有 No Skill | 把基础模型能力算给 Skill | 永久保留对照 |
| Candidate 看见 holdout | 过拟合 | 控制器隔离、只公开哈希 |
| 只给平均分 | 掩盖关键失败 | 分切片、硬门、保护任务 |
| 重试后只保留成功 | 洗掉 flake | 保留所有 trial |
| 模拟竞品冒充真实同行 | 伪市场结论 | `simulated` 标签且不升证据级别 |
| 只测输出不测 world state | 伪完成 | 真实文件、API、数据与重启后状态 |
| 先看结果再改阈值 | p-hacking | 首次 Candidate 前冻结合同 |
