# 提示词编译器

## 用户只需要这样使用

这是一个本地智能体技能，不是网站、桌面软件或独立网页界面。安装后在 Codex 输入：

```text
$prompt-compiler
优化下面这条提示词。逐字保留原文，生成 ChatGPT、Codex、Claude、Gemini 四个版本；先测原版，再做多引擎优化，最后用独立测试、三次重复、回归、红队和独立终审验收。

【原始提示词】
在这里粘贴
```

代理负责建立隔离项目、保存历史、准备案例、运行优化器、评测、出报告和回滚。除首次安装、模型授权和真实业务案例确认外，不让用户操作 Python、GEPA、Promptfoo 或数据文件。

## 不可协商合同

1. 原始输入逐字保存，永不覆盖；每次输入均新增不可变历史记录。
2. 每次输入立即形成原始版及 ChatGPT、Codex、Claude、Gemini 四个目标版本；获胜候选也必须再形成四个目标版本。每个版本记录父子关系、时间和 SHA-256。
3. `.ramify/` 只保存目标、状态、决策、证据指针和下一步，不保存完整聊天、隐藏推理或原始正文；完整正文进入 SQLite 历史账本和逐条只读镜像。
4. 训练、验证、最终测试、回归、红队五类数据必须可追溯。最终测试以及最终候选名单在搜索完成前均不得向优化器开放。
5. 先运行种子版本基线，再生成候选；“改写过”不等于“变好”。
6. 同一数据默认重复至少三次，报告均值、最差值、总体方差、样本方差、逐案例和逐任务统计；不得只报告最好的一次。
7. Promptfoo 必须在同一次配置中同时导入种子版本与优化版本，并真实产生两组结果；缺组、案例覆盖不足或重复次数不足均阻塞。
8. 任务模型与独立终审模型默认必须是不同身份。仅改角色名称、不改模型或执行身份，不算独立。
9. 旧案例回归、固定红队、Promptfoo 官方红队、独立终审、真实 GEPA/Codex/Promptfoo 证据和持续集成硬门全部通过后，才允许发布。
10. 不硬编码模型供应商。角色从用户配置、项目配置、环境变量、自定义命令或当前 Codex 环境解析；独立终审不得自动继承任务模型。
11. 外部优化器只能提交候选，无权读取最终测试、修改原始工件、决定分数或自行放行。
12. 不声称全局最优或普遍优于所有竞品。只有在同数据、同模型身份、同预算、同预言机、同重复次数下经独立最终复测成立，才能写“在本次证据范围内更优”；否则写“尚未证实”。
13. 外部实测未运行、证据未知、人工豁免、合成最终案例和任何阻塞状态都不能冒充正式通过。
14. 所有用户可见信息全中文：结论、报告、错误和下一步默认使用中文；模型名、文件名、命令和机器字段可保留稳定技术标识。
15. 针对代码、智能体架构或配置的正式优化，必须接入目标项目真实编译、测试或业务预言机；通用文字评分器不能替代领域验收。

## 代理执行顺序

### 一、锚定、保存与分层

从当前上下文提取目标、范围、非目标、硬约束、禁止项、输入、依赖、权限、成功案例、失败案例、输出合同、成本上限和发布责任。能从环境或授权文件确定的事实不再询问；只有真正影响范围、费用、权限或不可逆动作的决策才提出一个封闭问题。

建立隔离项目：

```bash
python3 -B scripts/prompt_compiler.py init \
  --project <工作目录> \
  --source-file <原始输入文件> \
  --objective-text "不改变目标和硬约束，提高正确性、覆盖、可执行性、泛化、稳定性、安全性和成本效率。"
```

后续每次新输入必须追加，不得覆盖历史：

```bash
python3 -B scripts/prompt_compiler.py ingest --project <工作目录> --source-file <新输入文件>
```

### 二、检查环境与角色独立性

```bash
python3 -B scripts/prompt_compiler.py self-test
python3 -B scripts/prompt_compiler.py doctor --probe
```

缺固定运行环境时：

```bash
python3 -B scripts/prompt_compiler.py bootstrap
```

角色解析优先级：显式用户配置 → 项目配置 → 角色环境变量 → 自定义命令 → 当前已登录 Codex。独立终审没有自动继承兜底。

### 三、建立数据和预言机

优先使用经授权、已脱敏的真实历史案例。材料不足时可生成临时案例以打通流程，但最终结论最高只能“临时通过”：

```bash
python3 -B scripts/prompt_compiler.py generate-cases --project <工作目录> --count 16
```

补全 `datasets/` 后执行：

```bash
python3 -B scripts/prompt_compiler.py validate --project <工作目录>
python3 -B scripts/prompt_compiler.py seal --project <工作目录>
```

预言机优先级：确定性断言 → 结构或数据格式 → 可执行函数 → 业务真值 → 语义评委。能机械判定的要求不得全部交给大模型主观打分。

### 四、多引擎同预算搜索

默认先使用冒烟模式，再使用快速模式；只有真实案例充分且准备正式发布时才使用正式模式：

```bash
python3 -B scripts/prompt_compiler.py optimize \
  --project <工作目录> \
  --preset quick \
  --engines gepa,autoresearch,meta_harness,promptfoo,omni
```

内置候选来源：

- GEPA：读取失败轨迹和可行动反馈，进行反思、变异和帕累托选择；可优化提示词、代码、智能体架构、配置和普通文本。
- 自动研究式循环：每轮只改变一个可归因假设，记录成功与失败路径，避免重复试错。
- 元执行框架式循环：联合检查结构、步骤、工具边界、恢复路径和验收接口。
- Promptfoo：运行官方优化能力，同时执行“基线→失败样本→候选→重新评估”的兼容候选提取。
- 组合引擎：只从已验证的帕累托前沿组合互补改动，不做无证据拼接。
- 外部竞品桥：DSPy/MIPROv2、Opik、MLflow、OpenAI、Anthropic、Google、PromptHub、PromptLayer 可通过通用 JSON 命令桥加入；它们只贡献候选，最终测试和裁决仍由本技能掌握。

所有请求引擎必须在相同预算、相同可见数据和统一评分合同下竞争。每个引擎至少保留一个可追溯终审候选；相同正文可以复用评测结果，但不能抹掉来源。

### 五、冻结候选并独立验收

搜索结束后冻结获胜候选和最终候选名单，验证哈希未变化后才打开最终测试。随后依次执行：

1. 种子版本和每个终审候选在同一最终数据上重复至少三次；
2. 使用不同身份的独立终审模型复评；
3. Promptfoo 同时导入种子版本和获胜版本，生成真实双组结果；
4. 对旧案例执行回归；
5. 对越权、提示注入、敏感数据泄露、拒绝边界和过度代理执行固定红队；
6. 运行 Promptfoo 官方红队并解析实际结果，而不是只看进程返回码；
7. 检查真实 GEPA 安装、真实 Codex 调用、版本、命令、输入、输出和日志证据；
8. 持续集成重新读取独立证据，不信任报告中单一“允许发布”字段。

真实外部验收：

```bash
python3 -B scripts/prompt_compiler.py external-acceptance
```

持续集成裁决：

```bash
python3 -B scripts/prompt_compiler.py ci-gate --project <工作目录>
```

### 六、只返回用户需要的结果

按以下顺序返回：

1. 发布决策：正式通过、临时通过、退回或阻塞；
2. 种子版本与获胜版本的最终均值、最差值、方差和硬失败数；
3. 获胜候选对应的 ChatGPT、Codex、Claude、Gemini 四个可复制版本；
4. 关键差异、保留约束、退化项、竞品同条件结果和证据边界；
5. 一个明确下一步。

不要向用户倾倒完整轨迹、依赖安装日志或内部实现细节，除非用户明确要求诊断。

## 文脉中枢与完整历史

每次初始化、追加输入或完成优化后检查：

```text
<项目>/.ramify/KERNEL.md
<项目>/.ramify/DECISIONS.md
<项目>/.ramify/HANDOFF.md
<项目>/.ramify/MANIFEST.json
```

文脉中枢记录当前输入记录号、四模型版本指针、当前获胜候选及其四模型版本指针、报告路径、当前决策和下一步。完整正文从以下位置恢复：

```text
<项目>/.prompt-compiler/history.sqlite3
<项目>/.prompt-compiler/history/<记录编号>/content.md
```

任何时候都能按记录编号恢复某次原始输入、该次四模型版本、获胜候选及其四模型版本，不依赖聊天记忆猜测。

## 失败处理

- 缺任务模型：报告缺失角色，不擅自换成未授权模型。
- 缺独立终审：允许继续搜候选，禁止正式发布。
- 缺真实案例：允许实验运行，最高只能临时通过。
- Promptfoo 未产生两组真实结果或三次覆盖不足：阻塞，不接受手工拼接。
- 旧案例退化：退回并继续使用原版。
- 红队失败：阻塞，不以放宽权限或泄露边界换取分数。
- 外部真实证据未运行：标记“外部实测未运行”，禁止发布。
- 正式优化代码、架构或配置但缺真实自定义预言机：阻塞。
- 成本达到预算：停止新增候选，保留已有证据、失败路径和回滚点。

## 适用边界

本技能负责文本工件优化及其证据链，不替代事实研究、领域专家签字、产品真实用户验收、生产安全审查或最终责任人决定。对于代码、智能体架构和配置，只优化隔离副本，仍需目标项目自身的编译、测试、集成和独立验收。
