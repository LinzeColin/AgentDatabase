# 架构、数据流与信任边界

## 一条端到端主链

```text
原始工件不可变入库
→ 需求与字面量合同
→ 训练/验证/最终/回归/红队分层
→ 数据集封印
→ 四竞品最低探测
→ 自适应总预算路由
→ 各竞品同层候选 + 下层机制证据
→ Prompt Compiler 逐维冠军合成
→ Pareto 与稳健排序
→ 冻结每引擎终审候选及哈希
→ 打开最终测试
→ 不同身份独立终审，至少三次
→ 逐竞品逐维 Bootstrap 冠军门
→ Promptfoo 双版/回归/红队
→ 外部真实证据
→ CI 重读证据与哈希
→ 发布或保持原版
```

## 五个平面

1. **治理控制面**：配置、版本、预算、身份、数据封印、注册表、证据哈希、发布门和 SQLite 历史。
2. **同层竞技面**：GEPA、AutoResearch、Meta-Harness、Promptfoo、Prompt Compiler 使用相同可见数据、统一预言机和一个总预算竞争。
3. **下层能力面**：四个竞品以能力执行器形式贡献候选、轨迹、失败模式和维度领先机制。
4. **独立评测面**：确定性断言、业务 Oracle、自定义评分器、不同身份最终评委、Promptfoo、回归和红队。
5. **持久证据面**：原文、四目标版本、候选谱系、数据封印、运行轨迹、冠军证据、发布报告和文脉指针。

## 权力分离

- 优化器只能提出候选；
- 竞品不能读取最终测试；
- 搜索期评分器不能独自放行；
- 最终评委只在候选名单冻结后运行；
- CI 不信任 Builder 或报告自评；
- Owner 决定权限、成本、法律和最终发布，不承担普通技术选型。

## 数据权威

项目内 SQLite 是运行历史与事务账本；原始工件镜像和报告可随项目进入受控 Git。若接入用户既定基础设施，长期结构化事实同步到 Private-Database，大对象进入 R2，运行节点 SQLite 只作可重建事务缓存。Skill 本身不自动上传私有数据。

## 依赖与降级

- 控制面仅依赖 Python 标准库；
- 官方 GEPA 和 Promptfoo 位于隔离运行环境；
- AutoResearch 与 Meta-Harness 只允许在可验证工作区中执行真实外部命令；不存在本地同名模拟或兼容执行器；
- 外部桥缺失时，不伪装成原生运行；若其为必选竞品，冠军门阻塞；
- 无模型、无网络或无凭据时仍可安装、自检、查看历史和准备数据，但不能形成正式冠军证据。
