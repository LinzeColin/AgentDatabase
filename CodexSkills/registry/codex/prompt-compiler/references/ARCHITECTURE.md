# 架构与信任边界

## 一条主链

```text
原始输入（不可变）
→ 需求合同与四目标版本
→ 真实或临时案例与预言机
→ 种子版本基线
→ 多引擎相同预算候选搜索
→ 帕累托前沿与最终候选名单冻结
→ 封印后的最终测试
→ 至少三次重复统计
→ Promptfoo 双组对照、回归、红队
→ 不同身份的独立终审
→ 外部真实证据
→ 持续集成发布门禁
```

## 控制面、优化面、评测面和持久层

- 控制面：标准库 Python 主运行时、配置、数据封印、身份解析、发布门禁和 SQLite 历史账本。
- 优化面：GEPA、自动研究式兼容执行器、元执行框架式兼容执行器、Promptfoo 官方优化、组合引擎和外部竞品桥。
- 评测面：确定性断言、自定义预言机、语义评委、Promptfoo、回归、红队和独立终审模型。
- 持久层：不可变原文、每次输入的四模型版本、获胜候选的四模型版本、候选谱系、运行报告、证据哈希和文脉中枢指针。

## 权力分离

优化器只产生候选，不拥有最终测试和发布权。任务模型负责实际执行；反思模型负责候选变异；搜索期评分器负责可行动反馈；独立终审模型只在候选名单冻结后比较种子版本和各引擎终审候选。身份键由运行方式、声明身份、模型和可执行文件组成；相同身份不能同时充当任务模型与独立终审模型。

## 为什么不能只使用单一工具

GEPA 擅长读取轨迹和帕累托演化；Promptfoo 擅长断言、数据集、模型对比、回归和红队；自动研究式循环擅长可归因小步实验；元执行框架式循环擅长结构、工具和恢复路径搜索。单独使用会留下互补盲区。本技能用统一数据、预算、预言机和外部裁决把它们变成可比较候选源。

## 外部竞品桥

桥接命令从标准输入读取 JSON，从标准输出返回候选数组。主控不会发送最终测试，也不会接受外部工具自报的分数或通过结论。适配器模板在 `scripts/external_engine_adapter.py`。可配置名称包括：

- `dspy_mipro`
- `opik`
- `mlflow`
- `openai_optimizer`
- `anthropic_generator`
- `google_optimizer`
- `prompthub`
- `promptlayer`

它们默认关闭，避免隐式费用、凭据泄露和供应商绑定。启用后仍必须在主控中接受相同预算和独立最终复测。
