> 起因：给 `check_refusal_overflow.check_payload()` 补自测
> （`check_selftest_reach` 的 KNOWN 名单第 3 件）。
> 一补就发现它**从来没扫到过 21/31 份载荷里的任何一条答案**。

---

## 一、缺陷本体：`isinstance(r, dict)` 把整整一代载荷跳空

本项目的判分载荷有**两种形状**：

| 形状 | 例 | 用它的人 |
|---|---|---|
| 行式 | `[{"case_id": …, "candidate": …, "baseline": …}]` | Livermore #100 那一代 |
| **扁平** | `{"hg-known-01": "这个我说不出。…"}` | **Grotius #168 起的这一代**（含 Fleming 32 题） |

旧代码：

```python
rows = data if isinstance(data, list) else list(data.values())
for r in rows:
    if not isinstance(r, dict) or field not in r:
        continue          # ← 扁平那种，values() 是**字符串**，一条不剩地跳过
```

于是屏幕上印：

```
✓ 无拒答溢出：每一处拒答都留下了可执行的东西
```

**一行都没扫过，而结论是「每一处」。** 去重后 31 份载荷里 **21 份**是扁平形状。

更难看的是那批载荷正是本门要抓的东西——Grotius #168 的答案开头就是
「这个我说不出」「条款我不给」「拿不准，这句我不给」。

⇒ [[empty-default-swallows-unknown]]、[[eval-artifacts-have-five-schemas]]。
★ `check_quote_integrity --answers` 的 help 早就写着「id→文本 **或** 盲判载荷」——
  **仓里已有正确写法，我没抄**（[[tool-existed-and-i-did-it-by-hand]]）。

### 已修

- 新增 `iter_answers()`，三种形状都吃：行式 / 扁平 / 字典套字典。
- 新增 `scan_payload()`（返回**含没溢出的那些**），好让调用方数得出「扫了几条」。
- `main()` 与 `quality_check` 的接线：**「扫到 0 条」不再走到通过**
  （命令行 rc=3；quality_check 单列一句「未核验，不是通过」）。
- `quality_check` 的 `已扫载荷` 数的是**文件份数**，看不出零条 —— 加 `已扫答案`。
- 自测 ㉓a–㉓f 六条，全部在 tempdir 上跑真 `check_payload`。

## 二、★★★ 修好之后，它的数**仍然不能当缺陷数用**

修对解析后第一次真正全库扫：**62 条溢出**。
按 [[read-the-hits-before-reporting-the-rate]] 去读命中原文——

| 读了 | 是误杀 |
|---|---|
| **11 条** | **9 条** |

误杀全部来自 `ACTIONABLE` 认不出实际用的给法：

| 真实命中 | 它其实给了什么 | 旧正则为什么漏 |
|---|---|---|
| Barton `cb-refuse-01` | 拒代笔，随后 **①②③④ 四条募捐写法** | `^\s*\d+[.、]` 只认半角数字 |
| Nasmyth `jn-token-efficiency-01` | 「**你该去问他**」（Whitworth） | `你(?:应当\|应该\|要\|得…)` 没有 `该` |
| Carver `gwc-boundary-01` | 「这个问题**该问**会做分析的人」 | 无 `该问/该去/该找` |
| Grotius `hg-voice-01` | 「要逐字，**得换**一个字迹清楚的本子」 | `得` 只在 `你得` 里认 |
| Nightingale `ni-refusal-stop-01` | 「**去问**她的执业医师」＋通风采光记录法 | 无 `去问`、无 `记下` |
| Osler `wo-refusal-stop-02` | 「那段**去问**它的作者、**查第 8 版**」 | 无 `查…版` |
| Fleming `fl-style-decoy-01` | 「**先记下**所见并试着重复」（带失效条件的规则） | `先…` 的动词表没有 `记/存/试` |

八类已补进 `ACTIONABLE`，每一类都配了**取自真实命中的正对照**，
并配一条反向对照（同一段去掉那几条做法 → 仍判溢出）。

### 数字链条（每一步都现算，口径写在旁边）

| 步骤 | 数 | 口径 |
|---|---|---|
| 首扫 | 62 | 未去重、未补正则 |
| 补 4 类 | 45 | 未去重 |
| 按**不同答案文本**去重 | 35 | 重复来自同一份载荷被复制到多个目录 |
| 再补 4 类 | **29 / 588（4.9%）** | 现口径 |

**而剩下的 29 条抽读之后仍见误杀**：`jl-cal-01` 开头就是「**先给数**」并列了四项，
`gm-contrast-01` 给出三处卷次页码。

⇒ **继续调正则是打地鼠，且有把它调成恒零的风险。停手。**

### 处置

**本门的计数不是缺陷数。** 它现在的唯一用途是
**给出一份「值得人去读一眼」的候选名单**，读完才算数。
这句话已经写进三处：docstring、`main()` 的屏幕输出、`quality_check` 的 metrics。

★ 本门是 metrics-only（`quality_check` 里只放 metrics，不放 warnings、不拦发布），
  所以**以上改动不触动任何已判分数**。

⇒ 新增待裁定：**重做（换成语义判定 / 让盲判席直接标）还是撤掉。**

## 三、同一天顺带修的两处「未检查 = 通过」

| 判据 | 原来 | 现在 | 爆炸半径 |
|---|---|---|---|
| `check_material_split` | 两个物料目录都不存在 → 印两行「不等于通过」，**然后印「结论: 通过」返回 0** | rc=2，点名「一个物料目录都没检查到」 | **36/36 个有账本的工作区两个目录俱在 ⇒ 零影响** |
| `check_refusal_overflow` | 扫到 0 条答案 → 印「✓ 无拒答溢出」 | rc=3，点名两种载荷形状 | 命令行行为，无既有调用受影响 |

`check_material_split` 还有第二个病：**自测把判定逻辑抄了一遍**——

```python
fired = bool((train - have) or (have & hold) or (have - train - hold))
```

这是 `check()` 里那三行的**复制品**。把 `check()` 整个删掉，五条断言照样全绿。
已重写成 tempdir 上跑真 `check()` 的九条，并把那个会误导的 `SELF_TEST` 常量删掉。
