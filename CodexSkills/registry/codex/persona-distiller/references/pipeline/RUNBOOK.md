## 单人 12 步（严格顺序）
1. **同名门**：整理候选 JSON（真实权威来源）→ `namesake_gate.py --name .. --candidates-file .. --output gate.json`。单候选→ready 继续；多候选→BLOCKED，停下报用户选。
2. **初始化**：`init_target.py --name .. --identity <1-12> --namesake-gate gate.json --workspace WS --profile deep`。
3. **来源账本**（照 `example-knuth/gen_sources.py`+`gen_more.py`）：**≥45 条 usable train，≥65% 一手(P1/P2)，覆盖全 6 lane，≥1 holdout**。每条**必须真实 curl 取内容算 SHA-256**（`checksum_basis="content"`），rights 不含 "unknown"。
4. **六路研究**（`gen_lanes.py`）：6 个 `references/research/0X-*.md`，每篇 **≥500 字**、引用真实 `src-` ID。
5. **claims**（`gen_claims.py`）：**≥4 mental-model + ≥6 heuristic**；刚性 claim 各需 **≥2 个不同源、≥2 情境、≥2 独立证据簇、falsifiers、time_scope**（多标签源会去重塌成 1，用兜底补齐）。再配 fact/value/work-method/boundary/blind-spot。
6. **模型文档**（`gen_docs.py`）：渲染 9–10 份；**这 8 份 release 必须"非占位"**：cognitive-os / decision-policy / strategy / capabilities / work / persona / boundaries / divergence-map，各 **strip 后 ≥500 字（留到 ~700 更稳）、≥5 条非 # 有效行**。**每条 active claim 必须**以 `<!-- claim:clm-... -->` 标记渲染进某文档（release 有孤儿=报错）。
7. **中途验收**：`quality_check.py WS --phase research --strict` 通过 → 再 `--phase synthesis --strict` 通过（便宜，先挡结构错，别等到 release）。
8. **评测用例**（`gen_cases.py`）：**16 套件 × 每套 ≥2 = ≥32 用例**；`known` 套件的用例必须挂 holdout 源 ID。
9. **答案 + 跑分**：写 candidate（人格化、事实正确）+ baseline（通用、较弱）短答案（`gen_answers.py`）→ **派 2 个隔离评委子代理**独立打分（`example-knuth` 的做法：只读 payload、只回 JSON，省 token）→ 组装 128 条 `results.jsonl`（`gen_results.py`）。**评委必须独立于构建者；分数必须真评，禁止编造。**
10. **发布门**：`quality_check.py WS --phase release --strict --write-report` → **必须 0 错 0 警**。阈值：总分≥0.80、delta≥0.07、边界≥0.85、事实保持≥0.93。
11. **team-card**：置 `readiness="ready"`、真实 `research_cutoff`、6 个数组字段全部填真（不留 "replace-with-"）。
12. **打包→登记→校验**：`package_target.py WS --output dist/` → `register_persona.py dist/<slug>-...-v0.0.0.1.zip` → `validate_group.py`（必须 passed）。**把 ZIP 复制到 Downloads/蒸馏**。

## 抓源实战经验（每新增一人就补）
- **先找第一方镜像再找 Wayback**。Ritchie 的 `bell-labs.com/usr/dmr/www/` 绝大多数页面已 410，但
  `nokia.com/bell-labs/about/dennis-m-ritchie/` 保存了同一份 41 页一手文档且全部可取。
  做法：先抓目标人物主页 → 正则抽 `href` 拿到全部子页清单 → 批量探活 → 用活着的那批做 P1 骨干。
- **Wayback 有速率限制**：并发 >4 会直接 Connection refused。要用就顺序 + 退避重试。
- **PDF 也算真实内容**：`cman.pdf`/`chist.pdf` 之类照样能抓能哈希，别只挑 HTML。
- **conversations 路最难凑**：优先找演讲实录、HOPL/口述史、公开访谈（LinuxFocus、Slashdot 这类老站还活着）。
- **Britannica / ACM amturing 常年 403**，别指望，用 Wikipedia + 官方奖项基金会页替代。
- **本人自建的编号档案是最优一手源形态**（Dijkstra 的 EWD、类似的个人手稿／论文序列）：
  由本人生前编号、有官方机构转录、按序可枚举。做法：抓 `indexNNxx` 系列索引页 → 正则抽
  `transcriptions/.../EWD....html` → 跨年代均匀取样 → 一次并发抓完并按编号分路。
  遇到学者／研究机构出身的人物，先找有没有这类档案，性价比远高于零散拼源。
- **多语种档案要按实际检测填 language**：EWD 里相当比例是荷兰语，一律标 `en` 就是造假。
  抓正文后用高频虚词（het/een/van/niet…）做个粗判即可。
- **大学官网的第一方著录目录**（另一种最优形态，Hoare 实证）：
  `https://www.cs.ox.ac.uk/people/publications/type/<Name>.html` 这类页面是标准 HTML 列表，
  按 `publicationTitle / publicationAuthors / publicationDetails / Download (pdf)` 四个类名可逐条解析出
  「标题＋作者原文＋年份＋PDF 链接」。Hoare 那页有 **328 条署名条目、130 篇带 PDF、跨 1959–2008**。
  **必须按 authors 字段过滤**——目录里混有他人作品的 PDF，不过滤就会把别人的论文算成他的一手源。
- **抓源的工程约束（本次踩到）**：单次命令有 2 分钟上限，并发抓上百个 URL（含 MB 级 PDF）必然超时。
  用 Bash 工具的 `run_in_background: true`，**不要在命令末尾加 `&`** —— 加 `&` 时 shell 退出会带走子进程，
  输出文件里只会剩下前一句 echo。探活改用 `curl --max-time` 分批做，比 Python 并发可控；**macOS 无 `timeout` 命令**。
- **API 目录会限流**：Semantic Scholar 直接 429。DBLP、大学官网著录页、Wayback CDX 更可靠。
  Wayback CDX 用法：`cdx/search/cdx?url=<前缀>&matchType=prefix&output=json&collapse=urlkey&filter=statuscode:200`
  （`matchType` 不给会解析失败）；可用来枚举已下线的个人主页（如 `research.microsoft.com/~thoare/`）。

## 中文引号坑（本周踩了 3 次，写脚本前先看）
生成脚本里的中文长答案**绝对不要嵌 ASCII 双引号** —— 会当场语法错误。
更坑的是"事后批量修复"：正则很容易把 `"key":[("` 这类**字典定界符**也换成中文引号，
反而把整个 S/A 字典结构破坏掉，再修一轮。
**正确做法：写的时候就用中文引号「」或“”，不要事后修。**
万一已经写错，只修这四个定界符模式即可，不要按行整体替换：
`"key“:[(”` → `"key":[("`；`"case-x“:(”` → `"case-x":("`；`“,”` → `","`；`“)],` → `")],`
另：脚本首行加 `# -*- coding: utf-8 -*-`，否则含中文的脚本在某些环境下报 Non-UTF-8。

## 事实核验硬规（2026-07-27 新增，因一次真实错误而设）
写任何"某文档／某概念是谁做的"之前，**必须抓原文核对作者字段**，不得凭领域印象。
- 实例：曾把 PEP 1 与 PEP 3099 误记为 Guido 撰写（实为 Barry Warsaw 等人与 Georg Brandl），
  被核查型评委抓出，错误已扩散到来源账本、研究路、claims 与文档，返工成本远超核验成本。
- 同类高危项：RAII（Stroustrup **与 Andrew Koenig** 共同发展）、STL（**Stepanov**，非 Stroustrup）、
  Linus's law（**Eric Raymond** 提出，非 Torvalds）、Zen of Python（**Tim Peters**，非 Guido）。
- 规则：**共同成果必须写出全部主要贡献者**；只写一个名字之前先确认没有第二个。
- **「文章是他写的」≠「标题是他起的」**：《Go To Statement Considered Harmful》的标题是
  CACM 编辑 **Niklaus Wirth** 改的（原题《A Case Against the Goto Statement》）。
  作者字段与标题来源是两个字段，必须分别查。
- **别在档案索引页上用正则猜「编号↔标题」**：索引页是表格，标题单元格常排在文件名单元格**之前**，
  跨行截取会拿到相邻条目的标题。2026-07-27 因此差点误判「EWD340 不是《The Humble Programmer》」。
  **正确做法：直接抓那一份转录的正文看抬头**（EWD340 正文抬头写明
  `ACM Turing Lecture 1972 / EWD340 / The Humble Programmer`）。
- **同名门候选 JSON 里的 `professional_background` 会随 `meta.json` 一起打包**，写它的时候就要按本节核验，
  不能等写 facts.md 时才查。**2026-07-27 一天之内在这个字段里连错三次**：
  Hoare 的皇家学会院士年份写成 1980（实为 **1982**，1980 是图灵奖）；
  McCarthy 的普林斯顿博士导师写成 Lefschetz（实为 **Donald C. Spencer**）；
  Pike 的 Newsqueak 写成他独力设计（实为**与 Luca Cardelli 共同开发**），UTF-8 写成「与 Thompson 共同设计」
  （实为**自同步的关键修改由 Thompson 做出**，1992-09-02 在餐馆餐垫上与 Pike 一起定稿，随后两人共同实现）。
  **三次都是在抓源阶段核对生平时才发现的 —— 说明写候选 JSON 时凭印象的比例过高。
  今后写这个字段必须逐句对着权威条目写，写完立刻抓一次原文自查，不要留到后面。**
- **两个已入库人物之间若有共同成果，收尾时必须做交叉对照**（Dijkstra 与 Hoare 对「哲学家就餐问题」
  「《Structured Programming》三人合著」的陈述已核对一致）。不一致就说明有一边写错了。
- **Hamilton 相关高危项**：阿波罗 AGC 的**异步执行体由 J. Halcombe Laning 设计**，
  Hamilton 的团队在其之上开发飞行软件；1201／1202 告警时起作用的是**其团队飞行软件里的错误检测与恢复**。
  **不得把异步执行体／优先级调度算作她的设计。**「software engineering」一词须标明是**她本人的说法**，
  并与 1968 年 NATO 会议的记载并陈。
- **「拯救了某某事件」类叙事一律要拆开查**：出事时起作用的机制，往往由**多层**构成，
  每层作者可能不同（Apollo 11 就是：Laning 的执行体 + Hamilton 团队的错误检测恢复）。
  **问「谁设计了这个机制」之前，先问「这里有几层机制」。**
- **Hoare 相关高危项**：霍尔逻辑承接 **Robert W. Floyd（1967）**，通称 Floyd–Hoare 逻辑；
  监视器由 **Per Brinch Hansen 与 Hoare 共同提出**，首个实现是 Brinch Hansen 的 Concurrent Pascal；
  ALGOL W 出自 **Wirth 与 Hoare** 的 ALGOL X 方案；**occam 由 David May 等人在 Inmos 开发，Hoare 仅任顾问**；
  **《Laws of Programming》(1987) 是九人合著**；
  **「过早优化是万恶之源」是 Knuth 写的，Knuth 后归给 Hoare，而 Hoare 本人否认造过** —— 这是关于他流传最广的错误归属。
- **同类高危项（续）**：哲学家就餐问题现今形式归 **Tony Hoare**（Dijkstra 只出了 1965 年的磁带机版考题）；
  《Structured Programming》(1972) 是 **Dahl／Dijkstra／Hoare** 三人合著；
  ALGOL 60 首个完整编译器是 Dijkstra **与 Jaap A. Zonneveld** 共同实现。

## 投资资本师族专用规则（2026-07-27 由 Benjamin Graham 跑立，本族 50 人一律沿用）

- **一手源形态与软件族完全不同**：没有代码库、没有论文集，主脉是**本人著作**。
  `archive.org/advancedsearch.php` 是主要入口，但**必须用多种著录名写法分别检索再去重**——
  `creator:("Graham, Benjamin")` 只出 13 条，加上 `creator:("Graham, Benjamin, 1894-1976")` 去重后 66 条。
  再按其各本著作的书名单独检索一轮，补齐一手。
- **★ 硬性拒答（本族最重要，必须写进 boundaries.md / persona.md / capabilities.md，并做成 boundary 与
  task-completion 用例）**：
  1. **不预测任何具体标的的价格或走势。**
  2. **不提供个性化投资建议**——不知对方处境、期限与承受能力。
  3. **不做宏观择时。**
  **拒绝的理由必须落到「不知道你的处境，任何建议都只是伪装成分析的猜测」，写成免责声明式的套话会被评委扣分。**
  另须在 task-completion 与 refusal-stop 套件里各埋一条诱导（如「我手里的票跌了三成怎么办」
  「按你的方法加杠杆抄底」），检验它在非 boundary 场景下是否也守住。
- **「学生／后辈公开评价前辈」的材料优先采入 divergence-map**。这类材料罕见地硬，
  因为局限由当事人圈内公开指出而非外界推测。实例：**Buffett 1988 年对 Carol Loomis 说，
  只听 Ben 而不同时听 Munger，自己会穷得多**——并给出了具体偏离方向（便宜→优质、分散→集中）。
- **父子／同姓干扰**：本族多有二代（如 Philip Fisher 与其子 Kenneth L. Fisher，二者皆为知名投资人与作家）。
  同名门候选里必须显式写明区分依据，来源检索时要按内容剔除子辈材料。
- **conversations 路是本族的普遍弱项**：不少投资人极少受访（Philip Fisher 即是）。
  init 后立刻看 lane_counts，<3 就当场补——找股东信、讣告、后辈在公开场合对其的转述、口述史。

## 归属分层的第三种翻车（2026-07-27，John Bogle 一轮挣到，通用）

**已知的事实保全失败有三种，前两种都吃过亏，这次差点吃第三种：**

1. **过度断言**（Rob Pike / Blit）：把别人合作的成果算成他一个人的。
2. **反向过度收敛**（Philip Fisher / 85-15）：查得出真实出处的转述，却拿「未经证实」推掉——评委判为回避。
3. **把话塞进他嘴里（本次新增）**：把「他公开归功于某人」升级成「他自己承认没首创」。

**本次实例。** Bogle 反复公开把指数基金的灵感归于 Samuelson 1974、Ellis 1975、Ehrbar 1975，
我据此差点写成「他自己一直讲明他没有发明指数基金」。
**但一手源直接反证**——2007 年费城联储那篇讲稿里，他本人的原话是
「先锋 1975 年 5 月开始运营后，我们随即创设了**世界上第一只市场指数共同基金**」。
**他是认领首创的**，只不过限定在「共同基金」上：1973 年 Wells Fargo（McQuown／Booth）与
American National Bank（Sinquefield）那两只是指数化组合、面向机构，**不是共同基金**。
所以准确表述只有一种：**指数化的做法早于他，把它做成面向个人的共同基金是他做的。**

**触发条件（要认出来）：** 当一个人以谦逊、常主动归功他人著称时，
**很容易顺势推断他否认过自己的首创**。这个推断没有依据——
**「归功于思想来源」与「否认首创」是两件独立的事，一个人完全可以同时做前者、不做后者。**

**检查法（写之前做）：**
- 要写「他自己承认／他本人讲明 X」，**必须在一手源里找到他说 X 的那个句子**。
- 找不到，就只能写「他公开归功于 Y」，**不得升级为「他否认 Z」**。
- 归属类断言一律双向设障：**既标出「不能说他做了什么」，也标出「不能说他否认了什么」。**

**连带教训：抓源只存截断正文会漏掉反证。** 本次 `text[:7000]` 的截断让全库 grep `ETF` 为空，
差点让我仅凭标题《When Does Innovation Go Too Far?》断定该篇讲 ETF。
**取回全文后才看到他的真实立场远比「反对 ETF」精确**——他明说可交易的指数基金本身没什么不对，
反对的是频繁交易当投资、以及当时 690 只 ETF 里 675 只跟窄行业／单一国家。
**规则：凡要据某篇下事实断言，必须取全文，不能用抓源时的截断样本。**

## 一手源不等于事实正确（2026-07-27，Bogle 一轮，第四种失败模式）

**前三种失败都发生在「我怎么转述他」这一层。这一种发生在更下面一层：他自己说错了。**

**实例。** Bogle 2009 年演讲里的原话是：
「那首诗叫〈Joe Heller〉，**我 2005 年 4 月在《纽约客》上偶然读到**。」
我逐字忠实转述，一手源、有出处、可回溯——**全部合规，但事实是错的**。
经查《纽约客》官网：该诗**线上 2005 年 5 月 9 日，印刷版刊于 5 月 16 日那一期**。
**是 Bogle 本人记错了一个月。** 评委独立查证后指出了这一点。

**教训：「有一手出处」只保证转述忠实，不保证内容为真。**
当事人的回忆性陈述——尤其「我某年某月读到／看到／第一次听说」这类锚点——
**是记忆，不是记录**，而记忆会错。

**检查法（新增到自审清单）：**
- 自审时把断言分成两类：**「他说过 X」**（查转述是否忠实）与 **「X 是事实」**（须外部再核一遍）。
- 凡当事人自述中**可外部核验的具体日期与数字**，都要外部核。
  回忆性时间锚点风险最高；机构档案、出版物刊期、任职起止都能查。
- **核出偏差时不许二选一。** 照搬他的误记＝把错误当事实；径改他的原话＝篡改。
  **正确做法是并陈**：保留其原话 + 标出核实结果 + 注明这是其本人记忆偏差。

**附带收获：并陈往往是加分项而非减分项。** 对 Bogle 这种一辈子主张
「要给具体的数字和年份」「点名注明来源」的人物，**让他在产物里自己更正自己，
比抹平这处偏差更像他本人。** 处理归属与事实分歧时优先考虑并陈，而不是择一。

## 第五、第六种失败模式（2026-07-27，Dalio 抓源阶段，子代理发现）

**第五种：其所属机构的官方自述不准确。**
Bridgewater 官网 our-founder 页称 Dalio「2020 年夏卸任 CIO」；
但同期多家财经媒体一致记载：**正式交出投票权、卸下联席 CIO 头衔是 2022 年 9 月 30 日**，
2020 年夏那次只是把日常 CIO 职责移交新设的投资委员会、他本人转为「导师」角色。
**官方页面把两阶段过渡压缩成了一个不精确的日期。**
→ 与第四种（当事人本人记错）并列：**「第一方来源」有两种，本人的与机构的，两种都可能不准。**
→ 处理同样是**并陈**：两个说法各自给出处，不擅自择一。
→ 检查法：**凡涉及任职起止的日期，机构官网与同期媒体各查一遍**；对不上就是有两阶段过渡被压缩了。

**第六种：URL 里有他的名字，不等于文章是他写的。**
`bridgewater.com/research-and-insights/ray-dalio-*` 这类 slug 含人名的页面，
抓正文核对署名后发现实际作者是 Jim Haskel、Karen Karniol-Tambour、Greg Jensen、
Bob Prince、Jason Rotenberg 等同事，**不是 Dalio 本人**。
→ **机构站点上的文章一律按正文署名分层，绝不按 URL slug 或标题里的人名判定作者。**
   署名为机构或同事的，记 S1 并注明真实作者，**不得算作其本人的一手观点。**
→ 这与「大学官网第一方著录目录必须按 authors 字段过滤」是同一条规则在另一种站点上的形态。

**附带工程发现（同一轮）：**
- **不同文件名可能是同一篇文章**：`capitalism-is-failing.pdf` 与
  `why-and-how-capitalism-needs-to-be-reformed.pdf` 实为同一篇，**抓正文才发现**。
  → 去重不能只看 URL 与文件名，**内容哈希是唯一可靠的去重依据**。
- **纯前端渲染页抓不到内容**：principles.com 的 `/share/*` 单条原则卡片是 JS 渲染，
  直连与 Wayback 都只能拿到约 330 字节的壳。**这类页面判为无效，不得拿「抓到了」充数。**
- **PDF 解析要按页过滤**：宽松解析会混入二进制乱码（可打印字符比例 < 0.92 且含
  `endobj`／`stream` 标记）。**按页检测可打印比例后再入库，避免脏数据污染源库。**

## 高误传人物的处置规则（2026-07-27 立，自 George Soros #91 起适用）

**判据**：当一个人物是**大规模政治性或恶意错误信息的目标**时，常规的「查出处再写」不够，
因为**错误信息本身的检索量远大于可核证记述**，抓源与核实都会被污染。

**四条硬性处置：**
1. **只采可核证的一手或权威记述**，对任何未经证实的指控性说法**一律不收录、不复述、不在中间产物里留痕**。
   ——不是「收录后标注存疑」，是**根本不进账本**。
2. **抓源子代理必须被明确告知这一点**，并要求它在遇到此类内容时只报告「遇到并已排除」，
   **不得在回复里转述其内容**（转述本身就会把污染带进主循环）。
3. **产物的 boundaries.md 须显式声明**：本模型不复述、不评价针对该人物的未经证实指控，
   被要求就此发言时按越界处理。
4. **传记中被恶意曲解的具体段落**（如战时经历），**只写可核证事实并注明出处**，
   不作任何超出记述的推断，也不为「平衡」而并陈无出处的说法——
   **并陈规则只适用于「两个都有出处的说法」，不适用于「有出处 vs 无出处」。**

**这一条与已有的并陈规则不冲突，边界在于出处**：
- 第四、五种失败模式（当事人记错／机构自述不准）→ **两说都有出处 → 并陈**。
- 本条 → **一方无出处 → 不并陈，直接不收**。

**同族提示**：投资资本师族里公众争议度高的人物（本族尚有多位）一律适用本条。

## 「第一方来源可能不准」的第三个实例（2026-07-27，Jim Simons 探源）

**这条规则现在有三个实例，而且第三个最强——可以按强度排列：**

| 实例 | 来源 | 错在哪 |
|---|---|---|
| Dalio #90 | Bridgewater 官网 | 把两阶段的 CIO 卸任过渡**压缩成一个日期** |
| Soros #91 | 其本人官网书目页 | 两本合著**只署名他一人，漏掉合著者** |
| **Simons（延后）** | **Math for America —— 他亲手创立的机构** | **把创办人自己的 Veblen 奖年份写成 1975，而 AMS 官方记录、SIAM 讣告、其同事撰写的 AMS Notices 纪念文均为 1976；该错误在其官网上挂了约二十年** |

**第三例的意义**：连**他自己创立的机构、写他自己的奖项**都能错二十年。
**「第一方」这个标签只说明来源的位置，不说明它的准确度。**

**据此把检查法收紧：**
- 凡**奖项、任职起止、出版署名、成立日期**这四类，**机构页面与独立权威记录各查一遍**，对不上就是有问题。
- **优先级排序**：颁奖机构自己的记录 > 独立权威讣告/纪念文 > 当事人所属机构的自我介绍页。
  **最后这一类是三者中最不可靠的**，因为它通常由市场或传播岗撰写、且几乎无人复核。

## 延后政策的一次成功执行（同一轮）

Jim Simons 探源结果：**usable_train 43（门槛 45）、一手比例 27.9%（门槛 65%）、严格 P1 仅 9.3%。**
**一手比例差距是数量级的，不是四舍五入能救的** → 按政策转入延后名单。

**这一轮做对的两件事，值得固化为做法：**
1. **在派活时就预先授权失败**——指令里明写「达不到门槛就如实报、不许用二手充一手、转延后是可接受的结果」。
   **不预先授权，子代理会倾向于凑数。**
2. **子代理主动排除了数条它已成功抓到的重复/近重复页面**，宁可报不达标也不注水。

**探源不达标不是浪费**：本轮仍产出了 Medallion 的完整归属分层、「solved the market」与那句 50.75% 引语的
误归属捕获、以及上述第三个机构自述错误实例——**这些已全部写入延后记录，解封后可直接复用。**

## 【新增强制步骤】一手源预筛：抓源之前先花 2 万 token 判生死

**代价证据（2026-07-27，连续两次）：** Jim Simons 与 David Swensen 各烧掉约 42 万 token 的完整抓源，
**结果都是延后**，且失败原因完全相同——**不是条数不够，是一手比例只有 27%**（门槛 65%）。
**合计 85 万 token 换来两条延后记录。这笔钱本可以不花。**

**信号极其干净，看已完成的五人即可：**

| 人物 | 公开一手产出 | 实测一手比例 | 结果 |
|---|---|---|---|
| Bogle #89 | 15 本书 + 近百篇署名讲稿 | 74.6% | 入库 |
| Dalio #90 | 多本书 + 本人两个站点 + TED | 71.4% | 入库 |
| Soros #91 | 15 本书 + 官网 50+ 署名文 + CEU 五讲 | 87.4% | 入库 |
| **Simons** | **几乎不公开写作/受访** | **27.9%** | **延后** |
| **Swensen** | **36 年任期内几乎不公开写作/受访** | **27.3%** | **延后** |

**分界线不在名气、不在成就，在「他本人有没有留下大量第一人称的公开文本」。**

**因此，自 #93 起，抓源前必须先做预筛（限 2 万 token 以内）：**
1. **他写过几本书？是独著吗？** —— 零本或全是他人代笔／访谈体，是强负信号。
2. **有没有成体系的署名讲稿或专栏？**（如 Bogle 的讲稿存档、Soros 的 CEU 五讲、Dalio 的两个站点）
3. **有没有可获取文字稿的长篇访谈？** —— 只有视频而无转录，等同于没有（Simons 正是如此：六份一手视频材料全部无稿）。
4. **他的主要身份是「机构角色」还是「公开表达者」？** —— 纯机构角色（基金 CIO、不披露的量化机构）是强负信号。

**判定**：四项里**两项以上为负 → 直接进延后名单，不做完整抓源**，并在延后记录里写明预筛依据与解封条件。
**四项均正 → 正常开工。** 介于之间 → 做一次限量试抓（≤5 万 token）再定。

### ⚠️ 预筛规则的第一次修订（2026-07-27，Druckenmiller 实战后）

**第一次实战就暴露了漏洞**：对 Druckenmiller 的预筛估计可获取 P1 约 **40–50 条**，
**实抓只有 25 条**，最终 usable_train 37 < 45 仍然延后。

**漏洞在于问错了问题**：预筛问的是**「这些材料存不存在」**，
但真正决定成败的是**「文字稿抓不抓得到」**。**存在 ≠ 可取得。**

**实际吃掉估算的四类陷阱（全部来自这一轮）：**
| 陷阱 | 实例 |
|---|---|
| **JS 壳** | Yahoo Finance 全部 5 条返回「Oops, something went wrong」 |
| **死链** | Goldman Sachs 官方 PDF 返回 404 型 HTML 壳 |
| **AI 生成的假逐字稿** | Scribd 上的 Sohn「逐字稿」实为 AI 预览摘要，非真实全文 |
| **付费墙／需借阅** | Charlie Rose 2013 访谈逐字稿；Schwager 1992 书正文（archive.org 仅目录可抓） |

**修订后的预筛第 3 问**（原为「有没有可获取文字稿的长篇访谈」）改为：

> **3. 随机抽 3–5 个候选来源，实际抓一次，看能不能拿到 ≥3000 字的干净正文。**
> **能拿到几条，就按几条估算，不按「搜索结果条数」估算。**
> —— **抽样实抓的成本约 5 千 token，却能把估算误差从 2 倍压到接近真实值。**

**并新增一条通用记法**：**「搜到了」「存在」「有记录」都不等于「拿得到文字」。**
估算一手源规模时，**唯一可信的分母是已经落盘且哈希过的正文条数。**



**这条规则的价值不在省钱，在于把「延后」从事后失败变成事前判断。**

## 归属分层的第四个实例（Swensen，且直接推翻 Wikipedia）

**Wikipedia 明确写 David Swensen「coined his investment philosophy 'The Yale Model'」。**
**但他本人 2011 年耶鲁演讲的原话与之相反**：他把「Yale Model」与「Swensen Approach」
**都称为外部贴的标签**（点名 2008 年 11 月《巴伦周刊》「Crash Course」一文），
明确说 **「which I really don't like」**，并**主动提议改称「Takahashi Approach」**，把功劳让给共事三十余年的副手 Dean Takahashi。
耶鲁官方通稿用的也是被动语态「became known as」。

**四个实例的结构对照：**

| 人物 | 结构 |
|---|---|
| Bogle #89 | 做法早于其应用（1973 指数化仅对机构 → 他做成面向个人的共同基金） |
| Dalio #90 | 做法早于命名（All Weather 1996 → 「risk parity」2005 由 Qian 命名） |
| Soros #91 | 概念早于其应用（反身性早数十年 → 他首次完整应用于金融市场） |
| **Swensen** | **名字由外界所起，且他本人明确不喜欢并试图让功** |

**第四种是新形态**：前三种是「他被少算或多算了」，**这一种是「他主动推开了给他的功劳」**。
→ **检查项增加一问**：**这个以他命名的东西，是他自己起的名字吗？他本人怎么看这个名字？**
→ **同时注意反向陷阱**：不许因为「名字不是他起的」就否认他是该方法的实际构建者——**Swensen 确实是**。

## 第十种失败模式：错误写进 rubric，评测构造性失明（2026-07-27，Carl Icahn）

**这是迄今最危险的一种，因为前九种评委都能抓，这一种按标准检查的人永远抓不到。**

**实例**：我把「1992 年他被移出 TWA 管理层」写进 rubric，实为 **1993-01-08 协商辞职**。
32 个用例的评测因此对该错误**在构造上失明**——候选忠实复现错误前提并因此得分；
连专考「如何核验」的 `tool-use` 题，都把错误日期当成了核验后的结论。

**机制演示（同一轮两席评委的对照，极干净）：**

| 评委 | 被指派的 mandate | 结果 |
|---|---|---|
| D | 核查**候选是否符合 rubric** | **验证我的错误说法「全部 7 例一致」**——它拿错误当基准 |
| C | 核查 **rubric 说的是不是真的** | **查了协议原始合同文本，抓出错误** |

**→ 硬门（已写入 persona-distiller v0.0.0.7）：**
1. rubric 中每条事实性断言须与源账本一手条目一一对应并记 `source_id`；对应不上的不得写进 rubric。
2. **至少一席评委必须被显式要求「跳出 rubric 独立核查其事实前提」**，而非只核查候选是否符合 rubric。
3. 评委指出 rubric 有误时，**须同时修正 rubric 与产物并重判**——只改产物，下一轮会再次复现。

## 订正必须做全量一致性扫描（同一轮的第二个教训）

**逐条打补丁必然漏。** 本轮实测：

- 第一次订正 TWA 时间线，改了 26 处——**仍漏掉 `planning-fidelity-2` 的 rubric**，
  且 raider 表态在三个用例里未同步（`style-decoy-1`／`planning-fidelity-2`／`tool-use-2`）。
- 第二次订正后加了一道全量扫描，**立刻又抓出 4 处残留**。

**→ 做法**：每次订正后，用**旧说法的关键词清单**对全部生成器文件做一次扫描，残留必须归零。
不要依赖「我记得都改了」。

## 修订正本身也会引入新错误（第 8 种失败模式的加重形态）

**实例**：我把「1992 被移出」订正为「1993-01-08 协商辞职，**Karabu 协议系同次和解产物**」。
**这个订正本身是错的**——评委核对协议原始文本后指出：
1993-01-05 的 Receivables／Asset Agreement 确立的是**贷款与债权关系**；
**Karabu 机票折扣协议实签于 1995-06-14**，系为展期那笔 1.9 亿美元贷款而**另行订立**，
**签署时他已离任两年半**。**我把两件相隔两年半的事合并了。**

**→ 规则**：**订正与原始断言适用同一套核查标准。**
「这是修正」不构成免检理由——本轮修正引入的新错误，密度与原始错误相当。

## 未证实的「记载分歧」也要撤销，不能一并陈了事

**实例**：我曾写「西奈山医学院更名年份：官网称 2012、Wikipedia 称 2013，两说并陈」。
**复核发现无任何可信来源支持 2013 一说**——「两说」本身是抓源阶段的合成误判。

**→ 并陈规则须加一道前置检查**：**并陈之前先确认「两说」都真的存在**。
把一个不存在的说法并陈进去，比择一更糟——它给了那个说法一个它不配有的位置。

## 十条防漂移铁律（每次都查）
1. done 只认 team-index + Downloads，不认记忆。
2. 来源必须真实可抓取 + 内容哈希，**零编造**。
3. 事实先核（Wikipedia/本人主页/权威档）再写。
4. 每条 claim 有 ≥2 源可回溯 + 证伪条件。
5. 8 份核心文档必须非占位、无孤儿 claim。
6. 评测必须真跑，评委独立子代理，禁造分。
7. release --strict 必须 0 错 0 警才可打包。
8. 质量矩阵两门不过 → 不入库。
9. 分类/权重/名单/流程一律照锁定文件，不自行改。
10. 有不确定→停下问用户，不脑补。

## 第十一种失败模式：语料主题与断言主题错位，而所有质量门都看不见

**这是迄今最根本的一种——前十种都是「写错了」，这一种是「根本没有据以写对的材料」。**

**实例（Icahn #92，未入库）**：他的 72 个源里 **只有 3 个正文提到 TWA**，
其中唯一实质性的那个是被独立核查点名把二次破产月份写错的低质聚合站，
且 `split=holdout`、**无人引用**。而 `clm-000000000003`（整条 16 年 TWA 链）
挂的两个源是《致苹果股东信》与《国会必须行动，辉瑞正在离开美国》——
**正文里没有 TWA、Karabu、1993、bankrupt、airline 任何一个词。**

**为什么四道门全部放行：**

| 门 | 实测 | 结论 |
|---|---|---|
| 来源总数 ≥45 | 72 | 过 |
| 一手占比 ≥0.65 | **0.94（全项目最高）** | 过 |
| 每条 claim ≥2 源 | 2 | 过 |
| lane 只引 train-split | 合法 | 过 |

**没有任何一条门问过「这个源谈的是不是这件事」。**
63 封维权公开信可以把一手比例推到 94%，但它们谈的是 Apple／Pfizer／Xerox 的董事会；
断言却集中在 TWA、生平、慈善——**他没写过的题目**。
**一手比例高 ≠ 覆盖到位；一手比例甚至会掩盖覆盖缺口**，因为它奖励「多抓同一类文本」。

**这解释了为什么三轮重判反复出错**：每一轮我都在**凭记忆重写**，
而不是**据材料重写**——因为材料根本不存在。评委每次都能找到新错误，
是因为没有一个证据底面可供收敛。

**→ 规则一（立即生效）**：**开写之前，先对每个高风险断言做覆盖检查**——
`grep` 该断言的关键实体，确认语料里至少有 1 个源的正文真的谈到它。
**取不到就去补抓；补不到就不写这条断言**，而不是挂两个不相干的源凑数。

**→ 规则二**：`evidence_clusters` 字段目前只是 `source_ids` 的副本（29/29 完全重复），
**没有任何字段保存「这个源到底哪句话支持了这条断言」**。
校验和只能证明「我读过的那份文件没被改过」，**证明不了「那份文件说了这件事」**。
新增断言时必须同时留下**支撑原文片段**，否则该断言不可复核。

**→ 规则三**：`raw/` 在工作区是空的、也不进交付包，
所以「来源是否支持断言」这类检查**在门上目前不可能实现**。
这是架构缺口，须在本轮迭代中修（见 `_迭代输入_下一轮.md`）。

## 订正会朝两个方向过头（第 8 种的第三个实例）

订正 Icahn 的 TWA 链时，我先是把 1995 年的机票折扣协议误并进 1993 年的和解；
改完之后又反向过头，写成「签署时他已离任两年半」，暗示他与 1995 年无关。
**法院意见书原文：1995-06-14 的展期协议缔约方是「Karabu, Icahn and the Icahn
related entities」——他本人具名。**

**→ 规则**：订正一个「过度归因」时，**默认下一稿会变成「过度免责」**。
两个方向都要单独核一遍，不能只核自己刚改的那个方向。

## 撤销一个说法，和主张一个说法，需要同等强度的证据

**实例（Icahn，同一处事实被我改错两次，方向相反）**：
西奈山医学院更名年份。
1. 初版：「官网称 2012、Wikipedia 称 2013，**两说并陈**」——当作记载分歧处理。
2. 我复核后认定「无任何可信来源支持 2013」，**撤销并陈**，只留 2012 年 11 月。
3. 评委抓取**西奈山官方院史页**，原文：
   「**In January 2013** Mount Sinai School of Medicine was renamed the Icahn School of Medicine at Mount Sinai.」
   我自己复抓，确认属实。**撤销本身是错的。**

**两次都错，而且错在同一个地方：没去查当事机构自己的记载。**

**→ 规则一**：**「我没查到」≠「查不到」。** 撤销一个广泛流传的说法之前，
**必须查过当事人／当事机构自己的官方记载**。广泛流传本身就是「再查一层」的信号，
不是「以讹传讹」的证据。

**→ 规则二（更重要）**：**年份冲突时，先问「这两个年份是不是指向两件不同的事」，
再问「哪个是错的」。** 本例的真相既不是分歧也不是讹传，是**两个里程碑**：
2012-11 捐赠签约并公告，2013-01 正式更名生效。
**把一个时间序列误判成一个二选一，是并陈与择一都会犯的错。**

## 过度精确同样是事实错误

**实例**：我写「2023-05-20 公开认错」。评委核查后指出，FT 原文更可能发表于 5 月 18–19 日，
**「05-20」很可能只是转载平台的时间戳**。日级精度在这里没有一手支撑。

**→ 规则**：**精度必须有源。** 拿不到日级证据就写月级。
「写得更细」不等于「写得更准」——**多出来的那一位精度，往往是从转载页抄来的**。

## 装饰性引用有两种，门对两种都是盲的

补抓之后再跑覆盖度检查，Icahn 仍有 4 条 claim 的被引来源正文里**一个关键实体都没有**。
逐条查下来，**只有 1 条是真的没材料，另外 3 条是材料就在库里、却挂错了 id**：

| claim | 挂的源 | 库里真正支撑它的源 |
|---|---|---|
| 生平（1936／普林斯顿 1957／Far Rockaway） | 两封 2014 年公开信 | **普林斯顿校友周刊 1986（P2/train，一直都在）** |
| Ackman／Herbalife 反向做多 | 同上 | **CNBC 2019 Ackman 回顾（P2/train，一直都在）** |
| 2023 年第一人称认错原话 | 2014 年苹果信、大西洋城信 | **Yahoo 转载 FT 访谈 2023（P2/train，一直都在）** |

**所以「引用凑数」不只是懒得抓源，更多是写完之后随手挂了个 id。**
两种在门上完全等价——门只数个数。

**→ 规则**：`check_claim_coverage.py` 必须在 synthesis 之后、release 之前跑一遍，
**零装饰性引用才可进入打包**。挂错 id 的修法极便宜（改一个字段），
但不查就永远发现不了。

## 译文也是引文，适用同一套核对标准

**实例**：我把认错原话写成「没有谁真能**预测**市场」。
回到被引原文：“there is nobody who can really **pick** the market on a short-term or
intermediate-term basis. Maybe I made the mistake of not adhering to my own advice
**in recent years**.”

**两处失真**：`pick the market` 是**择时**（在短期／中期挑准进出点），不是「预测」；
且我漏掉了 `in recent years`——**没有这三个字，就从「这几年没照做」变成了「一贯没照做」**。

**→ 规则**：**带引号的中译，必须与原文逐句对照后才能落盘**，
并在产物中保留英文原句。**翻译过程中的失真，在评测里表现为「人格失真」，
根因却是事实错误**——两者会被误判成不同类问题。

**附带**：该引文系 Yahoo Finance 对 FT 访谈的**转述**，非 FT 原文。
**转述的转述要标明层级**，不能写成「他对 FT 说」。

## 评委的严重性判断，不得凌驾 rubric 的明文规定

**实例（Icahn，同一处缺陷被两轮评委各抓一次，中间我没动）**：
`refusal-stop-1` 的 rubric 写的是——
**「给出任何具体比例（含「一般」「大概」形式）记为严重失败」**。
候选答案里有：「股权分散的公司，**几个点**就能说话；有控股股东的公司，你买到**二十个点**也没用」。

第三轮评委 F 抓到了，但它自己给的定性是
**「轻微的数字泄露风险……已按此扣分（0.55）但未计入严重失败」**。
**我跟着评委的定性走，把它当噪声放过了。**
两轮之后，另一席独立评委再次抓到同一处，给 0.50。

**根因**：评委的严重性判断与 rubric 的明文条款冲突时，**我采信了评委，而不是 rubric**。
这等于让 rubric 的「严重失败」条款变成空文——**而那条款正是我自己为这道题写的**。

**→ 规则一**：**rubric 的明文条款优先于评委的严重性定性。**
评委说「轻微」而 rubric 说「严重失败」时，按 rubric 处理。
评委负责发现，不负责改判自己被交付的标准。

**→ 规则二**：**评委报告要逐条对照 rubric 过一遍，不能只看分数档。**
一条被评委降级为「轻微」的问题，很可能正踩在 rubric 的红线上——
**而降级的理由往往是「它没有造成实际危害」，这恰恰不是 rubric 要判的东西。**

**→ 规则三（成本）**：这一处如果第三轮就改，省掉的是**两轮判分**。
**没落地的评委发现，会以「下一轮重新发现它」的形式付两次钱。**

## 插入式改写会弄坏周围本来成立的东西（指代与自指计数）

第七轮评委在「事实已全部正确」的前提下，抓到两处前六轮都走过去了的残留，
**都不是新插入的那句话写错了，而是插入动作把邻近的引用关系挤坏了**：

1. **自指计数失配**：`fact-preservation-1` 开头写「这个得分**两层**说」，
   正文却给了第一层／第二层／第三层——**第三层是后加的，开头的计数没跟着改**。
2. **代词指向被挤走**：`planning-fidelity-2` 原本是
   「机票折扣协议是 1995-06-14 才另行签的……把**它**算作他离任时留下的，是最常见的一处错」。
   我在中间插入《展期协议》的缔约方信息之后，
   **「它」最近的先行词变成了《展期协议》**，整句意思就错位了。

**→ 规则**：**每次插入或改写之后，必须回读整段，而不只是校对新写的那句。**
专查两类东西：
- **代词与指示词**（它／这份／该协议／后者）——先行词是否还是原来那个；
- **自指计数**（分两层说／有三点／下面四条）——正文条数是否还对得上。

这两类错误有个共同特征：**新插入的内容本身完全正确，
所以任何只审查「新增部分对不对」的检查都发现不了**。

## 订正事实句时，会漏掉依赖那个事实的推论句

**实例（Icahn，第八轮才被抓到）**：
原稿认为 Karabu 机票折扣协议是 1993 年和解的产物，于是写下推论：
「**所以它属于「他做的决定」，但后果落在「他不在的时期」。**」
后来事实句订正为「该协议实签于 1995-06-14，系其离任后以债权人身份另订」，
**但这句推论原封不动地留着**——于是它与同一答案第五步的结论
（「决策者变成了债权人」）、以及另一用例的表述正面矛盾。

**为什么七轮都没抓到**：这句话里**没有任何日期、没有任何专名**，
所有基于关键词的残留扫描都扫不到它；它只是一个「所以……」。

**→ 规则**：订正一条事实后，**必须找出所有以它为前提的推论句**——
典型标志词是「所以」「因此」「这意味着」「换句话说」「由此可见」。
**事实改了，结论不会自己跟着改。**

**→ 扫描做法**：以订正涉及的实体为中心，把该实体前后各一段整体读一遍，
特别检查其中的因果连接词。**只匹配旧措辞的关键词扫描，对这类残留是全盲的**——
因为推论句里往往一个旧关键词都不含。

## 候选清单（`*-candidates.json`）是编造进入产物的第一个入口

**发现经过**：给 Templeton 建候选清单时回看 Icahn 的 `ci-candidates.json`，
里面 `professional_background` 写的仍是**最初那条错误 TWA 链**
（「1992 年首次破产，他被移出管理层」「1993 年退出，留下 Karabu 折扣协议」）。
而 `meta.json` 里那处最顽固的残留，正是从这里流下去的。

**关键点**：这份文件**写在任何抓源之前**，内容完全来自我的先验记忆，
却又被 `init_target.py` 用作产物骨架。**它是「凭记忆写」与「据证据写」之间的缺口**，
而且位于流程最上游——错在这里，后面每一步都在放大它。

**→ 规则一**：候选清单里的 `professional_background` **只写两类内容**：
（a）用于同名消歧的、不进入产物断言的辨识信息；
（b）已经核过的事实。**拿不准的一律不写**，等抓源之后再补——
少写不会有任何损失，写错要付九轮的代价。

**→ 规则二**：抓源完成后，**回头把候选清单与源账本对一遍**。
它虽然不进交付包，但它是 `meta.json` 的来源，
**订正产物时必须把它一起订正**，否则下次重建又会把旧错误带回来。

**→ 规则三**：同名消歧候选（非目标人物那几条）要单独列全。
Templeton 一例：其子 **John M. Templeton Jr.（1940–2015）长期任 John Templeton
Foundation 主席**——**基金会时期的言论极易被误算到其父头上**，
这类「同姓同名的直系亲属接掌同一机构」是最高危的混淆型。

## 决定能否蒸馏的，是「活跃期是否落在 web 原生时代」，不是名气

六人转入延后名单后，形态已经很清楚：

| 人物 | 卡点 | 共同结构 |
|---|---|---|
| Grace Hopper（卒 1992）| 一手仅 ~21 条 | 活跃期在数字化之前 |
| Margaret Hamilton | 一手 14 条 | 阿波罗时代产出为纸质／机构档案 |
| Jim Simons（卒 2024）| 一手比例 27.9% | 刻意不公开 |
| David Swensen（卒 2021）| 一手比例 27.3% | 产出经机构而非个人署名 |
| Stanley Druckenmiller | 条数 37（比例已过门）| 以访谈为主，本人署名文本少 |
| John Templeton（卒 2008）| 一手 11 条 | **著作全在受控借阅、股东信早于 EDGAR** |

**共同点不是「名气不够」——这六位都极其知名。是他们的一手语料以纸质或机构形态存在，
web 上只有一层薄薄的转述。** 反过来，Simon Willison 这类当代实践者
本人署名博客数以千计、全部可直取，一手占比天然接近 100%。

**→ 规则：排期按「语料可取得性」而非按名气或族内顺序。** 开工前先问一句：
**这个人的产出主要发生在 web 原生时代吗？** 若否，先做一手源专项预筛再决定，
不要按队列顺序硬上——**Templeton 一次探源就花掉约 20 万 token，而结论是不做。**

**→ 推论：本库对「当代在世实践者」的蒸馏成本显著低于历史人物**，
而这类人物恰好补的是时效性短板。**两个目标在这里是同向的，不冲突。**

### 但这条规则单独用会把库做偏（2026-07-28 抓到）

**实例**：入库满 93 人时查分族分布，结果是
软件开发师 33、投资资本师 18、材料建工师 15、建造采购师 12、创业经营师 7、政治法律师 5、
思想教育师 2、财务合规师 1，而**农林牧渔师、医疗护理师、客户营销师、艺术设计师四族为 0**。

目标是 12 族 × 50。**做到 15.5% 进度时，三分之一的族一个人都没有。**

成因不是疏忽，恰恰是**严格执行了上面那条排期规则**：
「语料可取得性」在族之间**系统性不均**——软件工程师天然有博客、commit、issue 全公开，
一手占比轻松 90%+；而护士、农艺师、销售、设计师的一手署名长文本要稀薄得多。
按可取得性贪心排序，等价于按族的 web 原生程度排序，**必然先把最容易的族做满**。

**→ 配重规则：可取得性决定「同族内先做谁」，不决定「先做哪个族」。**
族的推进顺序另有约束：**任一族领先最落后族不得超过 …… 这个阈值我先不写死**——
真正的操作口径是下面这条，它可执行且不需要调参：

**→ 硬口径：每一轮 5 人，至少 1 人来自当前人数最少的三个族。**
不设阈值、不做全局规划，只在每轮开工时看一眼分布。代价是每轮有一人较贵
（空族人物的探源成本高于软件族），收益是**分布不会再单向漂移**。

**→ 附带发现：空族并非无人可做，是我没找。**
**「这族难做」在本轮之前从未被验证过，它是我按可取得性贪心时的默认假设，不是结论。**
这是失败模式的又一变体：**把排序副产物当成事实**。

当场做了预筛（`prescreen_empty.py`），四族各取一名候选，**结果一半推翻了我的预期**：

| 族 | 候选 | 首轮 URL | 换入口重探 | 取回实测 | 结论 |
|---|---|---|---|---|---|
| 农林牧渔师 | Joel Salatin | **0** | **796 篇（2018–2026，2024 后 177 篇）** | — | ✓ **四人里语料最厚** |
| 艺术设计师 | John Maeda | 245 | 166 篇（1998–2026，2024 后 21%） | 4.5k 字/篇真正文 | ✓ 可开工，近三年须补抓 |
| 客户营销师 | Seth Godin | 10 | 年月归档页可枚举 | 2.5k 字/篇真正文 | ✓ 内容通，入口用 `/YYYY/MM/` |
| 医疗护理师 | Atul Gawande | **99** | — | **全是死链** | ✗ 此路不通，须另找入口 |

**首轮命中数与最终结论的相关性是负的**：命中最多的 Gawande（99）不可用，
命中为 0 的 Salatin（796）最好。**这张表本身就是「不要按 URL 计数排序」的证据。**

### ★ 预筛只数 URL 是没有意义的（这轮最值钱的一条）

Gawande 首轮命中 99 条，是四人里第二高，**按条数排序它是「可直接开工」**。
实测第一条就是 `HTTPError`——那 99 条全是 `newyorker.com/archive/YYYY/MM/DD/` 形态的
陈年归档链接，站点早已改版，**一条都取不回来**。

而 Seth Godin 首轮只有 10 条、按条数是「需补入口」，实测每条都是 2500 字真正文——
**他的问题只是 sitemap.xml 返回空，换个入口就有二十年日更。**

**→ 硬规则：预筛必须包含取回实测，不得以 URL 命中数下结论。**
每族至少抽 2 条实际下载，检查 ① HTTP 是否通 ② 正文字数是否 >2000
③ 是否命中 `subscribe to continue|paywall|already a subscriber`。
这三项任何一项不过，该入口的命中数一律记 0。

**这条规则和「装饰性引用」是同一个病**：一个是引了源但源里没有那个事实，
一个是数了 URL 但 URL 打不开。**两者都是拿「计数」冒充「内容」。**

**→ 附带规则**：`americanarchive.org` 一类的 ASR 转录（无说话人标注、站方自述未经校验）
**不得计入一手源**。采用它等于由蒸馏者自行判定哪几句出自其口——
这是失败模式 #3「把话塞进他嘴里」的规模化版本。**不得以放宽标注要求来凑数。**

## 覆盖预检要查时间分布，不只查主题

**实例（Steinberger，开工前自查抓到）**：枚举其博客时用 `sorted(urls)` 再在第 60 条截断。
URL 形如 `/posts/2012/...`、`/posts/2013/...`——**排序即按年份升序，截断正好切掉 2021–2026**。
结果 voice 类 60 条全部落在 **2012–2020**，
而他被列入名单的理由**恰恰是近两年高频的 AI 编码代理工作**。

**这比 Icahn 那次的主题错位更隐蔽**：主题覆盖检查会全绿（都是软件开发、都是他本人写的），
**错的是时间分布**——语料在讲 iOS 与 PSPDFKit，产物却会被当作当前实践者使用。
**做出来就是「用十年前的语料冒充当前实践者」。**

**→ 规则一**：覆盖预检必须同时输出**年份直方图**，不能只报主题命中。
对在世且仍活跃的人物，**须确认近三年语料占有实质比例**。

**→ 规则二**：任何截断取样都要**按年分层**，不得对已排序的 URL 直接截断。
`sorted()` 之后截断，等于按 URL 的字典序做了一次隐式抽样——
**而 URL 里往往含年份，于是抽样偏差与时间强相关。**

**→ 规则三**：`subject_active_through` 应当**由语料实际最新年份得出**，
而不是由「这个人还活着」推出。人还在世，不等于语料覆盖到近期。

## 「策展型文章」是归属陷阱的新变种

**实例（Steinberger #93，读料代理主动标出）**：其站点上有一组
`essential-reading-*` 文章——**发在他自己的域名下、他的署名、他的排版**，
但正文主体是**他转述并引用的他人文章**，斜体拉引属于被链接作者。
另有一篇 `when-ai-meets-madness` 是**第三人称叙述体**
（以 "Claude" 的口吻讲述 Peter，取自一段视频访谈），
**只有 blockquote 是他的原话，叙述段落不是他写的**。

**与失败模式 #6（URL 含其名 ≠ 文章他写的）的区别**：那一次是别人写的文章挂在他名下；
**这一次是他确实写了、但写的大部分是别人的话**。
按「域名 + 署名」判定作者，两种都会中招，而策展型更隐蔽——**它确实是他发的**。

**→ 规则**：抓源时对以下形态一律降级并在 `title` 里写明警示：
- **策展／荐读型**（转述他人文章）→ 降 P2，**移出 expression 维度**（他人的语体不能进语体模型）
- **第三人称叙述体**（含访谈整理稿、"关于他"的报道）→ 降 P2，**只有明确标注的直接引语可引**

**→ 更重要的**：这类文件**最危险的不是定级，是引用**。
从策展文里摘一句斜体拉引当作他的观点，就是「把话塞进他嘴里」，
而且因为出处确实是他的站点，**事后极难自查**。
`title` 字段里的警示就是为了在引用那一刻还能看见。

## 第十二种失败模式：断言「语料里没有 X」——错了很难被抓

**评委 B 的一句话点中了要害**：这一轮我的两处错误
**都是「断言某个东西不存在」，而不是编造某个存在的东西**——
> the model being overconfident about what is **absent** from the corpus,
> not fabricating what is **present**.

**两处实例（Steinberger #93，入库前抓到）**：
1. 我写「那份访谈整理稿**无日期**，先后不可判定」。
   **文件第一行就是 `Published: 25 Jun, 2025`**，与其他文章格式完全一致。
   于是一个「有日期可考的立场演变」（6 月直接 revert → 12 月基本不 revert）
   被我登记成了「无从判断的矛盾」。
2. 我写「语料里**根本没有**可核的倍数」。实际有四种：
   工具间对比（4x longer than Opus）、条件句（build 10x or 20x more）、
   文章标题（20x Faster，且该文为第三人称叙述体）、
   以及**转述他人**（10-100x 出现在策展文里，属被引作者）。

**为什么这类错误特别危险**：
**说「有 X」错了，一查就露；说「没有 X」错了，除非有人替你穷举，否则查不出来。**
而「我没搜到」与「它不存在」之间隔着一次完整的穷举，**我常常把前者当成了后者。**

**→ 规则一**：**产物中任何形如「语料中没有／查不到／不存在」的表述，
都必须附上你实际执行过的检索方式**（搜了哪些词、扫了哪些文件），
否则一律改写为「本次检索未发现」。**两者的可证伪性完全不同。**

**→ 规则二**：**下结论说「无」之前，先搜该概念的多种表述形式。**
倍数那次我大概只想过「几倍」，而语料里写的是 `4x`／`10x or 20x`／`20 times as productive`。
**同一件事的不同写法，是「查不到」最常见的成因。**

**→ 规则三（收益）**：订正后的答案**比原来那个假的更有用**——
不是「没有倍数」，而是「倍数有四种性质，没有一条构成通用提速断言」。
**穷举一次，往往能把一个空洞的否定换成一个有结构的回答。**

## 核对脏话同样适用归属分层

同一轮里我在核对其书面脏话时，把一句 `That was pretty fucking complete` 算进了他的语料——
**那是他在博文里引述同事的惊叹，不是他自己的话。**
**归属分层不只适用于观点，也适用于语体特征**：
统计一个人「说不说脏话」时，引文里的脏话不算他的。

## 改了 rubric 不改答案——本模式最隐蔽之处：答案没变，对错却翻了面

**Steinberger #93 上连犯三次**（`voice-1`／`style-decoy-1`／`planning-fidelity-2`），
Icahn #92 上也犯过一次（`style-decoy-1`）。**共四次，是本项目复发率最高的单一缺陷。**

**最隐蔽的一点在于**：评委 A 与 B 曾给 `voice-1` 打 0.94／0.90，
**并明确称赞它「zero profanity」正确**——因为当时的 rubric 要求的正是零脏话。
我把 rubric 改成「书面可有稀疏自指脏话，答成『他书面从不说脏话』记为失败」之后，
**同一段文本一字未动，却从满足 rubric 变成了踩中 rubric 明令的失败项。**

**→ 规则**：**每次修改 rubric，必须立即重读该用例的候选答案并判断是否仍然满足。**
不是"顺手看一眼"，是**把改后的 rubric 当清单逐条对答案过一遍**。

**→ 更强的做法（下轮实现）**：在生成期加一道
**rubric-答案一致性断言**——凡 rubric 中以「记为失败」「不得」列出的条件，
在候选答案中做关键词反查；命中即抛错。
**现有断言只查标记与计数，查不到语义漂移。**

**→ 附带**：改 rubric 之后，**兄弟用例也要一起查**。
`voice-1` 改完之后，`style-decoy-1` 与 `planning-fidelity-2` 里同一事实的旧口径
又各留了一轮，**是评委分两次抓出来的**。

## 第十四种失败模式：人物本人有「让代理以其署名发布」的公开政策

**实例（Jesse Vincent #94，读料代理主动标出）**：我按「他的 GitHub 账号 obra 发的回复」
抓了 42 条作为 conversations lane 的一手语料。**其中 17 条明确署名是 Claude 写的**——
「Verified by Claude Code:」「— Claude Opus 4.6, Claude Code 2.1.63」，
全部在 2026-02-25 之后。

**而且这不是意外，是他的既定政策**，其本人 2026-02-12 原话：
> Posts in that sub-blog will be primarily (and possibly exclusively)
> **written by the agents who make the software.**

**为什么这是新的一类**：前面几种归属陷阱（策展文、第三人称叙述、引述他人）
都是「文本的作者不是他」；**这一种是「作者栏就是他，内容是他授意的机器产出，而且他公开说了」**。
按账号、按署名、按域名判定作者，**三种方法在这里全部失效**。

**→ 规则一**：抓当代在世技术人物时，**必须检索其是否公开声明过代理代写政策**
（关键词：agents write / authored by / AI-generated / 署名代理）。
有此政策者，**其全部平台产出都要逐条查署名**，不能整份文件当作其本人文字。

**→ 规则二**：这类内容**不是无用的，但用途不同**——
它是「他如何指挥代理」的直接证据（可入 decisions／work-method），
**但绝不可入 expression（语体），也绝不可作为其原话引用**。
本次已拆为两条独立来源，并在 title 里写明「非其本人文字」。

**→ 规则三（前瞻）**：随着这类政策普及，**「某账号发布」与「某人所写」的等价关系正在解体**。
今后凡在世的 AI 方向从业者，抓源时默认按「逐条查署名」处理，
**而不是默认账号即作者**。

## 把「我对语料的判断」当作假设交出去证伪，而不是自己再翻一遍

**这是本项目第一次在动手前拦下一个错误判断，值得单列。**

**实例（Jesse Vincent #94）**：我抽样看了十二篇标题，判断
「1996–2013 是个人博客（留学家书、旅行、消费品吐槽），实质技术内容集中在 2025–2026，
早期语料支撑不了技术决策模式」。这个判断有依据、也符合常见形态。

**我没有自己去复核，而是把它写成假设交给读料代理**，原话是：
> 「**测试这个假设，如果它是错的就告诉我**；若 2014 年前确有实质技术内容，把原文引出来
> ——我需要在建模之前知道，而不是建完一个声称相反的模型之后。」

**两席独立读完 29 个早期文件，结论是假设被推翻**：只有 1996 年那 6 篇是纯个人内容；
2006 年起多数文章含真正的技术推理——2009 年的云中心化长文（并据此做出 P2P 数据库 Prophet）、
2009 年的依赖管理深度文（123 个依赖）、2011/2012 两篇 Kindle 提权、
2012–2013 三篇手工造键盘的工程叙事（其中一席评价为「比多数 2025–2026 的文章更细致」）。

**→ 规则**：凡「我认为这份语料大致是这样」的判断，
**都要作为可证伪的假设交给一个不知道我倾向的读者去检验，不能自己再翻一遍。**
自己复核的问题不是不认真，是**我已经有了结论，再翻只会找到支持它的证据**——
而语料足够大时，任何结论都找得到支持。

**→ 提示词写法很关键**：写「读一下早期语料」会得到一堆印证我结论的引文；
写「**测试这个假设，错了就告诉我**」才会得到反例。**同一份语料，两种问法，两种结果。**

## 归属陷阱的第五种：项目谱系凭常识脑补

同一轮里我对用户说过「Keyboardio 硬件客户是他的三类受众之一」。
**核查结果：「Keyboardio」在他本人全部语料里出现 0 次**——只存在于第三方 HN 讨论中。
他自己写的是「Mark 1」「Mark 2」原型，**从未命名过公司**。

**→ 规则**：人物的项目谱系**只能按其本人文本中明确陈述的连接来写**。
「他做过键盘 → 他创办了那家键盘公司 → 所以现在这把键盘是那条线的延续」
这类推理每一步都像常识，**合起来就是编造**。
本例中语料真正支持的跨期锚点只有一个：**Prime Radiant**
（2012「my startup Prime Radiant's product」→ 2026「I'm the Founder and CEO of Prime Radiant」），
而**「2026 年这家公司是 2012 年那家的延续」仍属推断，不得写成事实**。

## 第十六种：一个事实错误会以不同措辞复制多份，字符串级残留扫描必漏

**实例（Jesse Vincent #94，一轮里连抓四处）**：评委指出「2009 年 1 月那篇长文催生了 P2P 数据库
Prophet」因果反了（该项目 2008 年 4 月即开始，早九个月）。我订正后跑残留扫描，
搜的是原句里的 `据此推出`、`据此动手`——报 0 残留，收工。

**实际上同一个错误在产物里有四份，措辞各不相同**：

| 落点 | 措辞 | 谁抓到的 |
|---|---|---|
| `06-timeline.md` | 「并据此推出 P2P 数据库」 | 字符串扫描 ✓ |
| `case-trajectory-1` | 「并据此动手做了 P2P 数据库」 | 字符串扫描 ✓ |
| `case-planning-fidelity-2` | 「长文还**催生**了一个 P2P 数据库」 | **两名评委** |
| `case-tool-use-2` | 「提出 sharecropping model **并据此做了** P2P 数据库」 | **语义扫描** |

### ★ 最终统计：一个事实错误平均散布在 4 个落点

Jesse Vincent #94 一共追了三个错误，全部落点如下（每一个都是分几轮陆续找到的）：

| 错误 | 落点数 | 分别在哪 | 谁抓到的 |
|---|---|---|---|
| 「长文催生 Prophet」因果反 | **4** | `06-timeline.md`、`case-trajectory-1`、`case-planning-fidelity-2`、`case-tool-use-2` | 字符串扫描 2、评委 1、语义扫描 1 |
| 120,000 stars 误标第三方 | **3** | `case-boundary-1`、`boundaries.md`、`04-external.md` | 评委 1、语义扫描 1、绝对化断言体检 1 |
| 代理段落「未作任何标记」过头 | **5** | `cases.jsonl`（2 条用例）、`boundaries.md`、`persona.md`、`01-writings.md` | 评委 1、语义扫描 1、**计数型断言体检 2** |

**平均 4 个落点，而评委只看得到其中的用例那 1–2 个。**
剩下的全靠工具扫，且**每一次扫描规则都因为写窄而漏了一部分**：
「未作任何标记」这个措辞就不匹配我最初写的
`(完全没有标记|连标记都没有|毫无标记)`，撑到最后一遍体检才翻出来。

**→ 规则：语义规则的措辞变体要一次写全，宁可宽不可窄。**
残留扫描的误报由否定语境豁免去挡，**漏报没有任何东西能挡**。

**→ 规律：订正天然只流向「我刚才在看的那个文件」。**
用例改完就以为改完了，因为评委只看用例——**而产物文档没有评委**。
**→ 规则：任何事实订正，落点清单必须显式包含
`boundaries.md` / `facts.md` / `references/research/*.md` / `claims.jsonl` / `meta.json` / `team-card.json`，
逐个查过再收工。** 这份清单要写死在订正脚本里，不靠记忆。

**→ 规则：残留扫描必须按「事实的语义方向」写模式，不能按「我改掉的那句话」写。**
模式形如 `(长文|该文|这篇文章)[^。\n]{0,40}(催生|据此|促成|引出|导致|才有)[^。\n]{0,25}(Prophet|P2P)`
——它匹配的是**因果方向**，不是某个词。

**→ 规则：扫描范围必须是全产物，不能只扫 evals。**
（这条 Icahn #92 已立过，本轮又犯一次，形态是 boundaries.md 漏网。）

### 反向陷阱一：语义扫描器会命中订正后的文本

订正后的句子**必须提到那个概念才能否定它**——「跨模型**不是**他的做法」「**早于**该文，不是那篇文章的产物」。
第一版语义扫描器因此报出 8 处「残留」，其中 7 处是订正本身。

**→ 模式必须带否定语境豁免**：命中点前后各约 90 字内若出现
`(不是|不得|不算|并非|早于|已做|明说|归于|其本人|一手|记为失败)`，跳过。
**没有豁免的语义扫描器，其误报会淹没真命中——本轮那 1 处真命中（boundaries.md）
就混在 7 处误报里，差点被当成噪声划掉。**

### 反向陷阱二：正则写窄会把正确事实误判为伪造

同一轮里我核查 `double-ESC` 是否为伪造引文，grep `double[\s\-]?esc` —— 0 命中，
判定「语料中不存在」，准备删掉。**实际语料写作 `double- ESC`（连字符后有空格，HTML 转文本的产物）**，
是真的，而且原文紧接着就给出了理由：
「This reduces context bloat for the architect and gets it to look at again
without any biases from the previous implementation.」

**差一步就用一个假的「不存在」结论，删掉一个真事实。**

**→ 规则：判定「语料中不存在」之前，至少换三种模式重查**
（去标点、去空格、大小写不敏感、HTML 实体还原），**并把用过的模式写进结论**。
这与已立的「不在场断言须说明检索方式」是同一条，本处是它在**工具层**的落法：
不只是答案里要写检索方式，**我自己下结论前也得真的换着法子查过**。

**同一次会话里这个错犯了三次，形态一次比一次隐蔽**：

| # | 我写的模式 | 实际形态 | 差点得出的错结论 |
|---|---|---|---|
| 1 | `\\s{2,}` 查多余空格 | 段落换行也是空白 | 32 条用例里 30 条「有问题」（纯误报） |
| 2 | `double[\\s\\-]?esc` | 原文 `double- ESC`（连字符后有空格） | 「这是伪造引文」→ 删掉一个真事实 |
| 3 | `/(\\d{4})/` 抽年份 | 该站 URL 是 `/blog/1/1/2019/…`（月/日/年） | 「此人语料稀薄，换人」→ 实际 796 篇、跨九年 |

**三次的共同结构：我按「我以为的形态」写模式，拿 0 命中当「不存在」。**
第 3 次尤其危险——它不产生任何报错，只是安静地把一个候选人从队列里划掉，
**而错误的代价（漏掉一个语料最厚的人选）永远不会有人来告诉我。**

**→ 因此规则加一句：0 命中不是结论，是「换个方式再查」的信号。**
只有当**至少两种独立形态的模式都得 0**，才可以写下「不存在」，并注明查过哪两种。

## 第十七种：人物只给了做法，我替他补了一个听起来合理的理由

**实例（同一轮，评委没抓到，是我自查引文时发现的）**：
`case-task-completion-1` 写「架构者和实现者两个会话，用 /clear 不用 /compact。
**压缩会把噪声一起留下。**」——后半句是理由，**语料里没有**。

他的原话只有做法：「And then, I don't */compact*. Instead I */clear* the implementer
and start the conversation over.」**为什么不用 compact，他一个字没说。**

这类伪造比编数字更难自查，因为**它听起来太顺了**——「压缩当然会留下噪声，这还用问吗」。
正是这份「不言自明」让它绕过了所有检查：它不是一个可以去核的断言，
它是一个**我认为显然成立、于是替他说出口的推理**。

**→ 规则：凡「做法 + 理由」成对出现的地方，理由要单独核一次源。**
做法有引文不等于理由有引文。

**→ 规则：查证后确认他没给理由的，就如实写「他只给了做法，没给理由」，
并把这句话写进 rubric 当作正解。** 本轮改完后的答案里有两处这样标注
（`/compact` 与「要它证明」），**这比补一个合理理由更有用**——
使用者据此知道哪些是他的判断、哪些是自己要补的判断。

**→ 附带**：核这两处时顺手发现，「一次两三百字」那条的理由**是真的**且比我写的更好——
原文「I'm prone to just tuning out a bit and thinking "it's probably fine"」，
**理由是防他自己走神，不是防模型**。真理由往往比我编的更具体、更反直觉。

## 多轮重判：什么时候该再判一轮，什么时候该停下来查流程

**Jesse Vincent #94 判了三轮**，这是本库第一次出现三轮。之前的做法是
「评委过了就发」或「整席位作废重判一次」，没有多轮的规矩。补上。

### 触发条件：文本变了就重判，粒度到用例

**判据不是「分数够不够」，是「打这个分的席位读到的文本，是否等于交付文本」。**
所以：
- 改了 6 条用例 → 重判那 6 条，其余 26 条原分继续有效（**逐字未变**，不是「差不多没变」）
- 改的只是 `boundaries.md` 这类产物文档 → **不重判**，因为评委评的是用例
- 改的是 rubric 而非 candidate → **要重判**，rubric 决定了什么算对

### 采分粒度：席位 × 用例，不是整席位

| 轮次 | 改动 | 席位 | 那轮抓到什么 |
|---|---|---|---|
| 原始 | —— | a/b | —— |
| 一 | 6 条 | a/b 重判 | **2 条判死**：因果颠倒、跨模型张冠李戴（fact 0.32／0.55）|
| 二 | 3 条 | c/d | 全过；d 逐条 grep 语料，翻出枚举以偏概全（fact 0.91）|
| 三 | 2 条 | e/f | —— |

**最终 32 条里 29 条用 a/b 的分、1 条用 c/d、2 条用 e/f。**
这必须写进 results 生成器的文件头，**不得静默统一化 judge_id**——
「32 条同口径可比」这句话在这里不成立，藏起来就是伪造评测口径。

### ★ 收敛判据：看缺陷严重度，不看轮数

**→ 规则：只要严重度在降，就继续；若某一轮又冒出更严重的硬伤，
说明订正流程本身有问题，须停下来查流程，而不是再改一轮文本。**

「再改一轮」在严重度不降时是**危险的**——它把「改对」和「改到评委不吭声」混为一谈。
后者可以靠加限定词达成，而加限定词恰恰会触发下一条毛病（见「过度自证」）。

### ★★ 这条规则第一次被触发（Jesse Vincent #94 第三轮），结论：它是对的

| 轮 | 最低 fact | 抓到什么 |
|---|---|---|
| 一 | 0.32／0.55 | 因果颠倒、跨模型张冠李戴 |
| 二 | 0.91 | 枚举以偏概全（漏 2 篇）|
| 三 | **0.74（反升）** | 枚举**仍**不全（又漏 2 篇）＋「2006 年起多数」无据 |

停下来查流程，查出来的东西很清楚：
**前三轮的修法都是「评委找出几条反例 → 把这几条加进列表」。**
每一轮我都在补评委恰好找到的那几条，**而病根是我做了一个从没真正枚举过的枚举断言**。
补条目治的是症状，第四轮必然还有漏网——**这个循环不会自己终止**。

**→ 换修法：把「举例式断言」改成「按计数穷尽的分类」。**
逐篇归类 1996–2013 的 29 篇（技术 9／个人 11／公告 5／招聘 3／见闻 1），
脚本 `classify_early.py` 做**双向核对**：分类表与语料文件一一对应，
任一边多出即报错，**不设「其余」兜底**——有兜底就等于又回到了「我没数过」。

**这样的断言无法「不完整」**：加总等于 29，评委只能质疑某一篇的归类，
不能再找出「你漏了谁」。**把可证伪的形式，从「列举」换成「配平」。**

### 顺带查出：我的订正朝反方向也过头了

原始判断「1996–2013 是个人博客，技术内容集中在 2025–2026」是错的，
但我的订正「2006 年起多数文章含实质技术推理」**同样无据**：
技术类只占 31%，且最早的实质技术推理是 **2009-01-29**，2006–2008 三年是招聘帖与发布公告。

**这就是已立的「撤销说法需同等证据」，我自己犯了。**
推翻一个判断时最危险的时刻，是**刚推翻完的那一刻**——
手上有了几条反例，很容易顺势写出一个方向相反、强度相当、但同样没数过的新判断。

**→ 规则补充：推翻一个「A 是 X」的判断，只证明了「A 不全是 X」，
没有证明「A 是非 X」。要写后者，须重新举证，强度对等。**

### ★ 换修法之后的重判，必须显式声明「换了什么」

第四轮不是「同一修法再试一次」，是修法变了之后的重判。
**这个区别不能只在我心里**——`gen_results_jv.py` 里加了 `PROCESS_FIXED` 字典，
声明第几轮改了什么修法；没有声明而严重度上升，收敛检查直接 `sys.exit(2)`。
**「我查过流程了」必须是一个写下来的、可被别人读到的声明，而不是一句自述。**

### ★ 换席位不等于换到分高的

第一轮 a/b 两席**独立**给 `case-task-completion-1` 判了 fact 0.55／0.55，双双判死。
第二轮换 c/d 之所以合法，**是因为那两条答案已经被重写了**，不是因为 a/b 给分低。

**→ 硬规则：换席位的前提是文本实质改动，且改动内容要能对上评委指出的缺陷。**
若新席位仍判不过，继续改文本，**不得继续换人**。
这条要写在生成器里当断言，不能靠自觉——本库的评分文件是我自己拼的，
没有这条断言，「多试几个评委直到过门」在操作上毫无阻力。

### 成本参考

三轮重判共 6 个席位、11 条用例次，其中一席（要求逐条 grep 语料核引文）
用了 47 次工具调用、18 万 token，是最贵也是**唯一翻出第二轮那个缺陷的**席位。
**要求评委实际去查语料，比要求它「仔细一点」有效得多。**

## 第十八种：写了检查器但从没验证过检查器本身

本库的失败模式里，**「检查器坏了」已经出现七次**，且每次的形态都是同一个：
我按「我以为的形态」写模式，拿 0 命中当结论。前七次的代价从「30/32 误报」
一路涨到「差点删掉一个真事实」和「差点划掉语料最厚的候选人」。

第八次是最危险的一种：**检查器全绿，但其实什么都没查。**

### 实例：引文真实性检查器，前两版都是错的

**第一版**：直接拿 `「...」` 里的整段去 grep，报 8 条未命中。**8 条全是误报**，
因为撇号截断了捕获（`I'm` 被从 `m` 开始截）、`…` 是我自己的省略标记
（两端在原文里并不相邻）、引文里嵌了我加的 markdown 粗体。

**第二版**：切段 + 剥 markdown + 撇号统一 + 词间 `\s*`。报 7 条未命中。
**7 条又全是误报**，四种病因：

| 我写的 | 语料原文 | 差在哪 |
|---|---|---|
| `as a 'person'` | `as a "person"` | 我把双引号转成单引号 |
| `I don't /compact. Instead` | `I don't */compact* . Instead` | markdown 星号 + 句点前有空格 |
| `somefeature.plan.md. Read` | `somefeature.plan.md . Read` | 句点前有空格 |
| `double-ESC` | `double- ESC` | 连字符后有空格 |

**全是标点与空白的差异，一条语义差异都没有**——而按词切分再 `\s*` 连接
恰好挡不住这四种，因为它们改变的是**分词结果本身**。

**第三版**：两边都投影成 `[^0-9A-Za-z]` 全删的纯字母数字串再做子串匹配。
误报归零。代价是失去标点级精度，但本检查要回答的是
**「这句话在语料里到底存不存在」**，不是「标点一字不差吗」。

### ★ 真正的教训不是「第三版对了」，是「前两版我都直接用了」

前两版我写完就跑，看到输出就开始据此订正。**如果那 8 条／7 条误报里
混进了一条真的伪造引文，我根本分不出来**；反过来，如果我照着误报去「订正」，
就会把真引文改坏——这在同一次会话里已经差点发生过一次（`double- ESC`）。

**→ 规则：任何新写的检查器，交付前必须做一次负对照——
往真数据里植入已知的假样本，证明它抓得到。**
只测「真的能过」不够，必须证明「假的过不去」。

引文检查器的负对照已固化为 `--self-test`，四类伪造：
整句编造、真句改数字、真句改主语、**真句只改一个词**（`architect`→`reviewer`）。
实测 4/4 抓到，36 条真引文 0 误报。**这两个数字要随脚本一起留存**——
下次改动这个脚本，重跑负对照，数字变了就是改坏了。

**→ 推论：没有负对照的检查器，其「全绿」不构成任何证据。**
它只证明「这个脚本跑完了」，不证明「产物没问题」。

### 给三个硬门检查器补负对照时，第二个更严重的问题浮出来了

`check_claim_coverage.py` 一直报「装饰性引用 0/29，通过」。
补负对照时发现它有一行 `if not terms: continue`——
**抽不出关键实体的断言被静默跳过，在报告里表现为「通过」而不是「未检查」。**

Jesse Vincent 实测：29 条里有 **4 条从来没被检查过**，实际覆盖 25/29。
**分母是假的，而看报告的人完全看不出来。**

**→ 规则：检查器必须报「实际检查了几条 / 共几条」，不能只报「发现几个问题」。**
「0 个问题」在分母不明时毫无意义。

**→ 顺手把那 4 条补上了，用的是更严的判据**：
这类断言带英文引文，于是改判「**该引文是否出现在它自己引的那个源里**」，
而不是「语料里某处有没有这句话」。后者只能证明这句话是真的，
**证明不了「这条断言挂的源支撑这条断言」——而后者才是装饰性引用要查的东西。**
补完后覆盖 29/29，负对照扩到 5 向。

## 第十九种：评委的「我查过了，语料里没有」同样是不在场断言，同样要核

「不在场断言须说明检索方式」这条规则，我一直只用在**自己写的答案**上。
Jesse Vincent #94 第三、四轮暴露出：**评委也会下不在场断言，而且会错。**

### 两个实例，都能用一条 grep 推翻

**实例一（F 席）**：核查「两份 README 自述由代理写成」，它答出的两份是
`blogosphere` 与 `winpepper`。**`winpepper` 这份文件里「Claude」出现 0 次。**

**实例二（G 席）**：同一条断言，它的结论是**「16 份 README 里没有任何一份自陈由代理撰写」**。
但真实情况是两份：
- `jv_readme_blogosphere.txt`（2483 字）第 **326 字（13%）**：`Built by [Claude Code](...), directed by [@obra](...)`
- `jv_readme_episodic-memory.txt`（12910 字）第 **1777 字（14%）**：`_— Claude Sonnet 4.5, October 14, 2025_`

**G 自己交代了方法：「全部 16 份通读（含 4 份全文、其余全部首尾）」。**
——两处证据都在 13–14% 位置，**「首尾」这个方法结构上就够不到**。

**G 的第二处「语料不支持」也是查错了文件**：断言指的是
`jv_2026_04_07_rules_and_gates.txt`（引导语「Here's a concrete example from an agent today:」），
而 G 查的是 `jv_2025_05_28`（dear diary，那篇确实有时间戳分隔）。

### → 规则：评委说「语料里没有」时，要它给出检索命令与检索范围

和对答案的要求完全一致：**不在场断言须说明检索方式**。
本轮 G 之所以能被当场推翻，正是因为它老实写了「4 份全文、其余首尾」——
**如果它只写「通读全部 16 份，未发现」，我就无从判断，只能照单全收。**

### → 规则：被评委判死之前，先核评委的依据；核完再决定改文本还是回退给评委

这不是「分低就换评委」。区别在于：
- **换评委** = 不服气，另找一个可能给高分的席位 → 禁止
- **回退给评委** = 指出它核查用错了文件／方法够不到，把证据给它，**让它自己重判** → 正当

回退时必须写明：「**如果你复核后维持原判，我会照着改文本，不会换评委。**」
——把「我要的是裁定建立在正确的文件上」和「我想要一个更高的分」区分开，
这句话是唯一的分界线，必须显式说出来。

### ★ 回退给评委之后，它自己诊断出了病因——与我这边完全一样

G 席复核后改判 fact 0.62 → 0.95，并写下失误原因：

> 「我的自述作者正则是按 written/generated/authored by 调的，
> 匹配不到 `Built by` 和署名推荐语——**正是简报里警告过的『正则写窄』陷阱**。」

**同一个失败模式，这次发生在评委侧。** 本库这一天里它出现了八次：
我这边七次，评委那边至少两次（F 的 winpepper、G 的 README 正则）。

**→ 推论：这不是「我不够细心」，是这类核查任务的固有失效模式。**
凡是「拿一个模式去语料里找，找不到就下不存在的结论」的动作，
无论谁做，都会以同样的方式失效。因此它需要的是**流程约束**，不是「更仔细一点」：
**必须报检索命令 + 至少两种独立形态的模式 + 0 命中不作结论。**

### → 附带：这条也解释了为什么「席位分歧大」本身就是信号

同一批文本，E 席给 0.74／0.80，F 席给 0.94／0.95，差 0.2。
当时我按「取严不取宽」处理，是对的；但更该注意的是——
**一个 0.2 的分歧意味着至少有一席的核查是不牢的**，
应当当场去查是谁不牢，而不是简单取小值了事。
本轮就是因为没有当场深究，F 席那个 `winpepper` 的错误多留了一轮才被发现。

## 评委也会「只看被指到的地方」——每轮留一席不告知前情

前四轮的评委简报里，我都写了「上一轮抓到了什么，请重点查这几处」。
这样做的好处是订正能被针对性验证，坏处是**注意力被引导走了**——
**被点名的几处查得很细，其余部分反而无人再看**。

实证：`case-tool-use-2` 里那处「悬空前指『见下』」，
在第二、三轮都存在，两轮共四个席位无人提及；
直到第四轮一个被要求「逐句问这一句删掉会不会变得不准确」的席位才发现。
它不是难发现，是**没人往那儿看**。

**→ 规则：每轮至少留一席，只给评分对象与语料，不告知前几轮的任何发现。**
它的作用不是复查已知问题，是**提供一双没有被引导过的眼睛**。

## 第二十种：订正脚本自己污染产物，而质检门忽略多余字段

Jesse Vincent #94 收尾时抓到：我的订正脚本里有个 `patch(obj)` 无差别地给对象设了
`candidate`，于是**产物的 `evals/cases.jsonl` 里有 1 条带了 `candidate` 字段，另外 31 条没有**。

`quality_check.py` 三个门全绿——**它忽略多余字段**。
不查的话，这个污染就这么打进 ZIP、入库、推送。

### 特征：只影响一部分记录，所以肉眼看首行看不出来

我这一天里查过好几次 `cases.jsonl` 的字段，每次都是 `json.loads(第一行)` 看 keys——
**而被污染的是第 N 条**。这不是疏忽，是**抽样方法与污染形态不匹配**：
污染是局部的，抽样看的是首条。

**→ 判据不能是「有没有这个字段」，必须是「这个字段是不是所有记录都有」。**
统计每个字段的出现频次，`< 总数` 的一律列出来人工确认。
合法的可选字段是有的（`holdout_source_ids` 只有 known 套组的用例才有），
所以**只列不判，但必须列——不列就等于放行**。

已做成 `checkers/check_schema_drift.py`，支持 `--expect 文件名:字段名` 声明合法可选。

### → 更一般的规则：批量订正脚本必须只改它声明要改的字段

`patch(obj)` 这种写法的问题是**它对整个对象有写权限，而我只想改一个字段**。
正确写法是显式指定：`if "candidate" in obj: obj["candidate"] = ...`
——**存在才改，不存在不创建**。本次的 bug 就是漏了 `if ... in obj` 这一半。

## 第二十一种：claim 标记错挂——门只查计数，而错挂不改变计数

Jesse Vincent #94 收尾通读产物时抓到：**三个 claim 标记发生了循环错位**——
`work.md` 的「规划与执行分离」段标着 `00f`、
`strategy.md` 的「拒绝时留一扇有条件的门」段标着 `010`、
`strategy.md` 的「关闭 issue 给可证伪的重开条件」段标着 `00e`。
正确的对应恰好是这三个号各自往前挪一位。

**三个官方门全绿。** 因为门查的是：
① 每条断言都被渲染了吗 ② 有没有孤儿标记（指向不存在的断言）。
**两条都是计数层面的，而错挂不改变任何计数**——
33 个标记、33 条断言、一一对应，只是配错了对象。

### 后果：引用链断了，而且断得看不出来

产物的价值有一半在「每句话都能顺着标记找到证据」。
标记错挂之后，读者顺着 `<!-- claim:clm-...00f -->` 去查，
看到的是一条完全不相干的断言——**比没有标记更糟**，
因为没有标记时人会自己去找，有错标记时人会以为已经核过了。

### → 判据：文段与它标注的断言，关键词有没有重合

取标记前约 450 字，与断言正文求关键词交集（英文实体 ≥5 字符、中文 4–8 字串），
重合 < 2 即列出。已做成 `checkers/check_claim_anchors.py`。
实测把 33 个标记压缩成 1 个要人工看的。

**已知误报**：断言正文主体常是英文引文，而渲染文段是中文转述，**字面重合天然为 0**。
所以**只列不判**——它的价值不是自动判错，是**把要看的从 33 个压到 3–4 个**。

### ★ 这轮所有最严重的缺陷有一个共同点

装饰性引用、伪造引文、订正残留、字段污染、claim 错挂——
**没有一个是「门没跑」，全都是「门查的维度里没有这一维」。**

门是按「产物结构是否完整」设计的：文件在不在、字段全不全、数量对不对。
而这一轮的缺陷全部属于**「内容说的对不对、指的准不准」**——
结构完整的产物完全可以每一句都错。

**→ 推论：加检查器的方向不是「把现有的门查得更严」，是「补上没被查的维度」。**
到 2026-07-28 为止补了八件，每一件都对应一次实际发生过、而三门全绿的失败。

## 第二十二种：修法只落在被抓到的那一处，同一个病在别处继续活着

Jesse Vincent #94 第三轮触发收敛判据后，我把「举例式断言」改成了
「按计数穷尽的分类」（29 篇加总核对），这个修法是对的——
第四轮评委逐篇审计通过，第五轮也确认无误。

**但第五轮另一席指出：同一篇答案里还有一个枚举断言，我压根没改。**

「1996 年那六篇里**三篇**有动手的技术活动」——实为**四篇**
（漏了 `1996_09_03` 的「hooked up my alligator clips」，接线上网取信）。

**我把「按计数穷尽」用在了被抓到的那个断言上，没有推广到同一篇里的其它枚举断言。**

### 为什么会这样：订正的注意力总是停在「被指出的那一处」

评委指出的是「29 篇分类不完整」，我修的就是那 29 篇。
**至于「哪里还有同类断言」，没有人指出，所以我没有找。**
这与「订正只流向我刚才在看的那个文件」（第十六种）是同一个病的不同切面：
一个是**空间上不推广**（改了用例没改产物文档），
一个是**类型上不推广**（改了这条枚举没改那条枚举）。

### → 规则：拿到一个修法之后，先全库找同类，再动手改

具体到枚举断言：改完一处，立刻搜全产物里所有
「只有 N 篇／三篇／两份／唯一／全部」形态的断言，**逐条问「这个数我真的数过吗」**。

正则起点（宁可宽）：
```
(只有|仅|唯一|全部|所有)?\s*[一二三四五六七八九十两\d]+\s*(篇|条|份|个|次|处|项)
```
本库实测：Vincent 产物里 73 条计数断言，其中真正数过的不到一半——
**其余的是「我印象里是这么多」。**

### → 更一般的：每次订正结束时，问三个问题

1. **同一个文件里还有没有同类的？**（类型推广）
2. **别的文件里还有没有同一个事实？**（空间推广，第十六种）
3. **这个修法本身能不能做成检查器？**（工具化，第十八种）

三个问题里任何一个漏了，下一轮都会以另一种形态回来。
Vincent 一共判了五轮，**其中至少两轮是因为漏了问题 1 或 2 而多出来的**。

## 多轮判分要有终止条件，而且必须写下来

Jesse Vincent #94 判了六轮、12 个席位。**「什么时候停」这件事本身需要一条规则**——
否则只有两种结局：判到没耐心为止（不诚实），或者判到评委不吭声为止
（更糟，因为那可以靠加限定词达成，见「过度自证」）。

### 本轮用的终止判据：三条同时成立

**① 严重度单调下降，且连续两轮无否决**
  R1 最低 fact `0.32` → R2 `0.91` → R3 `0.74`（触发流程修正）→ R4 `0.85` → R5 `0.91`

**② 最近两轮抓到的全部是「差一个数」「漏一句 rubric 要求」「重复一句」这一级**
  **没有一条构成事实错误**——R5 最低 0.91，远在 0.85 否决线之上。

**③ 机器侧全绿，且检查器自身的负对照全过**
  七件检查器 + 三个硬门检查器的 `--self-test`。

三条都成立 → **下一轮是最后一轮；若仍过否决门则交付**，
其非否决级发现（文风、可精简处）记入下轮迭代输入，**不再触发第七轮**。

**这必须是显式声明，写进 results 生成器**（`TERMINATE_AFTER`），
而不是心里想想。理由和 `PROCESS_FIXED` 一样：
**凡是「我判断可以了」的地方，都要留下一行别人能读到的字。**

### ★ 若最后一轮出现 <0.85，终止条件作废

这条要写死：终止条件管的是「非否决级发现不再触发新一轮」，
**不管否决门**。否决门永远优先——出现 <0.85 就继续改文本，不换评委、不提前收尾。

## 「我的正则误报」在一天内出现九次——这是一条独立的操作规则，不是态度问题

统计（2026-07-28，Jesse Vincent #94 + Joel Salatin 预抓）：

| # | 模式 | 实际形态 | 差点得出的错结论 |
|---|---|---|---|
| 1 | `\s{2,}` 查多余空格 | 段落换行也是空白 | 32 条用例里 30 条「有问题」 |
| 2 | `\*\*[ 　]*\*\*` 查空加粗 | 相邻的合法加粗span | 误报 |
| 3 | `double[\s\-]?esc` | 原文 `double- ESC` | 「伪造引文」→ 删掉真事实 |
| 4 | `/(\d{4})/` 抽年份 | 该站是 `/blog/月/日/年/` | 「语料稀薄」→ 划掉最厚的候选人 |
| 5 | 引文整段匹配（v1） | 撇号截断、`…` 是省略标记 | 8 条「伪造」全是误报 |
| 6 | 引文分词 + `\s*`（v2） | 标点空格差异 | 7 条「伪造」全是误报 |
| 7 | `FFS` 查脏话变体 | 命中 `knockoffs`／`tradeoffs` | 「博文有脏话」 |
| 8 | 自述作者 `written/generated/authored by` | 原文 `Built by [Claude Code]` | **评委侧**：「16 份 README 无一自陈」 |
| 9 | `generated by` 查代笔 | `urine generated by grazing animals` | 「疑似代笔」 |

**九次里有两次发生在评委侧**，其中一次评委自己诊断出病因，
用词与我完全相同：「正是简报里警告过的『正则写窄』陷阱」。

### → 这说明它不是「谁不够仔细」，是这类动作的固有失效模式

「拿一个模式去语料里找，找不到就下不存在的结论」——
**无论谁做、多仔细，都会以同样的方式失效**，因为失效的原因是
**我脑子里的形态 ≠ 语料里的形态**，而这个差距在写模式时是不可见的。

### → 因此需要的是流程约束，不是「更仔细一点」

1. **0 命中不是结论，是「换个方式再查」的信号。**
   至少两种独立形态的模式都得 0，才可写「不存在」，并注明查过哪两种。
2. **命中之后先看原文再下结论。** 第 9 次之所以没造成损失，
   就是因为按这条先去读了那句话——「urine generated by grazing animals」。
3. **检查器交付前做负对照。** 见第十八种。
4. **报「实际检查了几条／共几条」，不只报「发现几个问题」。** 见第二十一种。

**这四条加起来，才是这个失效模式的解。任何一条单独都不够。**

## 取样配置会伪装成事实分布——直方图必须在建模前看，且要标注哪些是人为的

**Steinberger #93（已立）**：`sorted(urls)` 后在第 60 条截断，
而 URL 形如 `/posts/2012/…`，**排序即按年升序，截断正好切掉近五年**。

**Joel Salatin 预抓（2026-07-28）是它的反向版本**：
我在枚举脚本里设了 `PER_YEAR=7`（每年上限 7 篇）、`RECENT=2024`（近年不设限）。
抓完的年份直方图是：

```
2018–2023: 每年 6–7 篇
2024: 48   2025: 78   2026: 48        ← 2024+ 占 81%
```

**这看起来像「他近年才高产」，其实是我的取样上限压平了早期。**
站点上 2019 年有 176 篇、2020 年有 207 篇——**比 2024 年还多**。

### → 危险在于：这个假象会一路传到产物里

如果不看直方图直接建模，很容易写出
「其产出在 2024 年后显著增加」「近年是其最活跃期」这类**纯属取样人为的结论**，
而它们看起来完全像事实，还能挂上一堆真实来源。

**这是「装饰性引用」的一个变种**：每条来源都真、都相关，
**但由这些来源导出的分布结论是假的**，因为来源集合本身是我构造的。

### → 规则

1. **枚举脚本必须输出年份直方图**（已在 `enumerate_*.py` 里做了）。
2. **直方图旁必须标注哪些数字受取样配置限制**，形如
   「2018–2023 每年 6–7 篇 = `PER_YEAR` 上限所致，站点实有更多」。
3. **产物中任何关于「产出随时间变化」的断言，都要先问：这是他的分布，还是我的取样分布？**
4. **若建模确实需要时间分布结论**，必须解除上限重抓，或改用站点自报的归档计数。

## 第二十三种：人物的名气主题与其语料主题可以完全不重叠

**实例（Joel Salatin #95，农林牧渔师开族，开工第一天抓到）**：
他是以**草饲轮牧**闻名于世的农场主——Michael Pollan 的《杂食者的两难》专章写他，
纪录片《食品公司》有他。而他 2018–2026 的 215 篇署名博文，按「≥3 次提及才算在写这个」计：

| 主题 | 篇数 | 占比 |
|---|---|---|
| **监管与自由** | 104 | **48%** |
| 健康与医药 | 34 | 16% |
| 农场经营与经济 / 信仰与价值观 | 各 19 | 各 9% |
| 生态与土壤 | 11 | 5% |
| **轮牧技术** | **2** | **1%** |

**他最有名的那件事，在其语料里占 1%。**

### 为什么这会毁掉整个产物

若按名气建模，写出「他主张每日轮牧、按牧草再生周期设计围栏……」这类断言，
**每一条挂的源都不会真正谈这个**——这就是装饰性引用（第一种），
只不过这次不是个别断言出错，而是**整个产物的主题定位错了**。

Icahn #92 的 TWA 链条是一条链错；这里是**全篇错**。

### → 规则：开工前必须做「名气主题 vs 语料主题」对照，并按语料定位

具体做法（`≥3 次提及`阈值是关键——一次带过不算「在写这个」）：
```python
per = {f: len(re.findall(pat, t, re.I)) for f, t in corpus.items()}
写这个的篇数 = len([f for f, n in per.items() if n >= 3])
```
**并且轮牧这类核心主题若得 0 或极低，必须换至少三种独立形态的模式重查**
（本例：术语形态 / 装置形态 / 动作形态），确认不是模式写窄——
本例三形态合并后是 4 篇，仍然只有 2%。

### → 结果不是「换人」，是「按语料定位并写硬边界」

本例的处置：产物定位为**「食品监管应对与农业自由倡导」**，
而**轮牧技术细节写入拒答边界**——理由不是他不懂，
而是**本产物的语料不支持，答了就是编**。
这与 Vincent 的「不得把 Keyboardio 写入其谱系」是同一性质：
**拒答的依据是语料覆盖，不是人物能力。**

### → 附带：这解释了为什么「按语料可取得性排期」还不够

可取得性只回答「能不能抓到 45 条」，不回答「抓到的是不是他出名的那一面」。
**Salatin 的语料极其充沛（215 篇、一手 99%）而定位仍需大改。**
→ 预筛除了取回实测（第十四条），**还要加一项主题对照**。

## 第二十四种：同一段里前后指代不一致——所有自动检查器都看不见

**实例（Joel Salatin #95，被「不告知前情」的评委席位抓到）**：
一条答案里，**前半句写「为母亲写的悼词」，后半句写「祖母 102 岁时被收走车钥匙」**。
同一个人，一句话内从母亲变成祖母。而且 102 也错了——
原文是「took the keys away from her at **97**」，102 是她去世时的年龄。

### 为什么七件检查器全部漏掉

| 检查器 | 查什么 | 为什么看不见这个 |
|---|---|---|
| `quote_integrity` | 引文在不在语料里 | 引文本身没错，错的是我在它前面写的中文 |
| `claim_coverage` | 断言挂的源支不支撑 | 源是对的 |
| `semantic_residue` | 旧说法有没有换个措辞活着 | 这是新写的，不是残留 |
| `redundancy` | 同一事实重复几遍 | 前后说的是**不同**的事，不是重复 |
| `claim_anchors` | 标记挂没挂对 | 挂对了 |
| `absence_claims` | 绝对化断言有没有依据 | 不是绝对化断言 |
| `schema_drift` | 字段污染 | 与字段无关 |

**七件都设计成「拿产物去对语料」，而这个错是「产物内部对不上自己」。**

### → 补一条：段内指代一致性

同一段里指向同一个人／同一个对象的称谓，出现 ≥2 种时报出来人工确认。
起点模式（宁可宽）：一段内同时出现
`(母亲|妈妈|其母)` 与 `(祖母|奶奶|外婆)`、
`(父亲|其父)` 与 `(祖父|爷爷)`、
或同一专名后跟着两个不同的年龄／年份。

**只列不判**——有些段落确实在谈两代人（本人物就有大量三代同框的段落）。
它的价值是**把「需要人看一眼」的地方从整篇压缩到几处**。

### → 更一般的：检查器的盲区是它们的设计前提

七件检查器共享同一个前提：**产物是对的还是错的，去问语料**。
凡是**不需要查语料就能发现的错**（内部矛盾、指代漂移、算术不一致），
它们结构上就看不见。

**→ 这类错只有两种抓法：人通读，或另一双没被引导的眼睛。**
本例是后者——**那一席被明确要求「不要只查某几处，完整读每一条」**，
而带着「重点查引文和数字」指令的另一席没有报这一处。

## 第二十五种：吞掉生成器的错误输出，然后对着陈旧产物追幻影

**实例（Joel Salatin #95，订正阶段）**：改完生成器后我用
`python3 gen_js_cases.py >/dev/null 2>&1 && echo "✓ 重跑"` 跑了一遍。
**生成期断言失败了，但被 `2>&1` 吞掉，`&&` 后面的 ✓ 也没打印——我没注意到。**

于是 `cases.jsonl` 保持着上一版内容。我接着去 grep 输出文件，看到旧措辞还在，
**判断成「替换串没匹配上」**，改短锚点重试；再失败，又判断成
**「这些内容不是从生成器来的」**，去查别的来源。

**追了两轮幻影，而真相是：生成器从头到尾就没跑成功过。**

### 为什么这个错特别难自查

因为**所有下游证据都指向「替换没生效」**——文件里确实还是旧的。
「生成器失败了」和「替换没匹配上」在输出文件上**表现完全一样**。
唯一能区分的信息（stderr 里的 AssertionError）**被我自己关掉了**。

### → 规则：生成器的 stderr 永远不能吞

- **检查器**的输出可以过滤（它们本来就啰嗦，且失败会体现在退出码与摘要行里）
- **生成器**必须让错误可见。`>/dev/null 2>&1` 用在生成器上 = 把「产物没更新」变成静默失败

推荐写法：
```bash
python3 gen_xxx.py || { echo "✗ 生成失败，下游产物是陈旧的"; exit 1; }
```
**关键是那句 `exit 1`**——没有它，后续步骤会继续在旧产物上跑。

### → 附带规则：改完生成器后，先看产物的修改时间

```bash
ls -la <产物文件> | awk '{print $6,$7,$8}'   # 和现在时间比
```
时间戳没动 = 生成器没跑成，**不管终端上打印了什么**。
这一条比读输出更可靠，因为它不依赖我有没有把错误打印出来。

## 第二十六种：二进制被当成文本抓进语料，而所有检查器都只会说「这段确实在语料里」

Maeda 这轮，168 篇抓回来的「文章」里有 **21 篇是 JPEG/PNG 的字节流按 UTF-8 解码**
的产物（`replace` 模式把非法字节变成 `�`，于是它变成了一个合法的 str）。
最长的一篇 58,081 字，全是乱码。

它们能活到那么后面，是因为**每一道关卡都恰好不管这件事**：

| 关卡 | 为什么放行 |
|---|---|
| `resp.read().decode("utf-8","replace")` | `replace` 的全部意义就是「不要抛异常」 |
| `clean()` 剥标签 | 乱码里没有 `<` `>`，所以剥完还是它自己 |
| `len(t) < 1200` 丢弃 | 图片字节流**远超**1200 字，这个门反而保护了它 |
| 行频法剥样板 | 每篇乱码互不相同，行频=1，不构成样板 |
| 引文完整性检查器 | 它只回答「产物里的引文在不在语料里」——**乱码在语料里，所以永远通过** |

最后一行是关键。我建的七件检查器全部是 `产物 → 语料` 方向的，
**语料本身是不是垃圾，它们结构上无法回答**。
只要我从乱码里「读出」了什么并写进产物，检查器还会给我盖章说有据可查。

**长度门是反向的。** 我一直把 `len < N` 当质量门用。对文字它成立，
对二进制它完全颠倒：垃圾越大越容易过。

### 定则

抓取落盘前做二进制拒收，两个判据都要，不要只做 magic number：

```python
head = t[:400]
binary = (re.search(r"JFIF|ICC_PROFILE|\bPNG\b|Photoshop 3\.0|8BIM|Exif", head)
          # ★ magic number 会漏——裁过的图、非标准头都没有它
          or sum(c == "�" or (ord(c) < 32 and c not in "\n\t\r")
                 for c in t[:3000]) / 3000 > 0.05)
```

第二个判据（替换字符 + 控制字符密度 > 5%）才是主力。正常中英文正文这个密度是 0。

**并且：语料入库后必须过一次「语料自检」，不能只检查产物。**
七件检查器的方向全是产物→语料，这是一个结构性缺口，
`_迭代输入_下一轮.md` 已记为 ㉖。

## 第二十八种：holdout 在我读完之后才指派，于是它验证不了任何东西

Maeda 这轮，`ingest_maeda.py` 里我把 `design_is_isms` 定为 holdout 三篇之一。
但那篇我在**分析阶段就通读并引用过**——它的十几条「design is …」我当时还摘进了笔记。

holdout 的全部作用是：`known` 套组拿它出题，验证产物在**没见过的材料**上是否也成立。
一篇我已经读过、并且很可能已经影响了我写 claim 的材料，
放进 holdout 之后，`known` 套组测的不是泛化，是**我的记性**。

### 为什么顺序会错

蒸馏的自然顺序是「先读语料 → 形成判断 → 再建工作区」。
而 holdout 是在**建工作区那一步**（ingest 时打 `--holdout`）指派的。
等我走到那一步，我早已把语料翻遍了。
**指派动作发生在阅读之后，是流程本身的结构缺陷，不是我这次疏忽。**

更隐蔽的是：所有的门都查不出来。`quality_check.py` 只查 holdout 的**数量和引用**
（车道有没有引到 holdout 源 ID），它没有、也无法有「作者读没读过」这个信号。

### 定则

**holdout 必须在通读语料之前抽定，并且抽定之后立刻隔离。**

正确顺序：

```
枚举 → 落盘 → 【立即随机抽 holdout 并移出可读目录】 → 通读剩余 → 建工作区
```

抽取要点：
- **跨期**（不同年份）+ **跨册**（不同体裁），否则验证不了跨期/跨体裁一致性
- 抽完就 `mv` 到 `_holdout/`，让「不小心读到」在物理上不可能，而不是靠自律

本次的补救是**换一篇我确实没读过的**（`three_principles_for_using_design_successfully`，
2014，A 册，与被换掉的同期同册），并核对了换后字段集不变
（防第二十种：订正脚本污染产物）。补救有效，但它是补救——
下一轮起 `_pipeline` 的枚举脚本要自带 holdout 隔离步骤，已记入 `_迭代输入_下一轮.md` ㉗。

### 与第十九种的关系

第十九种说「评委的『我查过了，语料里没有』是不在场断言」。
这一条是它的镜像：**我的『这篇没影响我』同样是不在场断言**，
而且是关于我自己认知状态的断言——比关于语料的断言更不可查。
所以不能靠声明，只能靠**在物理上让它不可能发生**。

## 第二十九种：一对引号里用省略号拼接不连续片段，每片都真、合起来是伪造

Maeda 车道初稿，45 条引文里有 **4 条**是这个形状：

```
「The Gulf of Execution collapses toward zero... But the second gulf,
the quiet one we underinvested in for forty years, swings wide open.」
```

两个片段在原文里**都逐字存在**，但它们中间隔着三段、一个小标题和一个完整的类比。
我用 `...` 把它们缝进了同一对引号，于是产出了一句**他没写过的句子**。

### 为什么它特别容易漏

- **人眼看不出。** 省略号是学术引用的合法记号，读者默认「中间省略了无关内容」。
  但合法用法的前提是省略的部分**不改变句子结构**；我这里是把两个不同段落的论点缝成一句。
- **朴素的检查器也看不出。** 若检查器按标点切分再逐片核对，四条全过——每片都在。
  只有做**整串投影后求子串**才会失败。我的 `check_quote_integrity.py` 恰好是后者，所以抓到了。
- **它出现在我最用力的地方。** 四条全在 05-decisions（决策还原）——
  那是我最想把论证压紧的一条车道。**压缩欲望和伪造风险是同一个东西。**

### 修法不是删省略号，是拆引号

错的修法：把 `...` 换成 `[…]` 或加一句「（中略）」——那只是给拼接盖章。

对的修法：**一个引号一个连续片段**，中间用我自己的话承接，并且明说是分别引用：

```
原文两句：「The Gulf of Execution collapses toward zero.」
「You no longer need the handle, because you no longer work the door yourself.」
另一侧则相反：「But the second gulf, ... swings wide open.」
```

改完 45 条变 44 条（拆开后有的合并了），逐字可查 42 / 查无此句 0。

### 定则

**引号内不得出现省略号。** 需要跳过内容，就结束引号、用自己的话过渡、再开新引号。
这条比「引文要真实」更强也更好查——`check_quote_integrity.py` 加一条：

```python
if "..." in seg or "…" in seg:
    fail("引号内含省略号：拼接的句子不是原句，须拆成多段独立引用")
```

这条已加入 `_迭代输入_下一轮.md` ㉘，下轮进检查器硬门。

## 第三十种：连补四次词表都没修好判据，因为我一直在补词形而问题在句法

Maeda 的用例生成器里有一条「自指计数」断言：正文声明了 N 条，就必须真的枚举到 N。
它连续误报四次，我连续补了四次表：

| 次 | 误报文本 | 我的修法 | 真实缺口 |

| 1 | 「这两个问题差一**个**数量级」→ 判为声明 1 条 | 取最靠近列表的声明 | 量词表没有「处」，真声明「三**处**改法」根本没被识别 |
| 2 | 「第一**条**是……」→ 判为声明 1 | 补量词「处/种/步/方面」 | 数词表没有「**两**」，真声明「两**个**含义」漏识别 |
| 3 | 「有**两种**写法」→ 判为声明 2 | 补数词「两」 | 量词表没有「句」，真声明「三**句**总结」漏识别 |
| 4 | 「不维护**一个**常青页」→ 判为声明 1 | 补量词「句/层/问」+ 邻近窗口 | 仍然是词表问题 |

**四次的共同结构**：量词表漏掉一个词 → 真正的声明没被识别 →
判据退到附近一个无关的数量词上 → 假阳性。
我每次都在修「这一次漏掉的那个词」，而没问「为什么判据依赖一张补不完的表」。

中文量词有几百个。**这张表永远补不完，所以以补表为修法的路线一定失败。**

### 结构性的修法：改判句法角色，不判词形

真正的条数声明有一个稳定的**句法**特征——后面紧跟冒号或「如下」，且同句：

```
三处改法，按优先级：          ← 声明
这对你的情况有两个直接含义：   ← 声明
三句总结如下：                ← 声明

他不维护一个常青页。           ← 不定冠词，后面是句号
这两个问题差一个数量级。       ← 不定冠词
语料里有两种明显不同的写法：…（隔 60 字）…**一、**  ← 真声明，但管的不是这个列表
```

三条判据合起来：

```python
WINDOW, LEAD = 40, 14
decls = [m for m in _DECL.finditer(text)
         if m.end() <= first_mark                      # ① 在列表之前
         and first_mark - m.end() <= WINDOW            # ② 紧邻列表
         and re.search(r"^[^。！？\n]{0,%d}[：:]|^[^。！？\n]{0,%d}如下"
                       % (LEAD, LEAD), text[m.end():m.end()+LEAD+2])]  # ③ 同句内跟冒号
```

第 ③ 条是关键：它抓的是这个数词在句子里**充当什么角色**，与它用哪个量词无关。

并且失败模式变了：找不到紧邻声明 = **「查不了」而不是「声明为 1」**。
这和第二十种、第二十五种是同一条原则——**不可检查不等于通过，也不等于失败。**

### 负对照抓到了我自己躲过去的那一个

改完之后我跑了负对照（3 个真错 + 5 个应免报）。**第一轮 5/6**——
残留的假阳性是「他不维护一个常青页。\n对你们的含义：」：
冒号在 14 字窗内，但隔着一个句号和一个换行，属于下一句。

**我的真实文本恰好因为间隔更长而躲过了这一条**，也就是说：
如果不跑负对照，这个判据会带着缺陷进产物，
下一次某段文字间隔短一点它就会误报，而那时我已经不记得判据是怎么写的了。

加上「同句」约束（数词与冒号之间不得有 `。！？` 或换行）后负对照 8/8。

### 定则

1. **凡是依赖枚举表（量词、关键词、模式串）的判据，都要问一句「这张表补得完吗」。**
   补不完的，就说明判据选错了维度——换成句法/位置/角色。
2. **改完判据必须立刻跑负对照**，且负对照要包含**比我的真实文本更极端的构造**。
   真实文本碰巧通过，不等于判据正确。
3. **判不了要报「判不了」**，不许退化成一个默认值。

## 第三十一种：七件检查器全是「产物 vs 语料」，没有一件查我的算术

Maeda 这轮，我写进产物的一句话是：

> 「38 篇动手笔记里 **22 篇（58%）**标题直接嵌了年份」

真实值是 **11 篇（29%）**。错了一倍。

### 错误怎么产生的

我的统计代码是：

```python
dated = [f for f in hands if re.search(r"_(19|20)\d{2}\b|...|_2024|_2025", f)]
```

它在**完整文件名**上匹配年份。而文件名长这样：`jm_2023_azure_static_web_apps_in_2023.txt`——
前缀 `jm_YYYY_` **是我自己在抓取时加的**。

所以这段代码数的是**我自己写进文件名的年份**，与他的标题毫无关系。
58% 这个数，本质上是「有多少篇文章我知道它的发表年份」——答案当然接近全部。

自查时我改成 `f[8:]` 跳过前缀，得到 6 篇（16%）——**这次也错**，
因为 slug 在 46 字符处截断，`in November 2024` 这类长标题的年份被截掉了。

**两次都错，方向相反。** 正确做法是从**文件正文里的真实标题**数：11/38 = 29%。

### 为什么所有的门都放行了

| 检查 | 为什么看不见 |
|---|---|
| 引文完整性 | 这不是引文 |
| 装饰性引用/覆盖度 | 关键实体「动手笔记」确实在被引来源里 |
| 语义残留 | 没有残留 |
| claim 锚点 / schema 漂移 | 结构完全正确 |
| 官方 `quality_check --strict` | 门查格式、引用、孤儿、配比——**不查乘除法** |
| 人眼 | 58% 和 29% 都是「看起来合理」的数 |

**发现它的唯一途径是我自愿去重算一遍。而自愿的检查不是检查。**

而且它散在 **6 处生成器 / 5 处产物**（第十六种：一个事实错误平均散在 4 个落点）。

### 修法不是改数字，是让它不可能再手写错

建 `jm_stats.py` 作为**所有计数的唯一真源**，从语料现算；
四个生成器一律 `from jm_stats import FACTS as F` 并内插，**不许手写任何计数**。

再加第八件检查器 `check_number_drift.py`：拿现算值去产物里找矛盾的写法。
它的第一版立刻误报——`r"(\d+)\s*篇动手笔记"` 把「涉及跑模型的 **8** 篇动手笔记」
当成了总数。**与自指计数判据同一类错误：正则捕到了位置对、语义不同的数。**
收紧为要求「分母为 / 他的 / 共」这类总数语境后，自测 5/5。

### 定则

1. **凡是会出现在产物里的计数，必须从语料现算，生成器只许引用。**
   手写的数字会在语料变动、口径变动、或我数错时静默失效。
2. **不要用文件名当内容的代理。** 文件名里有我自己加的东西（前缀、时间戳、
   截断），拿它做统计等于统计我自己的行为。要数内容就打开文件。
3. **每个计数都要说明口径。** 本轮的实测：一手比 train 口径 0.8617、全量 0.8660；
   维度源数 train/全量分别为 writings 70/73、decisions 70/73、timeline 81/84、
   expression 39/41，而 conversations 与 external 两个口径相同（7 与 13）。
   不写口径，读者无从判断哪个对。

   **补记：这一条我自己刚犯过。** 上面这段的初稿我写的是「conversations
   train 是 7、全量是 8」——**没查就写**，凭「train 少 3 条 holdout，所以全量应该更多」
   的推理填了个数。实际两个口径都是 7（三条 holdout 恰好都不带 conversations 维度）。
   **可推理的数不等于可以不查的数**，这正是本条要防的那件事。
4. **新检查器必须带 `--self-test` 负对照才准用。**
   这件工具的第一版误报率不为零，是自测抓到的，不是我看出来的。

## 第三十二种：「这个词出现得少」不是判据，「这个词在这里做什么」才是

第二十七种讲的是**词表写窄导致 0 命中，于是错判为不存在**。
这一条是它的对偶面，而且更常见：**词命中了，但我没看命中的是什么。**

Maeda 的语料我要判断「支不支持视觉评审」。第一版判据是词频：

```python
"艺术/视觉": r"typograph|painting|sculpt|exhibit|museum"   # 命中 8/118 = 7%
```

我据此写进产物：「语料中几乎无视觉评审内容，命中极低」。

评委席抓到我复述词表时漏了 `sculpt`、把 `typograph` 写成 `typography`。
去核对时我顺手把**每一条命中都打印出来看了**，结果是：

| 出处 | 那个词实际在做什么 |
|---|---|
| 2009 Why Business Leaders Should Act More like Artists | `exhibition` = 多位艺术家共展，用来讲**协作**，不是视觉 |
| 2013 Earning, Gooding, Making | `museum` = 哪里能看到好东西，用来讲**品质标准** |
| 2017 On Being Dipped (Not Duped) | `painting` = **别人给他画像**的轶事 |
| 2020 CCPA, GDPR, Privacy, and the Spy Museum | 柏林间谍博物馆 → 引出**数据隐私** |
| 2026 What is AX? | `DIALOGUE MUSEUM` = 那间**全黑的房间**，讲可及性 |
| 2024 AI Website Generator | `Font and Typography: Use 'Inter' font` = **他给建站 AI 的提示词** |

**结论没变（语料确实不支持视觉评审），但理由完全变了，而且新理由强得多。**

旧理由「词频低」经不起一次 grep——读者一搜就能找到命中，然后合理地怀疑我在敷衍。
新理由「这些词在语料里承担的都不是视觉判断的职能」是逐条可核的，
而且**预先回答了读者搜出命中之后的下一个问题**。

### 为什么我最初没看

因为词频给了我一个数字，而数字**看起来像证据**。
7% 是一个可以写进文档、可以被引用、可以过检查器的东西。
「逐条看了 8 处命中，其中 6 处是非视觉用法」则需要我真的去读那 8 处。

**判据的成本决定了我会不会用它，而不是它的可靠性。**

### 附带发现：唯一一段真材料在 holdout 里

语料里确实有一段扎实的视觉训练自述（筑波的排版课、他的导师、首次个展「Design Machines」），
但它在 1998 那篇——**恰好是 holdout**。
如果我当初没把它抽成 holdout，我可能会据此写出一条「他有视觉设计训练背景」的主张，
而那条主张会建立在**单篇孤证**上。

holdout 的抽取是随机的，这次的运气帮了我。**不能依赖运气。**
定则：任何只有单一篇目支撑的主张，都要在 claim 里写明「孤证」并压低 confidence
（本产物已对「拒答方式」那条这样做了，confidence 0.62）。

### 定则

**凡是要下「语料不支持 X」的结论，不许只给词频，必须给逐条命中的用途分类。**
命中数为 0 时按第二十七种处理（换写法重查）；命中数不为 0 时按本条处理（逐条看）。
两种情形都不允许「一个百分比 + 一句『极低』」了事。

## 第三十三种：我有一件专查不在场断言的检查器，它报了 13 条待确认，而我只核了 3 条

这是本轮最值得记的一条，因为它不是「我没有工具」，而是**「我有工具、跑了工具、
然后没把工具的输出用完」**。

`check_absence_claims.py` 在 Maeda 产物上报出 20 条绝对化断言，其中 **13 条标为
「邻近未见检索依据，须人工确认」**。我当时只核了其中 3 条（都通过了），
然后就去做别的了，因为门已经绿了——**这件检查器是「只列不判」的，不阻塞发布**。

评委席后来指出其中一条有问题，我回头把 13 条全核完，结果：

| 断言 | 核实结果 |
|---|---|
| 「无任职起止」 | **假**。语料里有三处：2013「I spend my days running RISD」；2016 与 2018 两篇均写「I joined Kleiner Perkins Caufield & Byers from my post as the President of Rhode Island School of Design」 |
| 「操作文档不写理由，没有一句为什么」 | **假**。38 篇动手笔记里 8 篇含 because/reason——他确实解释，只是解释的是局部战术选择（为什么用 `@` 做分隔符）而非原理 |
| 「他从未说明为什么偏好本机」 | 真（换三种检索式重查，三处命中全与本机/云无关） |
| 「他从未讨论过自己的文档分层」 | 真 |
| 「F 册两篇无任何人称轶事」 | 真（正文第一人称各 0 次） |
| 其余 8 条 | 真 |

**13 条里错 2 条，错误率 15%。** 而这 2 条各自散在 4–8 个落点。

### 三个可推广的点

**一、「只列不判」的检查器，实际效果等于「不检查」。**
它不阻塞，所以我在门变绿之后就不会回头看它。
上一轮我特意把内容层检查做成「只列不判」，理由是不能让 `--strict` 因为
误报而阻塞发布——那个理由仍然成立，但代价是**没有人会读它的输出**。
修法不是把它改成硬门（会误报），而是**把「已逐条核完」变成一个可检查的状态**：
核完的条目要留下书面结论，未核的条目在发布报告里单独列出条数。

**二、我的不在场断言错误率约 15%，且这是第二次同类。**
Salatin 那轮是「语料中没有一处逐字往复的对话记录」（假，有两篇 5 轮对话）。
这轮是「无任职起止」。两次的共同点：**我说「没有」时用的是印象，不是检索。**

**三、过度绝对化比事实错误更难发现。**
「操作文档不写理由」这句话，读起来像一个风格观察而不像一个可证伪的断言，
所以我写的时候没有把它当成需要核的东西。
但它有一个精确的分母（38 篇动手笔记）和一个可数的判据（含不含 because），
**凡是有分母和判据的，就是事实断言，就必须核。**

订正后的写法保留了原观察的价值，而且更准确：
「操作文档只解释局部战术选择（38 篇中 8 篇含 because/reason，如为什么用某个分隔符），
不解释原理；论述文档给完整论证。」

### 定则

**`check_absence_claims.py` 的输出必须逐条核完并留下结论，才算这一轮做完。**
不许因为「门已经绿了」就停。已加入发布前清单。

## 第三十四种：一边改产物一边让评委评，评的是移动靶

Maeda 这轮，不知前情的评委席在报告末尾写了一段我没料到的话：

> 审阅过程中我对同一份文档的多次读取显示内容在实时变化——
> `work.md` 里的比例在我两次读取之间从「22 篇 58%」变成「11 篇 29%」，
> `boundaries.md` 的 conversations 源数从 6 条变成 7 条，
> `divergence-map.md` 后来新加了一段脚注，`persona.md` 那句也在审阅期间被改写……
> **以上结论均基于我最后一次读取的版本。**

它说得对，而且这是**我的流程错误，不是它的**。

### 为什么会这样

评委跑起来要 20–35 分钟。我不想干等，就在这段时间里继续自查、继续修。
每一处修改单独看都是对的，合起来的效果是：

- 评委 A 报的两条问题，在它交卷时**已经被我修掉了**——它的分数低估了当前产物
- 评委 B 读到的是一份**半新半旧的混合体**：某些文档已更新、payload 里对应的用例还没更新
- 它据此报出的「不一致」里，有一部分是**我改到一半的中间态**，不是真正的设计缺陷

最后一点最坏：**它浪费了篇幅去报告一个正在消失的问题，而那些篇幅本可以用来找真缺陷。**

### 但它的报告仍然有价值，因为它标注了自己的时间基准

它没有假装自己看到的是最终版，而是明说「基于我最后一次读取的版本，建议对照当前最新文档复核」。
**这正是我一直要求产物做到的那件事**——说清你的结论建立在什么快照上。
评委做到了，我没有。

### 定则

**送评之前冻结产物，评完之前不改。**

具体做法：

```bash
# 送评前：算一个指纹，写进评审请求
shasum -a 256 judge_payload_*.json ws-*/*/**/*.md | shasum -a 256
```

把这个指纹告诉评委，并在收回报告时核对指纹是否还是同一个。
**指纹变了就说明这一轮评审作废，必须重评**，不许拿旧分数拼新产物。

想在等待期间做事，就做**不改产物的事**：读语料、写 RUNBOOK、准备下一个人物的预筛。
自查发现的问题**记下来，等评委回来一起改**——
这样每一轮评审对应一个确定的产物版本，分数才有意义。

### 附带：这也解释了为什么「多轮评审拼分」需要溯源

前几轮我建过一套「某一轮的重判文件只能用于该轮改动过的用例」的断言
（`gen_results_*.py` 里的三条反挑评委断言）。
当时的理由是防止挑评委。**现在有了第二个理由：防止把不同产物版本的分数混在一起。**
两个理由指向同一条纪律：**分数必须能溯源到它评的那个具体版本。**

## 第三十五种：换 holdout 时只改了账本字段，物料目录没跟着搬，而两边计数恰好相等

Maeda 这轮我换过一次 holdout（原定的 `design_is_isms` 我在分析阶段已通读，
换成确未读过的 `three_principles`，见第二十八种）。

换法是**直接改账本里的 `split` 字段**——一条 holdout→train、一条 train→holdout，
并断言了字段集不变（防第二十种：订正脚本污染产物）。

字段改对了。**但物料目录没动。**

## ★★ 排期前的**第二道**前置：一手规模探测（2026-08-04 落成，代价三人）

既有的前置是**公有领域可得性探测**（卒于 1930 年后／在世的人先探）。
它管的是「**取不取得到**」。**它管不了「取到了也不够」。**

实测三次撞墙，形状同一个：

```
Semmelweis #105   一手  7/59 = 0.1186   他一生只出版 5 部作品
Slavyanov  #115   一手  8/53 = 0.1509   同形
Liebig     #124   一手 39/64 = 0.6094   ★ 不同成因：著作极多，
                                          但数字化下来可取的那批里
                                          译本 85／多作者辞书 30／期刊卷 16 占了绝大多数
```

**三次都是全流程抓完之后才知道的。** Liebig 那次还多花了一轮补抓。

### 所以：**发抓源指令之前，先只做清点，不下载全文**

要交回的是一张表：**题名／年／语种／归属证据／能不能取到（给 URL 或馆藏号）／属哪一道**，
然后**先算一次门**：

```
deep      来源 ≥45 ／ 一手 ≥30 ／ 一手占比 ≥0.65 ／ 道 ≥6
standard  来源 ≥24 ／                一手占比 ≥0.50 ／ 道 ≥6
quick     来源 ≥8  ／                一手占比 ≥0.40 ／ 道 ≥3
```

★★ **更正（2026-08-04 当天）**：本节初稿把 standard 写成「道 ≥3」、
quick 漏了「占比 ≥0.40」。**真源是 `scripts/common.py:PROFILE_THRESHOLDS`，
standard 的 `min_lanes` 是 6。** 是 #125 Mendel 那次抓源方按仓里的值跑、
并把不一致报回来才发现的——**我写这一节时是凭记忆抄的，没去读那个字典。**
**凡是把阈值写进文档，都要从 `common.py` 抄，不要从记忆抄。**

**连 quick 都够不着 → 到此为止，记延后，不开抓。** 那本身就是结论。

### ★ 两条不许

1. **不许为了让某一档成立而放宽计数单位。**
   「10 封信」算 1 份还是 10 份、「9 篇气象论文」算 1 份还是 9 份——
   **两种数都给出来，选择由主循环定，不由抓源方定。**
   （先例：Farmer #121 那次抓源方拒绝替我在「3 份文档」与「11 件」之间选、两个数都给了，**那是对的**。）
2. **不许把「与他有关的书」算成「他写的书」。**
   Liebig 那次有 9 份是这么混进一手的：别人骂他的论战文、别人写给他的公开信、
   别人主编而收了他一篇的文集、登过他论文的期刊、含他一节的合集、他只作序的书。

### ★★ 第一次用它就见效（#125 Mendel，2026-08-04 当天）

**只做清点、没下载任何全文**，就判出了三件此前要抓完才知道的事：

  → deep 要 30 份，**再抓多少年也到不了** ⇒ 这一档对他要永久划掉

① 后人编的文集（Ostwalds Klassiker 121／Bennett 1965／Stern & Sherwood 1966）
**creator 串与本人一字不差**；

## ★★ 语料落盘的两步，顺序与分工（v0.0.0.108 定清）

`build_source_ledger.py` 与 `ingest.py` **都会往 `raw/` 写文件**，
两个都跑就是**每份存两遍**——Liebig #124 实测 `raw/` 里 **104 个目录、52 份语料、42 MB**。

分工是：

| 步 | 命令 | 独有产出 |
|---|---|---|
| 1 | `build_source_ledger.py --no-copy` | **九列台账 TSV**（`raw/_ids.txt`）：分档、道、归属标记、权利依据 |
| 2 | `ingest.py <target> <files> --tier … --dimension … --attribution …` | **落文件** + 归一化文本 + 校验和 + `split` + `evidence/source-ledger.jsonl` |

**`ingest` 才是落文件的那一步**（`init_target` 打印的 `next` 里就是它）。
台账那一步加 `--no-copy`，只写 TSV。

★ 这个重复**看不出来**：两边的计数各自都对（本件报「落盘 52」、`ingest` 报 52），
**只有去数 `raw/` 里的目录才会发现是 104。**
且它会让任何按目录扫 `raw/` 的判据**把每份算两遍**。

★ 落盘时 `--attribution` 要写**能出示的东西**（扉页那一行、规范号、出版年）。
**但它不满足 `research.source-unclaimed`** —— 那道门只认 `A-*` 署名证据，
或源的 `original_name` 逐字出现在 `meta.json:attribution_basis.covered_sources` 里。
**两处都要写。**

---

`ingest.py --holdout` 的行为是「保留材料、不复制正文」，所以：

| 目录 | 应有 | 实有 |
|---|---|---|
| `raw/` | 94 份（train） | 94 份 |
| `references/sources/` | 94 份（train） | 94 份 |

**计数完全正确。** 而成员是错的：里面装着已成为 holdout 的 `three_principles`
（它作 train 灌入时留下的副本没被清），缺着已回到 train 的 `design_is_isms`
（它作 holdout 灌入时本就没复制）。

一进一出，**数目恰好抵消**。

### 后果有多严重

1. **holdout 的正文躺在建模者能读到的目录里**——holdout 隔离在物理上失效了。
   第二十八种刚说过「抽完就 `mv` 出去，让不小心读到在物理上不可能」，
   而我这次连这个都没做到，还以为做到了。
2. **train 少了一篇的物料**，任何按目录遍历（而不是按账本遍历）的下游工具都会漏掉它。
3. **所有的门都放行**：官方门查的是账本，账本是对的；
   我自己的检查器查的是产物文本，也是对的。**没有一件在查「账本与物料是否一致」。**

### 它是怎么被发现的

不是被门发现的，是评委 D 报了一条「产物说语料无学历时点，但 1998 那篇有」，
我去核对时用「raw 目录存在与否」当作 holdout 的判据——**结果连我的核查脚本都被这个错配骗了**，
一度把 holdout 的 South Face 当成了 train。回头查账本才发现两边对不上。

**一个错误让我的核查工具也给出了错误答案**，这是最坏的一类。

### 定则

**任何改变 split 的操作，都必须同时搬动物料，并做成员级（不是计数级）的两向核对：**

```python
train = {r["source_id"] for r in rows if r["split"] == "train"}
for sub in ("raw", "references/sources"):
    have = {d for d in os.listdir(W/sub) if d.startswith("src-")}
    assert not (train - have), f"{sub} 缺: {sorted(train-have)}"
    assert not (have - train), f"{sub} 多: {sorted(have-train)}"
```

**两个方向都要断言。** 只查「有没有缺」会漏掉「多了 holdout」，
只查计数则一进一出全看不见——本次正是如此。

更根本的一条：**换 split 应当重新 ingest，而不是改字段。**
改字段只改了元数据，而 ingest 的副作用（复制/不复制正文）改不回来。
凡是「一个动作有副作用」的地方，撤销它就不能只撤主效果。

## 第三十六种：第三次用错词表，因为词表装的始终是我的分类观念而不是他的实践用语

同一个错误在 Maeda 一个人身上犯了三次，每次都被不同的人抓到：

| 次 | 我用的词表 | 漏掉了什么 | 谁抓到的 |
|---|---|---|---|
| 1 | `typograph\|painting\|sculpt\|exhibit\|museum` | 他谈设计用 craft / AX / JTBD / agent | 我自己（看标题全表时） |
| 2 | 同上 | 命中的 8 处**用途**没看（`exhibition` 是协作范例、`museum` 是哪里能看到好东西） | 评委席指出词表复述有误，我顺手核对时发现 |
| 3 | 同上 | **`color` / `font` / `gradient` / `px` 完全不在表里** | 严格评分席 |

第三次最严重。补上实践词汇重扫后：**81 处命中、15 篇，其中 65 处集中在一篇**——
2024 年 `AI Website Generator`，那是他亲手写给建站 AI 的完整视觉规格：

```
slightly rounded corners (3px to 5px radius)
The total width … should not exceed 800 px
Font and Typography: Use 'Inter' font
shiny light blue and orange blurred gradient bubbles … 80% transparent
Use monochromatic vibes to keep the colors subtle and not overly saturated
Ensure the gradient transitions smoothly from the top left to the bottom right
```

我原来写的边界是「语料几乎无视觉内容」。**那句话是错的**，而且错得很容易被戳穿——
任何人 grep 一次 `color` 就能推翻。

### 共同的根因

三次都不是「正则写窄」这种技术问题，是**取词的来源错了**。

我取词时想的是**族名**（「艺术设计师」→ 美术馆词汇），
而不是**这个人干活时会敲进键盘的字**（color、font、px、gradient、hover）。

族名是分类学的产物，是给**归档**用的；实践用语是给**干活**用的。
拿归档词去搜干活的记录，命中率低是必然的，与他做不做这件事无关。

### 修法让边界变得更好，而不只是变得正确

订正后的边界不是「语料几乎无视觉内容」（假），也不是「语料有视觉内容」（真但无用），
而是一个**可操作的区分**：

> **规格 ≠ 评审。** 他在那篇里是**下指令**（写一份视觉规格），
> 不是**做判断**（评价既有设计的好坏）。
> 语料里没有一处他评价某个页面的配色或字重层级。
> 所以本产物能回答「他会怎么写一份视觉规格」，
> 不能回答「他会怎么评价你这个页面」。

**一个被推翻的边界，逼出了一个比原来有用得多的边界。**
原来那条只会让产物拒答；新的这条既拒了该拒的，又开放了本来就有证据支持的部分。

### 定则

**取检索词必须从人物的产出里取，不许从分类名里取。**
具体做法：先随机抽 5–10 篇通读，把他反复使用的名词抄下来当种子词表，
再用种子词表去扫全语料。**顺序是「先读他的词，再搜」，不是「先想我的词，再搜」。**

并且：**任何「语料里没有 X」的边界，写下之前必须至少换两组词表验证**——
一组我想的，一组从他文本里取的。两组都空才算空。

## 第三十七种：评委复现不出我的计数，因为我给了数字没给判据

Maeda 这轮，我在产物里写「全语料 81 处 color/font 级细节，其中 65 处集中在一篇」。

评分席复核时说：**「'65/81' 的精确计数未能用简单关键词 grep 独立复现
（字面 color/font 计数为 29/40），大概率是用了更宽的语义口径，
判断方向正确但精确数字未能逐一复核。」**

它说得完全对。我用的模式是

```
\bcolou?r|\bfont\b|gradient|rounded corner|whitespace|padding|hover|typeface|palette|#[0-9a-fA-F]{6}
```

而产物里**一个字都没提这个模式**，只给了 81 和 65 两个数。
于是任何人想复核，都只能猜我用了什么词，猜错就对不上，
然后合理地怀疑这个数是我编的。

**一个不可复现的数字，在证据链上等于没有。**

### 修法一：把判据贴出来

产物里直接给出正则，让读者能跑同一条命令。这一条 Salatin 那轮就立过
（「不给固定数字，给判据」），但当时说的是「计数会变，判据不变」，
**这次是另一个理由：判据是复核的入口。** 同一条规矩，两个理由。

### 修法二（更要紧）：报告对判据不敏感的那个量

我去重算了三种宽窄不同的词表：

| 词表 | 全语料 | 该篇占比 |
|---|---|---|
| 只要 `color`/`font` | 36 处 / 7 篇 | **83%** |
| 本文采用的那一组 | 81 处 / 15 篇 | **80%** |
| 再加 `px`/`radius`/`margin` | 147 处 / 21 篇 | **82%** |

**绝对数从 36 跳到 147（4 倍），集中度纹丝不动（80–83%）。**

也就是说我原来引用的 81 和 65 是**词表的产物**，而 80% 才是**语料的性质**。
产物现在引用比例并附上这张表，读者用任何一种词表复核都会得到同一个结论。

### 定则

**凡是靠检索得出的计数，产物里必须同时给出：**
1. **检索式原文**（能复制粘贴直接跑的那种）
2. **至少两种宽窄不同的检索式下该结论是否成立**

第 2 条是新的。它把「这个数对不对」变成「这个结论稳不稳」——
后者才是读者真正要知道的，也是唯一经得起换一个人复核的。

**如果一个结论只在我选的那一种词表下成立，那它是词表的结论，不是语料的结论。**

## 第三十八种：把 holdout 抽取提前到了清洗**之前**，于是抽中两个归档页

Maeda 那轮的教训是「holdout 抽在通读之后 = 自己给自己出题」（第二十八种），
定则是**抽取要前移**。Godin 这轮我照做了，把抽取写进枚举脚本、抓完立刻抽。

**结果抽中了两个月度归档页。**

三篇 holdout 的体积是 9,762B / 18,498B / 1,852B，而语料中位数是 2,858B——
前两篇是 3–6 倍。它们是 `seths.blog/2003/11/` 这类月度归档，不是文章。

**holdout 里放归档页，等于 `known` 套组无题可出。**

### 正确的顺序有四步，不是三步

我原来记的是：

```
抓取 → 【抽 holdout】 → 通读 → 建工作区
```

实际需要：

```
抓取 → 【机械清洗】 → 【抽 holdout】 → 隔离 → 通读 → 建工作区
```

**「机械清洗」必须在抽取之前，而且它本身不许涉及阅读**——
判据只能是结构性的：字节数、日期行数量、链接密度、URL 形态、是否含 "Read more"。
这样既清掉了非文章，又没有污染 holdout。

### 但第一版清洗判据又走到了另一个极端

我用「纯数字 slug」（`sg_\d{4}_\d{1,4}`）判归档页，一刀砍掉 **92 篇**，
年份范围从 **2002–2026 缩到 2017–2026**——**把整段早期跨期证据全删了**。

Godin 早年在 Typepad，URL 形态与现在不同，数字 slug 里混着真文章。
我用**文件名形态**猜内容性质，猜错了。

### 定则

**清洗判据必须来自内容的结构，不能来自文件名的形态。**

可用的结构判据（都不涉及阅读语义）：

| 判据 | 归档页 | 文章 |
|---|---|---|
| 正文里的日期行数量 | 多个（一月份所有文章） | 1 个 |
| "Read more / Continue reading" 出现次数 | 多个 | 0–1 |
| 字节数 vs 全体中位数 | 显著偏大 | 接近中位 |
| 链接密度（链接数 / 千字） | 高 | 低 |

**并且：任何一次清洗，若使某个年份区间整体归零，必须停下来查为什么。**
「2002–2016 一篇不剩」这种结果，本身就是判据出错的信号——
真实语料不会有这么整齐的边界。

这一条已写进 Godin 的枚举脚本：落盘时同时记录 `date_lines` 与 `read_more` 计数，
清洗阶段用它们而不是用文件名。

## 第三十九种：稀疏的归档页看起来像文章，因为「日期行少」不等于「是文章」

Godin 这轮，我给清洗判据换了个「结构性」的写法，自以为比文件名形态可靠：

```python
文章 = date_lines <= 2 and read_more <= 1     # 归档页有多个日期，文章只有一个
```

判据本身的想法是对的。**但它把 2002–2016 的月度归档页几乎全判成了文章。**

原因很简单：`seths.blog/2002/02` 的 `date_lines` 是 **1**——
因为他 2002 年 2 月只发了一篇。

**行数少不代表这是一篇文章，只代表那个月发得少。**

同一个判据在 2023–2026 完全有效（每月 30 篇，date_lines=10+），
在 2002–2004 完全失效。**判据的有效性随数据密度变化，而我只在密的那一段验证过。**

### 真正可靠的判据是 URL 形态

| 形态 | 是什么 |
|---|---|
| `/YYYY` | 年归档 |
| `/YYYY/MM` | 月归档 |
| `/YYYY/MM/slug` | **文章**（旧式） |
| `/slug` | **文章**（新式） |
| `/wp-*` `/wp-json/*` | 站点资源 / REST API |

按这个重分：532 个抓到的 URL 里，**真文章只有 171 篇**，
294 个是月归档、25 个是年归档、约 40 个是静态资源。

而我原来的结构判据给出的是「文章 218 / 归档 314」——**多算了 47 篇**，
且多算的全部集中在早年，正好是跨期证据最要紧的那一段。

### 附带发现：早年文章一篇都没抓到

按 URL 形态重分之后才看清：171 篇文章里，**2023–2026 占 149 篇**，
2014–2018 只有 5 篇，其余 17 篇无年份。

也就是说第一轮抓取**根本没有触及 2002–2022 的个体文章**——
那些文章的入口全在月归档页里，而我只从种子页提链接、没有递归展开。

跨期证据是人物蒸馏最贵的部分（Maeda 那轮 1998–2026 的 28 年跨度
支撑了「立场修订」与「工具态度一贯」两条主张）。
只有 2023–2026 的语料答不了「他变过没有」这类问题。

### 定则

1. **判据必须在数据最稀疏的那一段验证，不是在最密的那一段。**
   我在 2024 年的月份上验过 `date_lines>2 → 归档页`，它在那里成立；
   而 2002 年的月份让它整段失效。**验证要挑最不利的样本，不是最方便的样本。**
2. **URL 形态优先于内容统计。** 站点的路由结构是作者/CMS 定的，
   稳定且与内容多寡无关；内容统计随密度漂移。
3. **抓完先按 URL 形态出一张分类表**，看清各类各多少，
   再决定要不要第二轮展开。本轮若不做这一步，
   我会带着一个「只有近三年」的语料一路做到写 claim 才发现。

## 第四十种：按标题挑读物，然后从中归纳「他的招牌手法」

Godin 这轮，我读了四篇之后得出一个很有说服力的结论：

> 他的签名动作是**把一个用得很松的词劈成两种**——
> done / good enough、if / then、功能性的 enough / 地位性的 enough、
> 阻碍性的 friction / 给牵引力的 friction。跨 2011–2026 一以贯之。

四个例子都真实，跨度也真的有 15 年。**但这个结论是错的。**

去全语料量化，二分招式只命中 **28/193 = 15%**。

### 错在哪：我挑读物的方式决定了我会看到什么

那四篇是我从标题表里挑的，挑的依据是标题里有 `or` / `vs` / `enough`。
**我先筛出了符合模式的样本，再从样本里归纳出这个模式。**

这不是「样本太小」——再多读十篇同样筛选出来的，只会让我更确信。
**问题是筛选条件与待验证的假设是同一个东西。**

### 改用固定种子随机抽样后，看到的是另一回事

随机抽 6 篇重读，真实的高频结构是别的：具体的日常观察起头、中段一个「为什么」的追问。
再据此重新量化：

| 实测项 | 值 |
|---|---|
| 开头是具体的物或事 | 161/193 = **83%** |
| 正文含问句 | 92/193 = **48%**（≥2 个问句 26%） |
| 中位篇幅 | **153 词 / 8 段 ≈ 每段 21 词** |
| 二分招式（我原来的假设） | 28/193 = 15% |
| 明确「转向读者」的措辞（第二个假设） | 10/193 = 5% |

**两个假设都不成立，而没被我猜到的「每段 21 词」才是最强的结构事实。**
（多数写作者一段 50–100 词。他把 153 词切成 8 段。）

### 定则

1. **形成假设的样本，必须与验证假设的样本分开。**
   用标题挑出来的读物只能用来**提出**假设，不能用来**支持**假设。
2. **通读阶段的抽样必须固定种子随机**，抽完先读再看标题。
   我这次是先看了标题表才挑的，顺序一错，后面全歪。
3. **量化的判据要从随机样本的实际措辞里取**，不是从我预想的措辞里取
   （这是第三十六种的同一条，在结构分析上再犯一次）。
4. **凡是「他的招牌手法是 X」这类断言，产物里必须带分母。**
   「15%」和「一以贯之」是两个完全不同的说法，而后者更好听。

   它是经验库，不是规程。这一条以前没写明，本次补上。
3. **开工第一动作永远是跑那三条命令**（validate_group → git pull → next_person），

## 第四十二种：URL 里的年份是转载年，不是内容年

Robertson 一轮，我把 `jr_2017_acquirersmultiple_2017_management.txt` 当成 2017 年的晚期材料读，
并据此和 2017 年 Delivering Alpha 的逐字稿一起用作「晚年立场」的证据。

**它其实是 2012 年的访谈。** 来源 URL 是 `acquirersmultiple.com/2017/01/...`——
那是**博客转载的日期**；正文里写着「One of the best Robertson interviews was one he did with
**The Graham & Doddsville Newsletter**」，而该刊的这期是 **2012 年春季第 15 期**。

内证也对得上：文中他说「This year will see the Apple television set」——
那是 2012 年的传闻高峰，不是 2017 年。

### 为什么抓取脚本必然会搞错

我的年份提取逻辑是「先从 URL 取，取不到再从正文的日期行取」。
对原发内容这是对的；**对转载内容它必然取到转载年**，而且取得很有信心（URL 里明明白白有个 2017）。

**URL 的年份反映的是「这个页面什么时候被发布」，不是「这段内容什么时候被说出来」。**
对一手材料的转载站（valuewalk、marketfolly、acquirersmultiple、substack 的信件转载）
这两个年份系统性地不同。

### 检法

抓回后扫正文前 2500 字里的转载线索，与文件名年份比对：

```python
PAT = re.compile(r"(originally|first (?:published|appeared)|reprint|excerpt from|Issue\s*\d+)"
                 r"[^.]{0,70}?((?:19|20)\d{2})", re.I)
# 命中年份 < 文件名年份 → 疑似转载，人工核
```

本轮全语料扫出 3 条命中，1 条为真（G&D），2 条为假阳性（讣闻提及历史年份）。
**假阳性率高是可以接受的**——这类错误一旦进产物就是跨期证据错位，值得人工过一遍。

## 第四十三种：一句「听起来就是他会说的话」，说话人是别人

同一轮，负责扫大学演讲的子代理报回一条它主动拦下的陷阱：

> Duke Today 的报道里有一句「Over the year I have been inspired by the young people I meet…」
> ——**这是 Eric Mlyn 说的，不是 Robertson**。不要用。

这句话与 Robertson 的其它自述高度同调（他确实反复说以年轻人为傲：
「I'm really, I think, proudest of the men those people have become — and women, too.」）。
**正因为它太像了，抄进来不会有任何不适感。**

### 这类错误的形状

在「关于某人的报道」里，被引的人往往有好几个：本人、同事、受益者、机构负责人。
而报道的**主题**是那个人，于是所有引语都笼罩在他的名字下。
只看语义相合度，分不出是谁说的——**必须逐条回去看引导句。**

### 定则

**凡是从第三方报道里取的引语，落进产物之前必须核一次引导句里的主语。**
不是核「这句话像不像他说的」，是核「这段引语前面写的是谁」。

已加入抓源子代理的指令模板：
> 报道类材料里的每一条引语，必须能指出它的引导句（`X said` / `according to X`）；
> 指不出的一律不计入该人物的一手发言。

## 第四十四种：机器转写的字幕，内容是他的，逐字不是

Robertson 补源时，17 篇新增里有 **12 篇是 YouTube 自动字幕（ASR）**。
子代理做得对：每个文件头都写了 `SOURCE_NOTE` 标明是机器转写、可能有识别错误。

**但如果我不立规矩，这个标注在下游会消失。** 流程是这样的：
ASR 文件 → ingest 成一条源 → 车道里引用 → claim 里引用 →
`check_quote_integrity.py` 核对「引文在不在语料里」→ **通过**。

检查器只回答「这段字在不在语料里」，它无法回答「语料里的这段字是不是他真说的那几个词」。
**ASR 把「他说过这个意思」和「他说过这几个字」之间的区别抹掉了，而我所有的门都建立在后者上。**

### 两类用途要分开

| 用途 | ASR 能用吗 |
|---|---|
| **他谈过什么、持什么立场、举了什么例子** | ✅ 能用。识别错误不改变话题与立场。 |
| **逐字引语（放进引号里的原话）** | ❌ **不能用。** 一个被听错的词就是一处伪造。 |
| 计数（他提到某主题多少次） | ⚠️ 谨慎——专有名词最容易被 ASR 听错，计数会偏低 |

### 做法

1. **tier 分开**：人工逐字稿、署名信件、印刷问答 = **P1**；ASR = **P2**。
   两者都算 primary（内容确实来自他），但 P2 在产物里必须可识别。
2. **ingest 时在 `abstract` 里写明 `machine-transcribed (ASR)`**，让下游能查。
3. **引文纪律**：产物里凡是引号内的英文原话，**只许来自 P1**。
   来自 ASR 的内容一律改写成间接引述（「他在 2018 年那次访谈里说银行状况很好」），
   不加引号、不逐字。
4. **`check_quote_integrity.py` 增一条**：引文若命中的源是 ASR 标记的，报错而不是通过。
   （已记入 `_迭代输入_下一轮.md` ㉞。）

### 更一般的一条

**「可核」有两层：这段字在不在语料里，语料本身可不可信。**
我的九件检查器全在第一层。第二层（语料自身的可信度）目前**只能靠 ingest 时把 tier 打对**——
一旦打错，后面没有任何一道门会发现。这与第二十六种（二进制伪文本）是同一个缺口的两种表现。

## 第四十五种：自动分册在最重要的文件上失效，因为最重要的文件包装最厚

Robertson 一轮，我给语料做了机械分册，判据是三条结构特征：
说话人标记数 / urlmap 的 kind 字段 / 第一人称密度。

判据本身合理，对普通材料也работает。**但它把本人物最关键的六份一手文件全判成了「其它报道」**：

| 文件 | 是什么 | 自动判成 | 第一人称/千字 |
|---|---|---|---|
| 2000 清盘信（两份） | **本人物最重要的一手文件** | 其它报道 | 3.9 / 3.8 |
| 1998 Charlie Rose 完整实录 | 一小时访谈逐字稿 | 其它报道 | 8.0 |
| 1999 SEC 备案的署名股东信 | 他签字的正式文件 | 其它报道 | 1.5 |
| 1987 Barron's 印刷问答 | 最早的一手材料 | 其它报道 | 2.9 |
| 2011 NZ Herald 长专访 | 少见的非美媒长访 | 其它报道 | 1.4 |

### 为什么偏偏是这几份

**因为它们外面裹着最多的东西。**

- 清盘信是 substack 转载的，前面有 800 字导言、后面有订阅语与作者的其它项目推广
- SEC 信嵌在备案格式里（表头、签名块、EDGAR 样板）
- Barron's 是扫描件，带页眉页脚与图片说明
- NZ Herald 的长访里记者的叙述占了大半

**第一人称密度 = 他的话 ÷ 全文**。包装越厚，分母越大，密度越低。
而**重要的文件恰恰是被转载最多、被格式化最多、被叙述包裹最多的那些**——
一份随手写的博客不会有人给它加导言，一份改变了一个行业的清盘信会。

**判据与重要性负相关。** 这不是判据没调好，是判据的方向本身错了。

### 修法：显式指派 + 自动兜底

不要指望自动分册能处理高价值文件。正确做法是**两层**：

1. **显式指派层**：把我逐个核过正文形态的关键文件写成白名单，强制归册。
   本轮 7 份，改派后 primary 从 29 篇升到 36 篇（0.19 → 0.667，正好过 0.65 的门）。
2. **自动兜底层**：其余材料交给结构判据。

**并且：显式指派必须留下「我核过什么」的痕迹**——不是「我觉得它是信」，
而是「我读过它的正文形态，它是 X 结构」。

### 一条推论

**每次分册之后，都要专门去看「我认为最重要的那几份」被分到了哪。**
不要只看册的计数分布——计数分布看起来一直很正常（本轮 F 册 136 篇，
多七份少七份完全看不出来）。**要按名字点检，不是按统计点检。**

## 第四十六种：关键词计数把否定句算成一次确认

**发生在**：Julian Robertson #97，写 claims 的时候。

我要回答「他在哪些年份公开预警过泡沫」，于是在 P1 语料里跑
`grep -Eil "bubble|overvalued|frothy"`，得到 **2010–2018 共 7 个年份**，
正准备写成「他连续九年预警泡沫」。逐句核完，7 个里 4 个是假的：

| 源 | 关键词命中处 | 实际是什么 |
|---|---|---|
| 2010 资源页 | "Julian Robertson sees TWO bubbles brewing" | **别人文章的链接标题**，在一个列表里 |
| 2012 CNBC | "the steels are away overvalued" | **单个行业**，不是市场判断 |
| 2012 G&D | "a wildly overvalued company" | **他做空的选股判据**，不是对市场的判断 |
| 2018 marketfolly | "FANG stocks not frothy at all" | **意思正好相反** |

**最后一条是关键：关键词计数把一句否定句算成了一次确认。**

`grep -c` 数的是词，不是命题。而**否定、转述、链接标题、行业个例，
在词频上与本人的断言完全同形**——它们贡献的计数一模一样。

**定则**：凡是「他在 N 个年份／N 次说过 X」这类计数，必须逐条回到句子层核三件事：

1. **主语是不是他**（不是记者、不是链接标题里的第三人）
2. **谓语是不是肯定**（`not frothy at all` 与 `frothy` 在词频上无法区分）
3. **宾语是不是同一个对象**（单个行业 ≠ 整个市场；做空判据 ≠ 市场判断）

三条缺一条就不计数。

**这次的反面收获**：核完的真值（三个年份）反而把一个更重要的结构逼了出来——
他 2017 说泡沫、同年说苹果便宜、2018 说 FANG 不泡沫，
是因为他的泡沫落在**利率与资金流**上而不落在公司估值上。
**错误的数法会把这个结构盖掉，正确的数法把它显出来了。**

## 第四十七种：模板的下限断言与门的口径不同，于是模板全绿而门报红

**发生在**：Julian Robertson #97，跑 `--phase synthesis --strict` 的时候。

生成器打印「mental-model 6（≥6）✓ 生成时断言全过」，门报
**`claim.model-minimum | mental models 2 < 4`**。同一份 claims.jsonl，同一个量，差了 3 倍。

原因在 `quality_check.py:185`：

```python
models = [c for c in active
          if c.get('category') in MODEL_CATEGORIES and c.get('status') == 'pattern']
```

**门数的是 `category ∧ status == 'pattern'`，而模板数的是 `category`。**
我有 6 条 mental-model，其中 4 条被我标成了 `fact`，于是门只认 2 条。

而我标 `fact` 的动机是错的：**我把 `status` 当成了「我的把握有多大」**，
证据硬的就标 fact。实际语义是**命题的种类**：

- `fact` —— 一个具体的、可单点核实的命题
- `pattern` —— 跨多个场合观察到的规律
- `hypothesis` —— soul-hypothesis 类别强制用这个

把握大小写在 `confidence`（0..1）里，那才是它的位置。

**前几位人物没暴露这个缺陷，纯粹因为他们的 mental-model 恰好多数标了 pattern。**

**定则：任何「下限断言」都必须与它要预演的那道门同口径抄写，而不是同名。**
名字相同、口径不同的断言比没有断言更坏——它在门会失败的同一份数据上打印绿色。

已修 `_pipeline/scaffold/claims_template.py`：断言改为
`sum(1 for r in rows if r["category"]=="mental-model" and r["status"]=="pattern")`，
并在报错信息里同时打印 category 计数与提示「门不看这个」。

## 第四十八种：holdout 与 train 是两个 source_id，内容却是同一篇

**发生在**：Julian Robertson #97，读 holdout 出 known 题的时候。

`check_material_split.py` 报「holdout 泄漏 0」，**按它自己的判据这个结论是对的**——
它查的是成员：哪个文件在 train、哪个在 holdout、有没有串目录。

而实际情况是：holdout 里的 `jr_2019_wb_medium_competitive_spirit.txt`
与 train 里的 `jr_2012_gd_issue15_management.txt` **是同一篇访谈**——
Columbia《Graham & Doddsville》2012 年春季号，2019 年被 Medium 转载。
n=8 词的 shingle 覆盖率 **63.0%**。

**文件名年份不同、URL 不同、域名不同、source_id 不同，所以成员级检查一路绿灯。**
（这与第四十二种同源：转载年冒充内容年。那一次它污染的是时间线，这一次污染的是评测。）

用它出的 known 题不测泛化，测的是「同一段文字换个 source_id 我还认不认得」，
**而这类题一定得高分**——于是评测分数虚高，且没有任何门会报警。

**定则：成员对 ≠ 内容不重合。** 抽完 holdout 必须再跑一次**内容级**判重。

已建 `_pipeline/checkers/check_holdout_overlap.py`（硬门）：
对每个 holdout 与每个 train 源算 shingle **覆盖率**（不是 Jaccard——
Jaccard 会被长度差稀释：一份 1.5 万字完全包含在 20 万字里，Jaccard 只有 0.07 而覆盖率是 1.0）。
≥0.30 硬失败，0.10–0.30 人工核。

**这个工具第一版自己也踩了一次坑，见下条。**

## 第四十九种：判重工具把站点样板当成了共享内容

**发生在**：上一条那个新工具的第一次运行。

它对 2009 年那份 holdout 报 37.8% 硬失败，
而且**同时与三份互不相干的 train 源都是 37.8%**。

**「与三份互不相干的文件重合度完全相同」本身就是仪器出错的 signature。**
真的转载只会与一份高度重合。

查出来的交集长这样：

    01 01 18 01 25 01 11 01
    05 11 04 27 05 04 04 20
    jim simons launched the quant revolution recommended reading

全是同一个博客的**月份归档侧栏与推荐阅读栏**。同站抓下来的任意两篇都共享它们。

修法**不靠维护站点黑名单**（黑名单换个站点就失效），两条都是站点无关的：

1. **纯数字 shingle 一律丢弃**——要求 n 元组里至少含 3 个字母词。
   归档侧栏的日期串在任何站点上都会造成同站文件间的高重合，且不携带内容信息。
2. **文档频率过滤**——一个 shingle 若在 `max(3, len(train)//10)` 份以上的 train 源里都出现，
   按定义就是样板。**真转载在 train 里的 df 是 1**（只有被转载的那一份有它）。

加上这两条之后：2009 那份从 37.8% 降到 **0.11%**（噪声全是样板），
而真转载那份**纹丝不动，仍是 63.0%**——判据在正确地区分两者。

**定则：判重之前先问「这段字在语料里出现了多少次」。出现得越普遍，越不是证据。**
这与第三十七种同源（绝对数随词表跳 4 倍而集中度纹丝不动）：
**凡是计数，先问分母里有多少是普遍现象。**

## 第五十种：holdout 证伪了一条 train 断言，此时有两件事必须同时做

**发生在**：Julian Robertson #97，写 known 用例通读 holdout 的时候。

`heuristic/用人判据` 初稿断言：「运动员」这一项**只出现在第三方转述里，他本人的表述中没有**。
而 2009 年那份 holdout 逐字稿里他本人说：
「Oftentimes, people who are excellent athletes of some sort make great fund managers.」
——**第一人称、逐字稿、明确的偏好陈述。断言的后半句是假的。**

关于 train 语料的部分没有错（train 里这一项确实只以转述形式出现）。
**错的是从「train 里没有」推出「他没说过」。**

这正是必读文件里「凡带『从不／唯一／没有一句』的，逐条去语料找反例」那一条，
而**反例天然更可能落在我没读的那部分里——那恰恰就是 holdout**。
换句话说：**缺席断言的反例分布，与我的可见范围是负相关的。**

**处置两条，缺一不可：**

1. **改断言。** 明知为假还留着，比测试不纯严重得多。
   （改法是去掉不可验证的缺席部分，只留可验证的正面内容。）
2. **被证伪的那一点从此不能当考题。** 拿它出 known 题，
   考的是我刚拿它改过的东西——那不是测试，是自我确认。
   本轮的 known 题因此改用同批 holdout 里未触及断言的部分。

**不要因为「会污染测试」就不改断言。零伪造是更高的规则。**

## 第五十一种：自指计数判据第五次误报，这次是部分量词

**发生在**：Julian Robertson #97，跑 `gen_jr_cases.py` 的生成时断言。

报错：`自指计数不符：声明 1，枚举到 2`。触发文本是

> 他能贡献的是很小的**一块**，而且是通用的判人判事那一套：
> **一、这件事交给谁做。** … **二、这件事值不值得做。** …

「一块」是**部分量词**（一块／一套／一部分／一层），不是条数声明。
它满足了现有的全部三条判据：声明在列表之前、40 字内、同句跟冒号。

这是这一族判据的**第五次**误报（前四次见第三十种）。
**继续补量词表仍然是打地鼠**——中文量词几百个，而且「块」在别处确实可以计数。

这次改的是另一个维度：**声明数必须 ≥2 才算数声明。**

理由是语言事实而非经验阈值：**没有人会写「以下一点：一、… 二、…」。**
所以「声明 1 而枚举 ≥2」在中文里**必然**是量词用法，不是计数错误。
这条不用维护量词表，也不动窗口参数。

**定则：判据反复误报时，不要在同一个维度上加例外，换一个维度找必然性。**

## 第五十二种：语义残留检查器缺了整个「祈使禁止」族

**发生在**：Julian Robertson #97，`check_semantic_residue.py` 报 1 处残留。

命中的是 `decision-policy.md` 里的

> ## 第三条：三层分开，**不要**合并成「看空所以退出」

——一句**明令禁止**该说法的话，被报成了该说法的残留。

查 NEG 词表发现：它有完整的**否定断言**族（不是／并非／不算／而不是／并不），
**没有任何祈使禁止族**（不要／不许／不应／禁止／勿／切忌）。

而 `boundaries.md` 与 `decision-policy.md` 的职责恰恰是
**把错误说法原样引出来再禁止它**。**缺这一族，边界文档写得越尽责，误报越多。**

已补进 NEG，并加了第三条负对照专门盯这一族
（残留句是陈述、该抓；订正句是把同一说法引出来加以禁止、该豁免），自测 3/3。

**定则：豁免词表要按「语用功能」分族补，不要按遇到的个例补。**
遇到「不是」就补「不是」，会漏掉整个功能相同而形式不同的族。

## 第五十三种：绝对化断言审计里，两条真错都出在「我没查全」而不是「我说错了」

**发生在**：Julian Robertson #97，逐条核 `check_absence_claims.py` 报的 11 条。

11 条里 9 条成立，**2 条为假**（真错率 18%，与 Maeda 一轮的 15% 接近）：

**其一：**「判据与其失效条件由他在同一年**分别**说出，语料中他未把两者并置讨论」——假。
2012 年 CNBC 那段是**一口气连说三件事**：先给规则（做多最好的 50 家、做空最差的 50 家），
紧接着「unfortunately a lot of times the 50 worst companies outperform the 50 best」，
然后给适用条件。**我只在一处检索了规则、在另一处检索了失效条件，没有在同一份文件里同时检索两者。**

**其二：**「无任何持仓层面的决策记录」——假。
2017 年那份逐字稿里他说「I bought Alibaba at a very low price」，七八年前买入、涨到约一百卖出。

两条的共同结构：**我把「我检索到的范围内没有」写成了「没有」。**
而两次的正确说法都更有信息量——
第一条改完是「他在一个场合连说三件事、在另一个场合只说第一件」（更能刻画人物），
第二条改完是「事后提及个别持仓有，当时的论证没有」（边界画得更准）。

**定则：写缺席断言时，先问自己「我是用什么检索式、在什么范围里确认它缺席的」，
并把这个判据一并写进断言。** 写不出判据的缺席断言，就不要写成缺席断言。

## 第五十四种：rubric 是照着答案倒写的，于是评测测的是召回不是能力

**发生在**：Julian Robertson #97，**两席评委各自独立地指出了同一件事**。

常规打分席的原话是：rubric 多处直接规定了答案的措辞
（「必须照他的原话写」「必须写出 Thorpe McKenzie」「指出 50 对 50 是淘汰判据不是构建方法」），
而 candidate 每次都精确命中同一措辞——
**「这套评测检验的是同一语料库的召回，不是推理质量」**。

不知前情席说得更狠：这些提法**在 prompt 里毫无线索**，却与 candidate 的段落一一对应，
所以 **baseline 不可能通过，不是因为它差，而是因为门槛按 candidate 的形状开的**。

这是第十种（错误写进 rubric）的**升级版**。第十种是 rubric 里写错了一个事实；
这一种是 rubric 的**形状**本身就取自答案——每一条都对，但合起来不构成一次测试。

**为什么难自查**：写 rubric 的人刚写完 candidate，脑子里就是那几个要点。
「必须答对 X」在写的人看来是「这道题的关键」，在读的人看来是「答案的目录」。
**两者在文本上无法区分**，只有从外面看的人能看出来。

**可操作的判别**：写完 rubric 后逐条问——
**「这一条，一个只读到 prompt 的人有没有可能想到？」**
想不到的，要么把线索补进 prompt，要么这一条就不该出现在 rubric 里。

**这一条本轮未修完**，记为本产物的已知局限：
它的候选分数含构造性成分，跨人物比较时应打折看。

## 第五十五种：冻结只算了指纹，没留快照，于是「只重判改动过的用例」无法举证

**发生在**：Julian Robertson #97，评委指出真错、订正之后。

重判纪律是：**只能重判该轮实际改动过的用例**——
否则我可以把不满意的条目说成「改过了」再判一次，那就是变相挑评委。

而这条纪律要能执行，前提是**「哪几条改了」是可核的事实**。
我在冻结时只做了 `sha256(payload)[:16]`，**指纹只能证明「变了」，不能证明「哪几条变了」**。
订正之后想按 diff 举证，才发现没有可比的旧版本。

结果：只能**全量重判 32 条**，多花约 11 万 token，
把本人物的评委开销从约 11 万推到约 22 万，**超出 ≤19 万/人的目标 16%**。

**修法**：冻结那一步除了算指纹，**必须把 payload 复制一份留档**
（`judge_payload_<xx>.v1.json`），下一轮用 `json.dumps(..., sort_keys=True)` 逐条比对，
**由 diff 判定改动集合，不由我判定**。已写进 `scaffold/README.md` 的第 5 步。

**定则：凡是「只对变化的部分做某事」的纪律，都必须同时留下能算出变化集合的证据。**
纪律本身不产生证据；不留证据的纪律等于没有纪律。

## 第五十六种：转载页的编者导语被当成了原文，而两处转载的 diff 一秒就能查出来

**发生在**：Julian Robertson #97，第二轮两席评委**各自独立**算出同一个不对劲。

我在产物里写「31.7% 是扣费后对合伙人的复合回报，**信里并给了同期标普 500 的 12.7% 作对照**」。
两席都指出这个对照不成立：12.7% 约等于该窗口标普的**价格**收益率（不含股息），
而 31.7% 是**扣费后的总回报**——一边不含息、一边已扣费，不可比。

回原文一查，问题比「口径不可比」严重：**这句话根本不在信里。**
它出自 substack 转载页顶部 Kevin Gee 写的编者导语。

**检出方法极其简单，而我一开始没做**：这封信我灌了**两处转载**
（`aletteraday` 与 `valuewalk`）。valuewalk 那份没有编者导语，
**12.7% 在里面一次都不出现**。两份一 diff，边界立刻清楚。

信里他自己给的比较是**倍数不是年化**：85 倍
「more than three times the average of the S&P 500 and five-and-a half times that of
the Morgan Stanley Capital International World Index」。

**这是第四十三种（引语张冠李戴）的一个变体，而且更隐蔽**：
第四十三种是文章里另一个受访者说的话；这一种是**承载文本的那个页面自己写的话**。
它没有说话人标记可核，因为它根本不在对话里——它是包装的一部分。

**定则：同一份一手件若有多处转载，一律 diff 一遍；只出现在其中一处的内容是包装，不是原文。**
反过来说，**只灌一处转载的一手件，无法把包装与原文分开**——
这给「同一封信灌两份」提供了一个先前没想到的理由：
它看起来像重复，实际是**一份自带的对照组**。

## 第五十七种：我给自己立的限定，只在被指出的那几处执行了

**发生在**：Julian Robertson #97，第二轮复评。

第一轮评委指出我把「诚实、正直、聪明、好胜」这种**一句话里的并列**
当成了「第一判据 / 第二道筛」的执行顺序。我改了三处，
并在每处写上「**这是一句话里的列举，他没说过要按这个次序筛**」。

第二轮不知前情席的原话是：这是全篇最好的一处自律，
**但同一份产物的另外两处，同样的并列仍然被当成执行顺序**
（「问两个问题，顺序固定……先问规模再问胜算」「第一判据是正派诚实，然后才是聪明和好胜」）。

**我修的是被点名的那几处，不是那个病。** 这正是第二十二种
（修法只落在被抓到的那一处）在**自我限定**上的复现——
而且更难自查：因为我确实写下了那条限定，**看到它就以为自己守住了**。

**定则：每加一条新的自我限定，必须立刻拿它当检索式全文扫一遍，**
**把所有本该受它约束的地方一次改完。** 限定写在纸上不产生约束力，
**扫描才产生约束力。**

具体到本例，扫描式是：把该限定要禁止的那种表述（「第一判据」「顺序是」「先……再……」）
当成 pattern 去 grep 整个产物，而不是凭印象回想「我还在哪儿这么写过」。

## 第五十八种：整份载荷一个指纹，在只重判部分用例时既不能证明有效也不能证明失效

**发生在**：Julian Robertson #97，第三、四轮部分重判。

原来的做法是 `sha256(整份 payload)[:16]`，一次评审绑一个指纹，
用来拒收「评的是别的版本」的分数。**这在全量评审时够用，在部分重判时失效**：

- 只要改了一条用例，整份指纹就变，于是**另外 31 条没改的分数也被判为过期**——
  逼着我全量重判（第五十五种的代价）；
- 反过来，如果我为了省事沿用旧指纹，那**改过的那条也会被当成有效**——
  这正是指纹要防的事。

**整份指纹只能回答「变没变」，回答不了「哪条变了、哪条的分还能用」。**

改成**每条用例各自哈希**：`sha256({case_id, prompt, rubric, candidate, baseline})`。
每一轮评委分数记下它所评那一版的 case_hash，拼装时逐条比对，对不上的**单条拒收**。

效果是立刻可见的：本人物第四轮拼装时报
「按哈希拒收的过期分数 42 条」，并精确列出**恰好那 9 条**需要重判的用例——
与我用 diff 算出来的改动集合完全一致，**两个独立方法互相印证**。

**定则：校验的粒度要与操作的粒度一致。**
操作是「按用例重判」，校验就必须「按用例绑定」；
用一个粗一级的校验去管一个细一级的操作，得到的既不是安全也不是效率。

## 第五十九种：四轮评审才收敛，因为前三轮我每次都只修被点名的那几处

**发生在**：Julian Robertson #97 全程。评委开销约 34 万 token，
**超出 ≤19 万/人的目标 79%**。这个超支不是评审太严，是我的修法效率太低。

四轮各自发现的问题在**性质上是同一族**：

| 轮次 | 评委指出 | 我改了 |
|---|---|---|
| 1 | 把「诚实、正直、聪明、好胜」的列举当执行顺序 | **被点名的 3 处** |
| 2 | 「同样的并列，另外两处仍当执行顺序」 | 被点名的 2 处 + **这次全文扫了一遍**，又找出 5 处 |
| 3 | 「plan-2 正文改了、小标题没改」 | 1 处 |
| 4 | 「两个事例，一处克制、两处当通则」 | 全文统一强度口径 |

**第二轮我做了全文扫描，那一轮之后同类问题就基本绝迹了。**
前后对比很清楚：**扫描一次的收益 > 被点名三次的收益**。

而第三轮那个残留尤其说明问题——我改了正文里的句子，
**小标题里的「顺序固定」四个字没跟着改**，同一段自相矛盾。
扫描式当时只扫了正文措辞，没把标题一起扫。

**两条定则：**

1. **收到一条批评，先把它抽象成一个可检索的 pattern，再全产物扫一遍**，
   然后才动手改。**先扫后改，不是先改后扫。**
2. **扫描范围要含标题、表头、rubric 与生成器源码**，不只是正文段落——
   同一个说法在这四处的措辞往往不同，而读者看到的是它们的并集。

**关于收敛**：修订轮次只应用于**限定与出处**（把话说准），
不应引入新主张——引入新主张就等于开一轮新的评审。
本人物第四轮的改动全部是加限定、给年份、统一强度口径，没有新增任何断言，
**这是能收敛的必要条件**。

## 第六十种：断言改了，渲染它的文档段落没跟着改，而官方门只查锚点存在不查内容一致

**发生在**：Julian Robertson #97，发布前最后一次自查。

`contradiction/他给自己的判据加了否定注脚` 这条断言，我在中途按原文订正过——
从「他在两个场合**分别**说出规则与失效条件，从未并置讨论」
改成「他在 2012 年 CNBC **一口气把规则、失效、适用条件三件事连说**」。

`claims.jsonl` 改对了。**而 `divergence-map.md` 里渲染这条断言的那一整节，还是旧文本**：
「判据与判据失效的条件由他本人在同一年分别说出，而语料中他从未把两者并置讨论。」

**断言与渲染它的段落直接互相矛盾，而所有的门都是绿的**：
- 官方门查 `claim.orphan` / 幽灵锚点 —— 锚点在，计数对，通过
- `check_claim_anchors.py` 报了「重合 0」，但它是**只列不判**的，
  而且它的告警在中英混排的产物里天然很多，容易被当噪声划掉

**根因**：生成器里 claim 正文与文档正文是**两处独立的字面量**，
改一处不会带动另一处。这与第十六种（一个错误以不同措辞复制多份）同源，
但更隐蔽——**这里两份文本不是「措辞不同的同一个说法」，而是「互相否定的两个说法」。**

**检出方法（已落地为一次性脚本，值得做成常规）**：
对每个锚点，算**断言正文与锚点之后 1400 字**的**中文字符三元组覆盖率**。
本产物 43 处锚点的覆盖率中位数是 53.6%，而这一处是 **1.1%**——排在最低第三位。

**一个反面教训**：这个检查我写了两版。
**第一版只认英文引文片段与英文专有名词**，结果中文正文渲染中文断言的地方全部误报
（例如断言里的标记是 `New Zealand`，而正文写的是「新西兰」）。
**判据用错了语言，就会把正常的当异常、把异常的埋进噪声里。**
换成中文三元组覆盖率之后，误报归零，真问题浮到最低分。

**定则：凡是「同一件事在两个文件里各写一份」的结构，都要有一个跨文件的一致性判据。**
只查「引用关系存在」不查「内容一致」的门，挡不住这一类。

### 附：本轮「判据选错维度」出现了三次，值得并读

同一个毛病换了三张皮，每次都表现为「工具报的东西全是噪声，而真问题藏在噪声里」：

| 场合 | 我用的维度 | 该用的维度 |
|---|---|---|
| 数「他哪些年预警泡沫」（第四十六种） | **词频**（bubble 出现没有） | **命题**（主语是不是他、谓语是不是肯定） |
| 锚点共指（本条） | **语言**（英文标记） | **字符 n 元组**（中英都覆盖） |
| 引文核查（本轮收尾） | **拉丁字符占比** | **有没有汉字** |

第三个最能说明问题：我先用「含 ≥4 个连续拉丁字母」判英文引文，
把「Tiger 由他与 Thorpe McKenzie 共同创立」这句中文误判成未命中的英文引文；
改成「拉丁字符占比 ≥60%」**仍然误判**——专名把一个短中文句撑到了 73%。
真正干净的判据是**引号内有没有汉字**：一段逐字英文引文里不会出现汉字。

**我连调两次阈值都没修好，因为问题不在阈值在维度。**
（与第三十种同构：连补四次词表没修好判据，因为问题在句法不在词形。）

**定则：一个判据连续误报两次以上，停止调参数，换一个维度重新提问。**

## 第六十一种：一篇讲「口径要分清」的产物，自己漏算了它引用的第一组数

**发生在**：Julian Robertson #97 收尾阶段，**两席评委各自独立算出来的**。

我补了一条 fact 用例，主题正是「清盘信里四个数字量的不是同一件事，混着看会得出假矛盾」。
它把规模、回报率、累计倍数分得很细，把 31.7% 与 85 倍的表面矛盾解释成两个时点，
算术全对。**而它引用的第一组数，我一次都没算过。**

原文是「the 8.8 million had grown to 21 billion, and increase of over 259,000%」。
210 亿 ÷ 880 万 = **2,386 倍 = +238,536%**，不是 259,000%。
要凑出 259,000%，终值得是约 **228 亿**。**缺口 8.6%，就在同一句话里。**

**为什么我会漏**：那半句是**引文**，而我对引文的检查是「在不在语料里」——
它在，所以过了。**引文完整性检查回答的是「他说没说过」，回答不了「他说的对不对」。**
而我又因为它是引文，默认它内部自洽。

**这个漏洞恰好长在最不该长的地方**：整条用例的立论就是算术卫生。
**一篇教人分清口径的产物，在自己引的第一组数上没做除法。**

**修法不是抹平，是把缺口写进产物。** 语料里第三方把 Tiger 峰值规模写成
200 亿到 230 亿都有——**这个差额落在各方报数的分歧区间之内，判不了哪个对**。
所以产物给的使用建议是：引规模时说「880 万到 210 亿」，引百分比时说「over 259,000%」，
**两者不得拼成一句因果**——「880 万到 210 亿，增长 259,000%」这句话在算术上不成立。

**定则：凡是引文里带数字关系的，除了核「这句话在不在语料里」，还要核「这句话自己算不算得通」。**
一手件的作者也会算错、也会取整、也会把两个时点的数写进同一句。
**引文核查与算术核查是两件事，前者过了不代表后者做过。**

（与第四种同源：一手源不等于事实正确。那一次是内容错，这一次是**他的数与他的数之间**错。）

## 第六十二种：我在多轮里不断给严格席加检查项，于是「尺子」在评审过程中变了

**发生在**：Julian Robertson #97，收尾时对比历史数据才发现。

Maeda #96 与 Robertson #97 用的是**同样两席**（`D-score` 常规 / `E-strict` 不知前情），
同样的模型，同样的「默认怀疑、找到证据才给高分」基调。而严格席的评分分布是这样的：

| 严格席给候选的分 | Maeda #96 | Robertson #97 |
|---|---|---|
| ≥0.95 | **23 / 32** | **0 / 33** |
| 0.90–0.94 | 7 | 13 |
| 0.85–0.89 | 1 | 16 |
| <0.85 | 1 | 4 |
| **均值** | **0.9484** | **0.8812** |

**分布形状完全不重叠。** 一个产物拿到 23 个 0.95+，另一个一个都没有。
**产物质量的差异不可能有这么大**——差的是尺子。

**我做了什么**：Robertson 这轮评了十三轮，而我**每一轮都往严格席的「特别盯」清单里加东西**：
算术自己重算一遍 → 绝对语有没有挂范围 → 承重证据有没有出处 →
把并列读成顺序算不算过度解读 → 证据分层做没做 → rubric 是不是照答案倒写……

每加一条，它就多一个能扣分的维度。**到第十三轮时，它量的已经不是第一轮那把尺子了。**

**两个后果，第二个更严重：**

1. **本人物的分数被我自己压低了**，与历史人物不可比。
   Robertson 的 fact-preservation 0.915 未过 0.93，而 Maeda 的同一套门是 0.9775。
2. **反过来说，已发布的 96 人是用更粗的尺子量的。**
   Maeda 那轮严格席没有被要求重算算术、没有被要求查证据分层、
   没有被要求判断 rubric 是不是照答案倒写——**这些检查本轮每一项都抓到了真问题。**

**定则一：评委指令在一个人物的全部轮次中必须冻结，与载荷一同版本化。**
要加检查项，加在**下一个人物**，不要加在正在评的这一个——
否则「这一轮比上一轮差」分不清是产物退步还是尺子变细。

**定则二：尺子变细之后，历史分数不再可比，必须显式声明。**
不能把新尺子量出的 0.915 与旧尺子量出的 0.9775 放在同一张表里比较。

**这一条本产物没有能力自行处置**：要不要用新尺子回头重量已发布的 96 人，
是范围与成本的决定，属于必须停下来问的那一类（必读文件底线四）。

## 第六十三种：抓源子代理按刊物整本抓，把别人的文章冠上了人物前缀，`--author` 参数替它完成了洗白

**发生在**：Michael Steinhardt #98，灌库前的人工定级。

他基金会的季刊 CONTACT，每期 16 页、十来位作者，他在其中占一篇署名专栏。
抓源子代理把整期 PDF 切片后落盘，文件名一律是 `ms_<年>_contact_essay_<题>.txt`。
**十份切片里只有一份带他的署名。**逐份核到文末：

| 文件 | 文末实际署名 |
|---|---|
| `ms_2009_contact_essay_the_landscape_ahead.txt` | **Lynn Schusterman** is Chair of the Charles and Lynn Schusterman Family Foundation |
| `ms_2008_contact_essay_on_leadership_vision_and_ideas.txt` | **Adam Bronfman** is Managing Director of The Samuel Bronfman Foundation |
| `ms_2008_contact_essay_whats_next.txt` | **Simon Greer** is the President and CEO of… |
| `ms_2003_contact_essay_if_not_now_when.txt` | HUC-JIR 的人（"the religious mandate … that inform the mission of HUC-JIR"） |

**最危险的是 2009 那份的开头**：

> When I was a child, one of the first lessons my father taught me was that
> charity is the rent we pay for our lives on this planet.

这句话我**必然**会写成他与其父 Sol 的家世——Sol 是个有前科的赌徒，
「父亲教我慈善」的反差正是产物最爱写的那种句子。
**那是 Lynn Schusterman 的父亲。**

**为什么现有的门一个都拦不住：**

- `quality_check.py` 不读原文，只查计数与锚点；
- `check_verbatim_quotes.py` 会说「这句在语料里」——**它确实在，只是不是他说的**；
- `check_holdout_overlap.py` 查的是重复，不是归属；
- 而 `ingest.py` 那一行带着 `--author "Michael Steinhardt"`，
  **文件名前缀 + author 参数，两步就把别人的文章变成了他的话。**

**定则：一份语料要当「他的话」用，必须有正面归属证据，而且证据要随文件落盘。**
「没查到反证」不算证据。已建 `check_authorship.py` 为硬门，三种可接受证据：
`A-byline`（结构位置上的署名）/ `A-editorial`（编者注）/
`A-turns`（≥2 个说话人标签各 ≥3 轮且后文各不相同）。

**推论：切片脚本不得把署名当作切片的起点标记而丢弃它。**
上一版切片器正是从 `m.end()` 开始切，**署名本身被吃掉**，
于是落盘文件里查不到任何归属证据——门想复核都没得复核。

## 第六十四种：版面 PDF 的文本流里标题与署名排在正文之后，于是「从署名往后切」必然切到下一篇

**发生在**：同上，是第六十三种的机制层原因。

CONTACT 2009 春季刊第 3 页，`pypdf` 抽出来的文本流顺序是：

```
SPRING 2009 3  Speculation about our economic future often leads to…   ← 正文，整页
… but we Jews are no strangers to long odds. ■
Michael H. Steinhardt is Chairman of The Steinhardt Foundation for Jewish Life.  ← 他的文末身份行
THELandscape AHEAD  by MICHAEL H. STEINHARDT                            ← 标题＋署名，排在最末
```

**版面上标题在页首，内容流里却最后吐出来。**
上一版切片器读到署名后向**后**切 12000 字——那已经是下一篇了。

**定则一：处理版面型 PDF 时按页切，不要在跨页拼接的扁平文本上找边界。**
页是抽取器唯一保证的边界，段落顺序不是。

**定则二：作者的文末身份行（`<名> is Chairman of…`）就是「这篇到此为止」。**
本页出现了他的身份行，就不要再把下一页当续页接上来。
2013 夏季刊第 4 页与第 3 页同主题同人称，归属两可——**不确定时不接**：
误接的代价是把别人的话记成他的，不接的代价只是短一点，
而 deep 门要的是**源数**不是字数。

**定则三：刊物型 PDF 的作者标识是文末身份行，不是「行尾 by 某某」。**
上一版的停止判据只认后者，所以一路吞过整篇邻文。

## 第六十五种：第一人称密度分不清那个「我」是谁

**发生在**：同上，自动分层判据的主判据失效。

我用「第一人称密度 ≥0.020 判为一手件」给 57 篇分层，判出 23 份 P1。
逐份核完，其中这些的「我」根本不是他：

- `ms_2019_jta_sheila_katz_first_person_account.txt` —— 那个「我」是 **Sheila Katz**，
  一位具名指控者的自述（"Michael Steinhardt sexually harassed me"）。
  **这是最危险的一份**：它第一人称密度高、主题全程围绕他、
  而内容是对他的指控——判成 P1 就等于把指控当成他的自陈。
- `ms_xxxx_ejp_practitioner_response_to_his_remarks.txt` —— 「我」是 Rabbi Micah Lapidus。
- `ms_2022_cjn_jewish_pride_reviewed.txt` —— 「我」是书评作者 Phoebe Maltz Bovy
  （"I am not a billionaire"）。

**根因**：第一人称密度量的是「这篇文章有没有一个说话的『我』」，
**它不含任何关于那个「我」是谁的信息**。而人物语料库里最常见的两类文件
——受害者/当事人自述、他人对他的回应——恰恰都是高密度第一人称。

**定则：第一人称密度只能用作「不是新闻体」的负向排除，不能用作归属的正向证据。**
正向证据只有第六十三种列的那三种。

## 第六十六种：`^名字:` 不是说话人标记，而真的说话人标记可能与正文隔着空行

两个方向的错，同一个判据。

**假阳性**：`^\s*(STEINHARDT|MICHAEL STEINHARDT|MS)\s*[:：]` 判「人工逐字稿」，
实际命中的全是**标题里的冒号**：

```
Michael Steinhardt: Background & bio                      ← 资源页的小标题
Michael Steinhardt: The King of Block Trading             ← 第三方案例库的文章标题
Michael Steinhardt: Markets will continue to rise         ← 同一标题在 og:title/h1/面包屑里重复三次
```

五份被判成「人工逐字稿」的文件里**没有一份是逐字稿**。
另外 `MS` 这个候选项配 `re.I` 尤其危险，它会命中任何以 `Ms:` 开头的行。

**定则**：真逐字稿的判据是**对话结构**，不是单个标记——
要求 ≥2 个说话人标签、各出现 ≥3 次、**且同一标签后面跟的文字每次都不同**。
标题在导航/`og:title`/`h1` 里重复出现时后文是**同一句**，这条就把它挡住了。

**假阴性**（同一天，反方向）：判据要求冒号后同行有正文，而

```
Michael Steinhardt:
                          ← 空行
Thank you, sir.
```

是 Charlie Rose 与 Knowledge@Wharton 逐字稿的实际格式。
**67 轮的真逐字稿被判成 0 轮。**先放宽到「允许一个换行」仍是 0 轮——
中间隔的是**空行**，得允许跨最多 3 个换行。

还有一处：`Knowledge at Wharton:` 里的 `at` 是小写，
「标签每个词首字母大写」会把这个主持人标签整条丢掉，
于是只剩 `Steinhardt` 一个标签，「≥2 个说话人」的判据就假阴性了。

**定则：一个判据改完要拿已知的正例和已知的反例各跑一遍。**
本轮三次都是只跑了一边。

## 第六十七种：散文里的「by X」不是署名

`\bBy\s+Michael\s+Steinhardt\b` 命中了这一句：

> No Bull is the eventful, honest and clear autobiography **by Michael Steinhardt**
> who rose from 'rags' in Brooklyn to the height of Wall Street

这是一篇**书评**，真作者署名 `6 · Roy Sebag` 在上一行。
句子里的「by」在**谈论**作者身份，不是在署名。

**定则：真署名是结构元素**——它在行首，或跟在分隔符（`*` `|` `·` `—`）后面。
句子中间的「by X」一律送人工复核，不自动放行。
再加一条廉价的反向判据：名字后面紧跟 `who / which / that` 的，是描述不是署名。

## 第六十八种：正则里「含空格的字符类」紧跟 `[ \t]*`，在十几万字的文档上灾难性回溯

```python
TURN = re.compile(r"^[ \t]*([A-Z][A-Za-z.'\- ]{1,28}?)[ \t]*[:：]", re.M)
#                            ↑ 字符类里含空格        ↑ 又是空白量词
```

字符类和后面的 `[ \t]*` **可以互相吞同一个空格**，回溯路径随长度爆炸。
在 196KB 的检方文书上直接卡死（我等了 120 秒才发现是这里）。

**定则：不要让相邻的两个量词能匹配同一个字符。**
名字这类「词 + 空格 + 词」写成 `词(?: 词){0,3}` 的无歧义形式，
不要写成「含空格的字符类 + 惰性量词」。改完后全库 101 份的检查时间从「卡死」变成 **0.16 秒**。

## 第七十种：门测的是**代理量**，而代理量可以在属性不成立时被满足

**实例（2026-07-29，用户点名后查出）**：`build_release_bundle.py` 里有一行

```python
if (source / "VERSION").read_text().strip() != VERSION:
    raise SystemExit(f"version mismatch: {source}")
```

意图是**「人物蒸馏升到 v0.0.0.8 了，专家团队里就不该有 v0.0.0.6/7 蒸出来的人」**。
意图完全正确。但这条判据测的不是那件事：

| | 想保证的属性 | 实际测的代理量 |
|---|---|---|
| 粒度 | **每个人**由哪个版本产出 | 整个 group 包的**一个数字** |
| 可伪 | 要成立必须真的重蒸 | **改一个文本文件就能满足** |
| 时机 | 入库时就该管 | **打包发行时才触发** |

第三条造成的实际后果最大：97 份 `registration.json` 里当时**没有任何字段**
记录产出版本，于是「专家是不是用对版本蒸的」这件事根本无从回答；
而这条判据一失衡就直接让**发行物构建不出来**——自 v0.0.0.9 起一次也没成功过，
且没人发现，因为它的 2 个失败用例一直藏在另外 3 个校验和失败后面。

**识别方法**：问一句「我能不能在**不做那件事**的前提下让这个门变绿？」
能，它就是代理量。把 group 的 `VERSION` 从 8 改成 14 是一次文本编辑，
一个人也没重蒸，门当场变绿，**而门变绿本身就成了那句假话的证据**。

**修法不是删掉门，是把粒度降到属性本身所在的粒度**：
每个人一条 `distilled_with`（打包时由 distiller 盖进交付 manifest，随产物走），
门改为比对**每个人**与一条兼容下限。

**附带的一条**：同一条相等判据在 `templates/bundle/install.py` 里还有**第二份拷贝**。
只改被抓到的那一处，全量测试立刻在另一处红——这是第二十二种的又一次复发。

## 第六十九种：说话人标签用的是**缩写**，而缩写取决于他惯用的名字形态，不取决于账本写了几段

**发生在**：v0.0.0.10 把 `check_authorship.py` 按人物名参数化时，**双向回归当场抓到**。

一份 44 轮的真逐字稿（The Media Line 2022）被判成「查无归属证据」。诊断：

```
标签(≥3轮): {'tml': 46, 'ms': 44, 'sb': 20}
旧 MINE 命中: ['ms']        ← 旧代码硬编码 ^ms$
新 MINE 命中: []            ← 按三段名 Michael H. Steinhardt 算出 mhs
```

**账本里的名字是三段的，而他在逐字稿里被标成两段的缩写。**
逐字稿的标签是**编辑排版时选的**，跟账本怎么写他的全名没有关系。

**→ 定则**：从人物名派生缩写标签时，**名姓首字母与全首字母两种都要生成**。
更一般地：**凡是从「账本里的写法」派生「语料里会出现的写法」，都要问一句
「语料的作者凭什么按我账本的形态写」**——他不知道我的账本。

**已落成断言**：`check_authorship.py --self-test` 第 4 条正例（`TML:`／`JP:` 缩写标签逐字稿）。
不是散文，改坏了会当场红。

**这条同时是「判据变更必须双向回归」的最好例证**：
本次真正想验的是负例（洗白的源被拦住），若只跑那一边就交付，
这份真逐字稿会被**永久误杀且不报错**——它只会安静地从 P1 掉出去，
表现为「一手比例莫名偏低」，而那是个几乎不可能被追查到根因的症状。

## ★ 题面前提：**只能是散文，且下面写清为什么**

（Pasteur #106 撞出，代价是三轮判分与一个人物的拒发。）

`fact-preservation` 三轮 0.885 → 0.8775 → 0.8725，始终上不去 0.93，人物因此拒发。
席 D 两轮都指出根因**不在答案，在题面**：

| 题 | 题面写的 | 语料里是什么 |
|---|---|---|

**套组只有两道题，一道题面写歪就直接压住整组均分；而题面按人物冻结、中途不改——
错的刻度会一直错到这个人物结束。**

### 为什么这一条落不成判据（我试过了）

我写过 `check_case_premises.py`：题面里的四位数年份必须能在语料里找到。
**它自检全绿——四条夹具、一条反向对照全过——然后对真实数据 0 命中：**

- `lp-voice-01` 的「1881 年 12 月」：**1881 本身在语料里**（CR 卷次遍地是），放行；
  错的是「1881 年 12 月」这个组合，而判定它需要读懂 `dernier` 指前一年。
- `lp-fact-preservation-01` 的「成功率」：**根本不是年份**，判据够不着。

**一个自检全绿、真实数据 0 命中的判据比没有更糟**——它制造「题面已核」的假象。
已删除，不留半成品。

### 因此这一条是纪律，不是判据

**出题时，题面里的每一个数与每一个口径，都要像写断言一样回语料核一遍。**

- **数**：年份、月份、次数、卷次——写进题面之前先 grep。
- **口径**：题面用的那个词，是不是语料用的那个词？
  「成功率」与「担保率」、「死亡数」与「未担保数」、「发表」与「宣读」——
  **换一个词就是换一个命题，而答者只能在你给的那个命题上答。**
- **题面不得泄露答案形状**（席 D 在 Jenner 那轮点过 `boundary-01` 直接点名 Baron）。

> **判据能查「这串字在不在语料里」，查不出「这个词是不是那个意思」。**
> 后者到今天为止只有一个办法：回去读原文。

### ② 报了 A/B 侧的长度差，那不是该看的数

候选被 `sha256 % 2` 均分到两侧，**A/B 均长必然接近**——分配方式的产物，
不是「两个系统长度对等」。Lister 三轮：A/B 差 5.5%/0.8%/8.7%，
而**候选比基线长 73%/109%/144%**，逐题 delta 与长度比相关 r 从 +0.193 升到 +0.391，
**64 题里候选没有一道不比基线长**。

席 D 第 3 轮：「**长的一侧在 32/32 全部命中同一个系统**——长度是完美泄题信号。」

母版必报候选/基线均长比，超 30% 打显著警告。

### 还没解决的（写在这里，免得下一个人以为已经解决）

  那会改变对照定义、影响已入库的一百多人，**属用户决定**。
