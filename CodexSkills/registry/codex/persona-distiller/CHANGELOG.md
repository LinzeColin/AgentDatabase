# Changelog

## v0.0.0.22 — 拒答溢出落成判据（2026-08-02）

**三次独立盲判指向同一处，而三次都停在散文态。**

| 场合 | 评委原话 |
|---|---|
| Livermore 双臂盲判 | 「**拿边界当答案**……**这些不是诚实的边界，是把能答的部分一并弃掉**」 |
| 三臂盲判 · 席 A | 「**用单一框架碾过题面**」 |
| 三臂盲判 · 席 B | 「**拒答溢出**」——「用户问的可答部分被一起推掉，**是净损失**」 |

实测代价：单人物臂 **−0.1044**（两次独立复现）。**本项目已测得的最大单项负收益。**

RUNBOOK 那条「每条发现二选一：落成判据，或显式写明只能是散文」，
**在这一条上被违反了三次**——它每次都被当成风格批评记下，从没被当成缺陷修过。

### 判据

一段答案同时满足即判溢出：**① 有拒答标记；② 可执行判断数为 0。**

用「且」不用「或」：只有拒答标记可能是正确的拒答；只有零判断可能是纯事实题。
**两者同时出现，才是「我不答，而且我什么也没留下」。**

### 实测：门刚立起来就在**已发布产物**里抓到 6 处

```
$ python3 scripts/check_refusal_overflow.py --self-test
负对照通过：3 条正对照未误杀（拒答+给路、纯陈述、拒答+指路），
2 类溢出全部抓出，带限定的正常回答未被误判

$ python3 scripts/check_refusal_overflow.py <Livermore 已发布载荷>
✗ 拒答溢出 6 处：jl-boundary-01 / jl-trajectory-01 / jl-fact-02 /
                 jl-tool-02 / jl-cal-01 / jl-refuse-02
```

**这 6 条全部通过了当时的所有门并已随 #100 发布。**

### 为什么只报不拦

判据数的是**句式**：`你应当`／`不要`／编号步骤会被计为可执行判断，
而**用陈述句给出的判断（「这题的关键在 X」）会被漏掉**。
以一个已知有假阴性的判据硬拦发布会误杀正当答案，**而误杀会让人把这个门关掉**。

**也不放 warnings**——`--strict` 下任何 warning 都会让门失败（v0.0.0.8 的教训）。
放 metrics：**让数字大到无法忽略，但不替执行者做发布决定。**

### 实测

```
$ python3 scripts/check_checkers.py scripts/ --json
{'OK': 9, 'NO-SELFTEST': 4, 'NOT-STANDALONE': 1}   ← 新检查器 = OK
$ python3 -m pytest -q          → 70 passed
$ python3 scripts/check_contract_drift.py → ✓ 无合同漂移
```

### 已知缺口

1. **数句式不数语义**，陈述句判断会被漏掉——这也是它不能当硬门的原因。
2. **只扫 `judge_payload`**，不扫十份交付文档。文档层的拒答溢出目前无人查。
3. **不判「拒答对不对」**——正确的拒答与错误的拒答在本判据下等价。

## v0.0.0.20 — 产品本身第一次有了负对照的判据（2026-08-02）

**动因：用户评分。**

> 如果所有人物都由同一个基础模型、同一个上下文和相似资料生成，它们主要提供的是
> **「结构化视角差异」，不是 97 份真正独立的认知与判断**……没有提供
> **「专家团队相对裸模型，在真实盲测任务上提高多少正确率」的公开结果**。
> 真正独立性 **40%**，已证实的决策增益**不足 40%**，实际**接近 0 分甚至负收益**。

### 一句话诊断

**本 skill 给每一件检查器都做了负对照，唯独没有给产品本身做过。**

RUNBOOK 第十八种（「没有负对照的检查器，其全绿不构成任何证据」）
被执行了三十多个版本——**从未对整个 600 人工程执行**。
「团队比裸模型强多少」就是这个工程的负对照，它一次也没跑过。

### ★ 最硬的证据来自本项目自己的评委，而它被记下后没有被执行

Livermore #100 第 2 轮，E 席原话：

> 17 条 baseline 全是零对冲零出处的稻草人，
> **候选/对照的分差被显著放大，不能当作能力证据。**

这句话被抄进了提交信息，然后 `delta 0.8012` 继续被当成绩报。
**`delta` 量的是「我写的产物 vs 我写的稻草人」**，在能力问题上等于零信息。
**已入库 100 人的全部 delta 都是这个性质。**

### 判据：`check_baseline_provenance.py`

`results.jsonl` 里每条 `system == "baseline"` 必须带 `baseline_source`：

| 值 | 能否作能力证据 |
|---|---|
| `bare-model-run`（裸模型对同一 prompt 的实答） | **能** |
| `prior-version`（本人物上一版产物） | 能（只证明「比上一版强」） |
| `self-authored-strawman` | **不能** |
| `unknown` / 缺字段 | **不能** |

**缺字段按 `unknown` 处理**——「没标」与「标了不能用」在证据上是同一件事，
不许因为省略而获得沉默的通过。**一条不可用，整份就不算能力证据**，混着算等于没算。

### 实测

```
$ python3 scripts/check_baseline_provenance.py --self-test
负对照通过：正对照 0 报，坏样本 4 类全部抓出（含「缺字段沉默通过」），
且 prior-version 未被误杀

$ python3 scripts/check_baseline_provenance.py <livermore>    # 已入库的真实产物
{"baseline_rows": 64, "by_source": {"unknown": 64},
 "usable_rows": 0, "unusable_rows": 64, "capability_evidence": false}
✗ 64/64 条基线不可作能力证据——**此产物的 delta 不得用于支持「比裸模型强」这类结论**

$ python3 -m pytest -q
69 passed in 52.41s                      ← 67 → 69
```

### ⚠ 该门在 `--strict` 下会让发布失败——**这是有意的**

`passed = not errors and not (strict and warnings)`，所以带自撰基线的产物
在 `--strict` 下过不了。**唯一的解法是拿真实的裸模型基线来跑**，
而不是给它开豁免。既有 100 人不追溯（发布时该门尚不存在），
但他们的 delta 一律不得再作能力证据引用。

### 这只是四项里的第一项

| # | 事 | 状态 |
|---|---|---|
| **1** | **真基线**（本版） | **判据已落成**；Livermore 的裸模型基线正在跑 |
| 2 | 三臂盲测决策增益（裸模型／单人物／团队） | **未做** |
| 3 | 伪共识检测（k 人物一致率 vs 同模型采样 k 次） | **未做** |
| 4 | 有效激活率（挂到被路由人物 `claim_id` 的实质行占比） | **未做** |

**在第 2 项有结果之前，不得把「专家团队」描述为比裸模型强。**
现有全部材料只支持一句：**过程约束是可核的**——这与「结论更对」无关。

### 已知缺口

1. **本版只管「基线是什么」，不管「基线跑得对不对」。**
   标了 `bare-model-run` 却实际手写，本门看不出来——它读的是账本字段。
   要堵这个缺口需要把裸模型的运行记录一并存档并校验，本版没做。
2. **`prior-version` 被列为可用，但它证明的是「比上一版强」，不是「比裸模型强」。**
   报数时必须写明是哪一种，本门不替你区分。

## v0.0.0.19 — `own_voice_ratio`：语料里有多少字真是他自己写的（2026-08-01）

**动因**：Livermore #100 的语料在 `primary_ratio` 上轻松过 deep 的门，
而他本人的话总共只有约 2.2 万词。

```
primary_ratio   = 0.9887      ← deep 要 0.65
own_voice_ratio = 0.0076      ← 同一份语料
```

**两个数差 130 倍，而且两个都是对的。**

### 为什么 `primary_ratio` 会这样

RUNBOOK 第 822 行定：**第三人称叙述体（含「关于他」的报道）→ 降 `P2`**，
而 `primary_ratio` 的分子是 `P1 ∪ P2`。
Livermore 的 532 份可用 train 里 **530 份是同期报纸对他的报道**，于是分子几乎等于分母。

**这两个数量的是两件事**：`primary_ratio` 量「材料是不是同时代一手文献」，
`own_voice_ratio` 量「材料里有多少是他本人的表达」。
**人物蒸馏要建的是后者的模型**，而此前没有任何一个数在量它。

### 判据

```
own_voice_ratio = 账本 author 命中人物姓氏的 train 源字节 ÷ 全部 train 源字节
```

**它不是代理量**：改 tier、改 dimension、再多抓一万份报道，这个数都不动；
唯一能抬高它的是**真的拿到更多他本人的文字**。
回归用例 `test_own_voice_ratio_is_not_satisfied_by_reclassifying_tiers`
把这一条钉死——**把第三方报道的 tier 全改成 P1，该比值必须纹丝不动**。

### 为什么只报不拦

对历史人物设阈值会**直接判死一整类人物**。Livermore 只出过一本书、
没写过专栏、无公开书信集——**瓶颈是史料本身不存在，不是抓取力度**。
按既定裁定「门达不到时选诚实退路继续，绝不为凑数放宽判据」，
正确动作是把这个数报出来并写进硬边界，
**不是拦住流程，也不是假装没这回事**。

### 实测（Livermore #100 全量语料）

| 量 | 值 |
|---|---|
| train 源总数 | 536 |
| 其中**本人所著** | **2**（那本书的 train 卷与 holdout 章） |
| train 总字节 | 16,284,924 |
| 其中**本人所著字节** | **124,173** |
| `own_voice_ratio` | **0.0076** |
| 对照 `primary_ratio` | 0.9887 |

同一人物的另一组对照数字（来自抓源报告）：他一生可公开抓取的原话
**约 22,500 词，其中 97% 压在那一本书上**；去掉那本书只剩约 **600 词**。
而 Lefèvre 那本小说 **112,180 词**，是他全部存世文字的 **5 倍**——
**这就是「Livermore 语录」绝大多数出自小说的结构性原因。**

```
$ python3 -m pytest -q

$ python3 scripts/check_contract_drift.py

$ python3 scripts/self_check.py

```

### 已知缺口

1. **按字节算，不按词算**。中英混排语料里字节会高估中文占比。
   本项目语料以英文为主，暂不影响；换语种时要重看。
2. **只认账本 `author` 字段**，不读正文。账本写错就算错——
   这条由 `check_authorship.py` 的归属门另行把关，两件事分开。
3. **没有阈值**。要不要设、设多少，需要先看几十个人物的分布，
   现在只有一个人物的实测值，**不足以定线**。

## v0.0.0.18 — 扫描件的版权页进入归属门；卷内换作者的边界写死（2026-08-01）

**动因**：Livermore #100 的 1940 年**亲笔**著作《How to Trade in Stocks》，
被归属门判成「无据」。署名页的 OCR 结果是

```
BY
JESSE 1. LIVERMORE          ← `L.` 认成 `1.`，且 BY 与名字分行
```

`A-byline`（`\bBy\s+<名><姓>\b`，同一行、中间名须以大写字母开头）**一条也匹配不上**。
`A-masthead` 不适用（不是站点），`A-turns` 不适用（不是逐字稿）。
**四类证据齐备，而一份货真价实的亲笔著作拿不到任何一类。**

### 新增第五类证据 `A-copyright`

判据：**行首** `COPYRIGHT`／`©` … `BY` 后跟人物的名与姓（允许跨行、允许中间名首字符是数字）。
版权声明是结构元素且由出版社出具，作为归属证据比正文里的 `by` 更硬。
反证约束照常生效——文中出现别人的身份署名时不放行。

### ★ 第一版判据在真件上仍然一条不中：我校验了一个不需要的字段

第一版写成 `(?:1[5-9]\d\d|20\d\d)?`，而那一页印的是 **`COPYRIGHT, 1040, BY`**
——**`1940` 本身也被 OCR 认错了**。

> **定则：判据不需要的字段就不要校验**，尤其当它来自最不可靠的那一层。
> 我为「让判据看起来更严」加的年份格式，把判据的召回打成了 0。

`1040` 这个真实形态已作为自测正例写进 `SELFTEST_POSITIVE_COPYRIGHT`。

### ⚠ 本门看不见的那一类：卷内换作者

同一本书的**前言署 `EDWARD JEROME DIES`**，正文才是 Livermore 的。
整本以 `--tier P1 --author "Jesse L. Livermore"` 灌进去，
Dies 那句 `Each move was touched with singular genius` 就变成了他的自述——
**这是 Steinhardt #98 那次失败模式的同款，只是这次发生在一个文件内部。**

`check_authorship` **按整份文件判归属，看不见文件内部换人。**
新增 `suspect_signature_lines()` 把疑似他人署名行**列出来**，但**只报不判**：
实测同一本书上它也会命中 `NEW YORK`、`EXPLANATORY RULES`，
**精度不足以当反证——当反证会误杀整类书籍**。

**正确解法是按作者把文件切开再入库，切法留成可复核的脚本**
（本轮用 `split_book_1940.py`，带 `--verify` 打印每段首尾各两行；
第一次把前言边界写成 133 行，`--verify` 当场显示尾部混进了目录的 `VIII.` / `IX.`）。

**切的时候要带上扉页**：归属证据（版权页）在扉页上，而要防的东西在前言里，
**两者不能一刀切掉**——切掉扉页会让亲笔著作重新变成「无据」。

### 实测（真件三向对照）

| 文件 | 有据 | 判据 |
|---|---|---|
| 整本未切 | True | `A-copyright` ← 所以必须切，门在这里帮不上忙 |
| **切出的正文（扉页 + 章节 I–IX）** | **True** | **`A-copyright`** |
| **Dies 前言（单独）** | **False** | —— ✓ |


## v0.0.0.17 — OCR 扫描件里的同形字进入门（2026-08-01）

**动因**：Jesse Livermore #100 是本项目第一个**只有扫描件**的人物（1877–1940）。
他唯一的亲笔著作《How to Trade in Stocks》(1940) 只有 OCR 文本可得，
实测 12.5 万字的英文语料里含 **1405 个西里尔字符 / 314 个「全同形字词」**：

| 语料里的样子 | 实际是 | 说明 |
|---|---|---|
| `HOW ТО TRADE` | `HOW TO TRADE` | `Т`=U+0422、`О`=U+041E |
| `РКЕҒАСЕ` | `PREFACE` | **七个字母全是西里尔同形字** |
| `Ву` | `By` | **连署名的 By 都是西里尔的** |

### 为什么已有的七件内容检查器一件也拦不住

`check_verbatim_quotes.py` 拿引文回语料里比对——**从语料里复制一段带同形字的话，
它会说「找到了」**。它回答的是「语料里有没有这句」，
**不是「这句里的字符是不是真的」**。`check_quote_integrity.py` 查截断改写，同样不看字符集。

于是：**门全绿，而交付出去的「他的原话」含有他绝不可能写下的字符。**
读者拿那句话回原书里搜，一个字也搜不到——**引文不可引用**。

### 判据（两条，语言无关）

- **A · 词内混用文种**：一个词里同时出现拉丁与西里尔／希腊字母。任何语言里都不成立。
- **B · 少数派文种的「全同形字词」**：文档以拉丁为主时，
  出现完全由同形字构成的西里尔词 → OCR 替换。
  **限定「完全由同形字构成」是为了不误杀真外文**——真俄语词几乎必然含有
  至少一个没有拉丁长相的字母（`привет` 里的 `и`），因此不会被判。
  代价是漏掉恰好全由同形字构成的真外文词。**宁可漏，不可误杀**——
  误杀会让人去关掉这个门。

### 两级严重度（有意如此）

| 位置 | 处置 |
|---|---|
| 断言／文档／用例里的**引文** | **release 阶段 error** |
| **语料文件**本身 | **只报不拦**，写进 `metrics['ocr_homoglyphs']` |

把语料也判成 error 只会导致「为了过门而不用扫描件」，
**而扫描件常常是历史人物唯一的一手件**。门要拦的是把脏字符交付出去，不是拦你用扫描件。
语料层在 **research 阶段**就报，**在写第一个字之前**告诉你哪些源是脏的。

### 一个必须写死的边界：还原函数不能拿来修引文

`restore()` 把同形字换成它**长得像**的拉丁字母，只用于报告显示。
自测时我把断言写成「`РКЕҒАСЕ` 应还原为 `PREFACE`」，**当场被自己的负对照抓出来**——
它输出的是 `PKEFACE`，因为第二个字符是 `CYRILLIC CAPITAL LETTER KA`（长得像 `K`），
**OCR 把原文的 `R` 认成了 `K`，并且用西里尔字母写了出来**：错了两层。

> **同形字表只能揭示「这里出过 OCR 错」，不能告诉你原文是什么。**
> 拿它的输出当「修好的引文」交付，就是编造。

断言已改为断言 `PKEFACE`，**保留这条正是为了钉死这个边界**。

## v0.0.0.10 — 归属门从「独立脚本」变成**真的门**（2026-07-29）

**动因**：v0.0.0.9 自己写下的已知缺口——
「`check_authorship.py` 目前是独立脚本，靠执行者记得去跑。**一个靠记性的门不是门。**」

它还有第二个缺口：**人物名写死在文件里**（`NAME = r"Michael\s+(?:H\.?\s+)?Steinhardt"`）。
写死一个人名的检查器只能给一个人用，**注定停在「独立脚本」这个形态**——
这两个缺口其实是同一个。

### 1. 按人物名参数化

`build_patterns(full_name)` 由 `meta.json` 的 `name` 生成全部正则。
判据只依赖**名 + 姓**，中间名一律可选，两种写法互相都能命中。

**取名字不要用 `\s+` 连接**：`First\s+(?:Middle\s+)?Last` 里两个相邻量词
会争抢同一段空白——这正是 v0.0.0.9 实测卡死 120 秒的那个形态。
可选中间名**自带尾随空格**才是无歧义写法。

### 2. 接进 `quality_check.py --phase research`

新增 `run_authorship_gate()`，**三个阶段都跑**（0.13 秒，可以忽略不计）。

**门开在账本自己声称的东西上**：只查 `tier == 'P1'` 且 `author` 指向本人物的源。
账本说「这是他写的」，门就要求它拿出证据。**没声称作者的源不在射程内**，
因此对既有产物零误伤（实测 56 个测试全部不受影响）。

**为什么必须在 research 而不是 release**：归属错了，
后面六路研究、断言、文档、用例**全部要重做**。
v0.0.0.9 把它放在收口手动跑，等于把这笔返工的可能性一直背到最后。

**射程边界（有意留的，不是遗漏）**：`tier=P1` 但 `author` 留空的源本门不判，
只在 metrics 报数。堵它会把所有历史产物一起拦下，违反「不因过不了门而卡住流程」。
**缺口大小随时可见，不会被误当成通过。**

### 3. 内置双向负对照（`--self-test`）

4 正 + 4 反，与 v0.0.0.8 三件硬门同一条纪律：
**负对照不过，该检查器的「全绿」不构成任何证据**——已接进门，自动先验。

### 参数化时实测抓到的一处真回归

`MS:` 标签的 44 轮真逐字稿被判成无据。
旧代码硬编码 `^ms$`，而我按三段名 `Michael H. Steinhardt` 算出 `mhs`。
**人在语料里用的缩写取决于他惯用的名字形态，不取决于账本写了几段**
——名姓首字母与全首字母**两种都要认**。已修，并把这个形态写进内置负对照。

**这条正是「判据变更必须双向回归」当场兑现的收益**：
若只跑负例（洗白的那份被拦住了）就交付，这份真逐字稿会被永久误杀。

## v0.0.0.9 — 语料的**归属**进入硬门（2026-07-28）

**动因**：Steinhardt #98 的语料准备阶段抓到一个能污染整个产物、
而 v0.0.0.8 的七件内容检查器**一件也拦不住**的缺口。

抓源子代理把人物基金会的季刊整期抓下、按页切片、**一律冠上人物前缀**
（`ms_<年>_contact_essay_<题>.txt`）。十份切片里**九份不是他写的**——
文末分别署着 Lynn Schusterman、Adam Bronfman、Simon Greer、HUC-JIR 的人。
而灌库命令带着 `--author "Michael Steinhardt"`。
**文件名前缀 ＋ author 参数，两步就把别人的文章洗成了他的话。**

最危险的一句是 2009 年那份的开头：

> When I was a child, one of the first lessons my father taught me was that
> charity is the rent we pay for our lives on this planet.

这句必然会被写成他与其父 Sol 的家世（Sol 是有前科的赌徒，反差极适合入产物）。
**那是 Lynn Schusterman 的父亲。**

**v0.0.0.8 的检查器为什么全部失效**：`check_quote_integrity` 会说「这句在语料里」
——**它确实在，只是不是他说的**；`check_claim_coverage` 查的是引用有没有支撑，
不是支撑属于谁；`check_holdout_overlap` 查重复不查归属。
**七件检查器全部假设「语料里的话就是他的话」。**

### 新增 `check_authorship.py`（硬门）

一份语料要当「他的话」用（P1），**必须有正面归属证据，且证据随文件落盘**。
「没查到反证」不算证据。三种可接受证据：

| 证据码 | 是什么 |
|---|---|
| `A-byline` | **结构位置上的**署名：行首，或跟在分隔符后 |
| `A-editorial` | 编者注（`[Remarks delivered by …]`） |
| `A-turns` | 对话轮次：≥2 个说话人标签各 ≥3 轮且后文互不相同 |

**署名型证据被他人署名污染即作废**（切歪了）；
**轮次型证据不受影响**——访谈里出现提问者的署名是应有之义，他的话逐轮标着。

单标签也可成立，但要求 ≥5 段互不相同**且各 ≥40 字符**的后文
——资源页的小标题（`Michael Steinhardt: Background & bio`）也各不相同，
用长度把「句子」与「短名词短语」分开。

回归：8 个已知正例过、6 个已知反例拒，全库 101 份 **0.16 秒**。

### 判据变更的连带修正（每一条都是实测的假阴／假阳）

1. `^名字:` **不是**说话人标记——命中的是**标题里的冒号**
   （`Michael Steinhardt: The King of Block Trading` 在 og:title/h1/面包屑里重复）。
   五份被判成「人工逐字稿」的文件里没有一份是逐字稿。
2. 反方向：真说话人标记**可能独占一行并与正文隔着空行**。
   只认同行会把 67 轮的真逐字稿判成 0 轮；只允许一个 `\n` 仍是 0 轮。
3. 全大写、**不带冒号**的标记也是真逐字稿
   （`MICHAEL STEINHARDT He grew up in Brooklyn.`）。
4. 标签第二个词起要允许小写连接词（`Knowledge at Wharton:`）。
5. 散文里的 `by X` **不是**署名——书评里的
   「the autobiography by Michael Steinhardt who rose from 'rags'」，
   真作者署名在上一行。加两条判据：必须在结构位置上；后面不能紧跟 who/which/that。
6. 行内**全大写**署名（`… by ANDREW KATZ 6 CONTACT`）也要认，
   只认「独占一行的 By X」会让一份 22KB 切片混进整篇邻文。

**每一条判据改完都要拿已知正例和已知反例各跑一遍**——本轮三次都只跑了一边。

### 版面 PDF 的切片方向修正（`ms_contact2.py`）

`pypdf` 抽出的文本流里，**标题与署名排在正文之后**（版面上标题在页首，
内容流里最后吐出）。从署名向**后**切必然切到下一篇。
**改为按页切**——页是抽取器唯一保证的边界，段落顺序不是。
作者的文末身份行（`<名> is Chairman of…`）＝「这篇到此为止」，本页有它就不接续页。

60 期切出 17 期他的署名专栏；另 4 期弃收（与他人文章同版交织／合署／
切片实为封底使命声明），**弃收理由逐条记录在清单里**。

### 分层判据的整体结论

**自动 tier 判据在本人物身上不可用。** 第一人称密度把一位**具名指控者的自述**
（"Michael Steinhardt sexually harassed me"，密度 0.026）判成了 P1——
密度量的是「有没有一个说话的『我』」，**不含任何关于那个『我』是谁的信息**。
改为两段式：**P1 由 `check_authorship.py` 判**，其余由显式清单判，一条一个理由。

### RUNBOOK 新增第六十三～六十八种

第 63 种（抓源冠名 + `--author` 的洗白链）、64（版面 PDF 文本流方向）、
65（第一人称密度分不清谁的「我」）、66（说话人标记的三种形态与两个方向的错）、
67（散文里的 by X）、68（正则里相邻量词吞同一空格 → 196KB 文档上灾难性回溯）。

## v0.0.0.8 — 内容层检查进入发布门（2026-07-28）

**动因**：Icahn #92 → Salatin #95 这五人暴露的严重缺陷**全部属于内容层**，
而当时官方三个门全绿。门原本只查**结构完整性**（文件在不在、字段全不全、数量对不对），
**而结构完整的产物完全可以每一句都错。**

### 新增七件检查器（`scripts/check_*.py`）

| 检查器 | 拦什么 | 原门为什么看不见 |
|---|---|---|
| `check_claim_coverage` | 装饰性引用：引了源但源正文里没这事实 | 门只数 source_id 个数，不看内容 |
| `check_quote_integrity` | 伪造引文 | 门不接触原始语料 |
| `check_semantic_residue` | 订正换个措辞又活了 | 门不知道什么被订正过 |
| `check_absence_claims` | 无依据的「从未／只有／完全没有」 | 门不判断断言强度 |
| `check_redundancy` | 同一事实在一段里说两遍 | 门不看可读性 |
| `check_schema_drift` | 订正脚本留下的字段污染 | **门忽略多余字段** |
| `check_claim_anchors` | claim 标记错挂 | **门只查计数，错挂不改变计数** |

### 接线方式

`quality_check.py --phase release` 新增 `--cache` 参数，跑 `run_content_checks()`：

- **硬门**（不过即拦）：装饰性引用、订正残留、以及**检查器自身的负对照**
- **只列不判**（写进 warnings）：绝对化断言、段内冗余、字段漂移、claim 锚点
  ——它们有已知的合理误报形态，自动判定会误伤
- **不给 `--cache` 时不静默跳过**，记 warning 明说「本次未做内容层核验」
  ——**「没查」和「查过没问题」必须能被区分出来**

### 三个硬门检查器都带负对照（`--self-test`）

- `check_quote_integrity`：4 类伪造全抓（含「真句只改一个词」），36 条真引文 0 误报
- `check_semantic_residue`：双向 2/2（残留抓到、订正后的否定表述豁免）
- `check_claim_coverage`：5 向（实体抽取／装饰性判定／真支撑不误判／
  无实体无引文显式计未检查／引文须在被引源中）

**负对照不过 → 该检查器的结论一律不作数**，这一条也是硬门。
理由：引文检查器的前两版误报率都是 100%，照着误报去订正会把真引文改坏。

### 接线时自己踩的三个坑（已修，记此备忘）

1. `pathlib.Path` 与 `from pathlib import Path` 混用。
2. **判据写成 `'结论: 通过' not in out`——而「不通过」这个串包含「通过」**，
   判断整个反了：真有装饰性引用时反而放行。改用**退出码**。
   **中文子串匹配天然有这个坑：否定式包含肯定式。**
3. 负对照用 `copytree` 造临时 target，被门判为 `target.invalid` 而提前退出——
   **「门没拦住」与「门没跑到」在结果上一样**。改在真实工作区植入并还原。
