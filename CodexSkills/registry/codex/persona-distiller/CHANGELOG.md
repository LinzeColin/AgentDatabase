# Changelog

## v0.0.0.15 — 蒸馏版本新鲜度：从包级代理量改成每人一条记录（2026-07-29）

**动因（用户澄清原始意图）**：`build_release_bundle.py` 里那条
「两个 Skill 的 `VERSION` 必须相等」，本意是**保证专家团队里的人
由正确的蒸馏版本产出**——人物蒸馏到 v0.0.0.8，团队就不该是 v0.0.0.6/7 蒸的。

**意图对，判据测的是代理量**：它是包级的一个数字，不是每人一条记录；
把 group 的 `VERSION` 从 8 改成 14 是一次文本编辑，一个人也没重蒸，门当场变绿。
且它在打包时才触发，实际后果是**自 v0.0.0.9 起发行 bundle 一次也构建不出来**。
（写进 RUNBOOK 第七十种：门测的是代理量，而代理量可以在属性不成立时被满足。）

### 用户裁定的新机制

- 每人一条 `distilled_with`，**下限 = 当前蒸馏版本号末位 − 10**
  （`v0.0.0.98` → `0.0.0.88`）
- **低于下限不重蒸、不阻塞**，只记台账
- **600 人整体完成后统一重蒸所有人**，对齐到当时的最新版本

### 变更

- `delivery_builder.py` 打包时把 `DISTILLER_VERSION`（读自 `VERSION`）盖进交付
  manifest——**随产物走**，不在登记时现取，因为登记可能比蒸馏晚很多天。
- `registry_core.py`（group）把 `distilled_with` + `distilled_with_source`
  写进 `registration.json`。第一手值永远优先，不被重建值覆盖。
- 新增 `scripts/backfill_distilled_with.py`（group）：从 git 回填既有 97 人。
  **回填是推断不是测量**，来源分四档；`a31cb12d` 的 70 人标为
  `bulk-repackage`，其值是**上界**——那次只重打包没重蒸。
  `artifact_created_at` 不能用作证据（99 条里 15 条恰好 `00:00:00Z`，
  且已核实至少一例与 git 矛盾）。
- 新增 `scripts/check_distillation_freshness.py`（带 `--self-test`），
  **默认只报不拦**；接进 `self_check` 作 **warning 不是 error**。
- **解绑两处相等判据**：`build_release_bundle.py` 与
  `templates/bundle/install.py`（同一条判据的第二份拷贝，
  只改一处会在另一处红——第二十二种复发）。bundle 改为如实记录两个
  Skill 各自的版本号 + 新鲜度实况。
- 新增 `scripts/bump_version.py`：一次盖 7 处声明位并自动跑漂移自查。
- `test_release_bundle` 里断言「group 的 VERSION 也等于 distiller 的」
  那一句是锁步假设的化身，已改为断言新契约。
- 新增 5 条回归用例。

### 实测

- 回填：97 份，`products` 仍 97 / `artifacts` 仍 99（受保护资产未缩）
- 新鲜度：99/99 ≥ 下限 `v0.0.0.4`，**其中 70 条是上界值**（只重打包未重蒸）
- **发行 bundle 构建成功**——自 v0.0.0.9 以来第一次，
  `PersonaDistiller-Final-v0.0.0.15.zip`
- 全量测试 **64 passed, 0 failed**（v0.0.0.14 时是 2 failed）

## v0.0.0.14 — 对外声明的版本与输入合同进入硬门（2026-07-29）

**动因（用户点名）**：公开树同时声明多个版本号，且 SKILL metadata 与正文的输入合同冲突。

实测比点名更宽——**同一个 skill 对外声明了 7 个不同的版本号**，
且衰减单调：`registry/index.json` = `0.0.0.4`、`registry.yaml` = `0.0.0.5`、
`VERIFICATION.md` / `handoff.md` / `PACKAGE_MANIFEST.json:version` = `v0.0.0.5`、
`README.md` = `v0.0.0.6`、`SKILL.md` 正文小节 = `v0.0.0.7`、
`VERSION` / `manifest.json` = `v0.0.0.13`。**离发布脚本越远的位置越旧。**

根因：`self_check.py` 的版本校验**只比 `VERSION` 与 `manifest.json` 两处**。
v0.0.0.8 记的「版本已建立单一真源」，建立的其实是**两点之间的一致**；
另外六处从来没有任何东西查过。**只覆盖 2/8 的单一真源，不是单一真源。**

**比版本更严重的一类**：`SKILL.md` 的 metadata 写
「one identity family **or weighted multi-identity selection**」，
而正文写「单一主身份；多重身份已移除」，`test_weighted_selection_is_rejected` 长期为绿——
**代码确实拒绝加权多身份，只有对外的输入合同还在提供它。**
metadata 是调用方唯一会读的那份，冲突直接落到调用方头上。

### 变更

- 新增 `scripts/check_contract_drift.py`：查 skill_version 的 8 个对外声明位置、
  builder_version 的钉住值、身份输入合同（族数 / metadata 多身份词族 /
  `registry.yaml` 列出的目录是否真的存在）。带 5 类坏样本 + 1 项反向对照的 `--self-test`。
- **接进 `self_check.py`**——独立脚本不是门（v0.0.0.10 的教训）。
- `build_manifest.py` 现在用同一个真源同时盖 `version` 与 `distribution.kind`；
  原先只盖后者，前者从 v0.0.0.5 起冻了 9 个版本，同一文件里两个版本号自相矛盾。
- 修 18 处漂移：`index.json`、`registry.yaml`（含 6 个已删除/不存在的旧族目录）、
  `PACKAGE_MANIFEST.json`、`README.md`、`VERIFICATION.md`、`handoff.md`、
  `CONTRIBUTING.md` 的 `seven-family`、`SKILL.md` 的 metadata 与历史版本标记。
- `README.md` 原来那行把 skill 轴与 builder 轴写进同一句，是读者混淆的来源，已拆分；
  检查器把「一行同时出现两轴版本号」单列为 `[轴混写]` 判定。
- `VERIFICATION.md` 重写为**当前发布号的复验记录**：每行都来自本次实跑，
  没跑的标 `未复验`，不沿用 v0.0.0.5 的旧结论。结果为 **PARTIAL**，不是 PASS。
- 新增 3 条回归用例（`tests/test_skill_contract.py`）。

### 实测

- `--self-test`：正对照 0 报，5 类坏样本全抓出，**故意钉住的 builder v0.0.0.5 未被误伤**
- 真实树：**18 条 → 0 条**
- 全量测试：`5 failed` / 56 个用例 → **`2 failed`, 57 passed** / 59 个用例（本轮新增 3 条回归）

### 未解决：发行 bundle 自 v0.0.0.9 起构建不出来

剩下 2 个失败用例同根：`build_release_bundle.py` 要求
`persona-distiller`（`v0.0.0.14`）与 `persona-distiller-group`（`v0.0.0.8`）
的 `VERSION` 完全相等，否则 `SystemExit: version mismatch`。
**从 v0.0.0.9 起 `PersonaDistiller-Final-*.zip` 一次也没能构建出来**——
此前未被发现，因为这 2 个失败一直藏在另外 3 个校验和失败后面。

**未擅自修复。** 把 group 从 `v0.0.0.8` 直接抬到 `v0.0.0.14`
等于凭空宣称 6 次没有发生过的 group 发布；
而放宽相等判据会改变发行契约。两者都需要先裁定「bundle 版本是一个号还是两个号」。

## v0.0.0.12 — 元检查器：查「检查器自己有没有被验证过」（2026-07-29）

**动因**：全量分诊排出的第 1 优先项。RUNBOOK 第十八种的推论
「**没有负对照的检查器，其「全绿」不构成任何证据**」此前只是散文。

落成后第一次跑，结果是 **12 件里 5 件根本没有负对照、1 件有但跑不起来**，
其中 `check_verbatim_quotes` 与 `check_quote_integrity` **都是硬门**。

**一个专门讲「没有负对照的检查器不算数」的项目，自己一半检查器没有负对照。**

### `check_checkers.py`

四档：`OK` / `NOT-STANDALONE` / `NO-SELFTEST` / `FAILED`，
**一律按退出码 ＋ argparse 报错形态判，不按输出串**
——各检查器的通过标记本就不统一（`负对照通过`、`自测 5/5`、`✓ 无关文本被放过`）。

### `quality_check.py` 改为普查全部

此前只**手工点名先验两件**，其余检查器有没有负对照从来没人问过。
`FAILED` 拦，`NO-SELFTEST` / `NOT-STANDALONE` 进 metrics 只报不拦
——拦了会让 5 件既有检查器当场堵死流水线。

### 交付前被自己的普查结果抓到的缺陷

第一次跑，6 件全被判成 `NOT-STANDALONE`，而 `grep` 说其中 5 件压根没有 `self_test`。
**根因**：argparse 缺必填参数时先报这一条就退出，永远不会再报
「unrecognized arguments」——两种含义完全不同的情况落进了同一分支。

**而元负对照没抓住它**，因为样本把 `--workspace` 写成了可选，真实的是必填。
→ **负对照的样本必须覆盖真实形态，否则它只验证了我想象的形态。**
已补第 5 档样本并改用 `--help` 判参数是否存在。

## v0.0.0.11 — 从源头堵掉归属门的射程外区域（2026-07-29）

**动因**：v0.0.0.10 自己写下的射程边界——
「`tier=P1` 但 `author` 留空的源本门不判，只在 metrics 报数。」

门查的是「账本声称本人所著的源有没有证据」。**没声称，就无从查起。**
于是「不写 author」成了一条绕过整道门的路径，而且是**最省事**的那条。

### `ingest.py`：`--tier P1` 必须给 `--author`

P1 的语义在 RUNBOOK 里是明确的：**人工逐字稿、署名信件、印刷问答**，
且「产物里凡是引号内的原话，只许来自 P1」。
**一份没有作者字段的一手件本来就不成立**——堵在源头比在门里补判据便宜。

判在**碰文件系统之前**做：参数层的错就该在参数层报。
否则 target 不存在时先报「target 无效」，真正的原因反而看不见
（第一版就是这么写的，实测负对照没有触发，才发现判早了一步还是晚了一步很重要）。

### 测试夹具改成**诚实的** P1，顺带给归属门做了端到端覆盖

夹具此前以 `--tier P1` 灌入合成语料却**不带 author**——
即「声称是他的话，但不说是谁的话」，正是本版要消灭的形态。
现改为 `--author 'Example Thinker'` ＋ 正文带 `By Example Thinker` 署名。

**实测确认这道门在套件里是活的**：把 byline 去掉，
`test_release_quality_gate_and_eval_aggregate` 当场变红；还原即绿。

## v0.0.0.10 — 归属门从「独立脚本」变成**真的门**（2026-07-29）

**动因**：v0.0.0.9 自己写下的已知缺口——
「`check_authorship.py` 目前是独立脚本，靠执行者记得去跑。**一个靠记性的门不是门。**」

它还有第二个缺口：**人物名写死在文件里**（`NAME = r"Michael\s+(?:H\.?\s+)?Steinhardt"`）。
写死一个人名的检查器只能给一个人用，**注定停在「独立脚本」这个形态**——
这两个缺口其实是同一个。

### 1. 按人物名参数化

`build_patterns(full_name)` 由 `meta.json` 的 `name` 生成全部正则。
判据只依赖**名 + 姓**，中间名一律可选，两种写法互相都能命中。

**取名字不要用 `\s+` 连接**：`First\s+(?:Middle\s+)?Last` 里两个相邻量词
会争抢同一段空白——这正是 v0.0.0.9 实测卡死 120 秒的那个形态。
可选中间名**自带尾随空格**才是无歧义写法。

### 2. 接进 `quality_check.py --phase research`

新增 `run_authorship_gate()`，**三个阶段都跑**（0.13 秒，可以忽略不计）。

**门开在账本自己声称的东西上**：只查 `tier == 'P1'` 且 `author` 指向本人物的源。
账本说「这是他写的」，门就要求它拿出证据。**没声称作者的源不在射程内**，
因此对既有产物零误伤（实测 56 个测试全部不受影响）。

**为什么必须在 research 而不是 release**：归属错了，
后面六路研究、断言、文档、用例**全部要重做**。
v0.0.0.9 把它放在收口手动跑，等于把这笔返工的可能性一直背到最后。

**射程边界（有意留的，不是遗漏）**：`tier=P1` 但 `author` 留空的源本门不判，
只在 metrics 报数。堵它会把所有历史产物一起拦下，违反「不因过不了门而卡住流程」。
**缺口大小随时可见，不会被误当成通过。**

### 3. 内置双向负对照（`--self-test`）

4 正 + 4 反，与 v0.0.0.8 三件硬门同一条纪律：
**负对照不过，该检查器的「全绿」不构成任何证据**——已接进门，自动先验。

### 参数化时实测抓到的一处真回归

`MS:` 标签的 44 轮真逐字稿被判成无据。
旧代码硬编码 `^ms$`，而我按三段名 `Michael H. Steinhardt` 算出 `mhs`。
**人在语料里用的缩写取决于他惯用的名字形态，不取决于账本写了几段**
——名姓首字母与全首字母**两种都要认**。已修，并把这个形态写进内置负对照。

**这条正是「判据变更必须双向回归」当场兑现的收益**：
若只跑负例（洗白的那份被拦住了）就交付，这份真逐字稿会被永久误杀。

## v0.0.0.9 — 语料的**归属**进入硬门（2026-07-28）

**动因**：Steinhardt #98 的语料准备阶段抓到一个能污染整个产物、
而 v0.0.0.8 的七件内容检查器**一件也拦不住**的缺口。

抓源子代理把人物基金会的季刊整期抓下、按页切片、**一律冠上人物前缀**
（`ms_<年>_contact_essay_<题>.txt`）。十份切片里**九份不是他写的**——
文末分别署着 Lynn Schusterman、Adam Bronfman、Simon Greer、HUC-JIR 的人。
而灌库命令带着 `--author "Michael Steinhardt"`。
**文件名前缀 ＋ author 参数，两步就把别人的文章洗成了他的话。**

最危险的一句是 2009 年那份的开头：

> When I was a child, one of the first lessons my father taught me was that
> charity is the rent we pay for our lives on this planet.

这句必然会被写成他与其父 Sol 的家世（Sol 是有前科的赌徒，反差极适合入产物）。
**那是 Lynn Schusterman 的父亲。**

**v0.0.0.8 的检查器为什么全部失效**：`check_quote_integrity` 会说「这句在语料里」
——**它确实在，只是不是他说的**；`check_claim_coverage` 查的是引用有没有支撑，
不是支撑属于谁；`check_holdout_overlap` 查重复不查归属。
**七件检查器全部假设「语料里的话就是他的话」。**

### 新增 `check_authorship.py`（硬门）

一份语料要当「他的话」用（P1），**必须有正面归属证据，且证据随文件落盘**。
「没查到反证」不算证据。三种可接受证据：

| 证据码 | 是什么 |
|---|---|
| `A-byline` | **结构位置上的**署名：行首，或跟在分隔符后 |
| `A-editorial` | 编者注（`[Remarks delivered by …]`） |
| `A-turns` | 对话轮次：≥2 个说话人标签各 ≥3 轮且后文互不相同 |

**署名型证据被他人署名污染即作废**（切歪了）；
**轮次型证据不受影响**——访谈里出现提问者的署名是应有之义，他的话逐轮标着。

单标签也可成立，但要求 ≥5 段互不相同**且各 ≥40 字符**的后文
——资源页的小标题（`Michael Steinhardt: Background & bio`）也各不相同，
用长度把「句子」与「短名词短语」分开。

回归：8 个已知正例过、6 个已知反例拒，全库 101 份 **0.16 秒**。

### 判据变更的连带修正（每一条都是实测的假阴／假阳）

1. `^名字:` **不是**说话人标记——命中的是**标题里的冒号**
   （`Michael Steinhardt: The King of Block Trading` 在 og:title/h1/面包屑里重复）。
   五份被判成「人工逐字稿」的文件里没有一份是逐字稿。
2. 反方向：真说话人标记**可能独占一行并与正文隔着空行**。
   只认同行会把 67 轮的真逐字稿判成 0 轮；只允许一个 `\n` 仍是 0 轮。
3. 全大写、**不带冒号**的标记也是真逐字稿
   （`MICHAEL STEINHARDT He grew up in Brooklyn.`）。
4. 标签第二个词起要允许小写连接词（`Knowledge at Wharton:`）。
5. 散文里的 `by X` **不是**署名——书评里的
   「the autobiography by Michael Steinhardt who rose from 'rags'」，
   真作者署名在上一行。加两条判据：必须在结构位置上；后面不能紧跟 who/which/that。
6. 行内**全大写**署名（`… by ANDREW KATZ 6 CONTACT`）也要认，
   只认「独占一行的 By X」会让一份 22KB 切片混进整篇邻文。

**每一条判据改完都要拿已知正例和已知反例各跑一遍**——本轮三次都只跑了一边。

### 版面 PDF 的切片方向修正（`ms_contact2.py`）

`pypdf` 抽出的文本流里，**标题与署名排在正文之后**（版面上标题在页首，
内容流里最后吐出）。从署名向**后**切必然切到下一篇。
**改为按页切**——页是抽取器唯一保证的边界，段落顺序不是。
作者的文末身份行（`<名> is Chairman of…`）＝「这篇到此为止」，本页有它就不接续页。

60 期切出 17 期他的署名专栏；另 4 期弃收（与他人文章同版交织／合署／
切片实为封底使命声明），**弃收理由逐条记录在清单里**。

### 分层判据的整体结论

**自动 tier 判据在本人物身上不可用。** 第一人称密度把一位**具名指控者的自述**
（"Michael Steinhardt sexually harassed me"，密度 0.026）判成了 P1——
密度量的是「有没有一个说话的『我』」，**不含任何关于那个『我』是谁的信息**。
改为两段式：**P1 由 `check_authorship.py` 判**，其余由显式清单判，一条一个理由。

### RUNBOOK 新增第六十三～六十八种

第 63 种（抓源冠名 + `--author` 的洗白链）、64（版面 PDF 文本流方向）、
65（第一人称密度分不清谁的「我」）、66（说话人标记的三种形态与两个方向的错）、
67（散文里的 by X）、68（正则里相邻量词吞同一空格 → 196KB 文档上灾难性回溯）。

## v0.0.0.8 — 内容层检查进入发布门（2026-07-28）

**动因**：Icahn #92 → Salatin #95 这五人暴露的严重缺陷**全部属于内容层**，
而当时官方三个门全绿。门原本只查**结构完整性**（文件在不在、字段全不全、数量对不对），
**而结构完整的产物完全可以每一句都错。**

### 新增七件检查器（`scripts/check_*.py`）

| 检查器 | 拦什么 | 原门为什么看不见 |
|---|---|---|
| `check_claim_coverage` | 装饰性引用：引了源但源正文里没这事实 | 门只数 source_id 个数，不看内容 |
| `check_quote_integrity` | 伪造引文 | 门不接触原始语料 |
| `check_semantic_residue` | 订正换个措辞又活了 | 门不知道什么被订正过 |
| `check_absence_claims` | 无依据的「从未／只有／完全没有」 | 门不判断断言强度 |
| `check_redundancy` | 同一事实在一段里说两遍 | 门不看可读性 |
| `check_schema_drift` | 订正脚本留下的字段污染 | **门忽略多余字段** |
| `check_claim_anchors` | claim 标记错挂 | **门只查计数，错挂不改变计数** |

### 接线方式

`quality_check.py --phase release` 新增 `--cache` 参数，跑 `run_content_checks()`：

- **硬门**（不过即拦）：装饰性引用、订正残留、以及**检查器自身的负对照**
- **只列不判**（写进 warnings）：绝对化断言、段内冗余、字段漂移、claim 锚点
  ——它们有已知的合理误报形态，自动判定会误伤
- **不给 `--cache` 时不静默跳过**，记 warning 明说「本次未做内容层核验」
  ——**「没查」和「查过没问题」必须能被区分出来**

### 三个硬门检查器都带负对照（`--self-test`）

- `check_quote_integrity`：4 类伪造全抓（含「真句只改一个词」），36 条真引文 0 误报
- `check_semantic_residue`：双向 2/2（残留抓到、订正后的否定表述豁免）
- `check_claim_coverage`：5 向（实体抽取／装饰性判定／真支撑不误判／
  无实体无引文显式计未检查／引文须在被引源中）

**负对照不过 → 该检查器的结论一律不作数**，这一条也是硬门。
理由：引文检查器的前两版误报率都是 100%，照着误报去订正会把真引文改坏。

### 接线时自己踩的三个坑（已修，记此备忘）

1. `pathlib.Path` 与 `from pathlib import Path` 混用。
2. **判据写成 `'结论: 通过' not in out`——而「不通过」这个串包含「通过」**，
   判断整个反了：真有装饰性引用时反而放行。改用**退出码**。
   **中文子串匹配天然有这个坑：否定式包含肯定式。**
3. 负对照用 `copytree` 造临时 target，被门判为 `target.invalid` 而提前退出——
   **「门没拦住」与「门没跑到」在结果上一样**。改在真实工作区植入并还原。
