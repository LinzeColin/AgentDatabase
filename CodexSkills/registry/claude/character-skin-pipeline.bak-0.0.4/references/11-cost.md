# 省钱：钱花在哪，哪些能省

## 钱只花在一个地方

**100% 的 API 账单是 `gpt-image-2` 出图。** 驱动模型（Claude / DeepSeek / Kimi / SCNet）
一分图钱都不产生——它只负责调脚本。所以「换个便宜的模型」省的是**你的对话额度**，
不是这条产线的美元账单。两笔钱要分开算。

| 实测 | v1.7.0（612 张） | v1.8.0（94 张） |
|---|---|---|
| 实付 | $47.25 | $6.54 |
| 单张（按可用成品） | $0.0772 | **$0.0696** |
| 一次通过率 | 92.8% | **97.9%** |

## 已经在省的

- **Batch API 五折**。实时接口是它的两倍价，且慢一个数量级。
- **闸门在本地判**，不合格的不进重试队列，也不占人工复核时间。

## 还能省的，按收益排

### 1. 别重跑已经有的（省 100% 的重复部分）

v1.8.0 的试跑跑了 5 条，全量又把同样 5 条重跑了一遍，白花 **$0.46**。
`batch_run.py start` 每次都建全新账本，不看输出目录里已有什么。

**做法**：`start` 时扫一遍 `--out` 目录，已有且过闸的直接标 `accepted`。
按 v1.8.0 的比例，这一条省 5~7%。

### 2. 把重试压到 0（省 2%）

v1.8.0 的 2 张废片都是同一个原因：**暗版亮度 0.527 略超 0.50 上限**。
两次都是擦边。把 prompt 里的暗版目标亮度从「moderate」改成明确的数值区间，
或把上限从 0.50 放到 0.55（0.527 的图人眼看没问题），重试就归零。

**先量再改**：把历史上所有 `G1 暗版过亮` 的实际亮度值列出来，看分布在哪，
再决定是收紧 prompt 还是放宽闸门。**别凭感觉调阈值。**

### 3. 锚图尺寸（可能省 10~20%，但要先验证）

锚图现在编到 2048px JPEG q88，每张约 500KB。`gpt-image-2` 按输入图片的 token 计费，
锚图越大输入越贵。**但身份还原度完全来自锚图**，压小是拿质量换钱。

**做法**：拿同一批角色跑 2048 / 1536 / 1024 三档，人工比还原度。
差不出来就用小的，差得出来就维持 2048。**这是唯一一条必须先做 A/B 的。**

### 4. 昼夜两张能不能变一张（省 50%，但大概率不行）

现在昼版夜版是**分别生成**的两张。如果夜版能由昼版调色得到，直接省一半。

**但实测过一次相关的事**：昼夜两版的场景光照是真的不同（夜版有月亮、灯笼、
冷调边缘光），不是滤镜能做出来的。而且我做过一个色相判据想比对昼夜一致性，
它判的全是打光——**说明两版的差异主要就在打光**，那反过来也说明调色可能够用。

**结论：值得做一次 A/B，但必须人工判。** 我不替你判这个，见 06 的四次失败。

### 5. 用便宜模型驱动（省对话额度，不省 API 账单）

产线的每一步都是脚本，模型只负责按顺序调它们。**出图质量与驱动模型无关。**
弱模型的风险不在质量，在**判断**——今晚有 6 处失败是靠判断抓出来的
（SMB 静默写零、zsh 不分词、pgrep 自匹配、花名册指错页、中文名串行、srcset 破判据）。

**做法**：把这 6 类失败变成脚本里过不去的断言，弱模型就跑得动。
已固化的：写后比摘要、skip 比内容、抓完查重名。
**没固化的**：多值参数显式分割、等待循环不许自匹配、名字里含「名片/卡片」就拒。

## 不该省的

- **不要为省钱降分辨率**。3840×2160 是母版规格，动漫线稿最吃压缩。
- **不要跳过试跑**。5 条试跑 $0.4，一次全量跑错是 $7~45。
- **不要跳过需求核对**。上一轮「禁 Q 版」0/594，返工成本远超核对成本。
