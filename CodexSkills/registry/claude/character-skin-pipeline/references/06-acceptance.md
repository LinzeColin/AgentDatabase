# 验收：机器判数字，人判审美

## 机器闸门（`runner.py` 的 `gate()`）

**实测阈值，别改成"看起来合理"的数**：

```python
DARK_MIN, DARK_MAX = 0.28, 0.50      # 暗版平均亮度带
LIGHT_MIN          = 0.55            # 昼版亮度下限
RIGHT_DETAIL_MAX   = 14.0            # 右 65% 的边缘能量上限
SPILL_MAX          = 0.55            # 中段/左段边缘能量比（主体溢出）
MAX_ATTEMPTS       = 3
```

四条判据：
| 代号 | 判什么 | 怎么算 |
|---|---|---|
| B1 | 比例是不是 16:9 | `abs(w/h - 16/9) > 0.01` |
| B2 | 宽度 ≥ 2048 | — |
| C3 | 右侧够不够干净 | 右 65% 缩到 800×450 后 `FIND_EDGES` 均值 |
| C2 | 主体有没有溢出左 35% | 中段(35%~62%)/左段(0~35%) 的边缘能量比 |
| G1 | 暗版亮度在 0.28~0.50 | 灰度均值 |
| G1b | 昼版亮度 ≥ 0.55 | 同上 |

**每条失败要带「下次：…」修正子句**，供重试时拼进 prompt：
```
C3 右侧细节 18.2 > 14.0（下次：右侧只要天空与水面，去掉一切远景物件）
G1 暗版过亮 0.53（下次：压低天空亮度，保留主体打光，目标 0.35 左右）
```

**这个闸门便宜且有效**——它接住了所有「暗版暗到看不见人」的废片。
但它**判不了审美**，见下。

## 人工复核：机器只负责把它变便宜

### 为什么不能用视觉模型判

用户点出一张图有第三条手臂（握杖的手臂从腰侧长出、没有肩）。三轮全废：

| 版本 | 问法 | 对已知坏图 | 结果 |
|---|---|---|---|
| 1 | gpt-5-mini +「拿不准就不报」 | 漏掉 | 废 |
| 2 | gpt-5 + 强制计数 + 上半身特写 + 禁止用遮挡开脱 | 抓到，**判词准确** | **100 张报 83 张** |
| 3 | 改问「普通人第一眼会不会注意到」0-10 分 | 又漏掉（3 分放行） | 废 |

第 2 版的判词其实是对的——它说某张图「手臂追不到肩」，我自己核过确实追不到
（被头发挡住）。**但那不是用户要的**：被遮挡 ≠ 一眼出戏。

问「能不能找出毛病」答案永远是能；问对之后它复现不了用户的阈值。
**再调第四轮就是拿用户的时间赌。**

### 正确的分工

1. **裁出关键区域并放大**。人物只占画幅左 35%，整图缩略里手指级缺陷根本看不见。
   裁 42% 宽、缩到 460px，同样的网格尺寸给到**三倍人物像素**。
2. **密网格**，一屏 40 张，612 张约 15 屏。
3. **点一下标记**，红框 + 半透明，再点取消。存 localStorage。
4. **导出 `<id>|<side>` 清单**，直接喂给 `regen.py`。
5. 模型分数**只用来排序**（把最可疑的排前面），不当判决。

### 定点重出

```bash
python3 regen.py --from-list bad.txt --note "上一版握杖的手臂没有肩部连接"
```

重出时：
- prompt 追加固定的解剖要求段 + 调用方给的具体缺陷描述
- **旧图不删**，改名 `<side>.rejected-N.png` 留在原地——新的不一定更好，得留退路
- 走实时接口不走 Batch（重做通常是几张到几十张，且用户在等）
