# 角色皮肤产线

从「游戏花名册」到「桌面应用换上皮肤并能轮播」的完整链路。
2026-08 在 HarnessUI 上跑通：原神 78 人 / 崩铁 54 人 / 绝区零 45 人，
612 张 3840×2160，**$47.25，一次通过率 92.8%**。

**下面每一条都是踩过才知道的。按顺序做，别跳步。**

## 一次运行长什么样：references/00-run-contract.md

**一个 IP 名字进，两份报告 + 一批已上线的素材出。**

```
输入：一个名字
  ↓  ① 立项报告   scout_ip.py  ← 唯一的停顿点，等用户点头
  ↓  ② 全量跑     试跑 5 条 → batch_run.py
  ↓  ③ 交付报告   delivery_report.py  + 素材总览 + 已部署上线
```

**① 必须有**：素材源、锚图质量（竖/横分布、短边中位数）、逐人清单与变体数、
总变体数与总图数、预估成本、已知缺口、试跑清单。**数字全部来自探测，不许来自记忆。**

**跑的过程中**：`progress.py` 给百分比 + 已完成/未完成 + **远端批次状态**。
批次在 OpenAI 那边烤的时候本机没有任何进程，只看本机进程会全显示「停」——
用户看到的就是「你什么都没在做」。见 `12-progress.md`。

**③ 必须有**：生成总数 / 可用成品 / **废片**（三个都要，不许只报可用）、一次通过率、
API 实付、耗时、三个保存地址、素材总览、上线状态与各宿主的生效方式。

部署在交付报告**之前**完成，七步一步不落，最后一步是**轮播周期清空重洗**——
不重洗，新素材这一轮走完之前一次都不会出现。

## 开工前必读：references/01-requirements.md

**这条排在所有技术细节前面，因为它是最容易丢的。**

用户的硬性要求会散落在几十轮对话里，而且**会被后面的技术细节挤掉**。
HarnessUI 上发生过：用户截图否决 Q 版之后，我改了三个版本的任务包，
而「禁 Q 版」这条**一次都没进过 prompt**——594 条 prompt 里一个字都没有，
直到用户看到成品才发现。

**做法**：开工第一件事是把要求写成一份**可核对的清单**（每条配一个判据，
说明怎么验证它进没进产物），每次改任务包都对着清单过一遍。
`01-requirements.md` 里有 HarnessUI 的完整清单和核对命令。

## 五条贯穿全程的原则

**1. 数产出，不数尝试。**
有质检闭环的产线里，「提交次数」和「成品数」是量级不同的两个数。
HarnessUI 上一度是 3:1（后降到 1.08:1）。我按提交数报「594 张需 59 小时」，
按成品算是 170 小时，**乐观 17 倍**。报产能/工期/预算前先量重试倍率。

**2. 机器判数字，人判审美。**
「有没有三只手」这类判定模型复现不了用户的阈值——试了三轮：宽松版漏掉已知坏图、
严格版 100 张报 83 张、改问「显眼度」又漏掉。机器的职责是**把人工判定变便宜**
（裁出关键区域放大 → 密网格 → 点一下标记 → 导出清单喂给重做），
模型分数**只用来排序**。

**3. 判据太严和太松一样有害。**
补中文名时用「中文条目能否反查回英文页」当判据，一次删掉 9 个——
其中 7 个是对的（中文站没挂互链 ≠ 名字错）。下游立刻把「有」报成「没有」。
按误判的代价方向调判据。

**4. 缺失 ≠ 异常。**
守夜进程在午夜误报停摆，因为日志按天轮转、新文件里查不到时间戳，
而判据把「查不到」当成了「静默无穷久」。任何「距上次 X 超过 N」的判据，
都要先区分「没发生」和「没查到」。

**5. 高价值产物要原生展示。**
一度为「切换快」把 3840 母版压成 380KB WebP，动漫线稿最吃这一刀，用户打 70 分。
实测自定义协议吐一张 7MB 母版只要 **33ms**——那个优化从一开始就没必要。
**为省几百 KB 削掉花钱买来的画质是错的取舍。**

## ★ 公开安全红线（v0.1.0 新增，最高优先级）

本 skill 产出对标**公开抖音**等平台，以下不可协商（依据：`14-public-safety.md` + `13-erotic-levels.md` 实测 + G-尺度分级.csv）：

1. **隐私部位一律不允许暴露**：生殖器/阴部/乳首 必须遮挡（服装/姿态/构图/合规条四选一）。产出物逐张人工复核遮挡后才落登记。
2. **色情度上限 = G 轴 L2**：泳装/沙滩可，但正常站姿、无低机位仰拍、无胸腰臀构图占主导（那属于 L3 = 限流 30 天）。
3. **L2 强制合规条**：帧内烧「海边泳装穿着 无不良引导」（圈子惯例，诚子/星小柯同做法）。
4. **PHYSIQUE 自然体型**：腿/腰/胯照锚图纤细体型，禁加粗（v1.9.2 爱莉希雅「腿太胖」教训）。
5. **分级路由**：需要 L3-L5（色情度拉满）→ 走 **character-skin-sexy**（非公开），本 skill 不产出、不写 L3+ prompt。
6. **版本纪律**：修复版才可发；发前核对素材总账 README 版本标记（v1.9.1 腿太胖不可用）。

> 判定一句话：**公开能发的 = 软色情 + 全遮挡；暴露隐私部位 / 滑向 L3 = 不能发。**

7. **prompt 由配方查表拼出，不再硬编码**（v0.2.0）。九轴唯一真源在
   `04_DouyinOps/00_治理与登记/05_素材维度/`，skill 只读不写；编译器
   `02_通用资产/axes.py` 里有五道硬闸，绕过闸门手写 prompt 视为违规产出。
8. **机位必须显式写进 prompt**。`H.机位` 为空 → 编译器抛错，不生成。
   公开线负向词硬钉 `low angle, from below, worm's eye view` ——
   低机位仰拍是限流实测触发条件（补_B06 限流 30 天），不靠人的记性。
9. **两套 L 分级不许混用**：G 轴 L0–L4 是题材与镜头语言（DouyinOps 唯一权威，
   决定被抖音限流的概率）；**W 轴 W1–W5** 是本 skill 的服装露肤度
   （决定被 OpenAI 安全系统拦的概率）。谁都不许再用裸「L2」说事。
10. **生成后端默认本地**（ComfyUI + WAI-Illustrious v17，$0/张）。
   API 通道保留，配方里 `BACKEND=openai|minimax` 切换；
   用户声明「先不使用 OpenAI API」期间只允许 `BACKEND=local`。见 `18-render-quality.md`。

详情见 `references/14-public-safety.md`；色情度档位表见 `references/13-erotic-levels.md`（公开档 L0-L2，L3+ 属 sexy）。
