## 触发这次迭代的缺陷

**不是新发现的缺陷，是 v0.0.0.9 自己写下的已知缺口**：

> 已知缺口：`check_authorship.py` 目前是独立脚本，靠执行者记得去跑。
> **一个靠记性的门不是门。** 下一版必须接进 `quality_check.py --phase research`。

它还有第二个缺口，当时没看出来与第一个是同一个：
**人物名写死在文件里**（`NAME = r"Michael\s+(?:H\.?\s+)?Steinhardt"`）。

**写死一个人名的检查器只能给一个人用——所以它注定停在「独立脚本」这个形态。**
不参数化就接不进通用门；接不进门就只能靠记性跑。
**两个缺口是一个缺口。**

## 交付物

### 1. `check_authorship.py` 按人物名参数化

`build_patterns(full_name)` 由 `meta.json` 的 `name` 生成全部正则，
判据只依赖**名 + 姓**，中间名一律可选。

**取名字不能用 `\s+` 连接**——`First\s+(?:Middle\s+)?Last` 里两个相邻量词
会争抢同一段空白，正是 v0.0.0.9 实测卡死 120 秒的那个形态。
可选中间名**自带尾随空格**（`first[ \t]+(?:mid[ \t]+){0,2}last`）才无歧义。

### 2. 接进 `quality_check.py`（`run_authorship_gate()`）

- **三个阶段都跑**（research / synthesis / release），实测开销 0.13 秒。
- **门开在账本自己声称的东西上**：只查 `tier == 'P1'` 且 `author` 指向本人物的源。
  账本说「这是他写的」，门就要求它拿出证据。
- **先验负对照**：`self_test()` 不过 → 记 `content.selftest-failed` 并**放弃本次判定**，
  与 v0.0.0.8 三件硬门同一条纪律。
- 判定分三档：**无据 → error（拦）**；**有据但另有他人署名 → metrics 存疑**；
  **无落盘原文 → metrics「未核验（不是通过）」**。

### 3. 内置 `--self-test`（4 正 + 4 反）

此前本检查器**没有负对照**——它是唯一一件没有的硬门。

### 收尾时踩到的一个坑（差点当成「无新增失败」交出去）

第一次跑 `self_check.py` 时多出一条**本次引入的**错误：

```
release checksum verification failed: checksum mismatch: references/pipeline/RUNBOOK.md
```

原因是操作顺序错了：先跑 `build_manifest.py` 生成校验和，**之后**才往 RUNBOOK 追加内容。
重跑生成器即消失。

**→ 定则：`references/` 下任何文件改动之后都要重跑 `build_manifest.py`，
而且必须是所有文件改完之后跑，不能中途跑。**
**更要紧的是：如果我只跑了 `pytest` 就下「无新增失败」的结论，这一条根本不会露面**
——`pytest` 不查校验和，只有 `self_check.py` 查。**验收要跑全套，不能只跑最像的那个。**

## 参数化时实测抓到的一处真回归（本次最有价值的一条）

`ms_2022_medialine_jewish_pride_exclusive.txt`——**44 轮的真逐字稿**——被判成无据。

诊断输出：

```
标签(≥3轮): {'tml': 46, 'ms': 44, 'sb': 20}
旧 MINE 命中: ['ms']
新 MINE 命中: []
```

旧代码硬编码 `^ms$`；我按三段名 `Michael H. Steinhardt` 算出 `mhs`，于是 `ms` 不再命中。

**结论：人在语料里用的缩写取决于他惯用的名字形态，不取决于账本写了几段。**
名姓首字母（`ms`）与全首字母（`mhs`）**两种都要认**。已修，
并把这个形态做成内置负对照的第 4 条正例，**变成永久断言而不是一条记忆**。

**这条正是「判据变更必须双向回归」当场兑现的收益**：
接线负对照（洗白那份被拦住）是我最想验的，若只跑那一边就交付，
**这份真逐字稿会被永久误杀，而且不会有任何报错**——
它只会安静地从 P1 掉出去，表现为「一手比例莫名偏低」。

### 顺带订正一处计数口径

清点时发现 **`## 第五、第六种失败模式` 是一条标题装了两项发现**。

README 里写的是「58 条（标题计数）」，措辞没错，但**用它当分母算转化率就偏了**。

这正撞在 RUNBOOK 第六十一种上——「一篇讲『口径要分清』的产物，自己漏算了它引用的第一组数」。
**同一个毛病，第二次。** 分子分母今后都按「实际发现数」算。
