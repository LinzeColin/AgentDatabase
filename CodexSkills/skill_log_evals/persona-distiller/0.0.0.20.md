# v0.0.0.20 — 产品本身第一次有了负对照的判据

**日期**：2026-08-02　**触发**：用户评分（不是某个人物）
**判据全文见 `CHANGELOG.md` v0.0.0.20 条**，本文件只留证据与自我定责。

---

## 一、触发（用户原话摘要）

> 人物同源同模型同上下文，提供的是**结构化视角差异**，不是 97 份真正独立的认知与判断；
> 存在**相关性错误、共同幻觉、伪共识**；没有「团队相对裸模型在真实盲测任务上
> 提高多少正确率」的公开结果。
> **真正独立性 40%；已证实决策增益不足 40%；实际接近 0 分甚至负收益。**

## 二、诊断：我给每件检查器都做了负对照，唯独没给产品做

第十八种「没有负对照的检查器，其全绿不构成任何证据」执行了三十多个版本，
**从未对整个 600 人工程执行**。「团队比裸模型强多少」就是这个工程的负对照。

## 三、★ 最硬的证据是我自己的评委给的，我记了却没执行

Livermore #100 第 2 轮，E 席原话：

> 17 条 baseline 全是零对冲零出处的稻草人，
> **候选/对照的分差被显著放大，不能当作能力证据。**

**我把这句抄进了提交信息，然后继续用 delta 0.8012 当成绩报。**

这不是「没想到」，是**想到了、写下来了、没有据此行动**。
本项目此前记过一条同型教训（v0.0.0.16：「抓到」和「不再发生」是两件事），
这次是它的第二次发作，而且发作在最要紧的地方。

## 四、实测

```
$ python3 scripts/check_baseline_provenance.py --self-test
负对照通过：正对照 0 报，坏样本 4 类全部抓出（含「缺字段沉默通过」），
且 prior-version 未被误杀

$ python3 scripts/check_baseline_provenance.py <已入库的 Livermore #100>
{"baseline_rows": 64, "by_source": {"unknown": 64},
 "usable_rows": 0, "unusable_rows": 64, "capability_evidence": false}
✗ 64/64 条基线不可作能力证据

$ python3 -m pytest -q          → 69 passed（67 → 69）
$ python3 scripts/check_contract_drift.py → ✓ 无漂移
```

**新门在真实的、已入库的产物上第一次运行就命中 64/64**——
这正是它该有的样子：判据不是为将来准备的，是当场就把现状照出来。

## 五、判定

**通过。** 判据落成、带 4 类负对照（含「缺字段沉默通过」这条最容易漏的）、
镜像同步、真实产物上命中、全量 69 绿。

## 六、这只是四项里的第一项，另外三项**一件都没做**

| # | 事 | 状态 |
|---|---|---|
| 1 | 真基线 | **判据已落成**；Livermore 的裸模型基线正在跑 |
| 2 | 三臂盲测决策增益 | **未做** |
| 3 | 伪共识检测 | **未做** |
| 4 | 有效激活率 | **未做** |

**在第 2 项有结果之前，不得把「专家团队」描述为比裸模型强。**

## 七、已知缺口

1. **只管「基线是什么」，不管「基线跑得对不对」。** 标了 `bare-model-run`
   却实际手写，本门看不出来——它读的是账本字段。堵这个缺口要把裸模型的
   运行记录一并存档并校验，本版没做。
2. **`prior-version` 证明的是「比上一版强」，不是「比裸模型强」。** 本门不替你区分。
3. **该门在 `--strict` 下会让带自撰基线的产物发布失败——这是有意的。**
   既有 100 人不追溯（发布时门尚不存在），但其 delta 一律不得再作能力证据引用。
