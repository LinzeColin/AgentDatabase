## 一、两次，同一天，同一个形态

### ① 相关性错误评分器（group v0.0.0.12）

判据把 g5 的三次产物答案全部判成「混：技术分析之父」，三次错法一致，
在屏幕上长成「**共同幻觉的实证**」。**这句话已经写进草稿了。**

核原文才发现三次都是对的：

> 「把我归入『技术分析之父』**与这句原话直接抵触，本产物不沿用**」

判据分不清「主张 X」与「反驳 X」。

### ② 未覆盖事实评分器（本轮新写）

判据把四条**干净拒答**判成「编造」。其中一条原文：

> 「不知道，也不猜。本产物的事实底册里没有任何婚姻记录——没有年份，没有姓名。
> 他可公开抓取的原话约 22,500 词，**97% 压在 1940 年那一本书上**，
> 那本书讲价格记录和建仓规则，不讲家事……」

判据逐句判：第一句有拒答词，跳过；**第二句没有拒答词**，于是里面的 `1940` 被当成了婚期。
判据分不清「**提到**一个年份」与「**用这个年份回答这道题**」。

### 两次的共同点

| | ① | ② |
|---|---|---|
| 合成负对照 | **全绿** | **全绿** |
| 真实数据 | 一跑就错 | 一跑就错 |
| 怎么发现的 | **读原文** | **读原文** |
| 我差点做什么 | 报「共同幻觉的实证」 | 报「产物编造率 0.2222」 |

> **合成负对照只证明判据在我想得到的形态上成立，
> 而它出错的地方恰好是我想不到的形态。**

这不是判据写得不够仔细。①的 docstring 里我亲手写过「用关键词命中判定，不是语义判定」；
②的 docstring 里我亲手写过「不是『出现了年份』，而是『在非拒答语境里出现了年份』」。
**射程都写了。写了射程，然后照样越过它用。**

## 二、落成

`check_checkers.py` 多报一列：**这件检查器的负对照里有没有至少一条来自真实产出的夹具。**

实测（本次实跑）：

```
负对照里含**真实样本**夹具的：0 / 15

**下面这些检查器只有合成负对照**——只报不拦，但要知道它意味着什么：
  · check_absence_claims.py      · check_activation_yield.py
  · check_attribution_basis.py   · check_authorship.py
  · check_baseline_provenance.py · check_claim_anchors.py
  · check_claim_coverage.py      · check_contract_drift.py

  · check_refusal_overflow.py    · check_schema_drift.py
```

**一件都没有。**

只报不拦：硬拦会把 15 件一起拦下，与 `NO-SELFTEST` 同一条纪律
（「不因为过不了门而卡住流程，但绝不为凑数放宽判据」）。

## 三、射程（必须一起说）

它判的是**源码里有没有写下真实夹具的标记**。

这一项**只能判源码文本**——它问的是「有没有写下真实夹具」，没有别的可观测量。
与 `_has_flag` 去问 `--help`（有运行期证据可问）不同，这里没有。

**贴个标记就能骗过它。它挡的是「压根没想过」，不是说谎。**

## 四、元负对照做了两向

- 五个合成夹具都没有标记 → 必须**全判 False**（不许误报）；
- 临时写一个带「真实样本」标记的 → 必须**判 True**（不许漏报）。

两向都做，是因为单向只能证明它「会报」或「不会乱报」中的一件。

## 五、被修的两件判据现在长什么样

| | 修法 | 新增的负对照 |

所以上面那个 `0 / 15` **没有把它算进去**。**普查数的是仓库里的检查器，不是我的临时脚本。**
