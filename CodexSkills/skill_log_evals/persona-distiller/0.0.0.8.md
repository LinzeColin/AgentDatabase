## 触发这次迭代的缺陷

Icahn #92 → Salatin #95 这五人暴露的严重缺陷**全部属于内容层**，
而当时三个官方门全绿。门原本只查**结构完整性**（文件在不在、字段全不全、数量对不对）
——**而结构完整的产物完全可以每一句都错。**

## 交付物

七件检查器（`scripts/check_*.py`）：

| 检查器 | 拦什么 | 原门为什么看不见 |
|---|---|---|
| `check_claim_coverage` | 装饰性引用：引了源但源正文里没这事实 | 门只数 source_id 个数，不看内容 |
| `check_quote_integrity` | 伪造引文 | 门不接触原始语料 |
| `check_semantic_residue` | 订正换个措辞又活了 | 门不知道什么被订正过 |
| `check_absence_claims` | 无依据的「从未／只有／完全没有」 | 门不判断断言强度 |
| `check_redundancy` | 同一事实在一段里说两遍 | 门不看可读性 |
| `check_schema_drift` | 订正脚本留下的字段污染 | 门忽略多余字段 |
| `check_claim_anchors` | claim 标记错挂 | 门只查计数，错挂不改变计数 |

### 接线

`quality_check.py --phase release` 新增 `--cache`，跑 `run_content_checks()`：

- **硬门**：装饰性引用、订正残留、以及**检查器自身的负对照**
- **只列不判**（warnings）：绝对化断言、段内冗余、字段漂移、claim 锚点
  ——它们有已知的合理误报形态，自动判定会误伤
- **不给 `--cache` 时不静默跳过**，记 warning 明说「本次未做内容层核验」
  ——**「没查」与「查过没问题」必须能被区分**

## 执行的验证（转述自 CHANGELOG，本记录未复跑）

三件硬门检查器各带负对照（`--self-test`）：

- `check_quote_integrity`：4 类伪造全抓（含「真句只改一个词」），36 条真引文 0 误报
- `check_semantic_residue`：双向 2/2
- `check_claim_coverage`：5 向

**负对照不过 → 该检查器结论一律不作数**，这一条本身也是硬门。
理由：引文检查器的前两版误报率都是 100%，照着误报去订正会把真引文改坏。

## 接线时踩的坑（转述）

1. `pathlib.Path` 与 `from pathlib import Path` 混用。
2. 判据写成 `'结论: 通过' not in out`——**而「不通过」这个串包含「通过」**，
   判断整个反了：真有装饰性引用时反而放行。改用退出码。
   **中文子串匹配天然有这个坑：否定式包含肯定式。**

## 事后评价（2026-07-28，由 v0.0.0.9 的发现回看）

**效果显著**：它第一次让「所有门全绿而产物有真错」这一整类问题可拦截。

**但它有一个当时未被发现的共同假设**：**七件检查器都假设「语料里的话就是他的话」**。
Steinhardt #98 证明这个假设可以整体失效——抓源冠名 ＋ `--author` 参数两步，
就能把别人的文章洗成人物本人的话，而七件检查器一件也拦不住。
`check_quote_integrity` 甚至会给出「这句在语料里」的肯定结论。

**这不是 v0.0.0.8 的实现缺陷，是它的作用域边界。**
由 v0.0.0.9 的 `check_authorship.py` 补上，见 [0.0.0.9.md](0.0.0.9.md)。
