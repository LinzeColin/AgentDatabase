# 「它是公有领域」不是一条依据，是四条（现在是五条）——而我把其中两条混成了一条

日期：2026-08-04　起因：#119 Michael DeBakey 可得性探测

---

## 一、混淆本身

DeBakey 的三卷政府出版物（*Vascular Surgery* 1955、*Cold Injury* 1958、
*Thoracic Surgery Vol II* 1965）**确实是公有领域**。

我排期时的直觉是「他当过联邦官员 → §105 联邦职务作品 → 他那一时期的东西都是 PD」。
**这个推论是错的。** 探测取到的作者脚注实录：

> \* Professor and Chairman, Department of Surgery, Baylor University College of Medicine.
> **Formerly** Colonel, MC, AUS.

1955/1958/1965 年他是**贝勒大学的平民教授**。§105 要求「联邦雇员/官员在职务范围内完成」，
**不满足**。这三卷是 PD，依据是**「1978 年前出版、无版权标记」（1909 年法）**。

## 二、为什么这不是文字游戏——两条依据的**射程**完全不同

| 依据 | 射程 | 能不能外推 |
|---|---|---|
| §105 联邦职务作品 | 这个人**在联邦任内**写的东西 | **能**——同期其他作品同理 |
| 1909 年法无标记 | **这一份印本**上没有版权标记 | **不能**——一份一份地判 |

把后者当成前者，就会得出「他有 §105 的口子、语料可望够 deep」。
**实际口径是 0 份、0 字。**

## 三、探测同时暴露的第二类错误：机构署名当成个人一手

两份联邦委员会报告（1964 总统心脏病/癌症/中风委员会 Vol I、1949 胡佛委员会）
探测报告标了 **P2（计入一手）**。它们是联邦出版物、是 PD，
**但 1964 那份是 28 名委员集体署名，1949 那份他只是分委会成员之一**。

**署名是机构不是人 → 归「归属不成立」，不是一手。**
一手份数 15 那个数没受影响（P2 本就单列），受影响的是那 89,236 字的**性质**：
**它不是他的散文。**

## 四、落成了什么

`scripts/check_pd_grounds.py`（v0.0.0.85，18 项自测，11 组反向对照）。

它要求每条 PD 主张**具名依据 + 附证据**，五条依据之一：

```
sec105           17 U.S.C. §105 联邦职务作品
notice1909       1909 年法：1978 年前出版且无版权标记
pre1929          1929 年前出版，版权已过期
congressional    国会记录/听证，GPO 印无标记
unpublished_303  17 U.S.C. §303 未刊作品：卒年+70，且 2003-01-01 下限已过
```

把住的：

- **只写「公有领域」不写凭哪一条** → 报出
- **§105 的证据里出现 `formerly`／卸任／退役** → 报「§105 不成立」
- **§105 拿「GPO 出版」当依据** → 报出（这是本判据的头号目标）
- **1909 那条必须报核验强度**，`html-transcript` 是弱、须显式承认
  （扉页背面是版权标记的常规位置，转录站可能根本没转）
- **§303 必须给卒年**，且证据里要有未刊/手稿表述
- **机构署名却标 P1/P2** → 报「归属不成立」

**它不做什么：不判某份东西是不是公有领域。** 那是调用方和法律的判断；
本件只核**主张的形式是否完整、证据是否与所主张的依据同类**。

## 五、真数据回归——判据在它诞生的那个错误上全中

```
把三卷 GPO 卷册按我原本的直觉标成 §105：
  报出 5 处，三卷一卷不漏
  「§105 且本人署名」从 **3 条** 纠正为 **0 条**
同一跑另抓出探测报告自己的分档错误：两份委员会报告标 P2 → 归属不成立
```

Blackwell #118 的 95 份台账也补齐了依据表：`pre1929` 45 份、`unpublished_303` 50 份。
那 50 份是 LoC 手稿（日记、书信、未刊讲稿）——**台账自己在 50 份上都写了手稿/未刊/LoC**，
不用假设。它们的依据不是「1929 年前出版」（它们从未出版），是 §303。

## 六、★★ 接线过程中，判据当场把我的老毛病做了出来：**覆盖率 104%**

第一版 `coverage()` 拿「依据条数 vs 工作区源目录数」相减，真数据一跑：

```
总条数 95　台账来源份数 89　写了依据的 93　**覆盖率 104%**
```

**一个不可能的数。** 分子来自台账 `raw/_ids.txt` 的 95 行，
分母来自工作区 `references/sources/` 的 89 个目录——**两组数不在同一个标识符空间**。
（89 是 train，另有 6 份在 `holdout/`。）

这正是长期记忆里记着的那条：
**「拿到两组数就相减，而没有先问这两组数是不是同一个空间里的」——我的默认失误形态。**

**修法不是调分母，是让这种错不可能再发生**：`coverage()` 只接受**标识符集合**，
分子取交集（所以覆盖率永远 ≤100%），并且

- 缺的**逐个列出来**，不是只报一个差值
- **主张指向台账里没有的 id → 单独报**，因为那说明两边根本不是一套东西

自测里为此留了一组反向对照，直接复现 104% 那一幕。

### 改完之后它立刻又抓到一处——这次是我生成依据表的脚本

```
覆盖率 98%　没写依据的 2 →
  ["letter-parsons-1848-06-24", "letter-parsons-1851-12-07"]
```

**它点名了是哪两份。** 成因：我按**标题**建 `work → short` 映射，
两封 Parsons 信标题相同，被折叠成一条。改成直接从台账行取 `short` 后 95/95、100%。

**如果 coverage 还是「条数相减」，这两封会被 93 vs 95 的差值盖过去，
永远不知道是哪两封。**

## 七、三条要带走的

1. **「公有领域」这四个字不是依据，是结论。** 写产物时必须写凭哪一条。
   两条依据可以指向同一个结论而射程天差地别。
2. **联邦出版物 ≠ 联邦职务作品 ≠ 个人一手。** 三个概念，DeBakey 一人身上全踩到。
3. **凡是要报「覆盖率/完整率」，先证明分子分母是同一个标识符空间。**
   份数相等不代表是同一批东西——这已经是第 7 次了。
