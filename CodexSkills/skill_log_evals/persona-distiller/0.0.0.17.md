## 一、触发缺陷（实测数字）

他唯一的亲笔著作《How to Trade in Stocks》(1940)，只有 OCR 文本可得：

```
$ python3 scripts/check_ocr_homoglyphs.py --mode corpus jl_1940_HowToTradeInStocks_01.txt
· 语料层（只报不拦）：1 份文件含同形字
  - jl_1940_HowToTradeInStocks_01.txt：非拉丁字符 1405 个／全同形字词 314 个／混文种词 0 个
      'ТО' 其实是 'TO'
      'Ву' 其实是 'By'
      'а' 其实是 'a'
```

12.5 万字英文，**1405 个西里尔字符**。`РКЕҒАСЕ`（=PREFACE）七个字母全是西里尔同形字。
**连署名的 `By` 都是西里尔的**——这也解释了归属门为什么会认不出他自己的书。

**已有的七件内容检查器一件也拦不住**：`check_verbatim_quotes.py` 拿引文回语料比对，
从语料里复制一段带同形字的话，它会说「找到了」——它回答的是「语料里有没有这句」，
不是「这句里的字符是不是真的」。

## 三、新增的两条测试，第二条才是要害

```python
def test_verbatim_quote_check_cannot_see_ocr_homoglyphs(self):
    """回归：逐字引文检查会说「找到了」，因为脏字符在语料里确实存在。"""
```

**它把两件门的分工钉死**：`check_verbatim_quotes` 答「语料里有没有这句」，
`check_ocr_homoglyphs` 答「这句里的字符是不是真的」。
没有这条，将来有人看到两件门功能重叠就会删掉一件。

## 四、自测把我自己抓出来的一次

断言原本写的是「`РКЕҒАСЕ` 应还原为 `PREFACE`」，**跑出来是 `PKEFACE`**——
第二个字符是 `CYRILLIC CAPITAL LETTER KA`（长得像 `K`），
**OCR 把原文的 `R` 认成了 `K`，并且用西里尔字母写出来**：错了两层。

> **同形字表只能揭示「这里出过 OCR 错」，不能告诉你原文是什么。**
> 拿 `restore()` 的输出当「修好的引文」交付，就是编造。

断言已改为断言 `PKEFACE` 并加注，**保留它正是为了钉死这个边界**。

## 六、已知缺口（**本版没解决**）

1. **同形字表手工枚举，必然不全。** 只收字形上真会混的那些；
   Unicode 混淆表远比这大。**它的价值在零误杀，不在全覆盖。**
2. **只查西里尔与希腊**，其他文种未收。
3. **纯拉丁范围内的 OCR 误认看不见**：`JESSE 1. LIVERMORE`（`L.`→`1.`）、
   `COPYRIGHT, 1040`（1940）——这两个都在同一本书的版权页上，**本门一个也抓不到**。
   要抓需要词典或语言模型，是另一件事。
4. **引文抽取靠引号配对**，没有引号的整段引用抓不到。
5. **归属门与 OCR 的交互未处理**：这本书的署名页被 OCR 成
   `BY / JESSE 1. LIVERMORE`（换行 + `L.`→`1.`），`check_authorship.py` 的
   `\bBy\s+<名><姓>\b` **匹配不上**——**正版署名反而认不出来**。
   本版没有为此放宽归属判据（放宽会同时放进别人的文章）；
   Livermore 这一份改用**逐段人工分层 + 在账本里写明**的办法处理，
   并把「扫描件的署名页需要另一种判据」记为下一版候选。
