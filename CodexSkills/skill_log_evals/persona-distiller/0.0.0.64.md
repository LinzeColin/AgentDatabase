# v0.0.0.64 —— 一个只会数数的判据，把一条对的记录改成了错的

日期：2026-08-04　撞出场景：给 Galen #101 补语料时自己造出来的

---

## 一、事情的经过

`check_corpus_presence` 从 v0.0.0.61 起只做一件事：
**账本条数 × 0.9 ≤ 语料 .txt 份数**。

v0.0.0.46 的手工审计曾记「Harvey #103 语料也缺」。
2026-08-04 我用这个判据复扫，得到 `46 / 60 ✓`，
于是把那条记录**「改正」为「Harvey 是齐的」**——并写进了长期记忆。

今天加上逐条解析之后：

```
wip-harvey-103    账本 46 条、磁盘 60 份、**指得到 0**
wip-galen-101     账本 60 条、磁盘  9 份、**指得到 0**
```

Harvey 的账本每一条都指
`raw/src-6fbbcce30c38/hv_works_willis_1847.txt`，
磁盘上却是 `raw/s_bub_gb_CdDfAc_ENH0C.txt` 这样的扁平文件名。

**那 60 份与那 46 条是两批互不相干的东西。**
份数相减，得出「多了 14 份，很健康」。

**v0.0.0.46 原本的记录是对的。是我用一个只会数数的判据把它改错了。**

## 二、判据改成三项，缺一项都会放过一整类

| | 问的是 | 漏了它会怎样 |
|---|---|---|
| ① 份数 | 账本 × 0.9 ≤ .txt 份数 | 语料整批没了也看不出（v0.0.0.46 的原始动机） |
| ② **指得到** | 每条 `local_path` 解析得到文件吗 | **两套编号被判成健康**（Harvey / Galen） |
| ③ **字节对** | 解析到的文件 sha256 == 账本 `checksum` | **换了内容的同名文件被判成原件** |

三项在报告里**分开列**，因为修法不同：

- 缺 → 去补；
- 指不到 → 去查是不是两套编号（改路径还是重新入库）；
- 字节不对 → 去查抽取方式。

**混为一谈会指错修法。**

## 三、③ 是我自己造出来的场景

同一天我试着补 Galen 的语料：账本 60 条、磁盘 9 份，
缺的 55 条全部指向 `github.com/galenus-verbatim/galenus_cts`（TEI-XML），
而那个仓库的副本还在会话 scratchpad 里。

我把 TEI 正文转成纯文本写回账本记的 `local_path`，
**份数当场 9 → 64，本判据变绿。**

逐份核校验和：

```
galen_tlg001_grc.txt: 账本 e8c851e990d2… vs 现盘 919d51eecb6d…
galen_tlg002_grc.txt: 账本 ebf8865c0051… vs 现盘 455fb20ae64b…
galen_tlg003_grc.txt: 账本 fea0902dd7f3… vs 现盘 b806d47f8812…
```

**55 份无一相同。** 抽取方式与当初入库的不同——我只取 `<text>`、丢掉
`teiHeader`、做了空白归并；当初用的是别的做法，具体哪一种已不可考。

### 处置

- 那 55 份**撤到 `_rederived_checksum_mismatch/`** 并附说明，
  **不留在 `raw/` 里冒充原件**。
- **没有去改账本的 `checksum` 迁就磁盘**——那等于让账本去迎合它本该监督的东西。
- 缺口重新显形：`wip-galen-101　60　9　**缺 51**`。

台账里已记过三次「判据绿了但指错了文件」。**这一次是我自己造的，所以立刻撤。**

## 四、自测当场抓出的两个接线错误

**① `local_path` 是相对工作区根的，不是相对账本所在目录。**

我按 `ledger.parent` 解析。账本有两种布局（顶层 / `evidence/` 下），
后一种布局里**一条也解析不到**，于是「0 份对不上」——**看起来像全对**。

本文件开头早就为「找账本」警告过这两种布局。**同一个坑在另一处又咬了一次。**

**② 校验和一支必须与「文件不在」分开计。**

文件不在时不能算进「字节不对」，否则报告会把「去补」和「去查抽取方式」
两件事混成一件（反向对照 ⑦ 守这一条）。

## 五、自测

19 项，其中 **12 条反向对照**。新增的四条：

```
── ★ 正向 ②：**份数够了，字节不对**（v0.0.0.64，我自己造出来的场景）──
  ✓ 20/20 份数齐 → 份数那一支不报
  ✓ **但 15 份校验和对不上 → 报出**
── 反向对照 ⑥：字节对得上的不许报 ──
  ✓ 20 份全部一致 → 校验和那一支 0
── 反向对照 ⑦：文件不在算「缺」，不算「字节不对」──
  ✓ 20 条账本、5 份文件 → 报缺，且校验和那一支为 0
── ★★ 正向 ③：**账本一条都指不到文件**（Harvey #103 的真实形态）──
  ✓ 46 条 / 60 份 → 份数那一支仍判「不缺」
  ✓ **但解析到文件的条数是 0 → 这才是真相**
── 反向对照 ⑧：路径对得上时，解析条数要如实反映 ──
  ✓ 30 条全部指得到 → 解析条数 30

✓ 自测全过
```
