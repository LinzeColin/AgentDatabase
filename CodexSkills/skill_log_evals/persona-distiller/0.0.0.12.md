## 交付物

### `check_checkers.py`（元检查器）

四档判定，**一律按退出码 ＋ argparse 报错形态判，不按输出串**：

| 档 | 判据 |
|---|---|
| `OK` | `--self-test` 独立可跑且退出码 0 |
| `NOT-STANDALONE` | 有 `--self-test`，但还要求别的参数 |
| `NO-SELFTEST` | 根本没有 `--self-test` |
| `FAILED` | 能跑但退出码非 0 |

**为什么不能按串判**：七件检查器的通过标记各不相同
（`负对照通过` / `自测 5/5` / `✓ 无关文本被放过`），
按串匹配等于只认其中两件的写法。且中文里「不通过」包含「通过」（v0.0.0.8 已踩）。

所以其余检查器有没有负对照，从来没有人问过。

## 交付前被自己的普查结果抓到的一处缺陷（本版最该记的）

第一次跑普查，6 件全被判成 `NOT-STANDALONE`。
而 `grep` 明明说其中 5 件源码里**根本没有** `self_test`。

**根因**：argparse 缺必填参数时**先报这一条就退出**，
永远不会再报「unrecognized arguments: `--self-test`」——
于是「压根没有 `--self-test`」与「有但还要别的参数」落进了同一个分支。

**而我的元负对照没抓住它**，因为我的样本 `check_meta_none.py`
把 `--workspace` 写成了**可选**参数，真实的检查器写的是**必填**。

> **负对照的样本必须覆盖真实形态，否则它只验证了我想象的形态。**

修法是**再问一次 `--help`**（判源码文本会被注释和文档字符串骗到），
并补上第 5 档样本「没有 `--self-test` ＋ 有必填参数」。

**注意这一条的位置**：它是在**我为「检查负对照」而写的检查器**上，
犯了**负对照覆盖不全**的错。**元检查器自己需要元负对照，
而元负对照同样会漏掉真实形态。** 这不是悖论，是提醒：
**任何一层的负对照都只覆盖它想到的形态，所以每一层都要拿真实数据再跑一次。**
本版是被真实的 12 件检查器跑出来纠正的，不是被样本纠正的。
