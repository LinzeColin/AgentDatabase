# v0.0.0.23 — 分族配重：**每一步都合规，而名册会停在 11 族**

**日期**：2026-08-02　**触发**：#100 完成后跑 `next_person.py`，`upcoming` 前六名同族

---

## 一、这个缺陷长什么样

`next_person.py` 从来没出过错。它按队列的 `priority, order` 取第一个待办，
每一次都是队列里最该做的那个人。**问题在队列的 `priority` 是按语料可取得性排的。**

100 人时的实测分布：

| 族 | 人数 | | 族 | 人数 |
|---|---:|---|---|---:|
| 软件开发师 | 34 | | 政治法律师 | 5 |
| 投资资本师 | 21 | | 思想教育师 | 2 |
| 材料建工师 | 15 | | 农林牧渔师 / 客户营销师 / 艺术设计师 / 财务合规师 | 各 1 |
| 建造采购师 | 12 | | **医疗护理师** | **0** |
| 创业经营师 | 7 | | | |

而 `NEXT` 与 `upcoming` **前六名全是材料建工师**——已经是第三大族。

队列里医疗护理师有 **21 个候选，`priority` 全是 11（最末档）**。
按原顺序，要先做完其余 195 个才轮得到第一个。
**名册会停在「11 族 + 一个空族」，而排期口径全程合规。**

> 这是「判据测的是代理量」的另一种形态：
> **`priority` 测的是「语料好不好拿」，我却拿它当「下一个该做谁」。**
> 两者在前 30 人高度相关，在第 100 人时已经彻底脱钩。

## 二、判据

```
slot = registry_products % round        # round 默认 5
slot == 0 且最少族有待办 → 从最少族取（该族 priority/order 最小者）
否则                    → 按队列原顺序取
```

**轮首不轮尾。** 轮尾会让「这轮没做完」等价于「这轮没配重」——
而这个项目的轮**经常没做完**（Steinhardt #98 就跨了两个会话）。

配重**默认开**。`--no-counterweight` 只为负对照存在，
文档里写死「**日常不要用它**」——一个默认关着的配重等于没有配重。

## 三、负对照六项，关键是第二项

| # | 项 | 判什么 |
|---|---|---|
| 1 | 轮首把 0 人族提上来 | 配重在该发生时发生 |
| **2** | **关掉配重必须复现漂移** | **开与关若选出同一个人，配重是装饰** |
| 3 | 非轮首 4 格均不配重 | 它是 1/5，不是每次 |
| 4 | 最少族无待办 → 退到次少族 | 凑满 50 的族不会把配重永久卡死 |
| 5 | 队首已是最少族 → 不重复 | 不做无意义的替换 |
| 6 | 缺 `category_counts` → 显式报告 | **读不到不许静默退化** |

第 6 项是照抄团队侧 `read_group_version` 的教训：
**读不到就返回一个恒等成立的默认值，会让「读不到」与「没问题」在机器眼里长得一样。**

实测：

```
负对照通过：轮首把 0 人族提上来；**关掉配重确实复现漂移**（证明它不是装饰）；
非轮首 4 格均不配重；最少族无待办时退到次少族；队首已是最少族时不重复；
缺 category_counts 时显式报告而非静默
```

## 四、真队列实跑

```
NEXT: Hippocrates（医疗护理师，priority 11, order 1）
why:  mode = counterweight, slot = 0
      least_family = 医疗护理师（0 人）
      displaced = Nikolai Slavyanov（材料建工师，已 15 人）
      reason = 轮首配重：名册里「医疗护理师」只有 0 人，
               而队列原本要给「材料建工师」（已 15 人）再加一个
```

`why` 字段是本版一并加的。**看不见理由的排期等于没有排期**——
配重顶掉了谁、为什么，必须在同一份输出里看得到，否则下一个人只会觉得它选错了。

## 六、遗留

**这个配重解决的是「排期」，不解决「队列本身」。**
医疗护理师被排到最末，是因为建队列时按语料可取得性给了 `priority 11`。
配重把它提上来了，但**队列里其余 11 族的相对次序仍是同一个口径排的**。
真正的修法是任务 #16（补齐 292 人进队列，各族凑满 50）时**重排 priority**，
把「族内优先级」与「族间排期」分成两件事。**本版没做这件事，记在这里。**
