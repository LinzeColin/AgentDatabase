## 一、触发：席 E 自己交代盲判破了

Barton #117 第 3 轮判完，长度门是干净的：

```
共有题 32 道；候选 8065 字，基线 9081 字
**总体均长比 0.89**（门 ≤1.3）　**候选更短 23/32 = 72%**（门 ≥25%）
  ✓ 长度指不出哪一侧是哪个系统
```

**就长度而言这句话没错。** 然后席 E 在报告第八节写：

> 按行文风格（用不用粗体与反引号）分成两组，**32 题干净分开，无一例外**
> ——所以这份数据靠一行正则就能破盲，我在评的过程中不可避免地知道了哪句属于哪一组。

### 实测输出（原文照录）

```
候选带标记的题：32/32   均 10.2 个
基线带标记的题：0/32    均 0.0 个
★ 「有无标记」这一条规则单独就能分开的题：**32/32**
  分不开的：一道也没有
```

**不是梯度信号，是二值的完美破盲。** 长度那次（Lister #108 R3）好歹还要评委估个字数。

### 不是一个人的事

```
人物                             候选带标记     基线带标记        单条正则可分
alexander-fleming             32/32       4/32        28/32
clara-barton                  32/32       0/32        32/32    ←全分开

★ 合计 **116/128 = 91%** 的题，靠「有没有粗体/反引号」一条就能指认候选侧
```

成因朴素：**候选由本流水线写成 Markdown，基线是裸模型的散文。两支笔，笔迹一直在纸上。**
**只有这 4 个人留了成对载荷，其余 113 人查不了——不是「没问题」，是没有数据。**

## 二、判据推广并改名

`check_answer_length_leak.py` → **`check_answer_surface_leak.py`**。
留着旧名字就是让下一个人以为它只管长度。

判据从「长度不许指认候选侧」推广为**「任何单一表面特征都不许指认候选侧」**，
量**定向可利用率** ＝ `max(只有候选具备, 只有基线具备) / 共有题数`，门 **≤75%**
——与 `shorter_frac ∈ [25%,75%]` **同源，不是新标准**。

### 通道不是拍脑袋列的，是逐条量出来的

| 通道 | Barton | Nightingale | Fleming | Osler | 处置 |
|---|---:|---:|---:|---:|---|
| 粗体/反引号 | **100%** | 94% | 88% | 81% | 收 |
| 空行分段 | **81%** | 50%（方向相反） | 3% | 0% | 收 |
| 破折号 —— | 25% | **59%** | **56%** | **56%** | 收 |
| 项目符号 | 28% | — | — | — | 收 |
| 直角引号「」 | 31% | 16% | 19% | 31% | **★ 不收** |
| 弯引号“” / 西文双引号 | 0–3% | 0% | 0–3% | 0% | 无信号 |

### ★ 直角引号故意不收——这是相容性核过之后的决定

四人 16–31%，**远在门下（两侧都在用）**。更要紧的是
`check_verbatim_quotes` 的正则是 `「([^」]{16,})」`——**它就是靠这个认出逐字引文的**
（它不认反引号）。

**若为了「更不像 Markdown」把引号也去掉，等于把三道引文判据一起弄瞎**，
它们会**因为找不到引文而静默通过**。已写进判据源码与生成母版。

### 接线上另修一处

**通过分支原先只回显长度那一行**，格式通道的数根本不打印。
**Barton 正是这么过的**——人看到「长度指不出哪一侧」，于是以为盲判成立。

### 泄题门提前到生成载荷那一步

Barton 的格式泄题是**第 3 轮判完之后**才被说出来的，**三轮判分全部作废在这上面**。
门装在发布阶段是对的，但那时候三轮已经用掉了。
`build_blind_payload.py` 现在生成载荷时当场跑，**未过退出 1、不许派发**。

## 三、汇总脚本同一处除以 10 做了两遍

发布门报 `candidate overall 0.080`，汇总同一份数据报候选均分 **0.797**；
而且汇总自己内部就对不上：**0.797 − 0.824 = −0.027，它却报 −0.0027**。

量纲归一（第 32–34 行）是**后加的**，三处旧的 `/10.0`（第 43／51／68 行）**一个都没删**。

| | 报过的 | **真值** |
|---|---:|---:|
| 三轮 delta | −0.0043 / −0.0009 / −0.0027 | **−0.0433 / −0.0089 / −0.0273** |
| 发布门 overall | 0.080 | **0.797** |
| 发布门 boundary | 0.081 | **0.812** |
| 发布门 fact-preservation | 0.085 | **0.848** |
| 断言配比相关系数 | r=+0.340 | **r=+0.388** |

**它躲过三重复核**：汇总把均分与 delta 分两行打印、**从不校验两者相等**；
发布门只读文件、**不知道文件该长什么样**；我每轮盯的是**趋势**
（−0.0043→−0.0009→−0.0027 逐轮向零），**而量纲错误不改变趋势。**

### 修法不是加断言，是收成共享件

本次数据本就在 0–1，「分数须在 0–1」那条**拦不住**。
两件每人一份的临时脚本已收成 `scripts/` 下的共享件：

- `assemble_judge_results.py`（11 项自测，**含一组直接复现该 bug 的反向对照**）
- `build_blind_payload.py`（7 项自测）

**delta 与均分之差在同一个函数里算出，没有地方可以插进第二次除法。**

这是「临时脚本不经过任何门」在同一位置的**第 4 次同形复发**。
