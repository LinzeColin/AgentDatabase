# 抓源台账 `raw/_ids.txt` 的固定格式 —— **写抓源指令时整段抄进去**

日期：2026-08-04（由 v0.0.0.77 的射程实测引出）

---

## 为什么要固定

台账格式一直是**每份指令各写各的**，于是十个人写出了三种格式：

| 格式 | 人物 | 有分档列吗 |
|---|---|---|
| 9 列制表符 | #115 Slavyanov、#111 Fleming、#112 Nightingale、#110 Osler、#109 Virchow | **有** |
| 竖线分隔 | #107 Koch、#108 Lister、#106 Pasteur、#105 Semmelweis | **没有** |
| 竖线四列 `id｜道｜年｜题` | #104 Jenner | **没有** |

后果实测：`check_corpus_ceiling`（入库前那一路）**十份台账只认得 5 份**。
另外五份只能报「判不了」——**这是对的（总比报「0 份一手」好），但等于没有保护。**

**入库之后不受影响**（`evidence/source-ledger.jsonl` schema 统一，
v0.0.0.77 起判据优先读它）。**但抓之前正是最该拦住的时候**——
#115 Slavyanov 就是抓完 53 份、花掉 65 分钟，才发现一手只有 8 份。

## 格式

首行注释：`# ── #<编号> <姓名> (<生卒>, <一句话身份>; wrote in <语种>) corpus ledger ──`

随后每份一行，**制表符分隔，恰好 9 列**：

```
短名<TAB>URL<TAB>篇名<TAB>年份<TAB>出处定位<TAB>语种<TAB>分档<TAB>标记<TAB>说明
```

| 列 | 内容 | 硬要求 |
|---:|---|---|
| 1 | 短名 | **与 `raw/<短名>/<短名>.txt` 的目录名一字不差** |
| 2 | URL | **必须是你真的取到过内容的那个** |
| 3 | 篇名 | 照录，不许凭印象 |
| 4 | 年份 | 只能来自文档本身／档案卡片／同卷可读的日期行，**并在第 9 列说明来源** |
| 5 | 出处定位 | 在卷内的物理位置（行号区间、页码、卷期）。**读不出页码就不写页码** |
| 6 | 语种 | `ru` / `en` / `de` … |
| 7 | **分档** | **`P1` / `P2` / `S1` / `S2` / `U` 之一，必须有** |
| 8 | 标记 | **归属标记必须恰好一个**：`HIS-OWN` / `CO-AUTHORED` / `THIRD-PARTY` / `ATTRIBUTION-UNCLEAR` / `OTHER-INVENTOR`；可另加 `POSTHUMOUS` / `TRANSLATION` / `DUPLICATE-SCAN` / `OCR-POOR` / `FULL-PAGE-SCAN` |
| 9 | 说明 | **必须以 `lane=<六条道之一>. ` 开头**，其后写你看过文档后的判断依据 |

分档的定义（**相对本人物而言**）：

- `P1` = **他亲笔／署名**的著作、专利、报告、书信
- `P2` = 同一材料的**降质版本**（重复扫描、OCR 更差、**译本**）
- `S1` = **同时代**第三方
- `S2` = **后世**研究／教科书
- `U`  = 无法定档（**入库后不计入 usable，会拉低可用份数**）

六条道：`writings` / `expression` / `conversations` / `decisions` / `timeline` / `external`

## ★ 抓源指令里必须一并写死的三句

1. **「分档列（第 7 列）不许空」**——它一空，入库前的一手占比就判不了。
2. **「归属标记恰好一个」**——多一个少一个都会让下游计数错。
3. **「`lane=` 必须写」**——`conversations` 为空是**硬失败**
   （`min_lanes 6`，standard 与 deep 都过不去），
   **抓的时候就要知道这条道有没有东西，而不是入库后才发现。**

## ★★ 抓完之后、入库之前，跑这一条

```bash
python3 scripts/check_corpus_ceiling.py --ledger <wip 目录>/raw/_ids.txt --profile deep
```

它会告诉你三件事：**这一档要几份一手**、**手上够不够**、
以及**是不是只有丢掉材料才够得着**（那是缩分母，不是达标）。

退出码：`0` 够得着 ／ `1` 够不着或要缩分母 ／ `3` **判不了（不是通过）**。
**看到 3 就说明台账格式没按本文件写。**

## 它防不住什么

- **防不住分档判错。** 台账写 P1 它就当 P1——格式对不等于内容对。
- **防不住「再抓能不能抓到」。** 只算手上这批的上限。
- **本文件不是判据，是指令模板的一部分。** 真正把关的是上面那条命令。

## ★★ 2026-08-04 新增：**每条来源必须写权利依据 `rights_ground`**

`build_source_ledger.py` 现在**强制**每条来源给出 `rights_ground`，七条具名取值之一：

| 取值 | 含义 | 附加要求 |
|---|---|---|
| `sec105` | 17 U.S.C. §105 联邦职务作品 | **须有在职证据**；见到 `formerly`／卸任表述即不成立 |
| `notice1909` | 1909 年法：1978 年前出版且无版权标记 | **须报核验强度**（扫本 OCR 是强，HTML 转录是弱且须显式承认） |
| `pre1929` | 1929 年前出版，版权已过期 | 年份须真的 < 1929 |
| `congressional` | 国会记录/听证，GPO 印无标记 | ★ **「印在《国会记录》里」≠ PD**——先判是委员会程序产物还是第三方转载 |
| `unpublished_303` | §303 未刊作品：卒年+70，下限 2003-01-01 | **须给卒年**，证据里要有未刊/手稿表述 |
| `publicly-accessible` | 公开可读、无付费墙、未绕过访问控制 | ★ **这不是公有领域**——记录口径认它，权利口径见待裁定 ⑧ |
| `other` | 以上都不是 | **须在 `rights_note` 里写清是什么** |

★★ **「公有领域」四个字本身不算依据**——它是**结论**，不是依据。
写它会被判据报「不具名」。

★ **任一条不过，`build_source_ledger` 就退出，一行都不写。**
真数据回验：Blackwell 旧台账 95 条倒回，**报出 95 处、全部是「没写权利依据」**
——旧数据喂进新校验会响，不会静默通过。

示例见同目录 `PD_GROUNDS_EXAMPLE_debakey119.json`
（那是 `_pd_grounds.json` 的形态，与台账的 `rights_ground` 同一套依据名）。
