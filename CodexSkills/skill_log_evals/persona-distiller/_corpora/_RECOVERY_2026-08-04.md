# 四个工作区的语料抢救（2026-08-04）

## 起因：清 C 档之前逐目录核了一遍

`~/.claude` 的清理分档规则里，**C 档（会话 scratchpad）是「每轮清」**。
清之前我逐个子目录对账本核了校验和，发现 `scratchpad/pd-work/` 下有
`vesalius-corpus` / `galen-corpus` / `harvey-corpus` / `core_livermore` 四个目录——
**四个被判为「语料缺失」的工作区，语料全在那里。**

**2026-07-29 清理前抢救出 Godin 194 份，是同一个形状。这是第二次。**

## 还原结果（全部按 sha256 匹配，复制后重新算哈希复核）

| 工作区 | 账本 | 还原 | 位置 |
|---|---:|---:|---|
| Vesalius #102 | 47 | **47** | git 工作区 |
| Harvey #103 | 46 | **46** | git 工作区 |
| Galen #101 | 60 | **60** | git 工作区（其中 5 条是全局按校验和搜出来的） |
| Livermore #100 | 536 | **536** | D 档 `verified-by-checksum/`（17 MB，体积裁定未变） |

**没有一份是按文件名放回去的。**

## 二次复验：校验和只证明「是那份字节」，不证明「内容可读」

对账本指得到的 689 份跑 `check_corpus_integrity`：

- Harvey 46 / Galen 60 / Livermore 536 —— **全部是真文档**
- Vesalius 47 —— **1 份可疑**：`vs_epitome_yiddish_1590.txt` 可读字符占比 42%。
  那是 1590 年的**意第绪文** Epitome，希伯来字母扫本 OCR 可读率低**属预期**，
  **不是取错了页**。它仍留在库里作旁证，**但不得从中取逐字引文**。

## ★ 这条规矩要补一句

> **清 C 档之前，逐个子目录对账本核校验和**——不是看文件名、不是看目录名。
> 匹配上的先还原（小体量进 git，大体量进 D 档），再清。

**没有这一条，「每轮清 C 档」这条规矩本身就是不可逆损失的来源。**

## 另一条：只按校验和放，不按文件名放

Livermore 的 D 档旧压缩包与账本**同名文件有 390 份字节不同**（是另一次抓取）。
按名字放回去，会把「语料不在」变成「**语料在但不是那一份**」——
**后者更坏，因为判据会因此变绿。**
