## ★★★★ 预登记：这台装置能分辨多大的差（**判分之前算的**）

`check_delta_resolution` 要两轮才算得出，本轮只有一轮。
但 Mendel #125 在**同一个 16 题 quick 档**上量过：
两轮之间**两侧文本逐字未动**的 7 题，delta 却动了（known −0.0300→−0.1800、
token-efficiency +0.1500→+0.2950），逐题差的 **sd = 0.0928**。

    单题噪声 SE  = sd / √2      = 0.0928 / √2  = 0.0656
                                （**两轮之差的方差 = 2×单轮方差，这一步不能漏**）
    16 题均值 SE = 上式 / √16   = **0.0164**
    quick 门 +0.03              = **1.83 个 SE**

★ **这三行我算错过一次，写在这里**：初稿直接写 `0.0928 / √16 = 0.0232`、门 = 1.29 SE，
  **漏了 `/√2`**。去读 `check_delta_resolution` 的实际代码才发现
  （`se_case = sd / math.sqrt(2)`），与它文件头的 0.0164 / 1.83 SE 对上了。
  **两个数差 40%，而我差点把自己算错的那个当成预登记的门槛。**

**也就是说：这台装置分不清「刚好过门」与「等于零」。**

★ 因此本轮的判读规则**现在就定死，判完不许改**：

| 实测 delta | 怎么读 |
|---|---|
| \|delta\| < 0.0328（2 SE） | **读作「测不出差别」**，不读作「打平」也不读作「略胜」 |
| delta ≥ +0.03 且 ≥ 2 SE | 才算「过门且分得出」 |
| delta ≤ −0.03 且 ≥ 2 SE | 才算「明确劣于基线」 |
| 两席跨零 | 无论均值多少，**一律读作测不出** |

★★ 这条预登记的用处只有一个：**判完之后我不能再挑一个对自己有利的读法。**
（Mendel 那次我差一点就把 +0.0278 写成「只差 0.0022」——那句话没有意义。）

★ 射程：sd 自身的不确定度很大（n=7 时 95% 区间约 [0.6, 2.2]×），
且假定「逐字未动的题」与「改写过的题」同分布——**未验证**。
所以上表的 SE 是**下限意义上的估计**，真实噪声只会更大不会更小。
