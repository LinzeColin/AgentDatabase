# #100 Livermore 语料状态（2026-08-04 复核）

## 它不是「丢了」，是按裁定放在 D 档

当初的决定（见 README.md）：

> **语料放 D 档 `~/Downloads/蒸馏/_corpora/livermore-100/`，不进 git**——
> 7.9 MB 一个人物，600 人就是 4.7 GB，**这个量级不能进仓库**。

所以 `check_corpus_presence` 报「账本 536 条、磁盘 0 份」是**如实的**：
它只看工作区里面。**但结论不该是「语料没了」。**

## ★ 然而 D 档那一份**不等于账本 attest 的那一批**

D 档现存 `corpus_newspapers_541.tar.gz`（7.2 MB，解出 541 个文件）。
逐份对账本的 `checksum`：

| | 条数 |
|---|---:|
| **checksum 对上**（同一份字节） | **143** |
| `normalized_checksum` 对上 | 0 |
| **仅文件名相同、字节不同** | **390** |
| 账本总条数 | 536 |

**390 条同名不同字节，说明那个压缩包是另一次抓取**，不是入库时用的那一批。

## 处置

- **没有把任何一份搬进 git。** 体积裁定仍然有效（4.7 GB 那笔账没变）。
- **没有把那 390 份按文件名塞回 `raw/src-<hash>/`。**
  **校验和对不上就不是同一份**；按名字放回去只会把
  「语料不在」变成「语料在但不是那一份」——**后者更坏，因为它会让判据变绿**。
- **没有改账本的 checksum 去迁就压缩包。** 账本是 attest。

## 结论

Livermore 的**可核语料只剩 143/536**。
重蒸（任务 #29）之前，要么重新抓一遍并重建账本，
要么接受「143 条可核 + 393 条只有著录」这个事实并在产物里写明。
**这是个需要重新抓源的活，不是一次文件搬运。**
