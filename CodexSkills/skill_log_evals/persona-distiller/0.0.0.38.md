# v0.0.0.38 —— 两件检查器都读不到本流水线自己产出的语料

日期：2026-08-03　撞出人物：#108 Joseph Lister　撞出时机：第 1 轮判完、跑发布门时

---

## 一、怎么撞出来的

Lister 第 1 轮两席判完，真 delta **+0.1595**（八人最好），跑发布门时多出一条错：

```
"code": "content.decorative-citation",
"message": "存在装饰性引用：断言挂的来源正文里找不到其关键实体"
```

去查是哪几条断言，判据自己先说了话：

```
$ python3 scripts/check_claim_coverage.py --workspace workspaces/joseph-lister \
      --cache workspaces/joseph-lister/raw
源账本 61 条，其中 0 条能回连到缓存正文
⚠️  过半来源取不到正文，本次检查结果不可信——先确认 cache 目录是否正确
```

**61 条源，0 条读到。** 而门把这个状态报成了「存在装饰性引用」。

---

## 二、三个根因

### 根因一：`glob` 不递归，语料在深一层

```
$ python3 -c "..."
非递归 raw/*.txt : 0
递归  raw/**/*.txt: 60
账本 61 条，用递归后校验和命中 60 条
```

| 检查器 | 原写法 | 对着 `raw/` 读到 | 改后 |
|---|---|---:|---:|
| `check_claim_coverage.py` | `cache.glob("*.txt")` | **0 份** | 60 份 |
| `check_quote_integrity.py` | `glob.glob(f"{d}/*.txt")` | **0 份** | 122 份 |

本流水线自己产出的布局就是 `raw/<source_id>/<file>.txt`。
也就是说这两件**从来没有在标准工作区上真正跑起来过**。

修后实测：

```
源账本 61 条，其中 61 条能回连到缓存正文
══ 装饰性引用（关键实体一个都没在被引来源里出现）: 0/35 ══
实际检查 20/35 条（其中按引文判据 3 条；语料元断言 0、无实体无引文 15 未纳入）
结论: 通过
```

### 根因二：「没查成」与「查出问题」共用一个出口

`check_claim_coverage.py` **是设了防的**——`return 2` 并明写「本次检查结果不可信」。
它的文件头甚至预言了这件事：

> 「只传一个目录会让另一部分源「回连不上」，从而**把工具缺陷误报成装饰性引用**。」

而调用点一句 `elif code != 0:` 把 2 和 1 收成同一个错。
**防线设在检查器里，在调用点被抹掉了。**

`check_quote_integrity.py` 更直接：调用点用的是 `'未命中 0 个' not in out` **串匹配**。
语料读到 0 份时这个条件同样成立。而这个代码库**自己在 claim_coverage 的接线处写过**：

> 「★ 判据用**退出码**，不用输出串。」

在一处立的规矩，在另一处没执行——**同类第九次**。

本版退出码分开：`0=干净　1=查出未命中　2=自测未过　3=语料读不到`，
调用点按码分派为 `content.coverage-unresolved` / `content.quote-unresolved`。
**仍是硬错**（不可信的结论不能当通过），**但错要报对。**

### 根因三：自测测不到装载，因为装载不在自测的射程里

两件的负对照此前**全部建立在「语料已经装好」之上**。
「一份都没装到」这个失败模式，自测在结构上就看不见——
而它恰恰会把每条引文都报成未命中，与「查出一片伪造引文」长得一模一样。

新增三条装载对照（一正两反），并**植回缺陷验证其有牙**：

```
$ （把 rglob 临时改回 glob）
  ✗ 嵌套布局 raw/<src>/x.txt 读到 0 份（流水线自己产出的布局）
  ✓ 平铺布局仍读到 1 份（反向对照）
  ✓ 空目录读到 0 份，不凭空命中（反向对照）
  ✗ 1 条不合——本检查器已失效，不得依赖其结论
$ （还原）
  ✓ 负对照通过（8/8）
```

两条反向对照保持绿，说明不是「什么都报红」。

## 三、一个差点引爆的连锁

`check_quote_integrity.py` 的自测此前直接吃调用方的 `--cache`，
它的真实夹具取自 **Jenner** 语料，于是**只有跑 Jenner 时才过**。
跑 Lister 时实测：

```
══ 真实夹具（Jenner #104 实际数据，一字未改）══
  ✗ 误杀  长 s 还原—须放行（未命中）
  ✗ 误杀  逐字命中—须放行（未命中）
  ✗ 2 条不合——本检查器已失效，不得依赖其结论
```

而 v0.0.0.38 把「自测未过」接成了**硬错**。
**若不同时修掉自测的语料依赖，除 Jenner 外每个人都会被这道新门挡住。**

> **加门之前先看门框。** 新加的硬门会被一个早已存在的缺陷引爆。

改法：自带夹具语料——三段从 Jenner 真语料**逐字符取出的原样**（含其 OCR 讹形），
文件名附在各段旁可回查；`--cache` 从 `required=True` 改为按需必填。

```
$ python3 scripts/check_quote_integrity.py --self-test
（不带任何 --cache，13 项全绿）
  ✓ 负对照通过
```

元检查器普查：可用负对照 **14 → 15**，
`check_quote_integrity` 从「负对照不可独立验证」升为 `OK` + `real_fixture: True`。

```
普查: {'OK': 15, 'NO-SELFTEST': 4}
```

## 四、修完之后，判据立刻抓到一条真的

答案层核验此前也没跑：门找的是 `evals/judge_payload.v1.json`，
而候选答案只在工作区外的 `jl_candidate.json` 里。
门是**诚实**的（它写了「答案层未核验（**不是通过**）」），但那条诚实的记录此前没人接。

把候选答案落进工作区后：

```
语料 122 份（已投影为字母数字串）
引文 17 条，切分后核验片段 15 个，未命中 3 个，长 s 还原后才命中 0 个
  ⚠ 断言/clm-2035706293de: 「Joseph Lister, Esq., F.R.C.S., Assistant Surgeon to the Royal Infirmary, Edinburgh, communicated by 」
  ⚠ 答案/jl-fact-preservation-02: 「Joseph Lister, Esq., **F.R.C.S., Assistant Surgeon to the Royal Infirmary, Edinburgh**, communicated」
  ⚠ 答案/jl-fact-preservation-02: 「Assistant Surgeon, Royal Infirmary, Edinburgh」
```

三条是同一句。语料原样（`src-00072e256447/b30556727.txt`）：

> `By Joseph Lister, Esq. F.R.C.S. Eng. and Edin., Assistant Surgeon to the Boyal Infirmary , Edinburgh. Communicated by Dr. Sharpey, Sec. R.S. Received June 18, — Read June 18, 1857.`

我写成「逐字引文」的那句：丢了 `Eng. and Edin.`、把 OCR 讹形 `Boyal` 悄悄改成 `Royal`、动了标点。
**这正是 Jenner #104 那轮立的规矩——长 s 还原可以，改 OCR 错字不行——我自己第九次违反。**

三套独立扫本的分歧（第一次真正用上「两套扫本互核」这个优势）：

| 扫本 | 作 |
|---|---|
| `src-00072e256447/b30556727.txt` | `Boyal Infirmary` |
| `src-247ed7b2d3b8/philtrans09346010.txt` | `Boyal Infirmary^`（另含 `Listee` `F.B.C.S`） |
| `src-3170a84631b1/jstor-111423.txt`（Proceedings 摘要） | `Royal Infirmary of Edinburgh` |

**分歧本身要写进答案，不是挑一个顺眼的。**

另核出一处：卷号 **148 不在任何一份语料里**。语料能给的只有起页 `[ 645 ]`、
页脚署 `MDCCCLVIII`、running head 页码。**常识不是语料**——同一条规矩，
Lister 的 `boundaries.md` 里因 Listerine 那次刚写下。
