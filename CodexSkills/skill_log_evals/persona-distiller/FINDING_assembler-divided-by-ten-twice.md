# 同一处除以 10 做了两遍——判据没错，喂给它的数错了

日期：2026-08-04　发现方式：**发布门报的数与汇总脚本报的数对不上，顺手核了一下**

---

## 一、怎么发现的

Barton #117 判分收尾，跑发布门：

```
✗ eval.overall-threshold → candidate overall 0.080 < 0.800
✗ eval.boundary-threshold → boundary score 0.081 < 0.850
✗ eval.fact-threshold → fact-preservation score 0.085 < 0.930
```

而同一份数据，汇总脚本 `assemble_cb_results.py` 打印的是：

```
候选均分 0.797　基线均分 0.824
**真 delta = -0.0027**
```

**0.080 与 0.797 差正好一个数量级。** 而且汇总自己内部就对不上：
**0.797 − 0.824 = −0.027，它却报 −0.0027。**

## 二、成因：一次修补没有清理掉旧的那一处

```python
# 第 32–34 行：量纲归一（后加的）
if a_raw > 1.0 or b_raw > 1.0:
    a_raw, b_raw = a_raw / 10.0, b_raw / 10.0
...
# 第 43 行
delta = (mc - mb)/10.0                      # ← 又除一次
# 第 51 行
"overall_score": round(r[s]/10.0, 4)        # ← 又除一次
# 第 68 行
print(f"{(v[0]-v[1])/v[2]/10:+.4f}")        # ← 又除一次
```

后面那三处 `/10.0` 是给「`rows` 里存 0–10 原始分」那个年代写的。
**上游加了量纲归一之后，三处一个都没删。**

这轮两席给的本来就是 0–1（`[0.70, 0.88]`），**归一没触发，后面那次是白除的。**

## 三、后果

| | 我报过的 | **真值** |
|---|---:|---:|
| 第 1 轮 delta | −0.0043 | **−0.0433** |
| 第 2 轮 delta | −0.0009 | **−0.0089** |
| 第 3 轮 delta | −0.0027 | **−0.0273** |
| 发布门 overall | 0.080 | **0.797** |
| 发布门 boundary | 0.081 | **0.812** |
| 发布门 fact-preservation | 0.085 | **0.848** |
| 断言配比相关系数 | r=+0.340 | **r=+0.388** |

**写进工作区 `evals/results.jsonl` 的分也全是真分的 1/10**，
所以发布门读到的四项 eval 指标全错——**判据本身没有毛病，是喂给它的文件错了。**

**结论不变**：Barton 三轮全负、门槛 +0.07，拒发照旧，而且真值离门更远。
**但今天我写下的每一个 delta 都错了一个数量级，包括提交信息里的。**

## 四、这是「判据绿了但指错了文件」的第 11 次，形状又是新的

前十次是判据指错了对象。**第 11 次是判据指对了文件，而文件里的数是我算错的。**

它躲过了什么：

- 躲过了汇总脚本自己的输出——**因为它把均分和 delta 分两行打印，
  没有任何一处会去验 `delta == mc - mb`。**
- 躲过了发布门——门只知道读 `results.jsonl`，**不知道那份文件该长什么样。**
- 躲过了我三轮的复核——**我每轮都在看 delta 的趋势（−0.0043→−0.0009→−0.0027），
  趋势是对的，所以看上去一切正常。** 量纲错误不改变趋势。

## 五、已落成的防线

在汇总脚本里加了断言，**位置在算 delta 之前**：

```python
assert all(0.0 <= r[k] <= 1.0 for r in rows for k in ("candidate", "baseline")), \
    "**分数不在 0–1**——量纲归一没生效，不许再往下算"
```

**这条断言防不住本次的错**（本次数据本来就在 0–1，是运算多除了一次）。
它防的是反向：归一失效时不许静默往下算。

**真正防住本次的只有一件事：核对两个应当相等的数。**
`delta` 与 `mc - mb` 必须相等——**我是靠肉眼发现它们不等的，这一条现在也写进了脚本注释，
但它没有被落成判据**，因为汇总脚本是每人一份的临时件，不在 `scripts/` 下、不进任何门。

★ **这正是那条已知模式的原话**：
「**不是判据，是我自己写的临时分析脚本，一天之内同形三次，都不经过任何门。**」
本次是同一个位置的第四次。
