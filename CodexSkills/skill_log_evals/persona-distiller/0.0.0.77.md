## ★★ 同口径，不是「差不多的口径」

口径逐字对齐 `quality_check.evaluate_sources`：

    usable  = split == 'train' 且 tier != 'U' 且 extraction_status != 'failed'
    primary = usable 里 tier ∈ {P1, P2}
    lanes   = usable 的 `dimensions` 并集

**本会话已经栽过四次「我算的和门算的不是一个数」**，所以这次不靠眼睛核，

## ★ 顺带修一处会再犯的错

两个解析器一度返回**不同形状**：`parse_ledger` 给 `(分档, 道字符串)`，
`parse_source_ledger` 给 `(分档, 道列表)`。
下游一句 `{l for _, l in rows if l}` 在两种形状上都不报错，**但数出来的东西不同**。

**那正是本会话四次「两套标识符空间相减」的同一个根。**
已统一为 `(分档, 道列表)`，并落成反向对照 ⑦ 专测这一条。

## 判不了什么

- **仍然判不了「再抓能不能抓到」**——只算手上这批的上限。
- **仍然判不了分档对不对**。入库 attest 写 P1 它就当 P1。
- **入库前只能退回 `raw/_ids.txt`**，那时格式问题原样存在（十份里 5 份可解析）。
  **但抓之前正是本件最有用的时候**——所以这条退路不能删，
  只能靠**统一抓源台账格式**来收窄，那是另一件事。
- **它不改任何门。** 只写 metrics；真正拦人的是 `min_primary_ratio` 与 `min_lanes` 本身。
