# v0.0.0.75 —— 交付里带齐分母了吗

日期：2026-08-04

## 触发

想从产物侧回算事实密度债，门槛是 `max(MIN_FLOOR, ceil(usable_train / 5))`，
而 **`usable_train` 从没被写进交付产物**。

拿 `sources_total` 代入把 holdout 也算了进去：
**Livermore #100 的 536 份 → 门槛 108，荒谬。**

`quality_check` 一直在算这个数（第 125–126 行），**只是没人把它交付出去。**

**交付里缺一个分母，一整类债就只能给上界。**

## ★★ 为什么必须在打包时管

**语料会被清掉**（分档 A–E，BCE 每轮清）。
清掉之后**产物就是唯一的证据——那时候缺的字段补不回来。**

## 实测输出

```
抽出 100 份 source-coverage.json
已入库产物：带齐分母 **0**，缺分母 **100**

── 样例（seth-godin）──
✗ **交付里缺分母——将来想回算这一类，只能给上界**：

    sources_usable_train     缺　（**事实密度门的分母**）
    sources_holdout          缺　（holdout 重叠核查）
```

## ★ 100% 这个数，先核了工具再信

按 v0.0.0.74 那条规矩办的：

- **这两个字段是今天才加进 `package_target` 的**，已入库产物不可能有——极端值有解释
- 另外三个字段（`sources_total`／`primary_ratio`／`lane_source_counts`）**100 份全都在**
  ——**说明判据不是空的，它分得出哪个缺哪个不缺**

## 修复侧的实跑（Lister #108）

```
sources_total       : 61
**sources_usable_train**: 60
**sources_holdout**     : 1
→ 真门槛 max(5, ceil(60/5)) = **12**（用 total 算是 13）
```

Lister 的 holdout 只有 1 份，两者差别很小；
**Livermore 那种 536 份的才会差得离谱。**

## 自测（6 条反向对照）

```
── ★★ 反向对照 ①：**缺 `usable_train` 必须被抓住**（这次的真事） ──
  ✓ 缺 sources_usable_train → 报
── ★★ 反向对照 ②：**键在但值是 None，也算缺** ──
  ✓ 值为 None → 报（不许「有这个键就算带了」）
── ★ 反向对照 ③：0 是合法值，不许当成缺 ──
  ✓ holdout=0 → 不报（真的一份没留也是个数）
── ★★ 反向对照 ⑤：**多带字段不算错** ──
  ✓ 多带一个字段 → 不报

✓ 自测全过
```

`pytest 70 passed`；`✓ 无合同漂移`。

## 判不了什么

- **判不了这张清单本身全不全。** 新增一道用新分母的门，
  **要同时把那个分母加进清单**——否则又是一次「回算时才发现」。
- **判不了旧产物。** 已入库的 100 个都缺，**只能等 #29 重蒸。**
