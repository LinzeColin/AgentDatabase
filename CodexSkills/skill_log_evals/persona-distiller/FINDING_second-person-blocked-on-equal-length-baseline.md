## 四、成因：裸模型的默认体裁就是长

基线由独立子代理跑裸模型对同一批 prompt 实答，**未给任何体裁指示**（给了就是污染对照）。
它自己交代的形态是：分条、空行分段、每题铺开讲。实测：

```
空行分段  候选 0/32　基线 24/32　可利用 75%（**恰在门上**）
破折号    候选 27/32　基线 30/32　可利用 12%
粗体/反引号 候选 1/32　基线 1/32　可利用 3%
```

**格式通道已经清干净了**（v0.0.0.81 那一轮的成果）——
候选与基线在粗体、反引号上不再可分。**剩下的是篇幅，而篇幅拉不平。**

要么候选把每题都铺开写到裸模型那个长度（那是**为对照而改产物**），
要么让裸模型也写到候选的长度（那是**改对照的定义**）。
**两条都不是我能自行决定的。**

**只差判分，而判分这一步现在过不去。**

**这属于待用户裁定 ⑤（长度混杂需要等长基线）。**
本条把那一项从「理论上要做」变成「**正在挡人**」：
它已经挡住连续两个人，而且挡的方式是「只差 6 个字」——
**这种差距只能靠灌水抹平，而灌水会让判据从此失去意义。**
