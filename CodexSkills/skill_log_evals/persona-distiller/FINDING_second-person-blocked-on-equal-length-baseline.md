# 连续第二人卡在同一处：过门只差 6 个字，而那 6 个字里没有实质

## 一、卡在哪

`check_answer_surface_leak` 两条长度判据：

| | 门 | #118 实测 |
|---|---|---:|

| 候选更短的题 | ≤ 75%（即 ≤24/32） | **26/32 = 81% ✗** |

**总量那条过了，一边倒那条没过。**

### 过门需要什么

```
要把 26 降到 24，须让 2 道由短转长。最省力的两道：
  eb-contrast-01       需再加 6 字   （候选 459 / 基线 464）
  eb-cal-02            需再加 8 字   （候选 420 / 基线 427）
```

**6 个字里不可能有实质。** 这不是「再努力一下就能过」，是**这道门在这里只能靠灌水过**。

## 四、成因：裸模型的默认体裁就是长

基线由独立子代理跑裸模型对同一批 prompt 实答，**未给任何体裁指示**（给了就是污染对照）。
它自己交代的形态是：分条、空行分段、每题铺开讲。实测：

```
空行分段  候选 0/32　基线 24/32　可利用 75%（**恰在门上**）
破折号    候选 27/32　基线 30/32　可利用 12%
粗体/反引号 候选 1/32　基线 1/32　可利用 3%
```

**格式通道已经清干净了**（v0.0.0.81 那一轮的成果）——
候选与基线在粗体、反引号上不再可分。**剩下的是篇幅，而篇幅拉不平。**

要么候选把每题都铺开写到裸模型那个长度（那是**为对照而改产物**），
要么让裸模型也写到候选的长度（那是**改对照的定义**）。
**两条都不是我能自行决定的。**

## 五、所以本人物停在这里

```
95 份来源（P1 73 / P2 4 / S1 15 / U 3），一手占比 82.8%，六道齐，去重后独立作品 56 部

```

**只差判分，而判分这一步现在过不去。**

**这属于待用户裁定 ⑤（长度混杂需要等长基线）。**
本条把那一项从「理论上要做」变成「**正在挡人**」：
它已经挡住连续两个人，而且挡的方式是「只差 6 个字」——
**这种差距只能靠灌水抹平，而灌水会让判据从此失去意义。**

参见 [[length-confound-in-blind-eval]]、`references/ledgers/_待用户裁定.md` ⑤。

## 六、一处我自己的规则错，以及为什么不回头改 #118

v0.0.0.81 我写的那条是「散文，不加粗体、不加反引号、**不分条**」。
写 #118 的答案时我把「不分条」执行成了「**不分段**」——通篇一段。

实测后果：

```
空行分段  候选 0/32　基线 24/32　可利用 75%（**恰在门上**）
```

**段落之间空一行是正常散文的写法，不是 Markdown 格式。**
禁的本该只是项目符号与编号列表。规则已改（母版与必读同步）。

### ★ 但 #118 的答案不回头重排

给每道答案加两三处段落分隔，**正好就是那 6 个字**——
`eb-contrast-01` 差 6 字、`eb-cal-02` 差 8 字，两三个换行就够了。

**改完就跨过了门，而我永远没法证明那不是动机。**

所以：**规则改对是给后来的人用的；#118 的阻塞照旧。**
这一条本身也是证据——**一个能被两三个换行符跨过去的门槛，
说明卡住的不是产物质量，是对照的定义。**

## 七、★★ 把两道门放在一起看：**五个人里，两道门都过的是 0 个**

写完第六节之后我顺手把两道门叠起来量了一次，结果比「两个人被挡住」重得多：

| 人物 | 格式可利用率 | 均长比 | 候选更短 | 格式门 | 长度门 |
|---|---:|---:|---:|---|---|
| alexander-fleming | 88% | 1.30 | 41% | **不过** | 过 |
| florence-nightingale | 94% | 1.29 | 31% | **不过** | 过 |
| william-osler | 81% | 1.30 | 44% | **不过** | 过 |
| clara-barton | 100% | 0.89 | 72% | **不过** | 过 |
| **elizabeth-blackwell** | **3%** | **0.79** | **81%** | **过** | **不过** |

**★ 两道门都过的：0 / 5。**

### 模式

- **老一代**（Fleming / Nightingale / Osler / Barton）：候选写成 Markdown，
  **格式门全不过**（81–100% 可指认）；但也因为分条铺开而**比基线长**，
  **长度门全过**（均长比 1.29–1.30，更短占比 31–44%）。
- **#118**：候选按裸模型的默认体裁写成散文，**格式门过了**（3%）；
  但散文写得密，**比基线短**，**长度门不过**（0.79 / 81%）。

### 这说明什么

**两道门在我的写法上是互相拉扯的。**
把候选写成裸模型那样的分条长文 → 格式泄题；
把候选写成密实的散文 → 长度泄题。

**中间那条路——体裁与裸模型一致、长度也与裸模型一致——
要求候选逐题模仿一个我看不见其取舍的对象。**
而基线是不给体裁指示跑出来的（给了就是污染对照），所以它的长度也无从预知。

**这不是「再调一轮就能过」的事，是这个对照的定义要求候选同时匹配对方的两个维度，
而那两个维度都由对方单方面决定。**

★ 这一节把待裁定 ⑤ 的证据从「两人被挡」升级为
**「五人零通过——从来没有一份答案同时过了这两道门」**。

## 附：一处我自己量错的时间，纠正在这里

本日曾报「`check_corpus_presence.py` 的自测跑 **4 分 43 秒**，被调用方超时后
报成『负对照未过——其检查结论不作数』」，并据此说它是「把没查成当成了查出问题」。

**那个 4:43 是错的读数。** 单独重跑：

```
python3 -u scripts/check_corpus_presence.py --self-test
  0.22s user 0.25s system 98% cpu  **0.480 total**
```

**自测只要 0.48 秒。** 当时的 4:43 是**并发争用**——那一刻同时在跑的有
发布门（6 分钟）、后台自测、以及基线子代理。
读数里 `2% cpu` 那一栏本来就在说「它在等，不在算」，我却把它读成了「它慢」。

**教训**：**在别的重活跑着的时候量一件事的耗时，量到的不是那件事的成本。**
要量就单独量，且看 CPU 占比那一栏——**98% 与 2% 说的是两回事。**

（`content.selftest-failed` 那次报错本身仍是真实发生过的，
成因是瞬时超时而非判据有问题；这一条的更正只针对「自测慢」这个判断。）

## 附二：一个我做到一半发现不能用的度量

为了给裁定 ⑤ 提供「短是文体还是漏项」的证据，我做了一次
「逐题数 rubric 要点在两侧的命中率」。结果看着很有利：

```
32 题、268 个要点：候选命中 49（18%）　基线命中 13（5%）
这些题的字数：候选 12600 / 基线 15983 = 0.79
每千字命中要点：候选 3.9　基线 0.8
```

**但这个数不能用。**

**rubric 和候选答案都是我写的**——我的答案自然会用我自己 rubric 里的词；
而基线那个子代理**从没见过 rubric**。
所以这个数量的是**我跟我自己的用词重合度**，不是覆盖率。

差一点又犯了同一个错：**报了一个统计量去回答另一个问题**
（与「A/B 侧差不是候选/基线差」同型）。

**要真的量覆盖，只能由不写 rubric 也不写答案的第三方来判——那正是评委的活。**
而评委这一步现在被泄题门挡着。**所以这个证据拿不到，本条不再尝试从这个方向找。**
