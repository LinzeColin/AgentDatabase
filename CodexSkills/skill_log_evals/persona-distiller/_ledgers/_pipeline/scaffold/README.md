# 生成器脚手架

每个人物**复制这四份**到工作目录，改文件头标注的几行，然后只填数据。
**不要每人重写全套脚本** —— 必读文件指明这是主循环最大的重复开销。

| 文件 | 每人要改的 | 只填的数据 |
|---|---|---|
| `stats_template.py` | `CORPUS_DIR` / `LEDGER` / `TITLE_RE` | `FACTS` 里加本人物特有的计数 |
| `claims_template.py` | `OUT` | `S`（源 ID 表）、`C`（29–31 条断言元组） |
| `docs_template.py` | `W` | `M`（映射）、`DOCS`（十份正文） |
| `cases_template.py` | `OUT` / `PAYLOAD` / `HOLD` | 32 个 `put(...)` 调用 |

## 顺序

1. 抓源（外包子代理）→ 清洗 → 分层取样 → **抽 holdout 并物理隔离** → 通读
2. `init_target.py` → `ingest.py` → `quality_check --phase research --strict`
3. 六泳道（主循环写）→ `stats` → `claims` → `docs` → `--phase synthesis --strict`
4. **`check_holdout_overlap.py`（内容级判重，硬门）** → 读 holdout 出 known 题
   → `cases` → **冻结并算指纹**
   > 成员级检查通过**不代表**内容不重合。Robertson #97 有一份 holdout
   > 与 train 是同一篇访谈的两次发表，覆盖率 63%，而成员级检查一路绿灯。
5. 评委 **2 席**（常规打分 + 不知前情）→ 结果拼装 → `--phase release --strict`
   > **⛔ 上限 3 轮**（用户 2026-07-28 定）。第 1 轮全量，第 2/3 轮只判 diff 出来的改动集。
   > 三轮未过门就不发布，归档待接手，去做下一个人。
   > **⛔ 指令用 `../judge_prompts/` 的冻结版，一个人物全程同一份，中途不得加检查项。**
   > Robertson #97 十三轮、103 万 token 未过门，且分数不单调——**加轮次补不上第一稿的差距。**
   > **冻结要做两件事，缺一不可**（Robertson #97 两次踩坑换来的）：
   >
   > **① 留 payload 快照** `judge_payload_<xx>.vN.json`。
   > 指纹只能证明「变了」，**不能证明「哪几条变了」**；没快照就无法按
   > 「只重判改动过的用例」举证，只能全量重判。**快照是纪律的证据，不是备份。**
   >
   > **② 指纹按单条用例算，不要按整份载荷算。**
   > 整份指纹在部分重判时两头不是人：改一条则 31 条没改的分数也被判过期；
   > 沿用旧指纹则改过的那条也被当有效。
   > 正确做法是 `sha256({case_id, prompt, rubric, candidate, baseline})` 逐条绑定，
   > 拼装时对不上的**单条拒收**。
   >
   > **③ 修订轮次只许加限定、给出处、统一口径，不许引入新主张**——
   > 引入新主张等于开一轮新评审，评审就不会收敛。
   >
   > **④ 收到批评先抽象成可检索 pattern，全产物（含标题、表头、rubric、生成器源码）
   > 扫一遍再动手改。先扫后改。** Robertson #97 前三轮都是「只修被点名那几处」，
   > 于是同一族问题被反复指出，评委开销超目标 79%。
6. `package_target` → `register_persona` → `validate_group` → commit + push
7. **立刻**回写 `_决策台账.md` / `_额度台账.md` / `_每次开工必读.md` 基线，再开下一人

## 十二件内容层检查器（`../checkers/`）

引文完整性 / 装饰性引用 / 段内冗余 / schema 漂移 / claim 锚点（引用关系）/
语义残留 / 不在场断言 / **账本-物料成员级核对** /
**holdout 内容级判重**（硬门）/ **锚点内容一致性**（只列不判）/
**文档与用例层逐字引文**（硬门）/ 早期分类

后两件都是 Robertson #97 新建的，各自补上一个「所有门全绿而产物有真错」的缺口：
前者抓「holdout 与 train 是同一篇的两次发表」（覆盖率 63%，成员级检查看不见），
后者抓「断言改了、渲染它的文档段落没跟着改」（两处互相否定，锚点计数却完全正常）。

「计数漂移」已移到本目录 `number_drift_template.py`——
它的规则由人物正文决定，是模板不是工具（放在 checkers/ 里时 `--help` 直接 ImportError）。

`check_absence_claims.py` 的输出**必须逐条核完并留下结论**才算这一轮做完——
它是「只列不判」的，不阻塞发布，而 Maeda 一轮它报的 13 条里有 2 条是假的（错误率 15%）。
