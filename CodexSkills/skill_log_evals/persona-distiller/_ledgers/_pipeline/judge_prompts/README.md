## 为什么要冻结

Robertson #97 用了十三轮评审，而**我在每一轮都往严格席的检查清单里加项目**。
后果是：**产物在变好，分数在变差**——

| 轮次 | 严格席给 fact-1 / fact-2 / fact-3 |
|---|---|
| r9 | — / 0.80 / 0.75 |
| r12 | — / 0.88 / 0.86 |
| **r13（按前十二轮结论整体重写）** | **0.88 / 0.85 / 0.82** |

r13 的产物明显优于 r9，分数却回落，因为 r13 的指令里多了
「证据分层查得细一点」「有没有哪一句本该是推断」这两项新检查。

**尺子在评审过程中变细，分数就不再度量产物，而是度量指令。**

再看跨人物：Maeda #96 与 Robertson #97 **同样两席、同样模型、同样基调**，
严格席给候选 ≥0.95 的比例是 **23/32 对 0/33**，均值 0.9484 对 0.8812。

## 两条硬规则（用户 2026-07-28 决定）

### 一、指令冻结，只对新人物生效

- 本目录的 `seat_D_score.md` 与 `seat_E_strict.md` 是**标准指令**，
  一个人物的**全部轮次**都用同一份，中途不得增删检查项。
- 要加新检查项，**加在下一个人物**，并给本目录升版本（v2、v3…），
  在 `_决策台账.md` 记明「自第 N 人起改用 vN」。
- **已入库的 96 人是用更粗的尺子量的，其分数与 v1 及以后不可比。**
  引用历史分数时必须带上这句话。

### 二、评分最多 3 轮

**一个人物的评审总轮数上限为 3。** 超过即停，不得再判。

- 第 1 轮：全量评。
- 第 2 轮：只重判**第 1 轮后实际改动过的用例**（由 payload 快照 diff 判定）。
- 第 3 轮：同上，且**这是最后一轮**。
- 三轮之后仍未过门 → **不发布**，如实记账，归档待接手。

**理由**：Robertson 一轮花了 103 万 token（目标 19 万）而门仍未过，
十三轮的分数没有单调上升——**加轮次补不上第一稿的质量差距**。
把预算前移到第一稿：按 `../scaffold/README.md` 的写法一次写对，比事后修十二轮便宜得多。
