## 2. 并发模型（git worktree 隔离 + 主线程收敛）—— ★ 多线程成败关键

**结论先行**：三线程**不得在同一工作树里并行 commit**。`register_product`（`registry_core.py:1101`）
会 `write_index` 原子重写共享的 `team-index.json`；三个进程并发写同一文件 = 撕裂/冲突/丢登记。
同一工作树里并发 `git add/commit` 也会互相踩 .git 索引。

**正确做法：**

1. 每个线程一个 `git worktree add`（或独立 clone），分支各自独立：
   - T1：现工作树 `AgentDatabase/`，分支 `main`
   - T2：`AgentDatabase-T2/`，分支 `thread2-301-450`
   - T3：`AgentDatabase-T3/`，分支 `thread3-451-604`
2. **每线程只 commit 自己的切片文件**：自己的 `_corpora/wip-<slug>-*/` 产物、自己的
   `persona-distiller-group/<族>/<slug>/`、自己的切片台账。
3. **共享文件只有 T1 主线程写**：`team-index.json`、`GOAL-STATE.json`、`GOAL-LOG.md`、
   `_蒸馏队列.json`、`_延后名单.json`。T2/T3 **只读**这些，改动一律以「问题/建议」上报给 T1。
   T2/T3 在自己的切片 JSON 里维护 `status`（同 T1 的清单格式），不回写主台账。
4. **登记冲突的裁决**：同一编号若 T1 与 T2/T3 都做了（如 T1 补做 T3 族缺口），按 git merge 时
   `persona-distiller-group/<族>/<slug>` 目录谁先合入 main 为准，后合入者跳过（register_product 会以
   「hash 已登记」拦截）。
5. **入库计数口径不变**：任何时刻权威计数 = T1 主树 `git ls-files …team-card.json | wc -l`。
   T2/T3 汇报时用**自己 worktree 里**的 team-card 数 + 「主树基线 117」，不得自报主树数字。
6. **合并协议（由用户/T1 执行）**：T2/T3 每完成一人即 commit；整批完成后，T1 依次
   `git merge thread2-301-450 --no-ff`、`git merge thread3-451-604 --no-ff`（或 cherry-pick 按人合并），
   合并后跑 `rebuild_team_views.py` 重建 team-index + `validate_group.py` 校验 + `validate_persona_registry.py`。
7. T2/T3 合并回 main 前，先 `git pull` 主树最新，避免 base 过期导致注册版本号冲突。

## 4. 规则（硬约束 · 全部线程强制执行）

1. 现算人数必须用 `git ls-files` 命令，禁止引用记忆里的数字。
2. 主树只提交 main、不 push（cron 每日 09:00 daily-sync.sh 负责推）；`git add -A` 只限 CodexSkills 子目录；永不碰 `_protected/`。
3. 语料原文不进 git（只进 `_corpora/wip-*/` 工作区，quality_check 会拦）。
4. 成本红线：95%+ 推理用 flash 档（workflow agent 必须写 `deepseek-v4-flash` 全名，短 id 无效）；盲判/答题/判分全部 flash；pro 仅关键决策（pro 抽审 4 触发：门线±0.03/两席分歧>0.1/首轮未过/发布门红）。
5. 双侧盲判必须同模型（全 flash 或全 pro），禁止混模型制造假 delta。
6. 零编造：每个 delta/分数必须来自真实盲判；判据先修答案再重判；不伪造进度。
7. 只取公有领域（出版年 ≤1930）；不碰付费墙/访问控制/验证码；rights 不含 unknown。
8. 门、席位、评委指令是**冻结资产**，任何时候不动（2026-08-12 授权裁定）。
9. 无人值守谷时只跑确定性管线；任何「顺手修一下」必须回到 P3 检查点流程。
10. 有不确定→停下问用户，不脑补。

## 5. 注意事项（多线程特有 + 前人 9 坑浓缩）

**多线程特有：**
- 共享文件只有 T1 写；T2/T3 发现台账不一致，写「问题上报」不动文件。
- T2/T3 开工前必须 `git pull` 拉主树最新（含 T1 新入库的 46 个包外人物与最新 skill 文件）。
- T2/T3 的 worktree 里 `_corpora/` 同样 gitignore，语料自抓自留，不共享。
- 每线程 ≤40 万 token 预算；超了停一轮，汇报 token 分账。

**前人 9 坑（HANDOFF，接手必读）：**
1. dimension 枚举固定 6 值（writings/conversations/expression/external/decisions/timeline）。
2. historical 人物归属路：meta.json `subject_origin:"historical"` + attribution_basis 四字段 + covered_sources 逐份点名。
3. 18 世纪长 s OCR：ſ→f；署名照录用载体实际形态。
4. holdout：apply 后 raw/src-* 与 references/sources/src-* 都移入 holdout；研究文档不得引用 holdout source_id；同文多馆一train一holdout=真重合，train 侧也密封。
5. candidate 低分模式（boundary/refusal/style-decoy 题「配合演出」）：persona 指令写死「必须拒绝」，判分后逐题核对。
6. no-quotes-to-verify：答案注入 2-3 条「」逐字引文（年份+source_id），必须与 normalized 语料逐字一致。
7. unsourced-name：答案人名必须在语料/排除记录可查。
8. package：team-card subject_uid 用内部 uid（person-xxx）不是 wikidata QID；--acknowledge-disclosure 用 warning 原文子串。
9. workflow 服务偶发降级：单 agent 调用、≤150 字输出、JSON 判分 prompt 最稳；答案 4 批×8、判分 8 批×4。

1. **单一事实源**：编号、切片、状态以 `_并行分片/T{1,2,3}-*.json` 为准；任何台账写人名前先 grep `_蒸馏队列.json`。
2. **进度实时推导**：next_person.py 的 done 从 team-index + Downloads ZIP 现算，不靠记忆；每会话开工先跑。
3. **计数纪律**：权威数只有 `git ls-files …team-card.json | wc -l` 一个口径，每周对账一次与 team-index products 数。
