## ① 「没有专家团队相对裸模型的公开盲测结果」

- 路由自己报 `routing_observability.telemetry_eligible_for_c: false`、
  `strategy_fallback_reason: "telemetry unavailable; C requires >=60 outcomes, ECE<=0.12 and task-slice coverage>=0.75"`。

★ **我补不上这一条。** `record_team_outcome.py` 必需 `--actual-success`（实测任务成功率）
与 `--delta-score`；这两个数要靠「真跑一次任务 ＋ 与裸模型盲比」得到。
本会话 harness 不许派子代理，凑不出两个互相独立的评委会话。
**编一个数就是造数据，不做。**

★ 需要区分的一件：**人物蒸馏侧是有真盲测 delta 的**（对真基线、三轮、两席、

**那是「单个人物 vs 裸模型」，不是「团队 vs 裸模型」。** 两者不要混为一谈。

## ② 「路由没有实质性收益」

**已量化。新判据 `_ledgers/_pipeline/measure_routing_discrimination.py`（已在 main）。**

6 个任务，相关身份族**按任务文本预先标注**（与路由器用的字段无关），
随机基线**从真实可选池按其族偏斜**抽 400 次、固定种子：

| | |
|---|---|
| 高于随机 / 低于随机 | 3 / 2 |
| 平均 | **+4.0 个百分点** |
| σ / SE | 8.5 / 3.5 pp |
| **离零** | **1.16 SE ⇒ 判不出与零的差别** |
| 要判得出需要 | 约 **18 个任务**（现有 6 个）|

最难看的一格：**SaaS 定价 −7.7 pp（比随机抽还差）**，选出的 9 人含焊接裂纹专家、
压力管道专家、两个编程语言设计者。

**根因（57 个入选席位 / 6 个任务）**：

| 分项 | 极差 |
|---|---:|
| `values.domain_match` | 1.0000 |
| `values.currentness`（人物年代新旧） | 0.6500 |
| `values.task_similarity` | 0.1195 |
| `values.capability_match` | **0.0499** |
| `values.boundary`／`values.evidence` | **0**（恒 1.0）|
| `telemetry_prior`／两个 `penalties` | **0** |

⇒ **五个分项在公式里却不携带任何信息。**
⇒ SaaS 定价那题**池里没有一人 `domain_match>0`**，而同题 `currentness` 极差
是全表最大的 0.650 —— **领域信号一失效，排序就落到「谁更近代」，结果低于随机。**

## ⑤ 「真正独立性 40%」

**这一条是结构性的，迭代改不掉。**

同一个基础模型的多个角色，相关性错误与伪共识无法靠流程消除。
任务包自己的不变量也写着「**不按多数票裁决，不把同一模型角色伪称独立模型**」——
设计上已承认射程。
⇒ **能做的只有把射程写清楚，不能做的是宣称已解决。**
