# 便宜模型**查得出缺陷，却答不出「没有」** —— DeepSeek V4 实测（2026-08-18）

## 为什么做这次实测

Owner 问：这个任务继续用 Claude Code + Opus 5，还是换 Kimi / DeepSeek 更划算。
我先给了一张**全是估计**的表。他随后给了 DeepSeek 的 API —— 于是把估计换成测量。

**估计不配当决定用。** 这和本仓对「1991 出现 0 次」那个数的处置是同一个标准。

## 装置

拿**今天真实修掉的两处缺陷**（不是编的题），破损版与修好版各问一次，**同一句问话**：

> 存在某种输入，使得写进 `review` 的那行结论与事实不符吗？
> 若存在：(a) 触发条件 (b) 那行结论会是什么 (c) 为什么与事实不符。若不存在，只回答「没有」。

- **T1** = `staged_not_ingested`：`else` 绑到了 `if _me:`，`_me` 空时把刚写的「未核」
  覆盖成一句 `✓ …（该人物在判据明细里…）`，而这句话在该分支上是假的。
- **T2** = `byline_in_carrier`：守卫 `… if info else '未核'` 只挡得住**空**字典，
  而判据回的是非空的 `{"状态": "…未核…"}` ⇒ 落进计数分支 ⇒「核过 0 条，指错 0 条」。

★ **题面不含任何提示词**：不出现「未核」「假绿」「守卫」等本仓术语，不暗示有 bug。
★ **修好版是负对照**：答「没有」才算对；编一个缺陷出来算**误报**。
  —— 负对照与判据不共用假设：两版只差那一处，问话逐字相同。

## 实测（`temperature=0`，`max_tokens=16000`）

| | T1-破损 | T2-破损 | **T1-修好（负对照）** | **T2-修好（负对照）** |
|---|---|---|---|---|
| `deepseek-v4-flash` | ✅ 完全正确<br>3723 tok / 33s | ✅ 完全正确<br>2827 tok / 23s | ❌ **误报**<br>8646 tok / 71s | ❌ 空输出<br>**16000 tok / 126s** |
| `deepseek-v4-pro` | ✅ 完全正确<br>3037 tok / 33s | ✅ 正确<br>7026 tok / 77s | ❌ 空输出<br>**16000 tok / 178s** | ❌ 空输出<br>**15998 tok / 159s** |

**破损题上两个模型与我的诊断一字不差。** pro 把覆盖过程拆成三步列了出来：
「先进入 `if not _me` 写入警告 → `if _me` 不成立进入 `else` → 再次赋值覆盖了刚才的警告」。

**负对照上两个模型都失败**，两种失败形状：

1. **编一个出来**（flash / T1-修好）：它说「未核」那句里的括号
   「本人物**可能**压根没走过抓源台账」与事实不符，因为真实原因是「没有外层 `raw/`」。
   —— 但判据自己的跳过理由原文就是「没有外层 `raw/`：**没走过抓源台账那一步**，无从比」，
   两者本就是同一件事，且原话带「可能」。**这是误报。**
2. **转不出来**（其余三次）：16000 token 全部烧在 `reasoning_content` 上，正文为空，
   最长 178 秒。**不是被 max_tokens 截断** —— 从 900 提到 6000 再提到 16000，同样收敛不了。

## ★★★ 这个形状正好压在本项目的要害上

**推理 token 计进 `completion_tokens`**（实测 85–100% 是推理），所以：

> **它在「没有问题」的那一档上，花得最多、给得最少。**

而本仓的问题分布正是这样 —— 今天我扫了 **22 个消费点，只有 3 个是坏的**：

| | 占比 | 便宜模型在这一档 |
|---|---:|---|
| 答案是「有问题」 | ~14% | **很好**：准、快、便宜 |
| 答案是「没有」 | **~86%** | **最差**：4–8 倍 token，换回空输出或一个假线索 |

⇒ **拿它当扫描器是负价值**：86% 的问题上多花钱、拿回噪声，而我还得逐条复核。

## 路由裁定（我定的，2026-08-18）

**用它做「已经怀疑某一块之后的第二意见」，不用它做「替我去怀疑」。**

- ✅ **该用**：我已定位到一段代码/一个读数，问它「这里在什么输入下会给出错的结论」。
  实测 4/4 命中（两处缺陷 × 两个模型），**单次约 ¥0.05**，且是**独立来源** ——
  本仓明写「同源自证：一致 ≠ 正确」，外部独立确认有真价值。
  **今天这两处诊断因此从「自述」升级为「有一条外部独立佐证」。**
- ❌ **不该用**：普查、巡检、「看看还有没有别的问题」。那是 86% 那一档。
- ❌ **也不该用**：能用 `grep`/Python 确定性做完的事（抽字符串、数份数、比镜像）。
  那些本来就不烧模型 token，换成模型只会更贵更不可靠。

**成本实测**：整场 13 次调用 **¥0.58**（按余额差额算，不是估的：¥566.52 → ¥565.94）。

## 这次实测本身暴露的两件事

1. **第一轮 `max_tokens=900` 我记成了「模型不回答」** —— 其实是推理吃光了额度、
   正文一个字没输出。**`out=900` 不等于「答了 900 token」。**
   靠单独打一次 `1+1=?` 才看见 `reasoning_content` 这个字段。
   [[pipe-to-tail-hides-the-exit-code]]（同族：**输出为空不等于没跑**）
2. **`temperature=0` 不保证 token 数可复现**：同一题 T1-破损，两轮分别烧
   1814 与 3723 token。**报「它要花多少」必须连轮次一起报。**
