# 方法：**照文档教的那个形态跑一遍** —— 一天查出三个真缺陷（2026-08-17）

## 起因

Owner 的第四条批评是「使用过程有显著性故障和阻碍点」。
以往我验的是「命令本身对不对」，今天换成：**把文档里教给别人的命令，
按它教的那个形态、从它教的那个位置，原样跑一遍。**

## 战果（三件，全部是真缺陷，全部已修已推）

### ① 验包脚本按说明书跑就是红的

封面信教接手方：`cd <交付目录> && verify_handover_bundle.sh . --expect-tip <sha>`。
照做 ⇒ **`✗ git bundle verify 不通过`**。成因：`git bundle verify` **需要一个仓**，
而交付目录不是仓。**同一个包、同一个脚本，站的位置不同结论不同。**

这脚本**随包发给接手方**。他照说明做，第一件事就是看到一个假红。
自测一直 8/8 —— 因为我每次都在仓里跑它。

★ 修第一处时当场引入第二个错（`git -C` 切目录后相对包路径失效），
  而我刚写的那条断言**抓不住**：它传的是绝对路径，**文档教的是相对目录**。
  ⇒ 补第二条断言，照说明书的形态跑。

### ② README 教的第一条验证命令是红的，而且要跑 12 分钟

`python3 …/self_check.py` —— **751.9 秒、rc=1**，全程一个字不吐（`-v` 输出被 capture）。
README 一处没提耗时，全仓 8 个文件提到 `--skip-tests`，**README 一次没提**。

三件红里**一件是我当天造的**：我写的 `test_profile_fallback_is_disclosed.py`
是个脚本不是测试模块，模块级 `sys.exit` 让 `unittest discover` 一 import 就
`SystemExit`。单跑它是 `自测 6/6` rc=0 —— **我只验了这一步，没走过套件那条链**。

### ③ `--size 16` 甩用户一段 12 行 traceback，且不说出路在哪

报错本身没错（small_team 是 5–15），但它不说合法区间、也不说
**换个 `--mode` 就行**（`--mode deep_team --size 20` 一直跑得通）。
现在：`error: … (valid: 5–15). Pass --mode to override, e.g. --mode deep_team.` rc=2。

## 同法查了、**没有缺陷**的两项（如实记，不凑数）

* **文档点名的脚本是否存在**：四份文档共 **31** 处点名，唯一「找不到」的是
  `/tmp/kc/kimi-code-hub/tools/kc_verify.py` —— 那是让读者自己解压出来的路径，
  **不是坏引用**。⇒ 0 缺陷。
* **路由排序是否确定**：同一道题跑 3 次 ＋ 三个不同 `PYTHONHASHSEED`（0/1/12345），
  入选顺序的哈希完全一致、第 6 名都是 Joel Salatin。⇒ 我报的名次与名单站得住。
  （这一条是按 [[same-command-twice-gave-two-numbers]] 主动补的负对照。）

## ★★ 方法本身的三条纪律（都是今天踩出来的）

1. **形态要一致**：文档写 `verify.sh .`（相对目录），自测就不能只跑绝对路径。
   [[the-comment-states-the-rule-the-code-narrows-it]]
2. **位置要一致**：文档教「站在交付目录里跑」，就必须真站在那里跑一次。
   判据的判定不许取决于 cwd。[[a-checkers-verdict-must-not-depend-on-cwd]]
3. **链条要走完**：单跑一个测试文件 rc=0 ≠ 它在套件里跑得起来。
   [[verifying-single-commands-is-not-verifying-the-chain]]

## ★★★ 而这一天我自己的探针错了**五次**，形状各不相同

| # | 写法 | 它报的 | 实际 |
|---|---|---|---|
| ① | `cmd \| tail; rc=${PIPESTATUS[0]}` | rc **空** | zsh 没有 `$PIPESTATUS`（是 `$pipestatus`） |
| ② | 只在 stdout 找 `✗` 判变异 | 「没抓住」 | 抓住了，靠抛栈（在 stderr） |
| ③ | `for a in "--size 14"…; cmd $a` | 三条**全红**，像回归 | **zsh 不做单词分割**；单跑全 rc=0 |
| ④ | `until ! pgrep -f "self_check.py"` | **永不退出** | 等待器**自己的命令行**含那个串 |
| ⑤ | ` ```(?:bash)?\n(.*?)``` ` | SKILL.md **0 条命令** | ` ```text ` 打乱配对，抓到的是块之间的散文 |

①②④⑤ 让我**低估**，③ 让我**误判成自己造了回归**。
⇒ 报「没抓住／没变化／挂住了」之前，**先怀疑跑法**：rc、stdout、stderr 三样都看。

## ★★ 还有一件必须写下来：**我在验证跑着的时候改被测文件，一天三次**

`self_check.py` 要 12 分钟。我把它挂后台就继续改 `route_team_moe.py` ——
三次都得掐掉重跑，白烧 36 分钟。第一次我**当场写下**「后台在读这棵树 ⇒ 只读区」，
然后照旧改了。**写下来不等于会照做。**
⇒ 起长验证前先问「这段时间我打算改仓吗」；打算改就**先改完再起验证**。
  验证结束后核一句：**被测提交 == 当前 HEAD 吗**。
