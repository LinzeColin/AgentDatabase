# 「声口」这道检查点，对全库 **39%** 的人物结构性不可用（2026-08-18）

## 怎么撞上的

给 Eiffel #142（法文语料）跑 `check_first_person_density`：

    正文字符 374,811
    语种（按字符）：可读语种（英文）0／不可读 374,811 ——**可读占比 0%**
    **本判据不适用**：只认英文的第一人称动词锚点（`I have`／`I find`／`I prefer`…），
                      德文 `ich habe`、法文 `j'ai`、俄文 `я` **一个都不认**
    **实质第一人称句**：null      **密度（每万字）**：null

**判据是对的** —— 它返回 `null` 而不是 `0`，没有给出一个会被读成「声口薄」的数。
（这正是 2026-08-11 那次修好的：Mendel #125 德文 1578 万字符曾报「实质 0 句」，
Koch #107 德文 2 亿字符曾报 0.07/万字 —— **那不是声口薄，是判据不认识那门语言。**）

而这道检查点**对非英文语料结构性给不出读数**。

## ★★★ 这不是新缺陷，是**射程缺口**

判据本身没错，也没有假绿（它明说不适用）。问题在于：

> **一道被当作「不达标当场结案」的检查点，对四成人物从来没有生效过；
> 而「未量」在下游被读成了「没问题」。**

对比「声口不够」这一档已判的三个人 —— Coffin #130（15 句 / 0.87）、
Bain #136、Sellers #154 —— **他们的语料都是英文**，读数成立，判定不受影响。
⇒ **本条不推翻任何既有判定**，它说的是另一侧：非英文那 19 位**根本没被这道门量过**。

## 处置（本轮只记，不动）

1. **不新造一把「能读法文/德文的声口尺」** —— 那会是为凑数造判据。
   要建，得先回答「非英文的第一人称锚点怎么定、怎么验」，那是独立一轮的活。
2. **Eiffel #142 抓源后**：声口一栏如实写「**未量：判据只认英文锚点**」，
   不写「够」也不写「不够」。
3. **既有 19 位**：属存量，按 ㊵「已判分即冻结」不动分数；
   但若将来重蒸，声口一栏同样只能写「未量」。
4. **`worth_starting` 的说明**里「声口…不达标当场结案」这句，
   对非英文人物是**够不到的门** —— 值得在那里加一句射程，但**改文案属决定**，本轮不改。

## 可复算

```bash
cd CodexSkills/skill_log_evals/persona-distiller/_corpora
python3 - <<'EOF'
import json, pathlib, collections, re
LANG = re.compile(r'"language"\s*:\s*"([a-z]{2,3})"', re.I)
rows = []
for ws in sorted(pathlib.Path(".").glob("wip-*")):
    langs = collections.Counter()
    for p in (list(ws.rglob("*fetch-manifest*.json"))
              + list(ws.rglob("source-ledger.jsonl")) + list(ws.rglob("meta.json"))):
        if p.stat().st_size > 4_000_000:
            continue
        for m in LANG.findall(p.read_text(encoding="utf-8", errors="replace")):
            langs[m.lower()] += 1
    if langs:
        rows.append((ws.name, langs))
non_en = [w for w, c in rows
          if (c.get("en", 0) + c.get("eng", 0)) / sum(c.values()) < 0.5]
print("有语种字段 %d 个｜英文占比<50%% 的 %d 个" % (len(rows), len(non_en)))
EOF
```
