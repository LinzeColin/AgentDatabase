# 同一批模板文案有**两个下游**：一个放人进门，一个决定谁干活

**日期**：2026-08-18　**包**：v0.0.0.36（准入）→ **v0.0.0.38**（分派）

`compile_task_graph` 生成的 `work_packets[].objective` 是**模板文案**。
这一个事实，在 `route_team_moe.py` 里有**两处**被当成「与任务的相关度」在用：

| 位置 | 表达式 | 后果 |
|---|---|---|
| `score_candidate` :191 | `packet_similarity = max(overlap_score(objective, 卡片))` | 进了准入的 `max(...)` ⇒ **放人进门** |
| `assign_packets` :350 | `compatibility = overlap_score(objective, 卡片)` | 进了分派打分 ⇒ **决定谁拿哪个包** |

**同一个坏零件，两个消费者。** 我先只查了第一个，差点就收工了。
[[one-requirement-two-consumers]]

## 机制（这次量得比上次更宽）

上一轮只在 `deep_team/14` 上证过「五道题的 objective sha256 相同」。
本轮在 **`auto` 档、12 个独立题面**上重证，并改看**字面**：

```
12 个题面 ⇒ 出现过的不同 objective 共 28 条
  · 5 条固定阶段包（问题编译／证据地图／方案／制品／…）
  · 23 条「独立处理第 N 个证据／方案／对象分片」——  N 只是编号
没有一条带任务内容
```

★ 扫「题面 4 字片段是否出现在 objective 里」只命中 **1 次**，而那次是**反向**的：
某道题面自己写了「证据缺口」，模板里本来就有
「建立事实、来源、未知、当前性和**证据缺口**地图。」
—— **不是模板抄了题面，是题面撞上了模板的词。**

## 消融

```
12 支多于 1 人的队伍；包合计 173 个
把 compatibility 置 0 ⇒ 换了主人的包 154 / 173 = 89.0%
```

### ★★ 射程必须和数字写在同一句里

置 0 之后剩下的只有 `0.28*base_score − 0.08*载荷`，**那个对照臂本身是退化的**
（全队按 base 排序、载荷惩罚轮转）。所以：

> **89% 不能读成「89% 的分派是错的」。**
> 它只支持一条：**决定谁拿哪个包的，主要是一个不含任何任务信息的量。**

## 过程里弃掉的一组数

第一次跑的是 4 道手写题，读数看着很好（compatibility 极差 0.26 vs base 极差 0.06）。
但**其中 3 道路由只给了 1 个人** —— 一个人时分派没有选择余地，
那三行**不构成证据**。已整组弃用，换成 12 个独立题面里真正多人的队伍重测。

> 这和「稀疏样本上数出的『唯一』是假的」是同一族：
> **样本里根本没有可比较的对象时，任何比较都是空的。**
> [[uniqueness-counted-on-a-thin-sample-is-manufactured]]

## 三件事连起来看

今天在同一条路由链上量到的三处，**名字都对，量的东西都不对**：

```
choose_mode   五个信号，实际只有 complexity 在起作用，而它量的是**题面长度**
准入 max(...) 五项里有一项与任务无关，最坏一题 **97.6%** 的人靠它进门
包分派        主要由那同一项决定，置 0 后 **89%** 的包换主人
```

⇒ **从「派几个人」到「派谁」到「谁干哪块」，三层各自都有一个与任务无关的量在主导。**
每一层单看都像小毛病，叠起来才是「路由到底在按什么选人」这个问题的答案。
