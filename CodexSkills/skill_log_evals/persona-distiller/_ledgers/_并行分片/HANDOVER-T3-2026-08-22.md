## 6. 通用 LLM Harness Agent / vibe-coding 经验（跨项目可借鉴）

1. **子代理后台任务随回合消亡**：agent 回合一结束，它起的后台任务即被杀。长任务必须前台阻塞跑完 + 同回合内提交；不要起后台等"自动通知"。
2. **lost 后 resume 保留上下文**：代理 lost 不要 fresh dispatch（会重蒸烧钱），resume 保留上下文续跑即可——本会话三代理同批 lost 一次 resume 全救回。
3. **断点恢复自查**：接手半成品不要信"已生成"断言，先查磁盘真实断点（产物行数/门报告），从真实断点补，不重跑已完成步骤。
4. **并行写互斥**：多代理共享状态文件时，dispatch 前查 status + 进程存活，避免重复派发互相覆盖。
5. **停顿阈值**：resume 恢复期首写前静默 19-35 分钟属正常，未到 40 分钟不杀不重发——乱杀会把正常恢复误判成死循环。
6. **成本分账可视化**：用 wf.py usage 每波对账（flash/pro 次数+金额），pro 占比超线即停；95%+ flash 是可持续的。
7. **防死循环 = 事件驱动**：等待完成通知而非轮询空转；每个回合只做一件有界工作，无动作就收尾等事件。
8. **经验三段式沉淀**：每条经验写「结论 / 为什么 / 代价」，无实测证据不改模板——避免把直觉当规律写死进工作流。
9. **核验不信任自报**：agent 报告"完成"只是输入，独立跑 verify 命令（commit 存在/切片状态/registry/errors 0）才可信。
10. **交付物 gitignored 也留 registry 副本**：dist zip 不入 git，登记副本在 registry/，交接靠副本不靠压缩包。
