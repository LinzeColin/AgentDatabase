# #123 ④ 复量：**不是 5 个恒定分项，是 2 个**；而摘掉它们是**可证明的空操作**（2026-08-18）

## 原记录：「**五个**恒定分项贡献精确 0.0%：接线还是摘掉？」

**「五个」不成立。** 两份样本各 10 条任务，逐条读 `routing_observability.ranking_components`
的 `sigma`，统计「在每一条上都 σ=0」的分项：

| 分项 | 权重 | 名册标签 10 条上 σ=0 | **72 道 oracle 10 条上 σ=0** |
|---|---:|---:|---:|
| `evidence` | 0.05 | **10/10** | **10/10** ← ★ 恒定 |
| `boundary` | 0.04 | **10/10** | **10/10** ← ★ 恒定 |
| `capability_match` | 0.14 | 4/10 | **0/10** |
| `user_value_match` | 0.07 | 4/10 | **0/10** |
| `domain_match` | 0.15 | 3/10 | **0/10** |
| `task_similarity` | 0.24 | 1/10 | **0/10** |
| `scenario_match` | 0.10 | 1/10 | **0/10** |
| `packet_similarity` | 0.15 | 0/10 | 0/10 |
| `currentness` | 0.06 | 0/10 | 0/10 |

⇒ **真正恒定的只有 2 个**：`evidence` + `boundary`，**权重合计 0.09**。

另外几个在名册标签上偶尔 σ=0（4/10、3/10…），**在任务口吻的样本上一次都没有**
—— 那是**任务的性质**（名词短语标签区分不出能力/用户价值），**不是分项的性质**。
把它们数进「恒定分项」，就是又一次拿标签当全部。

## 摘掉这 2 个会怎样：**可证明的空操作**

★ 我第一版推理错了，记下来：我写「`marginal_select` 里 `diversity_bonus 0.08` 与
`repeat_penalty` 是**绝对值**，base 整体下移 ⇒ 多样性的相对分量变大 ⇒ 选人会变」。
**推错了** —— 同一步里**每个候选都下移同一个常数**，`0.76*base + bonus - penalty` 的
argmax 不变。**这是可证明的空操作。**

实测印证（6 条 oracle 题、size=14、单开关消融、复原后断言回到原值）：
**名单变了 0 条。**

同时它也**不影响准入**：`accept_threshold` 判的是
`max(task_similarity, packet_similarity, capabilities, scenarios, domain_match)`
—— **evidence/boundary 根本不在那个 max 里**。

## ★★★ 但 σ=0 是**名册的性质，不是公式的性质**

    evidence = 1.0 if latest_artifact and team_card else 0.45
    boundary = 1.0 if hard_boundaries else 0.4

    实测在册 102 人：latest_artifact **102**｜team_card **102**｜hard_boundaries **102**
    ⇒ 两项**全场恒 1.0** ⇒ σ=0

**一旦有一个产物缺 `latest_artifact` / `team_card` / `hard_boundaries`，
`evidence` 就变成 0.45 vs 1.0、σ>0，它立刻开始影响排序。**

⇒ ④ 的真正问题**不是**「它们贡献 0.0%，要不要摘」，而是：

> **要不要保留两个「只对不合格产物才发火」的分项？**

- **保留**：代价是**恒定的 0.09** 加在每个人身上（可证明不影响任何判定），
  好处是**名册一旦出现残缺产物，排序会自动把它压下去**。
- **摘掉**：分数更可读；代价是**那道自动惩罚没了** ——
  残缺产物与齐整产物在排序上**从此等价**。

★ **我不替 Owner 选**：这是「要不要留一道目前用不上的保险」，属设计取舍。
  但**原来的问法（「贡献 0.0% ⇒ 是不是该摘」）会把人引向摘掉** ——
  而那个 0.0% 恰恰是**名册目前齐整**的证据，不是分项无用的证据。
