# 「四档都验收过」是假象 —— 四份证据**全是 `--mode` 指定跑出来的**（2026-08-18）

## 一句话

`evidence/v0.0.0.14-candidate-acceptance/` 下四份 `route-<档>.json` 看着正是
「四档都够得到」的反证。**逐份读它自己的字段**：四份都写着 `requested_mode = 该档`，
四份的 `task_graph.mode_reasons` 都是 **`['explicit owner/runtime override']`**。

⇒ 它们证明的是「**每一档被指定时跑得起来**」，**不是**「自动推断够得到每一档」。
  文件名 `route-swarm.json` 长得像后者。

## ★★★ 我差点写成另一件事，而且是错的

第一步我拿这四条题面用 `auto` 重编译，得到：

| evidence 文件 | 文件里记的 | auto 重编译 | |
|---|---|---|:--:|
| route-deep_team.json | deep_team | deep_team | ✓ |
| route-single_expert.json | single_expert | **small_team** | ✗ |
| route-small_team.json | small_team | **deep_team** | ✗ |
| route-swarm.json | swarm | **deep_team** | ✗ |

我几乎据此写下「**3/4 份验收证据漂了**」。**那是在比两个不同的东西** ——
证据是 `--mode` 指定跑的，我是 `auto` 跑的。真去查两个可能的成因，两个都不成立：

- **画像变了？** 证据文件自带当时算出的 `profile`。逐项对比：
  complexity / risk / parallelizability / coupling **每一个数当时与今天一模一样**。
  唯一变的是 swarm 的 `domains` **8 → 7**（掉的是 `creative-design`）——
  那正是 2026-08-17 把 `设计`/`design` 降为弱信号的**正确结果**，不是漂移。
- **门槛变了？** `git log -L '250,266:scripts/compile_task_graph.py'` ⇒ **只有一次提交**，
  就是创建它的那次。三行阈值**从未改过**，与证据落库那个提交里逐字相同。

**两个成因都排除之后，剩下的解释只有一个：那四份根本不是 auto 跑的。** 回去读字段，是。

★ 教训的形状：**一个看起来自洽的差异，先问「我比的两侧是不是同一个东西」，
  再问「是谁变了」。** 我把顺序做反了，差 10 分钟就提交一条冤枉记录。

## ★★★★ 最硬的那个数：为 swarm 量身写的题，自动推断仍然不选 swarm

swarm 那条验收题面是**照着 swarm 的门写的**：

> 「**全网批量并行**研究软件 AI、投资、财务、法律、创业、运营、营销、设计、材料、
>  工程、建造、采购、教育、农业和研究工具，将**至少四十个独立分片**合并为 benchmark 与交付任务包。」

`PARALLEL` 词表 14 个词，它一句话里塞进了 **3 个**（全网／批量／并行）—— 而

    parallelizability = 0.08 + (命中数/4) × 0.78
    3 个命中 ⇒ 0.08 + 0.75×0.78 = **0.665**   门槛 **0.72**   ⇒ **差 0.055**
    要过门得命中 **4 个**（= 一句话里把 14 个词里的 4 个全凑齐）

**有人专门为 swarm 写了一条任务，自动推断仍然不会选 swarm。**
这比「60 条标签上 0 次触发」更接近「结构性不可达」的直接证据 ——
标签可以说「样本不代表用户」，而这一条是**照着门写的**。

## 已落地（不动门、不动席位）

`check_mode_ladder_reachable.py` 新增 `evidence_arrival()` 段，把
「**靠推断到达**」与「**被 `--mode` 指定到达**」分两栏印。首跑：

    | 档 | 靠推断到达 | 被指定到达 |
    | deep_team     | **0** | 1 |
    | single_expert | **0** | 1 |
    | small_team    | **0** | 1 |
    | swarm         | **0** | 1 |

自测 8 → **12 项**，新增四项含两个负对照：
- **0 份要判「未核」**，不能判成「没有指定的」；
- ★★★ **只看 `requested_mode` 不够** —— 有的产物缺该字段而 `mode_reasons` 里写着 override，
  漏掉这一半会把「被指定」误报成「靠推断」，**那正是本段要防的那句话**；
- 坏 JSON 跳过不炸（读到 3 份不是 4 份）。

★ 写自测时我把外层 `chk` 的计数器 `n` 覆盖成了 int（`by, n = evidence_arrival(d)`），
  自测当场崩给我看。**自测抓到了自测自己的 bug** —— 已改名 `nf`。

全套 **绿 13 红 0**｜`validate_group` rc=0｜本件 rc=1（两档够不到，预期）。
