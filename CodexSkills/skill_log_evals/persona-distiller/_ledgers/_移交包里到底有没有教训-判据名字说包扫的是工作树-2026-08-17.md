## ★★★ 判据为什么没喊 —— 名字说 bundle，扫描面是工作树

### 已修：加第三个扫描面 —— 产物本体，且优先于工作树

    扫描面：读自移交包 agentdb-persona-distiller-full.bundle（27 个 ref，自足）
    ★★ **教训库覆盖面**：本机 212 条｜包里 197 条｜两边都有 184 条

**四种「量不到」全部返回 `None` 而不是空集**（空集会被读成「包里一条都没有」，
把一次未量报成 212 条全丢的假灾难 —— [[measurement-errors-all-point-the-same-way]]）：

| 情形 | 判定 |
|---|---|
| 本机没有包 | None |
| 路径不存在 | None |
| 不是 bundle ⇒ `git bundle verify` 不过 | None（**本机 sha 不许冒充包里的字节**） |
| 包是好的、**但对象不在本机 `.git` 里** | None（换台机器就是这样） |

★ 之所以敢拿本机 `.git` 去读包的内容：**verify 说包自足 ＋ git 是内容寻址**。
  这两个前提缺一个就必须报未量 —— 已各配一条断言。

### 自测 15 条 ＋ 四种变异全部干净地红

| 变异 | rc | 抓住的话 |
|---|---:|---|
| ① 量不到返回空集 | 1 | 「没有包 → (None, 原因)，不是空集」 |
| ② 产物本体这一面整个断开 | 1 | 「多个包时取文件名日期最大的那个（实得 None）」 |
| ③ verify 不过也照读 | 1 | 「不是 bundle 的文件 → verify 不过 ⇒ None」 |
| ④ 对象缺席时报 0 而不是未量 | 1 | 「包好、但对象不在本机 `.git` 里 ⇒ None，不是 0」 |

★★ ②④ **第一版都没抓住**，各自的成因不同，都得记：

* **④** 压根没断言 —— 补了一条：现造一个外来 git 仓 → `git bundle create` →
  拿到本仓来读，**本机 `.git` 里绝无其对象**。[[zero-hit-gates-must-prove-they-can-hit]]
* **②** 其实红了，但是靠 `AttributeError` 抛栈红的，而**抛栈发生在正对照之前，
  把后面的断言全挡住了** —— [[a-red-gate-hides-every-gate-behind-it]] 长在我自己的自测里。
  改成 None 安全后，它才说得出人话。
* 附带：我那次探针只在 stdout 找 `✗`，于是把「抛栈红了」读成「**没抓住**」——
  [[i-create-the-leak-channels-myself]] 的同族：**探针的形状 ≠ 实况的形状**。
