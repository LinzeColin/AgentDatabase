# 把新判据推广到上游包：**没有第二例**，而这正好验了它的一个设计决定（2026-08-18）

## 做了什么

刚在 `persona-distiller-group` 抓到「随包文档叫用户跑一个不在包里的脚本」（8 行里 4 行）。
**同一件判据直接指到上游 `persona-distiller` 包上**（它自带 `--package-root`）：

    python3 ../persona-distiller-group/scripts/check_cited_scripts_ship_with_the_package.py \
            --package-root .

## 结果：**上游没有这个病**

    判定面：SKILL.md、README.md、CANONICAL-ROOT-ROUTE.md —— 实到 2 份
    被点名 2 个：**包内 2｜包外 0**
      ✓ delivery_builder.py  ← README.md
      ✓ init_target.py       ← README.md、SKILL.md

**成因也清楚**：上游 SKILL.md／README **根本没有「怎么重跑」那类表**
（`grep -c "重跑\|可复算\|怎么验"` = 0）。
⇒ 那张表是 group 侧特有的诚实设计，**而正是它把「重跑入口」写成了对外承诺**，
  于是「入口不在包里」才成为一个缺陷。**没有承诺就没有违约。**
  ★ 这不是说 group 侧不该有那张表 —— 它是全仓最有价值的一页；
    该做的是让表里的入口**真的到得了用户手上**（v0.0.0.31 已披露 + 落判据）。

## ★★★ 顺带验了一个我拿不准的设计决定

新判据把 **CHANGELOG 划成「只报不判」**，当时的理由是「历史文档必然含举例名与已移走的工具」。
那条线是我划的，**划的时候没有独立证据**。这次上游包给了：

CHANGELOG 里点名而包外的 **7 个**，逐个查下去 ——

| 脚本 | 真相 |
|---|---|
| `check_answer_length_leak.py` | **改名了**：CHANGELOG 自己写着 →`check_answer_surface_leak.py`，**该文件在包里且自测 rc=0** |
| `check_case_premises.py` | **有意删掉的**：CHANGELOG 自己写着「写了自测全绿、真实数据 **0 命中**、随即删掉」—— 零命中的判据不留，是纪律不是丢失 |
| `build_wo_blind.py`／`ms_contact2.py`／`split_book_1940.py` | 某个工作区的一次性脚本，在 `_corpora/wip-*/` 下 |
| `registry_core.py` | 在 group 包里 |
| `check_profile_declared.py` | 在 `_ledgers/_pipeline/` |

**七个没有一个是真丢失的。** 若当初把 CHANGELOG 也算进判定面，
这七条会全部报红，**方向是逼人去改一份正确的历史记录**。
⇒ 「只报不判」这条线**站得住**，而且现在有实例撑着，不再只是我的判断。

★ 同一天早些时候，这条线是被我**自己的散文**逼出来的：我在 v0.0.0.31 条目里
  讨论自测负对照时写下的三个**举例名**被判成「未披露的包外脚本」。
  **一次误报促成设计，一次独立复核确认设计** —— 两条都记下来。

## 这轮的产出是一个**负结果**，照样要写

「推广到第二个包，没有第二例」本身是结论：
- 它把这个缺陷的射程钉死在 **group 侧那张「怎么重跑」表**上，不必再去别处找；
- 它同时证明判据**指得动别的包**（`--package-root` 真的能用，不是只对自己家绿）。
