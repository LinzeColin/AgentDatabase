# 200 MB 推送闸**在每个 worktree 里都不响**——本地裸仓实证

日期：2026-08-11。起因：#87 要在 8-13 晚把东西推上 GitHub，先算「这条分支要推多少」。

## 实证（全程本地裸仓，不碰任何远端）

| | 守卫出声 | 退出码 | **真落进裸仓的量** |
|---|---|---|---|
| ① 本工作树现状 | **0 次** | **0** | **920 MB 全进去了** |
| ② 把主树的守卫放进本树 `.githooks/` | 1 次 | 1 | 76 KB |

## 根因（两层，都不是「忘了写」）

1. `core.hooksPath = .githooks`（local 作用域，所有 worktree 共享这条配置），
   **是相对路径**，按各 worktree 的根解析；
2. 而 `.githooks/` **在版本库里 0 个文件被跟踪**（`git ls-files .githooks` 空）——
   它只是**主树的一个本地未跟踪目录**。

于是每个 worktree 解析出的 `.githooks/pre-push` 都不存在 → **整个 pre-push 环节静默不跑**。

★★★ **而铁律 2 要求一切开发都在 worktree。**
所以这道闸只护着**唯一不开发的那个地方**。

★ 另有一份 `.git/hooks/pre-push`（独立的批量闸，LIMIT_MB=200）——
`core.hooksPath` 一旦设了，git 就不看 `.git/hooks/`，**那一份从来没跑过**。

## ★★ 「整份拷过来」是错的——实测把合法推送堵死了

主树 `.githooks/pre-push` 尾部是
`exec "$repo/ops/memory-atlas/canonical_gate.sh" "$repo" quick`，
而 `canonical_gate.sh` **同样是主树独有的未跟踪文件**（`git ls-files` 命中 0）。

    整份拷过来后推一次合法的小推送 → `No such file or directory`，退出码 1，
    裸仓一个 ref 也没收到。

**那是把「没有守卫」换成「谁也推不了」，不是修好。**

## 修法：本树装只跑体积闸的钩子，跑不了的门**大声说**

`.githooks/pre-push`（本树，未跟踪）+ `.githooks/pre-push.worktree`（**已跟踪**，
接手的人 clone 下来就有，一条 `cp` 装上）。

三种情形实测：

    A 小推送     → 退出码 0，放行，**并打印「memory-atlas 的 quick 门在本 worktree 跑不了」**
    B 2106 MB    → 退出码 1，拒绝，裸仓零 ref
    C 逃生口=1   → 退出码 0，放行

★ 「没装就跳过」的分支**静默 exit 0** 是本项目吃过的亏
（[[untested-fallback-branches-only-fire-on-their-machine]]）——
所以 A 那一路明写「放行的是**体积闸判过了**，不是所有门都过了」。

## 顺带算清 #87 的数（`git rev-list --objects origin/main..HEAD` 实测）

    本分支比 origin/main 多 **1128 个提交**、新 blob **2106.2 MB**

## ★ 我在这一段里犯的一个错，记下来

第一次做实证时写的是 `git push ... "$C:refs/heads/probe"`，
**zsh 把 `:r` 当成了参数修饰符**（`${C:r}` = 去扩展名），refspec 被吃成
`...408efs/heads/probe`，推送在解析阶段就失败——
而我当时据此写了「钩子没拦」。**那句话当时是没有证据的**，
改成 `"${C}:refs/..."` 重做才拿到上面 ① 那一行。
