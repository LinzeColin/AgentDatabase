# 遥测终于有了家 —— 而记录数依然是 0（两件事要分开说）

**2026-08-17**｜对着 Owner 评分第 ④ 条「记录、自优化迭代没有实质性收益」。

## 真因不是「还没用」，是**结构上攒不起来**

| 组件 | `--telemetry` |
|---|---|
| `record_team_outcome.py`（**写**） | **必填** |
| `route_team_moe.py`（**读**） | 可选，**无默认** |
| `run_team_pipeline.py`（**读**） | 可选，**无默认** |

**没有任何一处命名过路径。** 写手和读手只有在人**每次手工把同一个路径传给两边**
时才会相遇。实测：记录数 **0**，每份 route-plan 都报 `telemetry unavailable`，
策略 C **一次都没启用过**。

C 需要 **≥60 条 outcome**。**一个没有归宿的计数器，连 1 都到不了。**

## 修了什么

`registry_core.default_telemetry_path()` 定唯一真源
`<registry-root>/telemetry/team-outcomes.json`，三处共用；写手的 `--telemetry`
改为可选。**行为一个字不改** —— `load_telemetry()` 对不存在的文件本来就退化成
`eligible_for_c: False`，加默认值不可能把一条能跑的 B 路由变红。

顺带：route-plan 现在印 `telemetry_path` / `telemetry_path_source` /
`telemetry_file_present`。此前一份写着「telemetry unavailable」的方案
**无法让人分辨「文件是空的」和「我找错地方了」** —— 而几个月来确实没有地方可找。

## 测试与两个反对照

`tests/test_telemetry_roundtrip.py` 在**临时目录**里跑完整回路
（合成 outcome 永远不会落进真的遥测文件）：

- 改掉**写手**默认 → 红
- 改掉**读手**默认 → 红

★★ **第一版只钉了写手** —— 把读手的默认删掉，测试照样绿。
**一个要求，两个消费者，其中一个没有守卫**。这是本项目记过多次的形状
（[[one-requirement-two-consumers]]），补上读手断言后两侧才都成立。
让读手可验的办法是**让它说出自己读了哪个文件** —— 可测性和如实披露是同一件事。

## 仍然为 0 的那一半，如实说

**记录数依然是 0。有了家不等于有了数据。**
`--actual-success`（实测任务成功率）与 `--delta-score` 要靠**真跑一次任务并与
裸模型盲比**才有；本会话 harness 不许派子代理，凑不出两个互相独立的评委会话。
**编一个就是造数据，不做。**

⇒ 这次解决的是「**攒不起来**」，不是「**已经攒到了**」。
Owner 评分第 ④ 条里，「自优化迭代从未启动」的**结构性障碍**已经拆掉；
「没有公开盲测结果」那一条**原样成立**。
