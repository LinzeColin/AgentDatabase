# 钩子现状复量：#124 的一半**已经不成立**，另一半根因定位到行（2026-08-17）

待裁定 #124 记的是「铁律 2 的 pre-commit 守卫处于断开状态」，
并附带一条「`pre-push.worktree` 也是 vestigial」。今天两半各自实测。

## 一、`pre-push` 那半：**记录已陈旧，现在是好的**

`.githooks/pre-push.worktree` 的文件头写着它必须存在的理由：

> `core.hooksPath = .githooks`（local 作用域，所有 worktree 共享），
> 而 `.githooks/` **在版本库里 0 个文件被跟踪** —— 它只是主树的一个本地未跟踪目录。
> 于是 git 在每个 worktree 里解析出的 `.githooks/pre-push` **不存在**，
> **整个 pre-push 环节静默不跑**。

**这个前提今天不成立了：**

    git ls-files .githooks/
      .githooks/pre-push          ← **已跟踪**
      .githooks/pre-push.worktree ← 已跟踪

两个 worktree（`_scratch/AgentDatabase-dingtalk-…`、`_scratch/agentdb-verifier-2_3`）
里 `.githooks/pre-push` **都在**。

★ 但「文件在」不等于「钩子响」。**实测**（在 worktree 里跑 `git push --dry-run`）：

    MEMORY_ATLAS_CANONICAL_GATE_PASS mode=quick failed=0
    守卫出声行数：1

⇒ **钩子在 worktree 里真的跑**。那道 200 MB 体积闸现在护得到开发的地方。
  `pre-push.worktree` 的存在理由随之消失（**未删，只记档** —— 删它不是我的活）。

★★ 顺带确认没有对外动作：dry-run 打了
`* [new branch] HEAD -> __probe_never_created`，看着像建了分支。
`git ls-remote --heads origin` 现问远端：**只有 `refs/heads/main`**，
含该名字的分支 **0 个**。`--dry-run` 不发送。

## 二、`pre-commit` 那半：**仍然断开，且根因在一行上**

    .githooks/ 里有：pre-push、pre-push.worktree —— **没有 pre-commit**
    core.hooksPath = .githooks   ⇒ git 只找 .githooks/pre-commit
    .git/hooks/pre-commit 存在（31 行，`linze-maintree-guard —— 铁律2 的机器强制版`）
    **但它永远不会被调用。**

根因在母仓 `tools/install-guards.sh`：

    第 20 行   hd="$r/.git/hooks"; mkdir -p "$hd"        ← **无条件装进这里**
    第 109 行  # 配了 core.hooksPath 的仓会绕过 .git/hooks —— 装了也不跑,必须点名说清楚
    第 110 行  hp=$(git -C "$r" config --get core.hooksPath …)
    第 112 行  echo "  ⚠ $r 配了 core.hooksPath=$hp,.git/hooks 不会被调用。"

**它知道这件事，然后打一句警告、照装不误。**
装完的结果是：一个存在、可读、写着「机器强制版」的文件，**一次都不会执行**。

## 为什么这一半仍然只能由人定

修法本身很短（`core.hooksPath` 有值时装进那个目录，或干脆让安装器在这种情况下 **rc≠0**）。
但**打开它就会改变工作方式**：本会话我在主树 main 上提交了 60+ 次，
守卫一旦生效，这些提交会被直接拒绝，必须先 `git worktree add`。
**这是流程决定，不是代码决定。**

⇒ #124 的射程从两件缩到**一件**：只剩 `pre-commit`，且已定位到
`tools/install-guards.sh:20` 与它自己第 109–112 行的那句警告。
