# 准入门的 `max(...)` 里有一项**与任务无关** —— 最坏一题 97.6% 的人靠它进来

**日期**：2026-08-18　**包**：`persona-distiller-group` v0.0.0.35 → **v0.0.0.36**
**触发**：`task_profile` 五个变量审完之后，把同一个问题（「名字说的 vs 实际量的」）
搬到**排序侧／准入侧**再问一遍。

---

## 1. 事实

`route_team_moe.score_candidate` 末尾那行（源码原文）：

```python
# Expert Choice: the expert declines tasks outside its demonstrated competence.
if max(task_similarity, packet_similarity, capabilities, scenarios, domain_match) < accept_threshold:
    return score, {...}, "expert-choice compatibility below threshold"
```

`max(...)` ⇒ **任一项过线即可**。其中：

```python
packet_similarity = max(
    (overlap_score(packet["objective"], text) for packet in graph["work_packets"]),
    default=0.0,
)
```

而 `compile_task_graph` 生成的 `work_packets` 的 `objective` 是**固定套话**：

```
把用户目标编译为交付物、约束、成功条件和停止条件。
建立事实、来源、未知、当前性和证据缺口地图。
在人物能力与边界内形成可执行解决方案。
把解决方案转成用户所需的最终制品或行动包。
独立处理第 N 个证据／方案／对象分片，并提交可合并的结构化产物。
```

**五道内容毫不相干的题** —— 遗留微服务重构／40 公顷再生农场轮作／医院灭菌安全论证／
供应商合同谈判／`zzq0 zzq1 …` 一串无意义词 —— 编出来的 **14 条 objective 的 sha256 完全相同**。

⇒ **102/102 人的 `packet_similarity` 跨题一个都不动。**

对照（正对照，证明探针看得见变化）：`task_similarity` 跨这五题**只有 4/102 不动**。

### 规模

24 条名册标签、策略 B、门 0.17：过准入的人里，**其余四项全部低于门、
唯一靠 `packet_similarity` 过线**的占比 ——

| | 读数 |
|---|---|
| 均值 | **62.8%** |
| 最坏一题（`positioning-and-worldview-choice`） | **97.6%（41/42 人）** |

**这些人没有任何与本题有关的证据，却被判为「能接」。**

## 2. 它和已知的那族是同一件事

| 已记的 | 形状 |
|---|---|
| `complexity` 名义是复杂度，实际量题面长度 | 名字对了，量的东西不对 |
| `risk` 名义是执行风险，实际量题材受不受监管 | 同上 |
| `coupling < 0.72` **恒真**，从不生效 | 永远为真 ⇒ 不产生信息 |
| `parallel ≥ 0.72` 真任务上 **0/72** 够得到 | 永远为假 ⇒ 不产生信息 |
| **本件：`packet_similarity` 与任务无关** | **常量 ⇒ 不产生信息，但它在 `max(...)` 里 ⇒ 直接放人进来** |

★ 前四条的后果是「这个信号没用」；**本件的后果是「这道门没用」** —— 差别在于
它坐在 `max(...)` 里：一个不产生信息的分量，在 `max` 下不是被忽略，而是**兜底放行**。

## 3. 发表前自己抓到的三个错（都会把数说大或说反）

### ① 拿错了卡片源 ⇒ 102 人读数全 0，差点写成「恒 0」

第一版用 `R.load_admission(root)` 取候选人，那返回的是**准入记录**不是卡片
（keys 是 `admission`/`canonical_name`/`dimensions`/…，**没有 `card`**），
`candidate_text` 只捞到 **32 字**（名字+类目），于是所有分量恒 0。

**发现它的是我自己写的对照**：`overlap_score(套话, 套话) = 1.0000` 而
`overlap_score(套话, 这个人的卡片) = 0.0000` 且 `task_similarity` 也 0.0000
⇒ **不是产品全 0，是我的扫描面空**。正确取法：`team-index.json` 的 `products`
（`candidate_text` 中位 **1001 字**）。

> 今天第 6 次「自己写的抽取器扫描面为空」。
> [[a-gates-scan-set-is-smaller-than-reality]]

### ② 键名错 ⇒ 会**多算**占比

准入那行用的是**局部变量** `capabilities` / `scenarios`，
而存进 `values` 字典时叫 **`capability_match` / `scenario_match`**。
我按前者 `.get(k, 0.0)` ⇒ 那两项恒读 0.0 ⇒ 「其余四项全部低于门」更容易成立
⇒ **占比被抬高**。第一版跑出来的 37/62/63/57 那组数**全部作废**，
正确口径下均值是 **62.8%**。

已落成一条测试，**直接对着 `route_team_moe.py` 的源码钉键名**，写错就红。
[[the-field-was-filled-with-the-filename]]

### ③ 四舍五入伪影 ⇒ 15 个人被误判成「跨题会动」

`score_candidate` 有两条返回路径：

- 接受：`{"values": {k: round(v, 4) for k, v in values.items()}, ...}`
- 拒绝（:263 / :270）：`{"values": values, ...}` —— **原样，不 round**

同一个人在「某题被接受、别题被拒绝」时，同一个读数出现 `0.1050` 和 `0.104972…`
两种精度 ⇒ 我的不变性比较判它「变了」。自测 ④ 因此从 87/102 变成 102/102。

**这是产品自身的一处不一致**：不影响任何判定，只坑读数的人 —— 我就是那个人。

## 4. 落了什么

- `scripts/check_admission_signal_depends_on_the_task.py` —— **9 项自测**：
  - ★**正对照**：`task_similarity` 必须跨题变，不变 ⇒ **rc=4 未量**（说明是探针死了，不是产品的结论）
  - ★**反对照**：把「冻结分量集合」置空 ⇒ 占比必须全为 0（证明这个数确实由「冻结」驱动）
  - 扫描面非空（`candidate_text` 中位 > 200 字 —— 直接钉死错误 ① 那条路）
  - 样本量绑定：传 `--limit` 而不给新地板 ⇒ **rc=4**
  - 地板可达性：`0 < BASELINE_SOLE_SHARE < 1`
- `tests/test_admission_signal_depends_on_the_task.py` —— **8 项**，含
  「地板压到 1% 必须判红」（一道永远红不了的门不是门）与「键名对着产品源码钉」
- SKILL.md「已测量的边界」新增一行
- 四个对照实跑：默认 rc=0｜地板 1% rc=1｜换样本量 rc=4｜自测 rc=0

**一个字都没改产品**。地板 **0.63** 贴着实测 0.6282 —— 本件钉的是
「**不许比现在更依赖那条任务无关的通道**」，不是「必须变绿」。

## 5. 射程（引用本件读数时必须一起引）

- 占比是在 **24 条名册场景标签**上测的 —— 那是**标签，不是用户会打的任务**。
  换成真实用户提问会不会变 —— **没量过**。
- 「五道探针题」是我写的。它们只用来**找差异**（写得越不一样越容易证伪「不变」），
  真正的护栏是正对照。但「除这五题外还有没有别的题能让它变」——**没穷举过**。
- 本件只说 `packet_similarity` **与任务无关**；它是不是**该**与任务有关，
  是设计问题，**要 Owner 定**（Task #135）。
