# 团队 skill 的完好性**已有承载** —— 别再造第二份校验清单

**2026-08-15**｜起因：给蒸馏 skill 修好 `checksums.sha256` 的覆盖缺口之后，
顺手问同一个问题「另一个 skill 呢」。差点造出一份多余的清单。

## 我先前的判断（**错的**）

`persona-distiller-group/` 目录里**没有 `checksums.sha256`**，只有 `VERSION` 与 `manifest.json`；
`manifest.json` 里没有任何 checksum/integrity 键；README 与 SKILL.md 也没提校验。

我 grep 了 `registry_core.validate_registry` 里的 `errors.append`，看到的全是
「族目录齐全 / 分类清单一致 / 必填字段 / schema 版本 / 登记类别与目录匹配」，
于是写下 **「它从不对任何文件算哈希」**，并准备给它造一份 `checksums.sha256`。

## 反例把它推翻了

在**副本**上真把东西改坏（不是读代码，是改了再跑）：

| 反例 | `validate_group` |
|---|---|
| 交付 zip 改掉 1 个字节（偏移 44361，`61 → 62`） | **`passed=False`**｜`✗ 创业经营师/david-packard/registration.json: artifact checksum mismatch versions/0.0.0.1/…zip` |
| `财务合规师/_category.json` 的 `folder` 字段改掉 | **`passed=False`**｜`✗ category manifest mismatch` |

**它抓得到，而且逐 zip 逐字节抓。**

真相：完好性是**每个产物自带**的 —— `registration.json` 记 `latest_outer_sha256`
与 `latest_runtime_sha256`，`registry_core` 用 `sha256_file()` 逐件复算。
`import hashlib` 就在 `registry_core.py` **第 5 行**。

★ 我 grep 的是 `errors.append`，**没盯 `sha256`／`hashlib`** ——
**按错误分支的函数名去判「它检不检查什么」，会漏掉判定本身。**
[[a-gates-scan-set-is-smaller-than-reality]]

## 结论：两件都不做

1. **不给团队 skill 造 `checksums.sha256`。** 完好性已有承载，再造就是第二把尺子；
   而且**全仓没有任何消费方**会去读它（团队 skill 连 `install.py` 都没有，靠拷贝安装）——
   那会是一个**没有调用方的判据**。[[a-checker-nothing-calls-is-not-a-checker]]
2. **「它不看内容」这句已撤回。**

## ★ 过程中还有一次「反例没落地」

第一次的反例用 `find . -name "*.md" -path "*软件开发师*"` 找目标，**什么都没匹配到**
（产物是 108 个 `.zip` 不是 `.md`）。于是 `cp`／追加全部失败，第二次跑的是
**同一份没改过的东西**，两边一起绿 —— 我差点据此写下「改坏了照样过」。

是那行 `cp: No such file or directory` 拦住的。
**反例必须先证明它真的改到了东西**，否则「两边一样」什么也不说明。
[[negative-control-must-not-share-the-assumption]]｜[[counter-example-red-can-be-red-by-coincidence]]

## 顺带确认的一件（也不是缺陷）

`check_verification_counts` 长期印 `名册人数：实况 102｜文中 None`，看着像漏。
**是有意不做**，判据里写着理由：文中的「600 人名册」是**项目目标规模**不是状态断言，
`正则分不出「目标」与「状态」——分不出就不要猜`。
而且它的判定字样是 `"文中没有这个数——**本件管不到，不算通过**"`，
**既不打 ✓ 也不计入对不上**。设计是对的，不要「修」它。
