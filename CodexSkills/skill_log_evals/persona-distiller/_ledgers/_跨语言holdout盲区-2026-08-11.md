# 跨语言 holdout 泄漏：判据看不见的一类（2026-08-11）

## 起因（Grotius #168，**开工时挡住的**）

重 OCR 找回六份干净拉丁语料，其中 `de_veritate_1809_lat` 的题名页字面：

```
HUGO GROTIUS DE VERITATE RELIGIONIS CHRISTIANAE … CUM NOTULIS JOANNIS CLERICI
BOSTONII, NOV-ANGLORUM; TYPIS THOMAS B. WAIT.   MDCCCIX
```

而该工作区的 **holdout** 台账写着：
*The Truth of the Christian Religion, in Six Books*（附 Le Clerc 第七书），**1809**。

`JOANNIS CLERICI` 即 Le Clerc。**同一部作品、同一年、同一注者，一个拉丁一个英译。**

→ 灌进去等于**把 holdout 的原本交给模型侧**。已写成硬约束，不 ingest。

## ★★★★ 为什么判据挡不住

`check_holdout_overlap` 按**内容重叠**判。
**拉丁本与英译本的 n-gram 重叠是 0**——门会安静地放行。
**这一类只能靠人挡。**

## 全库筛选：holdout 与 train **同年**的 25 处

★★ **「同年」是筛选器，不是判据。** 逐条读过：绝大多数是**同一年发表的不同文章**
（Gantt 1904 两篇 ASME、Paton 1919 三篇论文、Nightingale 1863 两份报告），
**同年 ≠ 同一部作品**。Grotius 那条成立是因为**同年 + 同注者 + 同题名**三重对上。

| 工作区 | holdout 年 | 备注 |
|---|---|---|
| adams-131 | 1911 / 1913 | 同刊同年不同篇（`conv-19xx-vxxx`） |
| barton-117 | 1864 / 1867 / 1871 / 1897 | 日记按年分册，同年有信件/演讲 |
| blackwell-118 | **未系年** | 25 份同为「未系年」——★ 这一格是**空值撞空值**，不是同年 |
| carver-127 | 1909 / 1916 | 同批公报的相邻号（`CAT313554xx`） |
| gantt-156 | 1904 / 1915 / 1919 | 同年不同篇 |
| **koch-107** | **1903** | ★ **已核：4 份全是 `language: de`，无语种差，跨语言风险不成立**；★★ 但 4 份的 `title` 全是文件名，**判不出是不是同一部作品**——见下 |
| nightingale-112 | 1863 / 1910 / 1911 ×2 / 1913 | 同年不同文献 |
| paton-162 | 1919 / 1928 ×2 | 同年不同论文 |
| rosenhain-138 | 1910 / 1921 | 同年不同论文 |
| semmelweis-105 | 1905 | 同年不同版本？**未核** |
| virchow-109 | 1877 | 同年不同文献 |

★ **本文件不给结论**，只把筛选结果摊出来。
真正要判的是「是不是同一部作品的不同语言/版本」，那要逐对回读题名页。

★★ `blackwell-118` 那一格尤其要注意：holdout 与 25 份 train 都标「未系年」，
**是空值撞空值，不是同年**——这正是 `empty-default-swallows-unknown` 的形状，
按同年筛必然把它捞出来，而它什么也不说明。

## ★★★★ 核 `koch-107` 时撞到的：**这一类核不动，因为 `title` 是文件名**

Koch 1903 那四份（含 holdout）：

| | source_id | title | language | tier |
|---|---|---|---|---|
| train | `src-efb168070db8` | `letter00koch.txt` | de | P1 |
| train | `src-fa15426ca4f5` | `spezifizittdera00dunggoog.txt` | de | S1 |
| **holdout** | `src-21864a2310b1` | `b28112933.txt` | de | S2 |
| train | `src-2031f1b4b303` | `festschriftzumse00jena.txt` | de | S2 |

**跨语言风险不成立**（四份全是 `de`）。**但也判不出它们是不是同一部作品**——
`title` 四个全是文件名，`b28112933` 是 Wellcome 条码，**不含任何题名信息**。

★ 这正是待办「台账 `title` 99% 是文件名」的具体后果：
**要判重复源，而唯一能判的字段没有信息。**

★★ 对照：Grotius #168 之所以挡得住，是因为他的 `title` 是**真书名**
（`ingest.py --title` 2026-08-11 才加，他是全库第一个 19 行 0 个文件名的工作区）。
→ **这条盲区的根治不在判据，在 ingest 时把题名写对。**
对存量而言，`propose_title_from_titlepage.py` 是既有工具（核验假设，不是抽取）。

## ★★★★ 一般化：**56 份 holdout 里 52 份（93%）的隔离无法用元数据核验**

24 个有 holdout 的工作区、共 56 份 holdout，逐份看 `title`：

| | 份数 | 占比 |
|---|---:|---:|
| `title` 是**文件名** | **52** | **93%** |
| `title` 是**真书名** | 4 | 7% |

真书名那 4 份，成因都清楚：

| 工作区 | holdout title | 为什么是真书名 |
|---|---|---|
| **grotius-168** | `The Truth of the Christian Religion, in Six Books` | **今天新加的 `ingest.py --title`** |
| **shewhart-165** | `Economic Aspects of Engineering Applications` | 昨天入库时手写 |
| nightingale-112（9 份里 2 份） | `NOTES ON NURSING: WHAT IT IS…` | `propose_title_from_titlepage` 核过的那批 |

### ★★ 这 93% **不等于「93% 有泄漏」**

它等于：**93% 的隔离，我们没有办法用元数据去查。**
内容重叠那道门仍在跑——只是它**跨语言看不见**（Grotius 这类），
**跨版本也看不见**（同一部作品的不同印次，n-gram 可以差很远）。

### ★★★★ Grotius 那次能挡住，靠的正好是这 7% 里的一个

**如果他的 `title` 也是文件名，那条 holdout 泄漏今天就会被灌进去**——
而门不会报，因为拉丁本与英译本的重叠是 0。

→ 这条把两件待办接上了：「台账 `title` 99% 是文件名」**不是整洁性问题**，
它是**让 holdout 隔离与重复源判定同时失效的根因**。

## ★★ 可修性：这 52 份**不是修不了**，是工作量

| | 份数 | 占比 |
|---|---:|---:|
| 有 `locator`（可回查题名页） | **45** | **87%** |
| 有 `url` | 0 | 0% |
| 两者都无 | 7 | 13% |

而那 7 份「两者都无」的，**文件名本身带信息**：

- `academica_de_finibus_tusculan_yonge_1891_en`（Cicero，Yonge 1891 英译）
- `tusculan_book1_yonge_1877_en`
- `paton-1919-transactions-between-partner-and-firm`（篇名直接在文件名里）
- `paton-1928-limitations-of-financial-and-operating-ratios`
- `paton-1928-special-applications-of-discounting`
- `05e-mnras-1854-lunar-craters`（MNRAS 1854）

**与 `b28112933.txt`（Wellcome 条码）那种完全不同**——那种才是真的无从下手。

→ **「离线修不了且文件名也无信息」的：0 份。**

### 这改变了「台账 title 99% 是文件名」那条待办的性质

不是「931 对清不掉」这种结构性障碍，而是：
**87% 有 locator 可回查，剩下 13% 文件名可读。**
用既有的 `propose_title_from_titlepage.py`（**核验假设**，不是抽取——抽取实测 2/9 已砍），
逐份给一个题名假设去核，是**可做的工作量**。

★ 但工作量不小：52 份 holdout 只是冰山一角，全库 1,943/1,969 行都是文件名。
**先修 holdout 那 52 份**——它们是隔离判定唯一的抓手，性价比最高。

## ★★ 可行性已验：工具在 holdout 上跑得通（2026-08-11，**dry-run，未改任何东西**）

取那 7 份「无 locator 但文件名可读」里的一份实测：

```bash
python3 scripts/propose_title_from_titlepage.py \
  --workspace <wip-paton-162/workspaces/william-andrew-paton> \
  --filter "transactions-between-partner" \
  --verify-title "TRANSACTIONS BETWEEN PARTNER AND FIRM"
```

输出：

```
核验题名 `TRANSACTIONS BETWEEN PARTNER AND FIRM`：**命中 1 份**｜未命中 0 份
  ✓ paton-1919-transactions-between-partner-   …Transactions Between Partner and Firm By W. A. PATon The personi…
```

**题名页字面印着它，署名 `By W. A. Paton`**（`PATon` 是 OCR 大小写坏）。
**假设来自文件名，核验来自正文**——正是这个工具设计的用法。

→ 「先修 holdout 那 52 份」**是通的，不是理论上可行**。

### ★ 但没有 `--apply`，理由是硬的

1. Paton #162 是**已记延后的归档件**，改它的台账等于动一份已判过的产物；
2. 那 52 份分布在 24 个工作区，多数是拒发/延后件——**动它们要先定「改不改已判过的东西」**，
   而那是 ㉖ 那一类的问题。

**本条只留可行性结论，不动数据。**
