### ★★★★ 2026-08-12 同日新增：**变异要在夹具上做，不要在真实语料上做**

本项目一直用「把判据改坏 → 看它红不红」来验判据。当天撞到这套做法的一个**盲区**：

给 `check_paper_lanes` 加了一个条件，然后**在真实语料上把它拆掉重跑
——全库输出一个字都没变**。

不是条件没用。是**没有任何现存工作区走得到那条分支**
（要同时满足「有纸面道」与「单道组合占比 ≥80%」，全库一个都没有）。
换成夹具（95% 单道 `writings` + 5% `writings+expression`）当场就验出来了，
夹具随后固化成自测 `F‴`。

**判断法**：变异之后若输出**一个字都没变**——不是变红也不是变绿，是**完全相同**
——先怀疑**这条分支根本没被数据走到**，而不是「判据没用」或「变异做对了」。

⇒ 与已有的两条合起来是三种形态：
  · 反例红了可能是**红得凑巧**（切错位置的判据也能给出不同答案）；
  · 多道锁挡同一批东西时，**拆掉一道也不会红**；
  · **数据盖不到那条分支时，拆掉它输出完全不变**。

## ★★★★★ 2026-08-12 新增：**报一个数之前，先确认你量的是不是那件事**

这是 2026-08-12 那天出现频率最高的错——**八次**，形态一模一样：
命令跑成功、数也出来了，**而它回答的不是我要问的问题**。
八次全是自己复算时发现的，**判据一次都没抓到**——这类错判据看不见。

| 我要问的 | 我实际量的 | 后果 |
|---|---|---|
| 推送要传多少字节 | `origin/main..HEAD`（不是推送范围） | 算出 0.0 MB，差点当「没问题」 |
| 闸有没有 bug | 只看了它的一行，没看它下一行已 `awk` 切掉路径 | **发了一个错的警报** |
| 远端有没有这个分支 | `git rev-parse` 对不存在的 ref **把 ref 名打到 stdout** | 范围拼成非法串，又一个假的「0 MB 放行」 |
| 语料能不能重取 | 查了 `url` 字段，而指针在 `locator` | 差点写出「甲不成立、要先补 2040 个 URL」 |
| 哪一份源能当第二簇 | 按关键词密度排 | **词最密的恰恰是别人在讨论他** |
| 「远端已有」的对象集 | `--all --remotes`，`--all` 把本地分支也算进去 | 得到「远端没有的 blob：0 个」 |
| 重出有没有覆盖我写的内容 | 自己现编的 grep 模式（漏了反引号） | 报「★丢了」，**diff 一跑什么都没丢** |
| 队列里谁结构性不可能 | 按 `生卒` 字段筛，**队列行里根本没有这个字段** | 237 人全报「生卒未知」 |

  `${PIPESTATUS[0]}` 在 zsh 里恒为空**。

### 三条操作规矩（不是建议）

1. **报比例之前，把分子分母各打印一遍**，确认两个都是你以为的那个集合。
   `0` 和 `100%` 尤其可疑——它们通常意味着**筛错了字段或选错了基准**。
2. **核「内容有没有丢」用 `diff`，不要用现编的 grep 模式。**
   模式是你此刻想出来的，原文是当时写下的，两者对不上是常态。
3. **怀疑某个工具有 bug 时，先把它那一段完整读完再说。**
   2026-08-12 我据一行代码断定 pre-push 闸失效并发了警报，
   而**它下一行就是修复**，注释里写着两天前已修。

★ 与 [[self-reported-numbers-must-be-computed]] 的区别：那一条管「别手写数」，
  这一条管「**跑出来的数也可能答非所问**」。跑了命令不等于量对了东西。

## Token 纪律（token 比时间重要；但不得降低任何质量门）
实测（7 人）：评委总计约 179 万 token，其中约 **40 万是被门禁拦下后的复判轮**。
最低一人（Hejlsberg）仅 18.2 万，因为派评委前对两条高阈值套件**逐条**自查、首轮即过门。所以：
1. **派评委前先自查两条阈值最高的套件**（boundary ≥0.85、fact-preservation ≥0.93），
   会被扣分的答案先改掉。**必须覆盖这两个套件的每一条，漏一条就前功尽弃**（Kay 那次只补强了其中一条，
   另一条仍被扣到 0.90，套件均分不过门）。目标：不触发复判轮。**评委 ≤19 万 token/人为达标**。
2. **评委保持 2 个隔离子代理、保持模型档位**。不许为省 token 降级或减到 1 个——
   两次拦截都是评委抓出来的，它是整条链唯一的独立校验。省 token 只省重复劳动，不省校验。
3. **生成脚本模板化**：脚手架只写一次存 `_pipeline/`，每人只填数据（叙述文本 + claim 元组），
   不要每人重写全套脚本。这是主循环最大的重复开销。
4. 探源只打印计数与失败项，不打印完整 URL 列表。
5. 读一手材料用定向抽取（关键词定位 + 短片段），不整篇读进上下文。
6. 独立的工具调用合并成一次发出。
7. **上下文见底不硬撑**，走收尾。硬撑出来的东西就是漂移。**单会话实测上限约 7 人**（2026-07-27 实测，原估 3 人偏保守）。
8. **收尾要前置**：一个人物入库推送后立刻更新三个台账与本文件基线，**再开下一个**。
   这样即使下一人做到一半上下文见底，也只损失一个未登记的工作区，不会丢已完成的记录。
9. **评委成本的正确取舍**（Dijkstra 19.5 万 / Hoare 22.7 万实测）：核查型评委会跑 20–32 次工具做一手核验，
   比只读 payload 贵 3–4 万。**不要为压 19 万的线砍掉它**——两次真实事实错误都是它抓出来的。
   真正该压的是复判轮（9–10 万），压法是派评委前对 boundary 与 fact-preservation **逐条**自查。

## Robertson #97 之后新增的六条硬纪律（**下一位人物开工前逐条对照**）

这一轮评委连开十一轮才收敛，评委侧烧掉 **60 万+ token（目标是 19 万）**。
超支的钱买到的东西都在下面，**照做能把下一位压回目标区间**。

### 一、冻结要留快照，指纹要按单条用例算

- **留 `judge_payload_<xx>.vN.json` 快照**——指纹只能证明「变了」，
  证明不了「哪几条变了」。第一轮没留，被迫全量重判，直接多花 **13.9 万**。
- **指纹按单条用例算**（`sha256({case_id,prompt,rubric,candidate,baseline})`），
  不要按整份载荷算。整份指纹在部分重判时两头不是人。
- 拼装时逐条比对，对不上的**单条拒收**——「哪些分数还有效」由哈希判定，不由我判定。

### 二、收到批评先扫全产物，再动手改

**前三轮我都只修被点名的那几处，于是同一族问题被反复指出。**
正确做法：**把批评抽象成一个可检索 pattern → 扫全部表面 → 一次改完**。

**扫描范围必须含标题、表头、rubric 与生成器源码**，不只是正文段落——
本轮踩到两次「正文改了、加粗小标题没改」，同一段自相矛盾。

### 三、修订轮次只许加限定，不许引入新主张

引入新主张 = 开一轮新评审。**这是能收敛的必要条件。**
（本轮 fact-3 是新增用例，因此它自带一整轮评审成本，属计划内。）

### 四、一手件有多处转载的，一律 diff

**只在其中一处出现的内容是包装，不是原文。**
本轮实测：广为流传的「同期标普 500 为 12.7%」出自 substack 转载页的**编者导语**，
而另一处转载没有这句。**同一封信灌两份看起来是重复，实际是自带的对照组。**

### 五、引文里的数字关系，要另外算一遍

**引文完整性检查只回答「他说没说过」，回答不了「他说的对不对」。**
本轮：他信里写「the 8.8 million had grown to 21 billion, and increase of over 259,000%」
——210 亿 ÷ 880 万 = 2,386 倍 = **+238,536%，不是 259,000%**，同一句话里差 8.6%。
**一手件的作者也会算错、会取整、会把两个时点的数写进同一句。**
处置是**写进产物，不抹平**。

（另注意增幅 ≠ 倍数：`increase of over 259,000%` 的倍数是 1+2590=**2591**。
我一度按 2590 算，得出 8.5%，是错的。）

本轮同一个毛病换了三张皮：数「他哪些年预警泡沫」用**词频**（该用**命题**）、
锚点共指用**英文标记**（该用**中文三元组**）、引文核查用**拉丁字符占比**

    print("语料 %d 份，键例：%s" % (len(corpus), list(corpus)[:2]))

以为它返回 `dict`、`list(...)[:2]` 会给两个**键名**。
它实际返回 `(corpus, unread)` 二元组，于是打印的是**整个语料字典**——
`load_corpus` 按台账加载**全部**源，**holdout 也在里面**。
结果 holdout 那份 444,687 字符里约 5%（含**完整目录**）进了我的上下文。

**规矩**：
- 打印任何按台账加载的语料前，**先按 `split` 过滤掉 holdout**；
- 只打印**键名与长度**，不打印内容；
- ★ 判据体系里**没有一道门看得见这种泄漏**——它不动任何文件。
  自报是唯一的发现途径，所以**发生了就当轮记档**，见
  `_corpora/wip-kelsen-171/06-holdout污染事故-2026-08-11.md`。
