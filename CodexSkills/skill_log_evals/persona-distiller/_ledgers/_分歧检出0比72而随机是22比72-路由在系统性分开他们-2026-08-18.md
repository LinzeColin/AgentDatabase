## 1. 先把扫描面补上（上次卡住的就是这一层）

`build_team_dossier.extract_divergences` 要的是**成员对象上的 `divergence_text`**，
而那个字段来自**每个人交付包里的 `divergence-map.md`**：

```
find_delivery(root, slug, card) → *.zip
read_persona_payload(zip)       → payload["divergence_text"]   ← _read_text(zf, ("divergence-map.md",))
```

我上一轮的抽取器按**工作区目录名**去对 `subject_slug`，**少了开包这一层**，也没做段落切分。

补上之后：**102/102 人的 `divergence-map.md` 非空**，长度中位 **943 字**（564–12791），
取不到包的 **0 人**。⇒ 扫描面是真的。

## 3. 新的那个数：**0 / 72**，而随机是 **22 / 72**

72 道 oracle 全量跑真实路由（`build_route(..., "auto", ...)`），队伍中位 **11 人**（10–28）：

| | 含 ≥1 个可检出分歧对的任务 |
|---|---|
| **真实路由** | **0 / 72 = 0.0%** |
| 同样大小的随机队伍（200 次重抽） | 中位 **22 / 72 = 30.6%**（范围 11–31） |
| 200 次随机里 ≤0 的次数 | **0** ⇒ 经验 p < 0.005 |

**⇒ 不是碰巧没凑到，是系统性地把它们分开。**

**机制**：`marginal_select` 里同族第 2 人要战胜一个新族候选，`base_score` 需领先
**(0.08+0.025)/0.76 = 0.1382**；而**唯一检得出分歧的 24 个配对恰好全部同族**。
⇒ **多样性配重与分歧检出结构性冲突** —— 一个的目标正是另一个的前提。

## 5. 落了什么

`scripts/check_divergence_pairs_survive_extraction.py`（**0.3 秒**）守的**不是** 0/72
（那要改多样性配重，属「门、席位一概不动」），而是：

> **可检出配对数不许掉到 24 以下。**

因为检出链条有三处会**静默**断掉，三种都让 `divergences` 恒为 `[]`，
而下游读起来像「专家一致」：

1. `divergence-map.md` 的段落被切碎到 <40 字 ⇒ 扫描面归零；
2. `canonical_name` 写法改了（加中间名等）⇒ 精确匹配失配；
3. 重打的包里没有 `divergence-map.md` ⇒ 字段为空。

自测 7+1 项，含 **★★退化对照**（清空全部 `divergence_text` ⇒ 必须 0 对）与
**★★★切碎反例**（把段落切到 <40 字 ⇒ 必须掉）。
★ 自测 ⑥ 第一版写成 `len(pairs) == len(cross) + (len(pairs)-len(cross))`
—— **恒等式不是断言**，已换成「每个配对里的人都取得到族标签」＋「族标签不止一种」。

调用方 `tests/test_divergence_pairs_survive_extraction.py`（6 项），含
「地板抬到 999 必须判红」与「`extract_divergences` 仍然会 `pop` 掉输入」
（判据因此传副本；这行为若变了，注释要跟着改）。

## 6. 射程

- **0/72 与 22/72 都是在这 72 条 oracle 上测的**，而那 72 条只有 **12 个独立题面**。
  换真实用户提问会不会变 —— **没量过**。
- 随机基线用的是**均匀抽样**，不含任何对口度约束；它回答的是
  「同样人数、不挑人，会不会撞上」，**不是**「一个好路由应该撞上多少」。
- 「可检出」= 权威抽取器的口径（全名/slug 精确出现于 ≥40 字段落）。
  **两个人实际有没有分歧，这个口径答不了** —— 它只答「文本里点没点名」。
