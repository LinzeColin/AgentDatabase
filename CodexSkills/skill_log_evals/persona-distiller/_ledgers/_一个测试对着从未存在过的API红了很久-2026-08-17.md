# 一个测试对着**从未存在过的 API** 红了很久

**2026-08-17**｜跑蒸馏侧全量测试（14 件）时发现 `test_group_contract.py` 红着：
`failures=1, errors=2`。

## 第一件事：**先证明不是我今天改出来的**

回到今天第一次改动之前的提交，抽出整棵 `CodexSkills` 重跑同一个测试 ——
**同样是 `failures=1, errors=2`**。⇒ **今天 32 个提交没有打坏它，它本来就红着。**

## 它红在什么上：**四个键，产品从来没有过**

| 测试断言的键 | 产品实际 |
|---|---|
| `plan['inferred_identity']` | **git 全历史 0 处** —— 从未实现 |
| `plan['actual_size']` | 现名 `persona_expert_count` |
| `plan['requested_size']` | 现名 `total_runtime_units` |
| `plan['control_roles']` | 现名 `control_plane` |
| 角色 `counterevidence-analyst` | 现名 `counterevidence-adversary` |

★ 一个 `KeyError` 会让整条用例**崩在第一行断言上**，
后面真正想测的东西（隔离控制面、人数上界、去重席位）**一条都没跑到**。
**测试红着≠测试在测。**

## 我改了什么、没改什么

**改：只改机械换名**，每处都用产品真有的字段表达**同一个意图**：

    inferred_identity → assertIn(族名, {m['registration_category'] for m in members})
    requested_size - control_roles → total_runtime_units - control_plane
    counterevidence-analyst → counterevidence-adversary

**不改：一个期望值都不动。** 特别是 `actual_size == 8` 那行 ——
把 8 改成产品现在给的数，就是**把测试改成产品现在的样子**，
那属于「模式判定该不该改」（待裁定第 ① 件），**不由我在测试里悄悄定**。

## 结果：`errors 2 → 0`，剩下 **2 条真失败**

崩溃没了，剩下的是**真正的契约分歧**，而且指名道姓、可复现：

    test_new_software_deliveries_are_available_to_routing
      期望入选：Barbara Liskov／Chip Huyen／Kent Beck／Martin Fowler／**Simon Willison**
      实得 23 人：前四位**都在**，**唯独没有 Simon Willison**

    test_new_operator_deliveries_are_available_to_routing
      期望入选：Anne Mulcahy／路易斯·郭士纳 —— **未入选**

★ **这五个人全部在册**（逐个核过 `team-index.json`）——
所以不是「人物不存在」，是**路由没选中他们**。
⇒ 这两条是**路由质量的实测证据**，与「路由 65% 驱动来自人工词表」同源。
已并入待裁定清单。

## 顺带一条：**这套测试没有被当成门在跑**

一个断言着从未存在过的键的用例，能红这么久，说明
`tests/` 目录**不在任何自动化关卡里**。
[[a-checker-nothing-calls-is-not-a-checker]] 的又一种形状：
**判据存在、会跑、会红，而没有人看。**
