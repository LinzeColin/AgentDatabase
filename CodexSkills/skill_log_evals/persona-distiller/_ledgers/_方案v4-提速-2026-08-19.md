# 方案 v4 · 提速版（2026-08-19 · 用户裁定：现在太慢，60 天不可接受）

> 用户量化：1 人 1-2h、3-5 人 3-10h、日产能 8-12 人、剩 480 人需 60+ 天（不含迭代与 bug 时间）→ 必须提速。

## 一、速度诊断（Machiavelli#177 全程实测 = 新流程基线）

Machiavelli 从冻结载荷到打包约 **40 分钟有效工时**（rubric 迁移 5m + 双侧答题 5m + 判分 5m + 门与打包 10m + 处置修复 15m）。
首次跑通含大量排障；后续人物可直接复用流程模板。瓶颈排序：
1. quality_check release 每次 5-9 分钟（每人物 2-3 次重跑 = 15-25 分钟浪费）→ **可预见问题前置修复，一次过门**；
2. dedup/缺失源等语料卫生（本次 15 分钟）→ **抓源阶段就做 dedup 声明**，不进发布门才修；
3. 双侧答题+判分（flash 并行 10 分钟）→ 已是批量结构。

## 三、并行边界（v4 教训安全线内）

- **人物内并行（安全，已实测）**：rubric 迁移 32 agent、双侧答题 8 agent、判分 8 席——全 workflow flash 并行；
- **人物间批量（新增）**：同一阶段的多人任务合并进一个 workflow（如 5 人的 rubric 迁移 = 160 agent 一批），主循环只调度 1 次；
- **永不并行**：工作区写入、判分裁决、发布登记（确定性串行，防工作区冲突——这是 v4 教训）
- **QC 前置**：dedup 判定在抓源阶段完成（抓一批源跑一次 check_source_dedup，当场声明），发布门一次过。

## 四、90% flash 结构强化（峰时空转根因修复）

| 问题 | 根因 | 修复 |
|---|---|---|
| 峰时轮次烧 token | 每轮跑 bash+汇报 | **峰时轮次零工具调用**：直接输出状态行（无 bash、无读文件），0 模型成本 |
| pro 主循环读大文件 | QC 报告 76KB×3 进上下文 | bash 输出一律 head -c 300/grep 截断；QC 只 grep code 行 |
| 轮次空转 | 等待谷时 | 轮次即时钟：峰时零耗轮次 = 等效自动 block（不依赖 pause/resume 机制） |

★ 峰谷自主机制（诚实边界）：DSH 的 goal pause/resume 需要用户直接请求、block 后无法自动恢复——
**「峰时零耗轮次 + 谷时全力」是等效实现**（无需人工、可无人值守）；若要用真 pause/block，需用户配合。
