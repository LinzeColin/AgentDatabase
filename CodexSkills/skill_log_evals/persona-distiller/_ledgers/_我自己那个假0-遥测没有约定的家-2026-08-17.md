# 我自己那个假 0 —— **遥测文件没有约定的家**

**2026-08-17**｜起因：我刚写完 `report_expert_team_state.py`，它印
「遥测文件 0 个｜记录行数 0」。**我随即去证明这个 0 找对了地方 —— 结果它没有。**

## 实测

    record_team_outcome.py   `--telemetry`  **required=True，无默认值**
    route_team_moe.py        `--telemetry`  可选，**无默认值**
    run_team_pipeline.py     `--telemetry`  可选，**无默认值**

⇒ **遥测文件的路径完全由调用方自带，系统里没有任何一处规定它该放哪。**

于是我那句「0 条」扫的是 group 目录 —— 一个**我自己选的**扫描面。
若有人把 outcome 记到了别处，我会报出一个假的 0。
[[zero-hit-gates-must-prove-they-can-hit]]

已改：报告先印**扫描面**，并明写「扫到 0 不等于全局没有」。

## ★★ 而这很可能就是「记录一直是 0」的一个真原因

C 层校准要 **≥60 条 outcome**。而 outcome 要写到哪儿，**没有约定**：

- `record_team_outcome.py` 强制你现场给一个路径；
- 下次跑路由时，`--telemetry` 又要你**再给一次同一个路径**；
- 没有任何默认值、没有任何文档规定它、也没有任何判据检查它。

**校准层的数据没有归宿，就永远攒不起来。** 这不是「没人去记」，
是「记了也不知道该记去哪、下次也读不回来」。

★ 与之一致的旁证：路由每次自报
`telemetry_eligible_for_c: false` / `strategy_fallback_reason: telemetry unavailable`，
而 `strategy` 实测**恒为 B** —— C 从来没有被激活过。

## 这条归 Owner（我不动）

给遥测定一个**约定路径**（例如 `persona-distiller-group/evidence/outcome-telemetry.json`）
并让三个脚本都默认指向它 —— 这是产品逻辑，受 TaskPack「不重新设计 API」约束，
**我不改**。

但代价已量清：**在它有家之前，那 60 条永远攒不到，C 层永远不会启动，
「自优化迭代」这一项永远是 0。**
