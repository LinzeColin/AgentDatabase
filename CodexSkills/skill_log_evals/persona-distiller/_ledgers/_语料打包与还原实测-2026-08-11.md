### ★★★ 分卷还原这条路**单独走过一遍**

第一次我用 `tar -xzf wip-koch-107.tar.gz` ——**那个文件不存在**，Koch 是分卷的。
正确姿势是：

```bash
cat wip-koch-107.tar.gz.part-a? | tar -xz -C <目标目录>
```

先核三卷各自的 sha256（**3/3 对上**），再 `cat | tar`，再逐份核内容。

★ **这条路必须单独测**：它是收件人最可能踩空的一条，
而「没测过的兜底分支只在别人机器上发作」这一条已经栽过。

## ★★★★ 再补一层：**逐文件核过了，而且是拿现树当参照**

上面写「没有逐文件核 sha256」，去做的时候先发现**那句话本身有问题**：
清单里**没有逐文件哈希**（只有每个 tar 的 sha256），所以「核 sha256」缺参照。
真正能做且有意义的是——**拿打包之后我没动过的那些人，逐字节比还原件与现树**：

    先用 git log 找出打包（13:50）之后动过的：wip-blackstone-169 / wip-grotius-168 / wip-holmes-170
    排除这三个，比对 **52 个未改动的 wip、9904 个路径**

    **逐字节相同 9900｜内容不同 0｜只在还原件 2｜只在现树 2**

### ★★ 那 4 条不是差异，是 **Unicode 归一化形式不同**

    还原件：`h` + U+0308（组合分音符）  ← NFD
    现　树：U+00F6（ö 单码点）          ← NFC
    NFC 归一化之后**相等**；两文件的内容 sha256 也**相同**

→ **真实差异 0 处。** 是 Liebig 那份德语文件名里的 `ö`。

### ★★★ 但这条要写进移交，它会在收件人那里复发

**任何按路径字符串比对的程序**（包括我刚才那个）都会把它报成「文件缺失／多出」。
本轮我差一点据此写出「9902 处不一致」——**那是量具的错，不是语料的错**。

**给收件人的规则**：比对路径前**先 `unicodedata.normalize("NFC", path)`**。
涉及非 ASCII 文件名的场合（本库有德语、中文名），这一步不做就会得到一份完整而错误的差异表。
