# #124 复量：铁律 2 的守卫为什么断 —— **修 A 的时候把 B 关掉了**（2026-08-18）

## 先认一件事

**本会话在主工作树的 `main` 上直接提交了 34 次。**
铁律 2 写着「主树只读，开发一律在 worktree」。**我违反了它 34 次，一次都没被拦。**
下面是为什么没被拦，以及为什么这不是「守卫写错了」。

## 根因（定位到配置项）

    git config --get core.hooksPath      →  .githooks
    ls .githooks/                        →  pre-push、pre-push.worktree   （**没有 pre-commit**）
    ls -l .git/hooks/pre-commit          →  存在、可执行 —— **但 git 不看这个目录**

`.git/hooks/pre-commit` 的抬头写着它是谁：

> `linze-maintree-guard —— 铁律2 的机器强制版。由 tools/install-guards.sh 安装。`
> 在 worktree 里 `exit 0`（开发本来就该在这儿）；
> 在**主树的 main/master** 上 `exit 1`，逃生口 `LINZE_ALLOW_MAINTREE_COMMIT=1`。

**它要是生效的，我今天这 34 个提交每一个都会被拒。**

### 为什么 hooksPath 被改到 `.githooks`

`.githooks/pre-push.worktree` 的文件头记着 2026-08-11 的实证：

> 「`core.hooksPath = .githooks`（local 作用域，所有 worktree 共享这条配置），
>  而 `.githooks/` **在版本库里 0 个文件被跟踪** —— 它只是主树的一个本地未跟踪目录。
>  于是 git 在每个 worktree 里解析出的 `.githooks/pre-push` **不存在**，
>  **整个 pre-push 环节静默不跑**。本地裸仓实测：推 2 GB 真分支 → 退出码 0、
>  守卫 0 次出声、**920 MB 真的落进裸仓**。」

⇒ 那次是为了**让 pre-push 在 worktree 里也生效**（现在 `.githooks/` 两份都已被跟踪，那个洞补上了）。
**但 `install-guards.sh` 装在 `.git/hooks/` 的 pre-commit 没有跟着搬过去，就此成了孤儿。**

> **修 A 的时候把 B 关掉了。** 一个 `core.hooksPath` 同时决定两道守卫的死活，
> 而只有一道被搬过去。[[one-flag-controlled-config-and-discipline]]｜[[fixed-the-symptom-kept-the-root-cause]]

## 可复算

```bash
cd ~/Documents/Codex/GithubProject/AgentDatabase
git config --get core.hooksPath            # → .githooks
ls .githooks/                              # → pre-push  pre-push.worktree（没有 pre-commit）
ls -l .git/hooks/pre-commit                # 存在、可执行，但被 hooksPath 绕过
# 横向对照
for r in ~/Documents/Codex/GithubProject/*/; do
  hp=$(git -C "$r" config --get core.hooksPath 2>/dev/null)
  [ -f "$r/${hp:-.git/hooks}/pre-commit" ] && s=有 || s=无
  printf "%-22s hooksPath=%-12s pre-commit=%s\n" "$(basename $r)" "${hp:-默认}" "$s"
done
```
