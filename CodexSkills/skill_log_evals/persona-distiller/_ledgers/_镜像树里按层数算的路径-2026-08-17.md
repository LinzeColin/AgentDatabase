# 判据有两份副本，而路径按层数写 —— 查了 12 件，只有 1 件该修（2026-08-17）

## 怎么撞见的

修 `doc.threshold-drift` 那处时发现：`check_threshold_doc_drift.py` 的默认文档路径
写作 `HERE.parent / "references/pipeline/RUNBOOK.md"`。
本判据**有两份副本**（`scripts/` 与 `references/pipeline/checkers/`，
合同漂移门要求**逐字节相同**），于是同一行代码在镜像那份里解析成

    references/pipeline/references/pipeline/RUNBOOK.md   ← 不存在

⇒ **从镜像树跑这道门永远 rc=3、永远跑不起来**。已改用 `_skill_root()`
（往上找同时有 `VERSION` 与 `SKILL.md` 的那一层），两棵树现在都 rc=0。

## 那还有几件同病？—— **代理指标不是结论**

`grep` 「按层数上溯」（`HERE.parent` / `parents[N]` / `.parent.parent`）：
两棵树都有的判据 **114** 件，命中 **12** 件。

但 grep 命中不等于有病。决定性的测法是**两棵树各跑一遍比退出码**：

| 判据 | `scripts/` | 镜像 | |
|---|---:|---:|---|
| check_checkers | 3 | 3 | 一致 |
| **check_contract_drift** | 0 | **1** | 不一致 |
| **check_disposition_exclusive** | 0 | **1** | 不一致 |
| **check_distillation_freshness** | 0 | **3** | 不一致 |
| check_doc_command_shapes | 0 | 0 | 一致 |
| check_holdout_mention | 3 | 3 | 一致 |
| check_namesake_separability | 2 | 2 | 一致 |
| check_paper_lanes | 0 | 0 | 一致 |
| check_threshold_doc_drift | 0 | 0 | 一致（**已修**） |

| **delivery_builder** | 0 | **1** | 不一致 |

⇒ 12 件里 **4 件**两棵树给出不同答案。
★ 跑完 24 次，`git status` 逐字对比 —— **工作树无任何改动**（写盘 0）。

## 这 4 件为什么**不改**

判「该不该修」的标准不是「路径写法丑不丑」，是**它失败时说的是实话还是假话**。
逐个打开看它们的输出：

    check_contract_drift        ✗ 缺 VERSION 文件（真源不存在）：…/references/pipeline/VERSION
    check_disposition_exclusive 名册读不到：…
                                ★ **有文件读不到时，本件的结论不完整** —— 不许读成「没有重复」
    check_distillation_freshness 用法错误：读不到 …/references/pipeline/VERSION
    delivery_builder            ModuleNotFoundError: No module named 'registry_core'（traceback）

**四个全部诚实失败**：都明说读不到什么、都非零退出，
`check_disposition_exclusive` 甚至自己印出「不许读成『没有重复』」。
**没有一个静默放行、也没有一个说了假话。**

而 `doc.threshold-drift` 那处不一样 —— 它把「文件找不到」说成
「文档门槛表与 `PROFILE_THRESHOLDS` 不一致，**改文档去迁就代码**」，
照那句去改，改的是一个没被读过的文件。**那是假话，所以修。**

★ 另一条：镜像的用途是**打包时逐字节相同**（`check_contract_drift.py:598` 的
B2 节要求两份一致，历史上抓到过「只在 scripts/ 里 ⇒ 装出去的包会少这一件」）。
`SKILL.md` 里 5 处示例命令**一律写 `python3 scripts/…`**，
**没有一处叫人从镜像树跑**。⇒ 这 4 件是**潜伏的，不是活的**。

## 留给以后的判别式

再遇到「两份副本 + 按层数算路径」，按这个顺序问，别按顺序改：

1. **两棵树各跑一遍，退出码一样吗**（grep 只是代理物）
2. 不一样的那些，**失败时说的是实话吗**（明说读不到什么 / 非零退出）
3. 说假话的才修；说实话的记档
4. 修就用 `_skill_root()` 找标志文件，**不许按层数写**
