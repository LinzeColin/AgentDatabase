# 排除名单是照**当时那一个文件名**写的，产物后来长出了八个兄弟

**2026-08-17**｜`check_first_person_density`（声口密度 —— 判「声口够不够」的依据）。

## 缺陷

    files = sorted(p for p in root.rglob("*.txt") if p.name != "_ids.txt")

排除清单只有**一个文件名**。而 Lincoln #174 的 `raw/` 下实际有：

    _ids.txt          _ids-union.txt    _ids-round2.txt   _ids-round3.txt
    _ids-delta.txt    _ids-delta3.txt   _ids-deltaF.txt   _ids-rebuild.txt
    _ids-final.txt

**八个兄弟全被当成语料读了进来。**

## 后果不是报错，是**归错成因**

那些文件的内容是一行行的 `src-xxxxxxxx`，不像英文散文。
于是本件报：

> **本判据不适用**：**这份语料多半不是英文。**

**而 Lincoln 的语料全是英文。** 真相是**正文根本不在盘上**
（`references/sources/` 已被全库移出 git）。

⇒ **对的结论（不适用）＋ 错的成因（语种）**。
这和今天早些时候 `check_source_dedup` 报「多为中日韩或纯噪声」是**同一个形状**：
判据探到空，就从自己认识的原因里挑一个最像的安上去。

## 修完之后我**自己造了一个新的假零**

把簿记文件整族排除（`not p.name.startswith("_")`）之后，
「多半不是英文」那条不再触发，于是掉进了 **0 份语料**这条**没有守卫**的路：

    可读占比 = en_c / lang_total if lang_total else **1.0**   → 0÷0 印成 **100%**
    实质第一人称句                                        → **0**

**改之前它至少是 `null`；改之后成了 0。** 而这一栏是用来判「声口够不够」的 ——
**报 0 等于说「他不说第一人称」，真相是一个字都没读到。**

⇒ 已补 0 份语料的守卫：报「不适用」＋ `null`，并把成因写成
「**语料正文不在工作区里，一个字都没读到**」。

★ **修一个成因，别造一个新零。** 这一条要单独记住：
我今天两次在「让判据说实话」的过程中，把它推进了另一个不说实话的分支。

## 落成守卫

自测 +5 条（簿记整族排除／报不适用／**null 不是 0**／成因写「没读到」／
**不许出现「可读占比 100%」**）。反对照实跑：撤掉守卫 **4 条变红**、rc=2。

★ 反对照那次我第一版**插入失败**（锚点没匹配），
于是「撤掉后 rc=0、红 0 条」——**我差点把插入失败当成反对照通过**。
第二次改用行号定位并**直接看 rc、不走管道**。

## 可执行的一条

**排除清单要按「族」写，不按「那一个名字」写。**
凡是 `!= "某个文件名"` 这种写法，都要问：
**这个名字会不会长出兄弟？** 流水线产物几乎一定会。
