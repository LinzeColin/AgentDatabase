# 镜像树：**逐字节相同，但一侧自测过、一侧不过**（2026-08-11）

## 起因

`check_contract_drift` 的已知盲区是「**只比字节，不管跑不跑得起来**」。
今天把镜像树 `references/pipeline/checkers/` 里全部 **86 件** `check_*.py` 各跑一遍 `--self-test`：

| | 件数 |
|---|---:|
| 自测通过 | **85** |
| **未过** | **1**（`check_holdout_mention.py`） |
| 无 `--self-test` | 0 |

★ 而 `cmp` 两侧**逐字节相同**，`check_contract_drift` 是绿的。**这不是漂移。**

## 根因（硬的，不是猜的）

`check_holdout_mention.py:221` 与 `:374`：

```python
tmpl_root = pathlib.Path(__file__).resolve().parent.parent / "templates" / "target"
```

| 跑的位置 | 解析出的路径 | 结果 |
|---|---|---|
| `scripts/` | `<包根>/templates/target` | **存在（32 项）**，自测过 |
| `references/pipeline/checkers/` | `references/templates/target` | **不存在**，模板读到 **0 行**，自测失败 |

实测：`templates/target` **只在包根下**，`references/templates/target` 与
`references/pipeline/templates/target` **都不存在**。

## ★★★★ 为什么这条要紧

`HANDOFF.md` 说镜像树是「**装出去的那份**」。
→ **接手方装完之后，这道门在他机器上自测不过**，
而它的失败方式是「**自测未过 → 其结论一律不作数**」——
也就是说 holdout 提及这道门**在装出去的那一侧是哑的**。

## 射程：同样写法的还有 2 件，但它们不受影响

`__file__).resolve().parent.parent` 这种写法共 **3 件**：
`check_contract_drift.py`、`check_distillation_freshness.py`、`check_holdout_mention.py`。
**只有第三件真去读那个目录**，另两件在镜像侧自测是过的（在那 85 件里）。

## ★ 没有改判据，理由

`__file__` 的定位方式是**安装布局**的问题——改它等于决定
「镜像树装出去之后该长什么样」（要不要把 `templates/` 也镜像过去、
还是让判据向上找包根）。**那是设计决定，不是 bug 修复。**

两个候选做法，**都没量过**：
1. 把 `templates/target` 也镜像进 `references/pipeline/`；
2. 判据改成向上搜到含 `templates/` 的那一级（而不是写死两级）。

★ 按今天定的规矩：**先量再决定**。这一条只留测量结果与根因。
