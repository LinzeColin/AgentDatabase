## 为什么不能直接推公开仓（实测，不是推测）

    gh repo view LinzeColin/AgentDatabase --json isPrivate
    → {"isPrivate": false}          ← **公开仓**

而 `origin/main` 上那份 HANDOFF 自己写着移交规则：
**「任何 private-only 资产一个字节都不许进 AgentDatabase」**。

把本地分支推上 `main` 会**新公开 11,631 个文件**：

| 类别 | 份数 | 说明 |
|---|---:|---|
| persona-distiller 其他 | 7,278 | 产物、模板、判据 |
| **语料正文** | 4,067 | 公开仓现有 246 份，会变成 4,313 |
| **★ 教训库** | 141 | 本机 `~/.claude/.../memory/` 的副本；**公开仓现在是 0 份**；其中 **19 份**出现 OVH／R2／Private-Database／token／账单金额 |
| 台账/流水线 | 141 | |

⇒ 走 bundle：**内容打包进私有仓 Release，公开仓只更新指针**。

## 第 1 步 · 上传 bundle 到私有仓（用户按）

包已在本地造好并验过：

    文件   agentdb-persona-distiller-full-20260813.bundle

    sha256 f028ceeedd46bde4acaf0e2978948600a65d52e0ff063276196b7155452703c5
    校验   git bundle verify → "The bundle records a complete history."
    tip    fe47c158…（= 本地 HEAD，今天的提交全在里面）

> ★ 上面的 sha256／大小／tip 是**打包当时**的值。若之后又有提交，

```bash

  --repo LinzeColin/Private-Database \

  <bundle 路径> --repo LinzeColin/Private-Database
```

## 恢复（接手方执行，公开仓 HANDOFF 里已有）

```bash
gh release download agentdb-handover-20260813 \
  --repo LinzeColin/Private-Database \
  --pattern 'agentdb-persona-distiller-full-20260813.bundle' --dir /tmp

git clone /tmp/agentdb-persona-distiller-full-20260813.bundle agentdb-restored
cd agentdb-restored
git checkout claude/character-distillation-skill-reorganize-d57595
```

★ `git bundle verify` **必须在一个 git 仓里跑**，空目录会报
`need a repository to verify a bundle`（演练时踩到过）。
