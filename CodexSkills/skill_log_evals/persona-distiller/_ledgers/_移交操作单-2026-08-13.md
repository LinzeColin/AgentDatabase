而 `origin/main` 上那份 HANDOFF 自己写着移交规则：

| 台账/流水线 | 141 | |

⇒ 走 bundle：**内容打包进私有仓 Release，公开仓只更新指针**。


**为什么可以只按这一条**（实测出来的，不是设计出来的）：
公开仓 `origin/main` 那份 HANDOFF 的下载命令写死的是
`--pattern 'agentdb-persona-distiller-full.bundle'`，
**而它没有写死 sha256**（只写「约 972 MB」）。
⇒ **原名替换资产即可，公开仓一个字都不用改，第 2 步整步取消。**

- 新包是旧包的**超集**（同一分支、`--all`、提交数从 1390 涨到现在），替换不丢东西。
- Release 标签仍叫 `…20260812`（名字旧一天，内容是新的）；要不要改名由你定，改了就得同步公开仓。

> ★★ **校验值不写在本文件里**，因为会循环：写进文档 → 文档要提交 → HEAD 变了 → 包又落后一个提交。
> **sidecar 与包同时生成。**
>
> ★★★ 而 sidecar 我第一版仍然写错了：它把 tip 记成**当时的 HEAD**，
> 而包是更早打的——中间又提交了两次，于是 sidecar 说 `d2d1008c`、包里其实是 `2122dc78`。
> **tip 必须从包里读。** 已做成可重跑脚本 `_ledgers/_pipeline/make_handover_bundle.sh`：
> 打包 → verify → **从包里读 tip 出 sidecar** → **真 clone 回读自验证**，四步一次跑完。
>
> ★★★★ **上一版包打在会话临时目录里，再找就没了**。三处都在被回收
> （构建树 / `_scratch/` / `~/Downloads`），**只有 `_protected/` 活得下来**。交付物一律放那儿。

★★ **Release 名与资产名必须与公开仓 HANDOFF 里那条下载命令逐字一致**
（`agentdb-handover-20260812` ／ `agentdb-persona-distiller-full.bundle`）。

`need a repository to verify a bundle`（演练时踩到过）。

## 重打包（若之后又有提交）

**跑第 0 步那条命令就行**，不要手敲 `git bundle create`。

★ 手敲的版本里有一条是错的：`git bundle list-heads … | grep …` 之后拿它去比

tip 该从包里读出来**写进 sidecar**，不是拿去跟工作树比。
