## 一、契约早就在那里

`references/team-output-contract.md` 从 **v0.0.0.7** 起就规定了第 2 条格式：

```
【<人物名>】<贡献内容> <!-- claim:clm-xxxxxxxxxxxx -->
```

并写死「**引用不出 `claim_id` 的贡献视为未发生**」。

**契约在，检查器不在。** 六个版本里没有任何一处代码读过团队产出、数过署名。
于是它跟 RUNBOOK 那 58 条一样，**停在散文态**——写下来了，没有牙齿。

2026-08-02 三臂盲判，席 B：

```

  - t1　宣称 3 票／人，实际点名 0 人（**一个都没有**）
  - t2　宣称 3 票／人，实际点名 0 人（**一个都没有**）
```

**席 B 报 1 处，实有 3 处。**
与 distiller v0.0.0.22 拒答溢出门那次完全同形：**评委看到症状，判据才数得清范围。**
这已经是第二次验证同一条经验——**评委的每一条批评都值得写成判据再扫一遍全量。**

## 三、判据与它为什么这样设

宣称任何票数／人数的合议时，正文必须至少点到同样多的成员名。

| 取舍 | 为什么 |
|---|---|
| 门槛取「点名」不取「分了几段」 | **分段可以任意切，只有名字能对上名册**——它是唯一可核验的锚 |
| 少说不算错 | 点名 3 人只说「其中两人反对」是诚实的收敛，不该罚 |
| 无数词的「大家一致」不判 | 堵它需要判定「大家」指几个人，**那是语义不是句式**，本门不越界 |

顺带的效果：这道门**强制了 v0.0.0.11 遗留的「团队产出必须逐条署名」**——
不点名就不能宣称票数，而团队几乎总要宣称票数。

## 四、射程（必须一起说）

**它数的是名字有没有出现，不是这个人是否真的持这个观点。**
把三个名字撒进正文就能骗过它。

> **它挡的是「凭空宣称票数」，不是「冒名代言」。**

后者仍由契约第 2 条的 `claim_id` 规则负责——引用的 claim 必须属于该成员本人。
**两者不可互相替代。**

## 五、负对照九项，两项是关键

| # | 项 | 判什么 |
|---|---|---|
| **1** | **用 t1 原文做真实样本** | 判据必须抓出它，且必须数出「点名 0 人」 |
| **2** | **清空中文数词表后 t1 必须不再报错** | **证明抓到它的是数词判据本身，不是巧合** |
| 3–4 | 点名 2 宣称 3；阿拉伯数字「3 票」 | 两类坏样本 |
| 5–7 | 点名足数／无合议宣称／少说 | 三类正对照不许误杀 |
| 8 | 英文正文只称姓 | 能对上名册 |
| 9 | 无数词的「大家一致」 | 射程外，不许误判 |

第 2 项是这个项目反复要求的那种反向对照：
**一个开关如果开与关结果一样，它就是装饰。**
本轮 distiller 的分族配重、团队侧的这道门，两处都做了同型的反向验证。

## 六、为什么这条值一个版本

| 臂 | 相对 |

| 团队 − 裸模型 | **−0.0219** |

## 八、遗留

**这道门只在有人跑它的时候起作用。** 团队答案由模型在运行时产生，
不像蒸馏那样有一条脚本化流水线可以挂钩子。
本版把它写进契约的自检清单，**但「自检清单」本身仍然靠人执行**——
这是散文与判据之间最后一段没有闭合的距离，**如实记在这里，不当已闭合。**
