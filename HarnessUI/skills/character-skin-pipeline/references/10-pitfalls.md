# 踩过的坑（按代价排序）

## 1. 数提交次数当产出量 → 工期报小 17 倍

我用「submissions 计数」估进度，报「59 小时」。真实数字是按交付目录里**成品文件数**
算出来的 **170 小时**。

> **3 次提交换 1 张成品**（594 张成品实际消耗约 1800 次调用）。
> 重试、废片、闸门打回全都在分母里。

**任何工期/额度估算都从「成品文件数 ÷ 已耗时」出发，不许用尝试次数。**

## 2. 用户的显式要求被挤掉

「不要 Q 版 / 不要 chibi」是用户**带截图**明确否掉的，
但复审时发现 **594 条 prompt 里 0 条**写了这句。

原因：从早期讨论过渡到批量生成时，我重写了 prompt 模板，
只按「视觉描述」组织，没有回去逐条核对用户说过的**禁止项**。

**修法（现在是 01-requirements.md 里的固定动作）**：
生成前把用户的每条要求列成表，每条给一个**可执行的检查命令**，
`grep` 全量 prompt 确认命中率 = 100%，再花钱。

## 3. `images` 参数连错三次，165 张全废

`/v1/images/edits` 走 JSON 时，参考图的正确形状是：
```json
"images": [{"image_url": "data:image/jpeg;base64,<b64>"}]
```
我先后试过 `image`（那是 multipart 的字段名）、纯字符串数组、
`{"type":"input_image"}` —— 第二种在 Batch 里**165 张同时失败**，
报 `Invalid type for 'images[0]'`。

**新接口的第一次调用永远先跑 1 张实时的**，成功了再灌 Batch。
Batch 的错误要等一整轮才看得到，一次错就是几小时。

## 4. Batch 取回把看门狗打死

237 张的结果是 **1GB+ 的 base64 JSONL**，一次 `.read()` 直接
`OverflowError: signed integer is greater than maximum`（抛在 ssl.py 里）。

```python
while True:
    chunk = response.read(4 * 1024 * 1024)
    if not chunk: break
    handle.write(chunk)
```

## 5. 午夜日志轮转 → 把活着的应用判成死了

网关日志在本地午夜轮转成一个空文件。我的探针只读最新那个，
00:00:57 时一个时间戳都没有，**「找不到时间戳」被当成「已经安静很久」**，
看门狗对一个健康的应用发了续跑指令。

```python
def newest_logs(count: int = 2) -> list[Path]:  # 读两个最新的
```
**「没有数据」和「数据表明异常」是两回事，`None` 不许走进异常分支。**

## 6. 只在进度变化时写日志 → 全量失败时零行日志

165 张同时失败，进度没动，于是一行日志都没有。
用户问「你怎么停止了」——我自己也无从判断。
**每一轮都写日志**，哪怕写「无变化」。

## 7. 判据太严和太松一样有害

中文名回填做了「反向链接校验」（要求中文页的 langlink 指回原页）。
太严，**删掉了 7 个本来正确的名字**。
后来做抖音清单交叉比对时报「14 个缺失」，实际上其中 9 个库里有。

**校验器要先在已知正确的样本上跑一遍，看它误杀多少。**

## 8. 去点用户正在用的应用

我以为前台是 DSH，实际是 Kimi——**328 个字符的诊断代码打进了他的对话框并发送**。

之后停掉所有基于鼠标的诊断，改成让代码自己回报状态
（插件里加一个 `POST /__diag` 端点）。
**别驱动用户正在用的应用，让程序自报。**

## 9. 花几小时查错方向：分辨率 vs 遮挡

皮肤背景不显示，我先后查了分辨率、滤镜、`backdrop-filter`、缓存。
真因是一个不透明的 `DIV.pI_x6G_frame` 盖在上面。

**一步判据**：把根容器以下所有元素的背景清空，图出来了 = 遮挡问题。
这一条现在写在 01 里，任何"背景不显示"先跑它。

## 10. 视觉模型判审美：三轮全废

见 06-acceptance.md。结论：
**模型判数字（亮度/边缘/尺寸），人判审美；机器的活是把人工判定变便宜（裁切+放大+密网格+点选）。**

## 11. 手工签名的 .app 启动即被杀

`codesign --force --deep --sign -` 复制来的 Electron.app，
在 Apple Silicon 上静默退出、无崩溃日志。用 `@electron/packager`。

## 12. SMB 连续写会崩

见 09-archive.md。四次重试 + 退避 + 每 8 个歇 0.4 秒。

## 13. 面板看起来是控制器，其实是只读的

浏览器里的面板只能写 localStorage，15 秒后被共享状态覆盖。
用户选的「1 小时轮播」根本没生效。见 08-runtime.md 的 `POST /__state`。

## 14. CSS 注释里的反引号打断了 JS 模板字符串

client.js 里的 CSS 写在模板字符串里，注释里一个反引号把它截断，
部署了一份坏文件。**改完立刻在宿主里验证一次，别靠肉眼读。**

## 15. sparse-checkout 静默拦下新目录

`git add` 报 "outside of your sparse-checkout definition" 时文件没进暂存区，
但 `git push` 仍然成功（推的是空提交）。
**push 之后要 `git show --stat` 核一眼真的有文件。**
