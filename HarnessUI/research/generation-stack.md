# 生成链路选型调研

2026-08-19。结论先行,再给证据。

## 结论：质量的决定变量是 LoRA，不是素材数量

把全网素材爬回来**不会**让产物变好。真正决定"画出来像不像雷电将军"的,是这条链路里有没有**该角色的 LoRA**。

三条路实测/调研对比:

| 路线 | 角色可辨认度 | 可控性 | 本机可行 | 成本 |
|---|---|---|---|---|
| mmx `image-01` 纯文生图 | **不可辨认**(实测) | 低 | 已验证 | 每图约 1 次调用 |
| mmx + `--subject-ref` 官方立绘 | 中(风格漂移) | 中 | 已验证 | 同上 |
| **ComfyUI + Illustrious 底模 + 角色 LoRA** | **高** | **高**(seed/构图/姿势全可控) | 需先下模型 | 一次性下载,之后本地免费 |

### mmx 纯文生图为什么不行（实测证据）

2026-08-19 用一段 200 词的详细描述(发色、瞳色、服装配色、金饰、和风元素)生成雷电将军,
产出是一个**通用紫发和风少女**——构图约束(左三分之一站位、右侧留白)被严格遵守了,
角色特征却完全不对。这不是 prompt 写得不够细的问题:文生图模型的先验里没有"这个具体角色",
再多形容词也只能逼近一个泛化的类型,逼不出一个特定的人。

`--subject-ref type=character` 能把角色钉住一部分(实测昼→夜两张确实是同一个人),
但它锁的是"参考图里那个人",要先有一张对的参考图,而且跨场景会漂。

### ComfyUI 路线为什么行

角色 LoRA 是在该角色的数百张图上微调出来的权重,它把角色特征编码进了模型本身。
配合底模,出图是"这个角色的新姿势",而不是"像这个角色的另一个人"。

**Illustrious XL 系是 2026 年动漫角色 LoRA 生态最大的一支**,原神/绝区零角色 LoRA 覆盖度最高。
底模建议 **WAI-Illustrious-SDXL**(风格中性,不带强烈作者风格,适合做 UI 背景)。
NoobAI-XL V-Pred 分数更高但需要 v-prediction 专用采样设置,且社区生态偏 NSFW,不适合做工作界面皮肤。

```

checkpoints: 0

```

跑得动(34GB 统一内存对 SDXL 绰绰有余),但**里面是空的**。要走这条路必须先下:

| 项目 | 体积 | 数量 |
|---|---|---|
| 底模 WAI-Illustrious-SDXL | 约 6–7 GB | 1 个 |
| 角色 LoRA | 约 100–250 MB / 个 | 按名单,最多 123 个 |
| VAE(通常内置,视底模而定) | 约 300 MB | 0–1 个 |

**全量 123 个角色的 LoRA 约 15–30 GB。** 建议先下底模 + 短名单(10 个)验证质量,再决定要不要铺全量。
