## 二、任务包复审改了什么（都在花钱之前）

| 版本 | 改动 | 原因 |
|---|---|---|
| v1.5.0 | 补入**禁 Q 版** | 你截图否决过，而原包 594 条 prompt 里一个字都没有 |
| v1.6.0 | 丝袜/露肤从「where the design allows」改为**强制**，并加优先级裁决 | 那个逃生口让原设穿长裤的角色直接跳过；且与同段「matching the reference exactly」直接冲突，模型只能随机取中 |
| v1.7.0 | `negative_prompt` 全文折入 prompt 正文；补 9 个绝区零角色 | **gpt-image-2 没有负面提示词参数**，那个字段一直发不出去；花名册存的是 `/Lore` 子页，子页无立绘 |

**优先级裁决原文**：身份（脸/发色发型/瞳色/标志配饰/配色）严格照锚图；服装造型照规则；**冲突时以规则为准**。

最难案例验证：`aloy`（原设全长裤）→ 出来是黑色吊带丝袜 + 高露肤度，身份完整保留。

## 三、DSH 皮肤插件（已建成，实测通过，**尚未安装**）

### 一个插件，两种模式

| 模式 | 行为 |
|---|---|
| **画廊** | 缩略图网格、按游戏筛选、搜角色、点击即时换、选择记忆 |
| **轮播** | 每 4 小时一换（可调 1/4/8h），**一周期覆盖全库不重复**，走完才重新洗牌 |

**为什么不做成两个插件**：皮肤中心是互斥的 —— `dsh-skin use X` 会把注册表里其余每一行写成 `disabled: true`。两个插件会互相关掉。

### 实测数据（对着真实 DSH 界面在浏览器里跑，全程没重启 DSH）

| 项 | 结果 |
|---|---|
| 挂载 / 作用域 | ✅ `body[data-dsh-harness-ui]` |
| 画廊渲染 | ✅ **304 张卡片**（原神 160 / 崩铁 59 / 绝区零 85），缩略图 lazy，**0 张失败** |
| 轮播不重复 | ✅ 周期 304 条**全唯一**，连抽 6 次零重复 |
| 昼夜跟随 | ✅ 暗主题→`dark.webp`，亮主题→`light.webp` |
| 切换耗时 | 681ms + 420ms 淡入（图片本身冷加载仅 8ms，其余是 2560×1440 解码） |
| 显示图 | **149KB WebP**（母版 6.6MB PNG，**小 45 倍**） |
| 缩略图 | 6.5KB |

### 三个被实测逼出来的架构决定

1. **素材必须走本地 HTTP 服务，不能内嵌。**
   这版 DSH 对每个插件**只服务 `client.js` 一个文件** —— 挂载中的皮肤，`client.js` 返 200，而 `preview/light.webp`、`package.json` 和该目录下任何其他路径**全返 404**。渲染进程还拒绝 `file://`（`<img>` 指过去直接 `error`），但 `http://127.0.0.1` 正常。
   参照皮肤（鲸鱼娘昼夜工坊）把素材全内嵌成 data URI —— 它 2 张图就 1.7MB，这套 611 张会变成几个 GB。

2. **资源服务必须带 CORS 头。**
   页面在 `:3080`，资源在 `:3099`，跨端口 `fetch` 会被拦。现象很迷惑：**图片能正常显示，但目录拉不到**（`<img>` 不受 CORS 限制，`fetch` 受）。`python3 -m http.server` 不发这个头，所以写了专用服务。

3. **不许有任何 `infinite` CSS 动画。**
   一个常驻关键帧动画铺满整窗，曾让 DSH 空闲时占 **111% CPU**，去掉后 **2.5%**。本插件只用一次性 transition。
