# Memory Atlas 变更记录

版本号语义：`主.次.修`
- **主** —— 数据契约或页面结构不兼容变更（旧 atlas.json 读不了新页面，或反之）
- **次** —— 新增数据块 / 新增视图 / 新增主题
- **修** —— 只修缺陷与口径，不新增能力

每条都要写清楚：**改了什么、为什么、怎么验的**。没验过的不写在这里。

## 0.4.3 — 2026-08-20

只修缺陷，不加能力。三条都是 v0.4.2 上线后自己跑出来的 —— 不是读代码推的。

### 星云宇宙：两个司机同时踩油门，回放等于失效

镜头有两个来源：滚动（往下滚＝往回飞）和视图（回放按周推进、点开某一天就停在那天）。
两条线一直都在，谁也没让谁 —— 实测：按下播放跳到 2026-W22，随手滚一下页面，
镜头立刻被拉回最新那天，回放的「飞回去」当场作废。

改成**滚动是默认司机，视图要接管必须说一声**：`holdCamera(true)` 期间滚动那条线断开，
`dispose` 里交还。接管的只有「回放」和「一天」这两屏 ——
日历／交付／复盘的悬停飞行仍然让位给滚动，那是对的：随手一扫不该锁住镜头。
主题切走时无条件把接管标志复位，不然下一套主题的滚动会莫名其妙不动。

### 星云宇宙：两套场景同时活着，一套在屏幕上跑，另一套接指令

上一条改完之后 `flyToDay` 还是不动 —— HUD 卡在 2026-07-27，怎么点都不走。
往下挖是启动竞态：`startCosmos()` 是异步的（要 import three.js），
而 `applyTheme()` 可能在它落地之前又跑一遍 —— 首屏恢复上次主题、紧接着用户手动切，
就是这个时序。两次交错的结果是**同时存在两套场景**：
模块里的 `cosmos` 指向已经脱离 DOM 的那一份，屏幕上跑的是另一份。
于是所有 `flyToDay` 全部落到看不见的那一份上，而作废那份的 rAF 还在后台烧显卡 ——
**每切一次主题泄一套 WebGL 场景**。

改成发号作废：先收摊（`gen++` 让在途的那份自己失效），再领号，
`await import` 回来后号对不上就整份丢弃，tick 每帧也校验一次。
负控：连切三次主题再点回放，相机从 2026-08-20 一路飞到目标周（08-07 → 07-25 → 07-06 …），
此前是纹丝不动。

### 白昼耦合矩阵：线性刻度把整张图压成一片淡色

最强的一对同时出现三位数次，绝大多数只有个位数。线性映射下后者全落在
0.16–0.2 的透明度区间里，肉眼分不开 —— 一张分不出深浅的热力矩阵，
等于没画。改成开方刻度（仍然单调：强的还是强，弱的看得见了），
并在图注里写明这是开方不是线性 —— 不写就是在骗读图的人。

### 一条留给下一个 agent 的坑（这一版**没有**顺手补，理由写在下面）

`MemoryAtlas/.gitignore` 里只有 `node_modules/` —— 带斜杠只匹配目录。
而铁律 2 要求开发一律在 worktree，worktree 里没有 `node_modules`，
跑 `canonical_gate.sh` 前得把主树那份**软链**过来；软链不是目录，
于是 `git add -A` 会把它收进提交（一条指向本机绝对路径的链接）。本轮就踩了一次。

补一行无斜杠的 `node_modules` 就能堵死。但 **`MemoryAtlas/**` 是
`Memory Atlas Acceptance` 工作流的触发路径，而那条工作流在 `main` 上已经是红的**
（`tests/test_memory_atlas_local_agent_source_registry.py` 没有 capability owner，
2026-08-20 05:18 的 main 就已经失败）。动一行 `.gitignore` 会把这条与本次改动
毫无关系的红灯拖进本 PR，只剩两个选择：带红合并，或者去修别人子项目的治理欠账。
两个都不该由这个 PR 做 —— 所以这里只把坑写下来，不动那一行。

### 怎么验的

- 回放：按播放 → 滚动页面 → 相机 HUD 仍停在回放当前周（此前会跳回最新一天）。
- 竞态：连切三次主题后 `flyToDay` 仍然生效（此前无效）。
- 矩阵：同一份数据下，可分辨的深浅档位从 2 档变成肉眼可数的 5 档以上。
- 3 主题 × 12 视图 × 深浅两色 = 72 种组合复跑，0 报错 0 空白页。
- 切主题耗时复量（页面在前台，各切三轮取中位数）：琉璃 13ms、星云 5ms、白昼 8ms。
  注：同样的测量在后台标签页里会读到 400–1000ms，那是浏览器的定时器节流，不是页面慢 ——
  这条写下来是为了下次别再被这个数吓一跳。

## 0.4.2 — 2026-08-20

### 主题重排：删两套，补两套，一共三套

删掉「控制台」和「手记」。现在是三套，各自有自己的 shell / kit / views，
**不共用任何一条样式规则** —— 换主题换的是版式和交互，不是配色。

| 主题 | 主张 | 背景 | 图表长什么样 |
| --- | --- | --- | --- |
| 琉璃（默认） | 半透明面板 + 加色辉光 | 2D 粒子场 + 鼠标视差 | 星河散点、3D 力导图、竞速条 |
| 星云宇宙 | 内容浮在一整片真 3D 星图上 | WebGL：一条会话＝一颗星，一个领域＝一团星云，时间＝纵深 | 星历带、时间光谱、相机穿越回放 |
| 白昼 | 瑞士国际主义：栅格、发丝线、一个红 | 没有背景动效（纸上不该有星星） | 小倍数折线、邻接矩阵、印刷网点、百分比堆叠条 |

「星云宇宙」是照着 `home.linzezhang.com` 做对照做的。差别在一句话：
那边是先做好一个漂亮场景再往上贴数据，这边是**场景本身由数据生成** ——
4786 颗星对应 4786 条真实会话，往下滚就是往回飞，鼠标停在日历某一天，
星图会飞到那一天。数据变了星图就变，数据是空的星图也该是空的。

「白昼」是调研后补的第三套。它刻意不画 3D：同一份耦合数据在这里摊成**邻接矩阵**，
因为点线图会重叠打结，矩阵不会。三套主题各用各的强项，不是同一张图换皮。

### 切主题从「非常缓慢」变成 3–31 毫秒

原来每次切换都改同一个 `<link>` 的 href：旧样式先被移除、新样式还没到，
中间既白屏又要等一次网络往返。改成**启动时把三套 CSS 全插进去、切换只翻 disabled 布尔位**，
外壳模块在空闲时预取。实测（1440×900，本机）：琉璃 20ms、星云 31ms、白昼 3ms。

### 一级和二级菜单的区别做实

三套主题各用各的办法把层级做到一眼可辨，而不是靠缩进那 8 个像素：
琉璃／星云用「一级小型大写 + 字距 0.22em，二级正常字号 + 连接短线」，
白昼直接上编号 —— `01 时间` / `01.1 日历`。
一级 ≤5、每个一级下二级 ≤5 的约束加了机器守卫，写超了控制台立刻报错。

### 修掉的缺陷

- **HTML 被当字符串转义**，页面上直接出现 `<span class="st" ...>通</span>` 这种东西。
  根因是 kit 对所有字段统一 `esc()`，而视图往里塞了 HTML。补 `kHtml` 字段分开走。
- **星图构建成功但屏幕全黑**：4786 颗星只点亮了 0.35% 的像素。
  远处的点被 `sizeAttenuation` 压到亚像素 —— 亚像素在屏幕上就是不存在。
  给 `gl_PointSize` 加了 1.9px 下限，相机进到星管里面，星云团透明度从 0.055 提到 0.15。
- **浅色模式下星图整片消失**：加色混合在白底上等于什么都不画。
  浅色改走正常混合 + 压暗的星色，「浅色」不再等于把这套主题关掉。
- **左侧菜单压到主题按钮上**：`#nav` 是 flex 子项但没有 `min-height:0`，
  于是它不肯收缩、内容直接溢出去盖住下面。三套主题一起修。
- **缺画布的主题让全站崩溃**：白昼没有 `#fxlayer`，`initFX` 直接 `getContext` 于 null。
  「这套主题不要背景动效」是合法选择，不该是错误。

### agent 契约统一分发

新增 `atlas/AGENTS_CONTRACT.md` 与 `build/install_agents_md.sh`：
用一对哨兵注释把契约段圈起来，整段替换，段外内容一个字节不动。
一次分发到 Claude Code / Codex / DSH / Kimi Code / 工作区五个入口，
内容没变就不写文件。已接进 `daily.sh`，靠人手工同步五份文件是同步不住的。

契约里写死了收尾动作：**归档时先复审这一轮 → 写进对应仓的 AGENTS.md → 跑
`~/.memory-atlas/on-archive.sh` 推 GitHub**。Claude Code 和 Codex 已挂钩子自动触发，
Kimi Code 和 DSH 没有钩子机制，契约里明确要求手动跑那一行。

### 怎么验的

- 3 套主题 × 12 个视图 × 深浅两色 = **72 种组合逐个打开**，
  统计 `console.error` / `onerror` / `unhandledrejection` 与渲染后的内容长度：
  0 报错，0 空白页。
- 分发器负控：故意改坏一个文件，`--check` 必须报出来并以非 0 退出 —— 报出来了。
- 星图渲染用 `readPixels` 逐点回读验证，不靠"看起来有了"。

## 0.4.1 — 2026-08-20

### 接上 DeepSeek Harness（一直漏着的一个来源）

`~/.dsh/sessions` 有 **1937 个会话、216MB**，此前完全没抽。之前把 DSH 记成
「只有 Electron 缓存」—— 那说的是 `~/Library/Application Support/DSH Desktop`，
判断错了对象。

解析踩到两个坑，都写进代码注释了：
- DSH 把**每一行当成独立的 zstd 帧**追加，一个文件上千帧；
  `zstdDecompressSync` 只解第一帧，照着拿每场只得到 273 字节的元数据 ——
  1937 场全是 0 轮 0 消息，「抽到了」其实什么都没抽到。改为按魔数切帧逐个解。
- 1937 场里 **1929 场 `origin=subagent`**，是 agent 自己派生的。不标出来，
  「你亲自开口」会一夜多出近两千场。现在标为机器，真人只有 5 场。

顺带补上 provider/model：DSH 的 `request/header` 里有
`deepseek-official/deepseek-v4-pro`、`scnet/DeepSeek-V4-Flash-0731`、
`scnet/Qwen3.8-Max` —— 正是 Owner 说的 DeepSeek 与 SCNet。

### 脱敏补宽

原本只按**键名**过滤密钥，挡不住嵌在 `oauth` 下的令牌。改为按**前缀族**匹配
（oat- / dfrt- / xox / glpat / JWT 三段式 …）并加一条通用的
`*_token|*_secret|apiKey` 取值抹除。五个负控全过。

### 开发经验沉淀有地址了

权威副本推到 `LinzeColin/Private-Database` 的
`Private-AgentDatabase/dev-notes/`，推送前硬校验目标仓可见性必须是 PRIVATE。
同时在站点 `/brief/` 留一份（Access 后面）。

新增归档钩子 `on_archive.sh`：上下文压缩或会话结束时刷新沉淀并上传，
30 分钟去抖，只复审不重抽（重抽 60 秒，放钩子里会卡住 agent）。

## 0.4.0 — 2026-08-20

### 对齐 Anthropic Economic Index

上一版只做对了「五种协作模式」那一层，把它当成了 AEI 的全部。
实际读了 AEI 的三份报告之后，补齐它真正的框架：

- **五个经济原语**：任务复杂度、技能层级（术语密度代理）、用途（工作／学习／个人）、
  AI 自主度（1–5）、任务成功（三信号合成）
- **产物分类**：从工具调用派生的产出类型分布
- **行业／领域分布**：从对话原话认领域，IDF 加权，不是拍脑袋分类
- **上下文分布**：以项目／工作区替代 AEI 的地理维度（单人单地区，如实说明替代关系）
- **任务覆盖率 + 有效覆盖率**（成功率加权）
- **按领域的 token 消耗**：对标 AEI 的「按职业 token 消耗」
- **Cadence**：小时 × 星期热力
- **转换轨迹**：领域份额随时间迁移
- **ROI**：token 投入 vs 交付产出（提交／PR／Release）
- **明确列出做不到的**：O*NET 职业映射、问卷层、真实地理分布

### 导航重构

一级菜单移到左侧、可折叠；**一级不超过 5 个，每个一级下不超过 5 个二级**。

### 主题

控制台与手记两套重做；琉璃保留（上一版由 nebula 改名而来 —— 它没有任何星云元素）。

### 视图

网格、回放重做。
