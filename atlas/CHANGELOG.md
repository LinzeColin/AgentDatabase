# Memory Atlas 变更记录

版本号语义：`主.次.修`
- **主** —— 数据契约或页面结构不兼容变更（旧 atlas.json 读不了新页面，或反之）
- **次** —— 新增数据块 / 新增视图 / 新增主题
- **修** —— 只修缺陷与口径，不新增能力

每条都要写清楚：**改了什么、为什么、怎么验的**。没验过的不写在这里。

---

## 0.5.5 — 2026-08-20

**站上所有 token 绝对量都虚高约 2.3 倍。这是一个真 bug，不是口径分歧。**

### 一个 API 响应在 JSONL 里不是一条记录

`extract.py` 对每一条 JSONL 记录做 `rec["tok_cache_r"] += u["cache_read_input_tokens"]`。
但 Claude Code 把一个 API 响应**按 content block 拆成多行**（1 个 `thinking` + 6 个并行
`tool_use` = 7 行），而**每一行都带着同一份完整的 `usage`**。会话 resume 时还会把
整段历史再重放一遍。

于是同一次响应的 778,766 个 cache_read 被加了 7 遍。

**实测（全语料 1,528 个 transcript）**：322,284 条 usage 记录只对应 **130,138 个不同的
`message.id`** —— 每个响应被算了 **2.48 次**。我另外独立抽样 60 个文件复核，得 **2.26 次**。

### 修完之后，站上的数字变成这样

| 指标 | 修前 | 修后 | 虚高 |
|---|---:|---:|---:|
| 读进去的（含缓存） | 141,514,921,534 | **62,326,715,383** | 2.27× |
| 其中缓存命中 | 141,308,913,840 | **62,120,664,687** | 2.27× |
| 模型写出来的 | 392,929,062 | **150,880,732** | 2.60× |
| 缓存写入 | 1,473,984,015 | **490,454,556** | 3.01× |
| 每条提交摊到的新 token | 730,326 | **420,631** | 1.74× |
| 「最贵的一天」 | 130.8 亿 | **38.2 亿** | 3.43× |

### 为什么它活了这么久

**因为缓存命中率对它免疫。** 四类 token 一起虚高，比值几乎不动：

```
0.998544  →  0.996694
```

而命中率恰恰是这一块最常被看的数字。**一个只看比值的人永远发现不了分子分母同时错了。**

### 还有一件更糟的：虚高是不均匀的

**一轮里并行工具调用越多，虚高越狠** —— 单场从 1× 到 4.99× 不等。
也就是说**最 agentic 的会话虚高最严重**。
所以这不是「整体乘个常数」能修好的：按天/周/来源/项目的**排序都被非均匀扭曲过**。

### 改法

按 `message.id` 在单个会话文件内去重（`seen_usage` 集合）。`PARSER_FINGERPRINT` 因此变化，
下一轮会全量重解一次（实测 69.5 秒）。codex 那条支路用的是 `max()` 不是 `+=`，不受影响。

### 这条是怎么被发现的

和 0.5.3 / 0.5.4 一样，不是自查出来的 —— 是 token 效率方向的调研直接扫了
`~/.claude/projects/` 全部 transcript，把 `usage` 记录数和不同 `message.id` 数对了一遍。
**我事后独立复算过才敢改。**

## 0.5.4 — 2026-08-20

两个口径缺陷。都是「页面/简报上有这一栏，但那一栏说的不是它字面的意思」。

### 每个 agent 读到的「常见话题」全是空的

`AGENT_BRIEF.md` 的项目进入简报里，**30 个项目 30 个「常见话题：—」**。

根因：主题分类发生在 `build.py` 的 `assign_topics()`（要全语料 IDF 权重），
而 `sediment.py` 读的是抽取产物 `*.sessions.jsonl` —— 那里根本没有 `topics` 字段。
`d["topics"].update(s.get("topics") or [])` 于是永远更新一个空列表。

**没有在 sediment 里重判一遍** —— 那会变成第二个分类器，两套口径迟早给出两个答案，
到时候没人知道该信哪个。改成读 `build.py` 已经判好的那份（新增 `--atlas` 参数）。

改后：空的从 **30/30 降到 7/30**（剩下 7 个是真的一条主题都没命中，照实留空）。

### 「每场平均 213 次报错」数的是「error 这个词出现了 213 次」

`extract.py` 的口径是 `joined.lower().count("error") + joined.count("报错")` ——
数的是**会话文本里这个词出现的次数**，不是工具真的失败了几次。
一段贴进来的报错日志能一次贡献上百次「提及」。

原来的注释其实写对了（「报错**提及**最密集」），但页面上的卡片标题是
「每场平均 213.0 次报错」—— 读的人不会以为那是词频。

本轮**只改标签，不改口径**：
- 卡片标题 → 「每场平均**提到** 213.0 次 error/报错」
- 排行条数值 → 「213.0 次**提及**/场」
- 小标题 → 「按『每场会话里 error/报错 这个词出现几次』排 —— 是**消耗代理**，不是 bug 数」
- 新增 `lessons.pain_note` 把口径写进数据本身

**为什么不顺手换成真信号**：各家日志里有 `is_error` 字段（实测抽样 120 个 claude-code
会话文件，51% 含 `is_error:true`）。换成它要重解全部会话（`PARSER_FINGERPRINT` 失效），
属于能力变更不是修缺陷 —— 写进 PRD 等授权，不在这一版偷偷做。

### 这两条也是调研查出来的

和 0.5.3 一样，不是自查出来的：agent 记忆方向的调研实测了本机数据，
指出「4,814 场会话里带非空 topics 的 0 场」和「报错口径差约 17 倍」。回头一查，都对。

## 0.5.3 — 2026-08-20

**修一个我自己一直在引用的假数字。**

### 「被问过 738 次」不是有人问了 738 遍

`AGENT_BRIEF` 的头号结论一直是「最贵的一条被问过 738 次、烧掉 2.27 亿 token」。
我把这句话写进了 agent 契约、分发到 5 个入口、还当成事实向 Owner 复述过多次。

实测：**那 738 次全部发生在 2026-08-17 一天之内**，`gist` 是
「用 Read 工具打开图片 /tmp/kmvideo_work/video_sheets/…」——
**一批图片标注扇出，不是一个人问了 738 遍。**

同一个毛病在 `lessons.repeats` 里更严重：**25 组里有 21 组 `days<=1`**。
排第一的「问了 15 遍」是 2026-08-14 一天之内的一批评委打分提示词。
而 v0.5.0 的 **Primary Champion 正是建立在这份榜单上的** —— 它的头号证据
`15 遍 / 2026-08-14 → 2026-08-14` 是一次批处理。

### 为什么 `kind == "human"` 过滤没挡住

挡是挡了 —— 扇出检测（同来源同小时 ≥15 场）和批处理检测（前 80 字重复 ≥5 次）都在跑。
但**评委面板类工作流每条提示词开头都带不同的人名**（「你是 Henry Clifton Sorby #133…」），
前缀判重抓不到；而它们分散在几小时里，也够不上「同小时 ≥15 场」。

### 改法：跨天 **且** 每天 ≤5 遍

只加「跨天」这一条不够 —— 一个评委面板跑 4 天照样产出 340 条一模一样的提示词。
加上速率闸之后：

| | 改前 | 改后 |
|---|---|---|
| 判为「反复问」的组 | 41 组（含 738×/1天、340×/4天、297×/2天） | **13 组** |
| 榜首 | 「用 Read 工具打开图片…」738 次 | 「wholefood 是什么」**14 次 / 5 天** |
| 第 2、3 名 | 讲义作者 340、独立评委 297 | 「Codex Automation」10 次/10 天、「中文」9 次/2 天 |

后面那几条才是**一个人隔几天又问了一遍**。

### 两种病，两种药 —— 都留着，但绝不同名

被剔出去的没有被丢掉（丢掉的东西不参与校验，总量就永远显得是对的）：

| 类别 | 判据 | 说明 | 该做什么 |
|---|---|---|---|
| **跨天复发** | 跨天 且 每天 ≤5 遍 | 上一次的答案没留下来 | 写进对应仓的 `AGENTS.md` |
| **批量重放** | 其余 | 同一段提示词被机器/手工重放 N 遍 | 做成脚本/workflow，把提示词参数化 |

落点：`AGENT_BRIEF.md` 拆成「一、隔天又问过的事」与「一之二、被批量重放的提示词」；
「转化」页的沉淀债务同样拆成 `repeat_no_asset` 与 `batch_no_script` 两类。

### 这条是怎么被发现的

不是我自查出来的 —— 是这一轮 AEI 方向的调研在核对 AEI 的「有效样本门槛」
（≥15 对话且 ≥5 个账号）时，顺手指出本机把「没测出来」当成了「测出来是第三类」，
并点名 `repeats` 榜单前 6 名里至少 5 名是机器批次。**回过头一查，是真的。**

## 0.5.2 — 2026-08-20

只修一个缺陷，但它是**最危险的那一类**：定时任务会静默跑出半份数据。

### cron 拿不到 `gh` 和 `node`，而且不会喊

每日任务的入口 `bootstrap.sh` 从来没设过 `PATH`。cron 是非交互 shell，不读 `~/.zshrc` ——
实测本机在最小 PATH 下这两个**根本找不到**：

| 工具 | 真实位置 | 最小 PATH 下 |
|---|---|---|
| `gh` | `~/.local/bin/gh` | ✗ |
| `node` | `~/.local/bin/node` | ✗ |
| `python3` / `rsync` / `ssh` / `git` / `tar` | `/usr/bin/` | ✓ |

后果不是「报错退出」，是**静默降级**：

- `node` 缺 → `extract.py` 解 DSH 那 1937 场会话要走 `helpers/dsh_reduce.js`，直接哑掉
- `gh` 缺 → `github.py` 拿不到交付数据；`push_brief.sh` 与 `sync_compound.sh`
  各自 `command -v gh || exit 0`，**退出码 0，日志里看着像成功**

然后站点照常渲染、照常显示「数据截至」，只是里面少了一大块。没有任何一处会喊。
**这正是 MEMORY 里「换机六类静默失效」那一条的形状** ——「配置一致 ≠ 能用」。

同一台机器上 `~/.dsh/cron/daily-sync.sh` 早就写了这一行，我这边漏了。

### 怎么改的

1. `bootstrap.sh` 显式 `export PATH="$HOME/.local/bin:/opt/homebrew/bin:/usr/local/bin:..."`。
2. 加**起飞前检查**：7 个必需工具缺任何一个就写日志并 **exit 1 中止本轮**。
   为什么是中止而不是继续：**缺一半数据的一轮比不跑更坏** ——
   站点会用它覆盖上一轮的完整数据，而顶部的「数据截至」还是新的，看起来一切正常。
3. `push_brief.sh` / `sync_compound.sh` 缺 `gh` 时不再只说「跳过」，
   改成「**本轮没有推送**（不是没变化，是根本没跑）」并打印当前 PATH。

### 怎么验的

把起飞前检查那一段**单独摘出来**跑正负控 —— 不能拿 `bootstrap.sh` 本身当测试，
它会一路跑到生产部署（本轮就误跑过一次，内容与 v0.5.1 一致、自检全绿，无害但不该发生）：

- 负控：`PATH=/nonexistent-bin` → 列出 7 个缺失工具、写日志、**exit 1** ✓
- 正控：真实 PATH → 放行 ✓

时间线：cron 条目 `10 3 * * *`（悉尼）装于今天 14:48，**首次触发是明早 03:10** ——
也就是说它一次都还没跑过，这个缺陷是在它第一次触发**之前**发现并堵住的。

## 0.5.1 — 2026-08-20

只改文案与信息主次，不动任何口径与结构。

### 「转化」那一屏的机器用语让位给中文

漏斗六档原本显示成 `CAPTURED　发现候选` —— 英文在前。
但 `CAPTURED` 这类词是 **schema 名，是给 agent 写事件时用的契约**，
不是给人读这一屏时该先看到的东西。改成中文在前、英文降到数值旁边的注脚位：

| 位置 | 改前 | 改后 |
|---|---|---|
| 漏斗行标题 | `CAPTURED　发现候选` | `发现候选` |
| 漏斗行数值 | `1` | `1　CAPTURED` |
| 状态变化表 | `QUALIFIED　证据够了` | `证据够了` |
| 候选全表首列 | `ADOPTED　被第二个任务用了` | `被第二个任务用了` |
| Champion 副标 | `QUALIFIED` | `漏斗六档里的第 2 档` |
| 无事件提示 | `还没有收到任何 closeout 事件` | `还没有收到任何收尾事件（closeout）` |

这条是照着 Owner 早前那句「机器用语太多了」来的 —— v0.4.2 修的是转义泄漏，
这次修的是**主次**：英文没删（agent 写事件要照着它填），只是不再占主位。

## 0.5.0 — 2026-08-20

新增一个数据块、一个视图、一条收发链路。**沉淀（做过什么）→ 转化（变成了什么）。**

### 为什么加这一层

Memory Atlas 到 v0.4.x 已经能回答「时间去哪了」。它答不了下一个问题：
**这些时间最后沉淀成了什么？被第二个任务复用了吗？离经济结果还有几步？**

这一版补的就是这段闭环。北极星没变，也没有新造第二个产品 ——
新的一屏挂在「档案」下面，紧跟「沉淀」。

### 两个平面，一条事实链

```
A 确定性信号面（每天/归档触发，零模型）
  repeats / pain / 烧得贵却没产出 / GitHub 交付信号
                ↓
B 语义事件面（ChatGPT 定时任务 或 agent 收尾）
  memory_atlas.compounding_event.v1
                ↓
C 复利投影（atlas/build/compound.py）
  CAPTURED → QUALIFIED → EXPERIMENT → ADOPTED → OUTCOME → ECONOMIC_IMPACT
                                          ↘ HOLD / REJECT
```

**Atlas 的日常流水线仍然零 token、零 agent。** 语义判断由 B 面产出，
`compound.py` 只做形状校验、合并、去重、状态投影 —— 运行期不调用任何模型。
这条红线不因为新功能破例。

### 三条由代码执行的纪律（不是写在文档里的君子协定）

1. **「做完了」不等于「被采用」。** 文件写完、commit、部署成功，都只是 OUTCOME 之前的事。
2. **没有采用证据不许升到 ADOPTED；没有 OBSERVED/VERIFIED 的经济证据不许升到 ECONOMIC_IMPACT。**
   事件里声称更高的，系统按证据**压回去**，并在页面上「被压回去的」那张表里点名 —— 可审计。
3. **金额未知就是未知。** 不自动填 0 —— 0 是一个断言（「没赚到」），
   而真实状态是「没有可核的金额入口」。两件事不能混。

这三条各自都有负控测试守着（见下）。**只写在文档里的规则等于不存在。**

### 新的一屏：档案 → 转化

顺序是固定的，因为 Owner 打开它应该先拿到一个**决定**，不是更多数字：

1. **这周最值得转化的一件事** —— 一个 Primary Champion：是什么、为什么是现在、
   7 天做什么、30 天要看到什么、什么情况下停手。允许 NO_PROMOTION —— 逼着每周造一个新
   Skill 是把这套东西做坏的方式。
2. **做了很多，但还没变成结果** —— 沉淀债务。这比「又找到一个新 Skill」重要：
   新 Skill 是增量，债务是漏水的地方。四类，全部从本机记录确定性派生，每条都指得回具体证据：

   | 类型 | 判据 |
   |---|---|
   | 问了很多次，还没固化 | 同一个问题被问 ≥3 遍（`lessons.repeats`） |
   | 烧得很贵，没有可观测产出 | 当天 token 高但 GitHub 0 提交 |
   | 反复出错，还没有守卫 | 每场平均报错 ≥1 次的项目 |
   | 上过线，没有第二次复用 | 谈过部署但此后几乎没再被碰 |

3. **转化漏斗** —— 强调**状态变化**，不只是累计数量。
4. **价值实现** —— 七条真实路径分开列（直接收入／销售线索／成本下降／少踩一次坑／
   资产被复用／改变了决策／领先指标），金额未知就显示未知。
5. **最近的归档变化** —— 只放新教训、别再犯、未了事项，不放完整聊天。
6. **失败有没有变成防复发资产** —— 只有「根因已证实」且「已有可复用守卫」的才算复利，
   普通报错不许冒充。

没有任何语义事件时，这一屏如实显示 **说不准 + 「还没有收到任何语义事件」**，
下面照常给出派生的债务信号 —— 不是假 0，也不是空白页。

### 收发链路

- `atlas/build/sync_compound.sh pull` —— 从私有仓拉语义事件进本机收件箱
- `atlas/build/sync_compound.sh push` —— 把派生投影回推私有仓
- 两个方向都硬校验目标仓可见性必须是 PRIVATE（与 `push_brief.sh` 同一道门，
  故意不共用代码：任一处被改坏时另一处还在）
- 已接进 `daily.sh`：抽取 → **拉事件** → 构建 → 沉淀 → 推简报 → **推投影** → 部署

### 沉淀地址统一到 `dev-notes` 分支

此前流水线推 `main`，而另一些 agent 往 `dev-notes` **分支**写项目经验 —— 两条事实链。
Owner 指定的地址是分支那一条，于是 `push_brief.sh` 的默认分支改成 `dev-notes`，
main 上那份 README 改成一块路牌（明说「不再更新，照着读会拿到过期数据」）。
**静默陈旧比缺失更坏**，所以留路牌而不是留内容。

### agent 契约加一节

《收尾必须回写》后面补了「产一条成果复利事件」：最小 schema、推到哪、
以及四条硬规矩（做完≠被采用、没证据别写高、金额未知留 null、别放完整聊天）。
已分发到 Claude Code / Codex / DSH / Kimi Code / 工作区五个入口。

### 怎么验的

- **21 条负控**（`atlas/build/test_compound.py`，全部通过）。这些测的不是「能不能跑通」，
  是**能不能挡住不该通过的东西**：
  - 声称 ECONOMIC_IMPACT 但零证据 → 压到 CAPTURED
  - 声称 ADOPTED 但只有一条证据 → 压到 QUALIFIED
  - 金额只是 ESTIMATED → 最高 OUTCOME
  - 金额 OBSERVED → 才允许 ECONOMIC_IMPACT
  - 压回去的动作必须留痕（否则页面上看不出它本来声称更高）
  - 未知金额保持 `null`，没有被填成 0
  - 4 条失败输入里只有 1 条算形成防复发资产
  - 空输入时状态不是「通」、champion 是 `null` 而不是占位对象
  - 坏 JSON / 错 schema / 缺 event_id 三种都被拒收**且说出原因**（不静默跳过）
- **3 主题 × 13 视图 × 深浅两色 = 78 种组合**逐个打开：0 报错、0 空白页、0 个首屏透明节点。
- 拉取链路对**真实私有仓**跑过：远端还没有 `compounding-events/` 时如实报「尚无事件」并跳过，

原来每次切换都改同一个 `<link>` 的 href：旧样式先被移除、新样式还没到，

三套主题各用各的办法把层级做到一眼可辨，而不是靠缩进那 8 个像素：

白昼直接上编号 —— `01 时间` / `01.1 日历`。
一级 ≤5、每个一级下二级 ≤5 的约束加了机器守卫，写超了控制台立刻报错。

## 0.4.1 — 2026-08-20

### 接上 DeepSeek Harness（一直漏着的一个来源）

`~/.dsh/sessions` 有 **1937 个会话、216MB**，此前完全没抽。之前把 DSH 记成
「只有 Electron 缓存」—— 那说的是 `~/Library/Application Support/DSH Desktop`，
判断错了对象。

解析踩到两个坑，都写进代码注释了：
- DSH 把**每一行当成独立的 zstd 帧**追加，一个文件上千帧；
  `zstdDecompressSync` 只解第一帧，照着拿每场只得到 273 字节的元数据 ——
  1937 场全是 0 轮 0 消息，「抽到了」其实什么都没抽到。改为按魔数切帧逐个解。
- 1937 场里 **1929 场 `origin=subagent`**，是 agent 自己派生的。不标出来，
  「你亲自开口」会一夜多出近两千场。现在标为机器，真人只有 5 场。

顺带补上 provider/model：DSH 的 `request/header` 里有
`deepseek-official/deepseek-v4-pro`、`scnet/DeepSeek-V4-Flash-0731`、
`scnet/Qwen3.8-Max` —— 正是 Owner 说的 DeepSeek 与 SCNet。

### 脱敏补宽

原本只按**键名**过滤密钥，挡不住嵌在 `oauth` 下的令牌。改为按**前缀族**匹配
（oat- / dfrt- / xox / glpat / JWT 三段式 …）并加一条通用的
`*_token|*_secret|apiKey` 取值抹除。五个负控全过。

### 开发经验沉淀有地址了

权威副本推到 `LinzeColin/Private-Database` 的
`Private-AgentDatabase/dev-notes/`，推送前硬校验目标仓可见性必须是 PRIVATE。
同时在站点 `/brief/` 留一份（Access 后面）。

新增归档钩子 `on_archive.sh`：上下文压缩或会话结束时刷新沉淀并上传，
30 分钟去抖，只复审不重抽（重抽 60 秒，放钩子里会卡住 agent）。

## 0.4.0 — 2026-08-20

### 对齐 Anthropic Economic Index

上一版只做对了「五种协作模式」那一层，把它当成了 AEI 的全部。
实际读了 AEI 的三份报告之后，补齐它真正的框架：

- **五个经济原语**：任务复杂度、技能层级（术语密度代理）、用途（工作／学习／个人）、
  AI 自主度（1–5）、任务成功（三信号合成）
- **产物分类**：从工具调用派生的产出类型分布
- **行业／领域分布**：从对话原话认领域，IDF 加权，不是拍脑袋分类
- **上下文分布**：以项目／工作区替代 AEI 的地理维度（单人单地区，如实说明替代关系）
- **任务覆盖率 + 有效覆盖率**（成功率加权）
- **按领域的 token 消耗**：对标 AEI 的「按职业 token 消耗」
- **Cadence**：小时 × 星期热力
- **转换轨迹**：领域份额随时间迁移
- **ROI**：token 投入 vs 交付产出（提交／PR／Release）
- **明确列出做不到的**：O*NET 职业映射、问卷层、真实地理分布
